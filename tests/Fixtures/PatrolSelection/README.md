# Source patrol area selector expectations

The TSV contains literal candidate order for all16 linked-ID masks, independently
written from `Things_Paths.c:1018–1068`: Insert skips areas whose nextid is nonzero,
Append keeps the physical list order and all five IDs. It does not use Core's
selection filtering implementation. ID5 supplies a valid unlinked occurrence so
source command availability is satisfied in every case. Both native and DKM
checks mutate physical IDs to3,1,4,2,5 before creating the manager. Viewing and
cancel checks compare complete live buffers, local lists, counters and history.

These are model/source expectations. The original C/GUI and actual EN/RU WPF
controls are not executed by the fixture. Preserved packed next/wait offsets are
native31/24 and project52/56; acceptance byte expectations are encoded literally
and checked independently of the product field schema.
