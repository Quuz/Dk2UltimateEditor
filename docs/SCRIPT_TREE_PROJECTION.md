# Original scenario tree topology

The preserved `Triggers_SelectCreateNewTrigger` creates the AND subtree under the condition and its OR continuation under the same parent as the condition. `Triggers_SelectCreateNewAction` likewise adds the next event under the same parent; actions have no children. `ScriptTreeProjection` now preserves this topology, with explicit empty AND/root placeholders for connection editing and leaf markers for missing, shared and cyclic targets. It never treats native ACTION.ChildAnd payload as a link.

Traversal uses iterative enter/exit steps. Flat OR/next chains do not consume child depth. Actual ancestor paths still include preceding siblings for cycle detection. Rendering limits do not change graph reachability: deeply connected events hidden by a limit are not listed as unlinked components. Unlinked heads are selected before their continuations, including a negative/signed project action ID followed by a smaller positive condition ID.

The WPF view captures incoming parent event IDs and the project link's scope/owner fields before records move. Selection is restored by connection, not just by event ID. This handles ACTION shifts after condition insertion and TRIGGERLINK shifts after earlier binding deletion. Containers are explicitly deselected before replacing ItemsSource because WPF can otherwise retain a removed hierarchical SelectedItem. If a renamed/removed parent cannot be resolved and multiple displayed occurrences remain, selection is cleared; the view does not silently choose another shared parent.

Regression evidence: native/project fixtures verify exact hierarchy, empty/missing contexts, shared/cycle distinctions, orphan-head order, budgets, unchanged bytes and no change notifications. Two temporary native maps hold 6000-event flat/deep chains; full flat rendering at a larger test-only entry budget and bounded deep rendering both terminate. Four WPF EN/RU × native/project cases verify actual tree contents, action leaves, reserved bytes, live translation, exact incoming selection after insertion/undo/redo, shared-root selection after binding compaction, safe ambiguous-selection clearing and closed-document cleanup. Existing branch buttons and loaded-map cases are rerun against the new hierarchy. See the [parity ledger](FEATURE_PARITY.md) for current suite totals, including later selection-buffer coverage.
