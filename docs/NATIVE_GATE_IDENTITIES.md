# ID ворот в рабочем документе

15 октября 2026, NativeGateIdentity-20261015. Рабочие ID теперь сохраняются
после удаления других ворот, в истории, вложенных копиях, генераторе,
конвертации DKM и в результате компиляции DKM. В игровом комплекте остаётся
ровно семь файлов; новые игровые поля или дополнительные KLD не создаются.

## Правила исходного редактора

`Files_Game.c` при чтении назначает несердечным GAMEGATE последовательные
редакторские ID от1, независимо от `bGateID`. Сердца типа14 в MapGates не входят.
`RectEx_GetGateAtMapPos` выбирает первые ворота с точными координатами,
а ACTION_DESTROYGATE сохраняет их ID в `param5`. Отсутствующая цель получает0.

`RectEx_GetFreeID` ищет первый свободный положительный ID. Команда добавления
отказывает, если первый свободный ID больше255. Удаление освобождает ID ворот,
но само по себе не переписывает `ACTION.param5`. Поэтому новые ворота с этим ID
снова становятся целью прежнего действия, даже в другой точке карты.
Writer получает текущую позицию через ID и записывает два WORD с прибавлением1.
Для отсутствующего ID writer использует `1,1`; ID0 не выделяется новым воротам.

Снимки функций и SHA256 исходников находятся в
`artifacts/Evidence/NativeGateIdentity-20261015/source-capture.json`.
Удаление DKM ворот с входящим действием реализовано в
[ProjectGateRemoval](PROJECT_GATE_REMOVAL.md). Остаются общие подтверждения
удаления и их suppression/remember, точный порядок после исходного Undo ворот.
Сверка `Triggers_GetFirstTrigger` и `Triggers_IsUsed` показала, что при
SCOPE_GATE ссылка только из ACTION_DESTROYGATE не устанавливает Used=TRUE;
ветвь отдельного used-dialog не достигается. Это вывод из исходного кода,
а не результат физического запуска старого редактора. Лишний DKM guard
входящих ссылок исправлен в ProjectGateRemoval; другие entity guards сохранены.
Историческая фиксация найденного расхождения сохраняется в
`artifacts/Evidence/NativeGateIdentity-20261015/next-used-gate-work.json`.

## Текущая реализация

`NativeGateBindings.cs` сохраняет таблицу физических адресов, редакторские ID
ворот и отдельный ID цели каждого физического действия. Физический порядковый
номер включает сердца, логический ID — только проверенные несердечные ворота.
Удаление ребазирует адреса, освобождает ID и сохраняет ID цели действия.
Добавление/дублирование ворот и генератор используют первый свободный ID.
Повторное использование ID проецирует только два координатных WORD зависимых
действий. Остальные байты действия, его ID, связи и резервные поля сохраняются.

Копирование сценария сохраняет также отсутствующий ненулевой ID цели.
Неизвестная цель0 не захватывается появившимися воротами в точке fallback.
Замена ворот удалением и вставкой в одной внешней операции работает и при
совпадающей позиции. Операция имеет общий Undo, счётчик и уведомление;
сбой откатывает игровые буферы и всю рабочую таблицу. При глубине истории0
правила ID действуют без хранения Undo.

Просмотр и синхронизация рабочей таблицы не меняют игровые координаты.
Generic Resize сохраняет прежний raw-контракт. Вложенные копии содержат полную
таблицу; мастер сценария разрешает менять связь своего действия, но запрещает
изменять таблицу ID ворот или связи других действий. Общее окно свойств карты
по-прежнему разрешает только свои настройки, а не произвольное добавление ворот.

Выбор ворот в интерфейсе EN/RU показывает действительный рабочий ID и координаты,
вместо порядкового номера строки. Текстовые ресурсы остаются прежними.

## Внутренний формат D2GB, версия2

Это внутренний NativeFile `#GateBindings`: он участвует в истории и защищённом
source ZIP проекта, но не входит в `Files`, ссылки KWD или игровой экспорт.
Все числа little-endian, адреса и ID — Int32, координатные stamps — UInt16.

| Часть | Байты | Содержимое |
| --- | --- | --- |
| Заголовок | 20 | Signature D2GB, version2, полная длина, число действий, число ID ворот; по4 байта |
| Строка действия | 24 | Файл D2 +0, смещение +4, файл BE +8, ordinal ворот +12, WORD X +16, WORD Y +18, ID цели +20 |
| Строка ворот | 12 | Файл BE +0, ordinal +4, редакторский ID +8 |

Адрес отсутствующих ворот — `-1,-1`; ID цели при этом может оставаться
положительным. Проверяются размер, версия, предел миллиона строк каждого
вида, адреса, уникальность физических действий и уникальность ID/адресов ворот.
Обычный импорт может содержать более255 ворот; чтение не ремонтирует такие карты.
Новая команда всё равно требует свободный ID в диапазоне1–255.

Прежняя версия1 (заголовок16/строка20) читается. Живой адрес получает рабочий ID
при обновлении таблицы. Уже потерянный в старой версии ID удалённой цели
восстановить достоверно невозможно: она остаётся целью0. Обновление метаданных
не переписывает игровые файлы.

## DKM и игровые файлы

Конвертация использует сохранённые ID, включая разреженные и повторно занятые;
действие получает именно свой `param5`. Отсутствующая ненулевая цель сохраняет
ID и блокирующую диагностику; политика компиляции отсутствующих целей не смягчена.
Компиляция DKM переносит исходные ID в рабочий native результат, включая выбор
между двумя воротами в одной точке. Компилятор отдельно обрабатывает временно
создаваемые сердца, чтобы они не занимали диапазон редакторских ID.

Экспорт KWD/KLD сохраняет исходный формат без редакторских ID. При повторном
открытии обычного игрового KWD ID снова назначаются последовательно, а цель
определяется координатным reader. Для сохранения рабочего выбора используйте DKM.

## Подтверждение и ручная приёмка

`NativeGateIdentityChecks` проверяет буквальные ID1/2, освобождение и повторное
использование1, точные байты действия, клонирование отсутствующей цели,
неприобретение цели0, замену в одной транзакции, полные Undo/Redo/rollback,
нулевую историю, Cancel/Apply родительского resize, разреженные ID7/9 через
реальный compiler, генератор, чтение буквальной версии1, предел255/отказ256
и семифайловый экспорт с последовательными ID после обычного повторного открытия.
Интеграционные проверки охватывают конвертацию, архивы, сохранение, удержание
native payload, сценарии, resize и вложенную генерацию. Результаты текущей DLL
и полного корпуса — в [CURRENT_STATUS](CURRENT_STATUS.md).

Вручную: создать двое ворот, выбрать первые в действии уничтожения; удалить
первые, затем добавить новые в другом месте. Оставшиеся старые ворота сохраняют
ID2, новые получают1 и становятся целью действия. Проверить Undo/Redo,
сохранение DKM и выбор в EN/RU. После обычного открытия экспортированного KWD
ожидается новое последовательное назначение ID. Игровой тест — только
`DK2Preview_6a88240eaf814f78` через
`DKII-DX.exe -q -level DK2Preview_6a88240eaf814f78`.

Окна, renderer, звук, системные диалоги и игру агент не запускал.
