# Удаление области и патрульная цепочка

15 октября 2026. Команда удаления регионов обрабатывает выбранные записи
в порядке отображения списка. После удаления области первая оставшаяся область,
чей `nextid` указывал на удалённую, получает её исходящий `nextid`.
Например, удаление B из A → B → C превращает маршрут в A → C.
Если несколько областей ссылались на B, меняется только первая в физическом
порядке карты. Остальные ссылки не исправляются автоматически.

Правило взято из `RectEx_RemoveRects` в `Source/Sources/Things/Things_RectEx.c`:
сохранить `SavedId`/`SavedNextId`, удалить запись, пройти MapAreas и завершить
поиск после первого изменения. Порядок группового удаления влияет на результат
для неоднозначных цепочек; он не заменяется сортировкой по смещениям файла.
Смещения ещё не удалённых записей пересчитываются после каждого удаления.

Операция одинаково работает с DKM MAPRECTEX и native GAMEAREA. Меняется только
поле следующей области: DWORD по смещению52 в MAPRECTEX или BYTE по смещению31
в GAMEAREA. Удаление, изменение связи и заголовков коллекции входят в одну
транзакцию, один шаг Undo и одно увеличение счётчика. Undo возвращает полные
прежние буферы, Redo повторяет результат. Поздний отказ в том же пакете
откатывает уже выполненные удаления и переадресации; запомнённое подтверждение
остаётся настройкой сеанса вне истории.

Низкоуровневый `DeleteRecord` сохраняет прежний запрет удаления ссылочной
области. Исключение для входящих патрульных `nextid` действует только внутри
подтверждённой команды удаления регионов на этапе AreaRemovalPatrol. Следующий
этап [USED_AREA_REMOVAL](USED_AREA_REMOVAL.md) добавил второй вопрос Yes/No/Cancel,
сохранение orphan scopes и source-политику сценарных ссылок областей/эффектов.
Generic reference guard и защита неизвестных layouts сохраняются.
Подробности общего вопроса — [REGION_REMOVAL_CONFIRMATION](REGION_REMOVAL_CONFIRMATION.md).
Порядок регионов после Undo в исходнике остаётся отдельной задачей E;
согласованный пользователем полный Undo предметов сохранён.

Проверки используют независимый oracle полных буферов:60 native/project
сочетаний графа и порядка удаления, простая цепочка, несколько предшественников,
циклы, самоссылки, отсутствующая цель и удаление всех областей. Два дополнительных
случая проверяют полный rollback при отказе на более поздней записи. Общий
API с reference guard и canonical field schema также проверяются отдельно.
Результаты сборки/CLI и SHA DLL — в [CURRENT_STATUS](CURRENT_STATUS.md),
исходный фрагмент — `artifacts/Evidence/AreaRemovalPatrol-20261015/source-capture.json`.

Физические окна и игра агентом не запускались. Ручной случай на копии карты:
создать A → B → C, удалить B через список областей, убедиться в A → C,
затем проверить Undo/Redo. Для игры используется только
`DK2Preview_6a88240eaf814f78` через `DKII-DX.exe -q -level DK2Preview_6a88240eaf814f78`.
