# Состав и заголовки отрядов в мастере точки сценария

21 октября 2026. Этап ScenarioPointBandDetails-20261021, часть I13.

В мастере добавления/изменения точки сценария восстановлены два представления
из `Triggers_PointDlgParamsInit` в Triggers_ActionPoints.c:

- На странице отрядов8 заголовок является кандидатом владельца. Под ним
  показаны участники отряда: имя существа, уровень, отметка лидера, его цель
  и номер области для цели23. Эти подробности нельзя выбрать владельцем.
- На странице участников16 каждый отряд имеет недоступный заголовок.
  Владельцем выбирается конкретный участник, если существующий
  `ScenarioPointOwnerChoice.CanSelect` разрешает выбор. Строка содержит
  те же подробности и картинку существа.

Отряды и их участники сохраняют физический порядок записей и слотов.
Повторяющиеся/нулевые ID отрядов не объединяются и не перенумеровываются.
Соответствие владельцу определяется файлом, смещением, длиной записи и
индексом участника, с отдельной ссылкой BandRecord для native. Показ не
выдаёт новой authority и не обходит reserved/duplicate/already-bound guards.

Состав показывается до первого неактивного слота, максимум16. Для project
это исходный isvalid, для native — ненулевые creature ID/behavior. Импортированный
хвост после пропуска остаётся в байтах файла и не становится дополнительным
видимым кандидатом в мастере. Базовые API владельцев и их политики не менялись.
Пустой отряд сохраняет заголовок. Неизвестные creature ID/objective/raw level
не исправляются; отображаются исходные значения. Для неизвестного существа
используется существующий общий значок400 из источника мастера.

`ReadScenarioPointBandPreviews` возвращает снимок по текущей приватной сессии.
Он использует тот же выделенный читатель, что существующие списки сценарных
параметров. Их проверка повторена, поскольку общий код чтения действительно
изменён выделением метода. Структуры/native offsets/исторические поля и
правила числового чтения остались прежними.

`ScenarioPointBandRows.Build` соединяет снимок с текущими допустимыми Choices
через индекс физических владельцев. Это линейное построение, без поиска всех
owners заново для каждой строки. Заголовки16 и подробности8 не содержат Choice.
UI не даёт им фокус, а программная попытка выбрать такую строку восстанавливает
предыдущего допустимого владельца. Значение выбранного владельца не сбрасывается.

Снимок лениво создаётся при первом показе типа8/16 и повторно используется при
смене языка. Иные страницы мастера не читают весь состав отрядов. Пользовательское
имя project-отряда сохраняется буквально; native-формат не получает выдуманного
имени. Изменение документа делает сессию устаревшей по прежним guards, а старый
снимок не начинает незаметно читать новые байты.

Новые ключи EN/RU и BMP не добавлены. Использованы существующие переводчик
`ScenarioBandPreviewRows`, строки целей и оригинальные картинки. Apply/Finish,
Cancel, allocation identities, counters, Undo и компилятор не менялись.

Ручная проверка: откройте новую точку сценария и выберите тип «Отряд».
Под отрядами должен быть состав, выбирать можно только заголовок. Затем
вернитесь и выберите участника отряда: заголовки должны быть недоступны,
участники — доступны согласно прежним ограничениям. Проверьте EN/RU,
сохранение выбора, leader/objective/area, прокрутку и DPI. Для осмотра не
нужно нажимать Finish: закройте мастер через Cancel. Эта проверка пока не
выполнена; редактор, игра и Computer Use не запускались.
