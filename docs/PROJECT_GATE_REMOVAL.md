# Удаление ворот DKM с входящим действием

Обновление24 октября: [исходный compiler fallback](COMPILER_GATE_FALLBACK.md)
теперь1,1 при отсутствующем ID. Прежний лишний отказ исправлен по writer
и validator исходника; удаление и остальные guards не менялись.

15 октября 2026, ProjectGateRemoval-20261015. Из общей защиты ссылок удалён
лишний запрет на удаление проверенных проектных ворот. Действия уничтожения
сохраняют ID цели и все свои байты. Предупреждение об отсутствующей цели,
проверка перед компиляцией и защита остальных видов ссылок сохраняются.

## Что следует из исходника

`RectEx_RemoveRects` после общего подтверждения вызывает
`Triggers_IsUsed(..., SCOPE_GATE)`. `Triggers_GetFirstTrigger` проверяет
владельцев сценариев, но не SCOPE_GATE; этот бит не пересекается с проверяемыми
битами владельцев. Поэтому для ворот Used оказывается FALSE.
Ветка ACTION_DESTROYGATE проверяет `param5` и переходит к Done, не устанавливая
Used. В результате функция возвращает `-1`, а отдельный used-dialog ворот
не достигается. Затем удаляется запись ворот, `ACTION.param5` остаётся прежним.
Снимки функций, значения scope bits и SHA256 находятся в
`artifacts/Evidence/ProjectGateRemoval-20261015/source-capture.json`.
Это сверка исходного кода, не физическая проверка его GUI.

## Изменение текущего кода

В `IdentityEditing.cs`, после проверки известных layouts, разрешено удаление
`Project.MAPRECTEX` с EntityKind.Gate. Проверки входящих ссылок для областей,
отрядов и эффектов не менялись. Защита входящих связей сценариев, проверка
принадлежности записи документу и отказ при неизвестных layouts сохраняются.
Native ворота не имеют проектного ID в игровом поле `bGateID`; их отдельная
[рабочая модель ID](NATIVE_GATE_IDENTITIES.md) не менялась этим блоком.

Удаление использует прежний `DeleteLegacyRecord`: из раздела KREC удаляется
только выбранная запись, размер раздела уменьшается, остальные записи и
разделы сохраняются буквально. Действия не удаляются и не переподключаются.
Обычная операция даёт один счётчик/Undo/уведомление; модельное пакетное удаление
в одной внешней `Edit(...)` имеет общую отмену. Ошибка внешней операции
восстанавливает целые буферы. При глубине истории0 удаление работает без Undo.

После удаления EntityReferenceDiagnostics сообщает DK2N026 о ненулевой
отсутствующей цели. Проверка не меняет карту. Такой незавершённый DKM можно
сохранить и снова открыть с тем же ID. Компиляция в игровую карту записывает исходный fallback1,1,
когда цель отсутствует. Логический ID в DKM не меняется. Добавление ворот занимает первый свободный ID;
если он совпал с сохранённым `param5`, действие снова получает цель.
Копирование действия также сохраняет отсутствующий ID.

## Подтверждённые проверки

`ProjectGateRemovalChecks` удаляет первые, средние и последние из трёх ворот,
на которые ссылаются два действия. Независимый oracle удаляет буквальный
диапазон записи из ожидаемого KREC и меняет только DWORD размера +8;
все игровые разделы и все байты действий сравниваются целиком.
Проверяются счётчик/один Undo/одно уведомление, Undo/Redo, rollback,
нулевая история, пакетная операция, отказ для ссылочных областей/отрядов/
эффектов/сценариев и чужой записи. Есть реальный DKM Save/reopen с отсутствующей
целью, исходный compiler fallback1,1, клонирование действия, повторное использование ID1,
буквальные WORD16/18 в результате compiler и ровно семь файлов экспорта.

Общая проверка typed identities теперь отдельно требует source удаления ворот
с сохранением действия и прежнего отказа для остальных entity kinds.
Результаты текущей DLL и полного упорядоченного корпуса — в
[CURRENT_STATUS](CURRENT_STATUS.md).

## Ручная приёмка и остаток

В DKM создать двое ворот и действие уничтожения первых. Удалить первые через
существующую команду с подтверждением. Должны сохраниться действие с ID1,
вторые ворота с ID2 и предупреждение об отсутствующей цели. Проверить общий
Undo/Redo, DKM Save/reopen; затем добавить новые ворота в другой точке.
Они должны получить1, действие — выбрать их, компиляция — использовать новую
позицию. Игровая проверка только с `DK2Preview_6a88240eaf814f78` через
`DKII-DX.exe -q -level DK2Preview_6a88240eaf814f78`.

[Общее подтверждение и remember/suppression](REGION_REMOVAL_CONFIRMATION.md)
с REQUEST_RECTEXKILL реализованы отдельно. Специальные решения об используемых
областях/ссылках, полнота менеджера и физическая modal/ENRU/DPI/игровая приёмка
остаются. Отдельно остаётся исходный порядок ворот после Undo удаления;
согласованный полный Undo удаления предметов этим не изменяется.
Этот блок не закрывает все23 области [FEATURE_PARITY](FEATURE_PARITY.md).
