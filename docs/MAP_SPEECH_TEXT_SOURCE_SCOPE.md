# Source scope: map speech and text workflows

Read-only source audit and initial resource prerequisite, 2026-10-07. The subsequent [named metadata/browser/playback-route implementation](MAP_SPEECH_TEXT.md) follows this audit; prerequisite counts below remain historical component evidence. Neither stage replaces the full editor-parity objective or game acceptance. Original source/game resources are not modified.

## Speech dialog

`Properties_Map_Voices.c` and resource dialog **6804** edit the 32-byte `SpeechFile` plus five WORD values: `SpeechPreLevelID`, `SpeechWinID`, `SpeechLooseID`, `SpeechNewsID`, `SpeechGenericPreLevelID`. The parent map-properties draft is accepted atomically by `Properties_Map_Global.c`, not an immediate series of child writes. Changing the selected bank does not reset the five IDs; choosing None clears the bank only. Imported unknown names/IDs must not be silently cleared by modern controls.

`BuildList` enumerates folders under `Data/Sound/sfx`, uppercases and retains names beginning `SPEECH_`, with a None entry. It does not require that each folder contain a usable bank. In this installed game, the three demo folders lack their expected HD.SDT files: retain the choice and show resource unavailability, do not fabricate audio or remove metadata. The actual resource path is `<folder>/<folder>HD.SDT`.

ID inputs have the source **0..Mentor-count** bound, not the selected custom-bank count. `Init` reads `SPEECH_MENTOR` and falls back to **1505** if unavailable. Zero means no sound, while list/payload IDs are **1-based**. A custom bank may contain fewer sounds than Mentor: this must not invalidate a retained metadata ID or index below zero. Source listbox selection/double-click code uses a row index plus one; modern rows should carry the real resource ID rather than depending on a sorted visual index.

`GetSoundList` reads a DWORD count and an absolute DWORD offset table. At each offset is a **40-byte** header: DWORD header size, DWORD payload length, then a bounded **32-byte name**. Payload playback requires header size 40; bytes are copied to an MP2 temporary file and opened with configured/default external playback. This proves the source playback route, not codec verification of every payload. Source allocates only **38 bytes** for its 40-byte read, and checks only `Identifier > Count` before indexing `Identifier-1`; these unsafe defects must not be reproduced. Modern extraction must be bounded and read-only, with safe zero/negative/overflow/truncation guards.

Corresponding text uses the suffix after the first underscore, with **MENTOR → Speech.STR**, otherwise `<suffix>.STR`, in `Data/Text/Default`. Missing text does not remove the audio metadata. The source playback temporary-file overwrite/deletion/sleep loop is not authority to overwrite arbitrary user files; later integration needs uniquely owned temporary files and bounded lifetime cleanup.

## Text dialog

`Properties_Map_Texts.c`, resource dialog **6805**, `Map.h`, and the compiler/native reader assignments identify `TextTableID`; seven ordinary WORD IDs (`TextTitleID`, `TextPlotID`, `TextDebriefingID`, `TextObjectiveID`, `TextSubObjective1ID`–`3ID`); and **eight** pairs of BYTE `TextIntroCreatureID0`–`7` plus WORD `TextIntroTextID0`–`7`. Text numeric controls clamp changed values to **0..9999**. All original replacement creature choices are **None + BadCreatures + BadElites + Heros**; elites are present in source and must not be omitted.

`Datas_Map.c` `TextFiles[]` has **59 entries including None**, with explicit IDs/order and two optional files (Current/Briefing). IDs are not list ordinals: e.g. My Pet Dungeon starts at 26 and Multiplayer starts at 25; ID 40 has no source entry. Secret briefing filenames use `LEVELS<n>_BRIEFING.STR`. Three Demo entries have no briefing file. The text browser switches selected table/current-or-briefing and provides a read-only list, not arbitrary STR authoring. Source `Save` updates `TextTableID` only when the selected index is nonzero, so None does not clear an existing table in that implementation; this asymmetry must be decided explicitly during named metadata integration, not silently mistaken for a normal reset.

The source STR reader takes count at byte **8**, DWORD offsets at **12**, each relative to byte **12**. Each indexed entry has byte type, little-endian WORD payload length, byte reserved, then that many glyph bytes. Installed files have `BFST` signature. Source preview decoding is a custom glyph mapping, **not UTF-8 or CP1252 for the payload**: reversed Latin letter ranges, digit range and explicit punctuation/accent cases. `Source/Includes/Editor.h` enables **DEBUG_TEXTS=1**: its configured unknown-glyph display is **`$XX*`**, while the branch with that setting disabled emits `*`. Both are supported and independently checked for all 256 glyph IDs; the default follows the actual configured source. Do not pretend another locale has been fully decoded. The editor's English/Russian interface does not translate external game text resources.

`Compatibility.h` and `Files_Editor.c:391–480` verify historical project availability: V1 has no SpeechFile; V2/V3 both use MAPPROPERTIESV2 and V4 uses MAPPROPERTIESV4, with the bank name but none of these text/speech ID fields. V5–7 contain all thirty speech/text storage fields. The existing modern schema dispatch matches this, and explicit upgrade preserves the original prefix and initializes new fields with source fixes. Named writes still need historical draft/upgrade fixtures, not inferred padding aliases; native writes use original GAMEINFO assignments (including packed WORD aliases). The complete original metadata wizard is not implemented by these readers.

## Implemented prerequisite and acceptance boundary

`GameTextResource`, `GameSpeechBank` and `MapTextCatalogues` implement read-only bounded immutable snapshots, original indexed STR/SDT layouts, exact source glyph mapping plus unknown-byte diagnostics, source text-table and ordinary/elite/hero catalogues, safe single-segment resource names and speech-folder selection. STR caps are 16 MiB/65536 entries/8 MiB aggregate preview input; SDT caps are 64 MiB/65536 entries. Counts/offsets/payloads use widened bounds before slicing. Shared/reordered offsets are legal; copied raw data/payload access cannot mutate snapshots. No resources are re-encoded, edited, played, or extracted to temporary files by this prerequisite.

`GameResourceChecks` covers source IDs/file pairs/elite order, all 256 glyph IDs in both configured/release branches, every truncation of independent small fixtures, zero/negative/max identifiers, malicious counts/offsets/lengths, unknown headers, bounded nonterminated names, snapshot ownership, shared-offset amplification, oversize loader refusal and original missing-bank directory semantics. The optional installed-resource corpus independently compares raw index/payload bytes and before/after hashes. Named EN/RU controls, guarded atomic metadata Apply/Undo, text-browser UI, playback configuration/lifetime, pending/stale/closed guards, historical/corpus projections and WPF/game acceptance remain open.

Both configured-glyph Debug/Release solution builds have zero warnings/errors; the focused Release resource test is terminal exit 0. Installed read-only checks cover **92 STR files / 7024 entries**, **99 SDT banks / 170626450 payload bytes**, and **36 original speech-folder choices / 3 missing banks**, with every file hash unchanged. The initial focused failure assumed every enumerated speech folder had audio; the corrected independent fixture retains missing-bank folders like the original rather than filtering them out. An earlier full regression snapshot used the disabled-DEBUG_TEXTS branch as default; the follow-up reread found actual DEBUG_TEXTS=1 and corrected the default, then reran fresh uniquely named configured-glyph gates. Earlier reports are retained, not substituted for current-code results.

All fresh configured-glyph prerequisite gate handles are terminal: `game-resources-final-core-debug-configured-20261007.json` has **80 groups / zero failures**, exit 0; `game-resources-final-ui-{debug,release}-configured-20261007.log` have **242 PASS cases each**, exit 0; Release `expanded-corpus-game-resources-configured-20261007.json` has **1729 passes / 94 failed checks**, exit 1, with the complete ordered failure array exactly equal to level options. Counts are 80 synthetic / 560 native / 530 supported-text / 559 original-policy passes, not a green whole-corpus claim. Separate Release `game-resources-real-text-configured-20261007.json` has **81 passes / zero failures**, exit 0, including real Ancients.map. At that reader-only checkpoint no named speech/text panel existed, so those WPF regressions do not prove the subsequent panel. Its newer evidence is recorded in [MAP_SPEECH_TEXT](MAP_SPEECH_TEXT.md). Original Source/Binaries remained unchanged; tracked diff whitespace and new reader/test trailing-whitespace checks passed.

## Subsequent integration decisions

- `AppSettings.GameResources` and the actual named panel now provide resource-root and custom/default-player selection, existing-map ancestor detection and session/JSON persistence without map mutation. Native file dialogs themselves remain a visible-interaction acceptance requirement.
- Native `szMainSpeech` is now WesternAnsi, independently tested with non-ASCII names and retained unknown/full-width/padding/no-op bytes. Compilation copies the exact 32-byte source field like original CopyMemory. The native BYTE text-table field is explicitly distinguished from project WORD storage.
- Named Apply explicitly retains the original nonzero-only text-table behavior. None is a preview selection, not an accidental reset of stored metadata. Speech None independently clears only the bank.
- The [implementation](MAP_SPEECH_TEXT.md) adds complete guarded atomic drafts, read-only browsers, explicit playback, argument-list custom launch and uniquely owned temporary files. Automated launch interception and owned/unowned cleanup are verified; actual codecs/players, locked-file cleanup retry/notification, native dialogs and game acceptance remain open.
