# Подтверждение удаления регионов

15 октября 2026, RegionRemovalConfirmation-20261015. Добавлен общий запрос
удаления областей, ворот и генераторов эффектов: Yes/No, запоминание Yes,
автоматический ответ и сброс. Он подключён к списку записей и панели регионов
в EN/RU. Это первый вопрос `RectEx_RemoveRects`; специальные решения об
используемых областях и их связях остаются отдельной работой.

## Поведение для пользователя

В панели регионов есть кнопки «Удалить» и «Спрашивать перед удалением регионов».
В списке записей для регионов доступны Ctrl/Shift и групповое удаление одного
вида. Смешанный выбор областей, ворот и эффектов не удаляется: нужно выбрать
один вид. Остальные категории сохраняют прежний одиночный выбор и подтверждение.
Сердца хранителей не входят в логический список регионов. Номера native ворот
в этом списке — рабочие ID, а не повторяющееся игровое поле `bGateID`.

Вопрос показывает вид и число выбранных записей. Yes — ответ по умолчанию.
Флажок запоминает только Yes и отключает No. Закрытие окна/Escape отменяет
запрос, включая случай установленного флажка. При запомненном Yes следующий
общий запрос не показывается; это состояние общее для трёх видов регионов
и сохраняется при переключении документа в текущем рабочем окне.
Кнопка сброса возвращает подтверждение. Это настройка сеанса, не данные карты.

Undo/Redo изменяет карту, но не отменяет запомненный ответ. Один подтверждённый
пакет даёт один счётчик/Undo/уведомление. При глубине истории0 операция работает
без хранения Undo. Окно у курсора использует исходную иконку вопроса; тексты
и запись истории имеют переводы EN/RU. Физические клавиатура/мышь/фокус/DPI
ещё требуют ручной приёмки.

## Модель и границы команды

`EditorRegionRemovalPolicy` хранит REQUEST_RECTEXKILL=`0x10` отдельно от
документа. Другие биты не меняются. `EditorRegionRemovalRequest` содержит
независимый неизменяемый список записей, вид, ревизию и полный fingerprint.
Описания полей берутся из текущих проверенных записей карты и замораживаются;
переданное вызывающим кодом другое описание полей не обходит reference guard.
Проверяются актуальность карты, принадлежность записей, известный layout,
однородность выбора, отсутствие повторов, активной транзакции и штриха.
Чтение списка не требует исправлять неотображаемые координаты.

Перед применением карта проверяется заново. Изменение карты, сырых байтов,
документа или выбора делает старое подтверждение неприменимым. Принятие
повторно запрещено. Сброс/закрытие владельца потребляет текущий запрос.
При обновлении языка сохраняется множественный выбор неизменённого документа;
при изменении ревизии старый выбор автоматически не переносится на новые записи.

Запомненный ответ записывается перед вызовом удаления, как в исходном
`Misc_MessageBoxExtReset`. Поэтому при отказе существующей команды карта
откатывается, а уже принятая настройка остаётся. Отказ команды отличен от
ошибки уведомления после успешного commit: во втором случае запрос считается
принятым и не применяется повторно. Интерфейс сообщает, что удаление уже выполнено.

Удаление выполняется в общей транзакции. Команда обходит выбранные строки
в порядке списка и [переадресует первого предшественника удалённой области](AREA_REMOVAL_PATROL.md).
Общий API сохраняет reference guard; исключение для патрульных `nextid`
ограничено этой командой. Native working metadata и схема игрового экспорта
сохранены. [Удаление ссылочных DKM ворот](PROJECT_GATE_REMOVAL.md)
уже поддерживается. Второй вопрос Yes/No/Cancel, удержание orphan scopes,
пустые native точки и удаление ссылочных эффектов добавлены следующим этапом:
[USED_AREA_REMOVAL](USED_AREA_REMOVAL.md). Переадресация первого `nextid`
реализована. Физическая приёмка и отдельные resize callers остаются открытыми.

## Сверка с исходником

`RectEx_RemoveRects` передаёт `Config.RequestsFlags`, бит0x10,
MBF_AUTOREPLY, defaultgadget1 и MBP_FOLLOWMOUSE. Общий вопрос одинаково
используется для областей/ворот/эффектов. `Misc_MessageBoxExtArgs` возвращает
ответ по умолчанию при установленном бите. `Misc_MessageBoxExtReset` меняет
только этот бит и только для ответа по умолчанию. Обработчик checkbox1200
отключает остальные кнопки. WM_CLOSE возвращает0 без запоминания.
Снимки функций и SHA256:
`artifacts/Evidence/RegionRemovalConfirmation-20261015/source-capture.json`.

## Проверки

Модельные проверки охватывают шесть native/project × area/gate/effect матриц:
No/checked-No/close, Yes/default/remember/reset, общий бит между видами и
документами, неизменяемый пакет, полные ожидаемые буферы и поля заголовков,
один count/Undo/notification, целые Undo/Redo и history0. Дополнительно:
устаревшая/сырая/чужая/смешанная/повторная запись, не-регион/сердце,
вложенная транзакция/активный штрих, завершённый/сброшенный запрос,
отказ текущего reference guard и ошибка observer после commit.

`--region-removal-confirmation-ui-only` в WindowsSmoke подготавливает четыре
EN/RU × native/project случая настоящих контролов: множественный выбор,
checked-close, обновление языка, общий Undo/count, suppressed reply после смены
документа/вида, сброс и отказ при изменении выбора. Есть проверка исключения
сердца из логического picker. Harness собран, но агентом не запускался.
Фактические CLI-результаты и полный корпус — в [CURRENT_STATUS](CURRENT_STATUS.md).

Ручная проверка на копии карты: выбрать двое ворот в списке, удалить с
запомненным Yes, выполнить Undo и снова удалить — общего вопроса быть не должно.
После сброса вопрос должен вернуться. Проверить No, закрытие с установленным
флажком, EN/RU и Escape. Карта для игровой проверки остаётся только
`DK2Preview_6a88240eaf814f78`, запуск через
`DKII-DX.exe -q -level DK2Preview_6a88240eaf814f78`.

Source/Binaries и установленные карты сохраняются. Игра, renderer, WPF-окна
и исходный GUI агентом не запускались. Все23 области и семь очередей
