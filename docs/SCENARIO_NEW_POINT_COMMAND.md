# Новая точка действия и открытие привязки

ScenarioNewPointCommand-20261018. MC06 — подпункт I17. В сценарном менеджере
есть отдельная команда EN/RU «Новая точка действия…» / «New action point…».
Она всегда открывает частный мастер создания с первой страницей выбора типа.
Выбранный в дереве сценарий или уже привязанный владелец не превращают
эту команду в открытие либо изменение существующей точки.

Прежняя команда «Открыть / создать привязку владельца» сохраняет своё
назначение: выбирает найденную точку; при отсутствии открывает создание
с выбранным владельцем. New Point не является New Root condition, Insert
Point или Modify/Reassign. Все эти команды остаются отдельными маршрутами.

При первом New Point выбирается тип игрока. Последний выбранный тип мастера
сохраняется в контексте рабочего пространства, в том числе после Cancel.
После смены документа или выгрузки workspace он сбрасывается. Выбранная
старая точка и её цепочка не передаются как Existing; InsertBefore отсутствует.
Владелец выбирается на следующей странице. Для игрока прежний мастер
предпочитает player3, когда он доступен. Новая точка имеет пустой trigger0.

Мастер сохраняет исходные ограничения владельцев. Одна точка уровня уже
блокирует Finish для нового Level. Занятый игрок/объект не предлагается как
свободная привязка. «Дополнительные DKM global points» в конечной MC06 таблице
означают отдельные точки **других** игроков рядом с Level/прежними точками,
а не несколько Level roots или дубли одного player. Это подтверждено
Triggers_ActionPoints.c:182/226, 664–684, а не новым ограничением продукта.
При добавлении DKM новый TRIGGERLINK идёт в конец списка; прежние точки,
события, ссылки и неизвестные байты сохраняются. Отмена не выделяет новые
идентификаторы и ничего не записывает. Общий Core wizard/preflight/Apply/Undo остаётся прежним.

Native имеет физические entity roots и не хранит Action Point list order DKM.
Пустой player/level root не получает придуманную запись или companion только
ради New Point. Принятие прежнего native no-byte-change по-прежнему учитывает
команду, а distinct persisted empty points/order остаются границей I01/I03.
Новая команда не объявляет этот форматный вопрос решённым. Игровой экспорт
сохраняет прежние семь файлов.

## Контекст и проверка

New Point требует загруженного workspace, вкладки сценариев, живого документа
и отсутствия live pen. Уже открытый point/event wizard сохраняется с понятным
EN/RU сообщением; новый черновик его не заменяет. После CommitFields сверяются
документ, context, revision и pen. Общий point caller также проверяет lifetime
владельца перед Finish; старое окно не записывает данные нового документа.
Сообщение об ошибке идёт по прежнему RecordOperation. Смена языка сохраняет
черновик; Close/Cancel не создаёт map bytes или Undo.

Исходник: Source/Sources/Triggers/Triggers_Select.c:171–175 — ID103 с
Modify=FALSE/Insert=FALSE; Triggers_ActionPoints.c:35–69 — частный TempLink,
trigger0 и retained type/default Player3; 1111–1340 — выбор владельца,
новый link и List_AddEntry. App: ScriptScopeControls.cs и EditorWorkspace.xaml.

Новый CLI `--scenario-new-point-only` исполнен: существующий Level со своей
веткой, Cancel/private preflight, два последовательных дополнительных player
points, exact прежние point/event bytes, пустой новый trigger, одно принятие,
DKM append/Undo/Redo, occupied level/player refusal и stale session.
Native проверяет существующие roots без придуманного списка. Этот CLI
проверяет модельный контракт общего мастера; сам WPF caller не исполняется.

Четыре WPF набора EN/RU × native/DKM только скомпилированы: actual New button
отличается от Open existing, retained type после Cancel, перевод, два player
points, занятый владелец, pending wizard, hidden tab, live pen и закрытый
контекст. Агент не запускал редактор/WPF/Computer Use/renderer/игру.
Core sources/DLL не менялись, полный корпус и прежние успешные checks не
повторялись. Исторический full той же Core — ScenarioExpansion1831/63;
новый focus не прибавляется к нему. Поставка и подтверждённые exit codes —
CURRENT_STATUS и artifacts/Evidence/ScenarioNewPointCommand-20261018.

## Ручная приёмка M18/M20/M23

1. В DKM с уже существующей точкой Level выбрать её владельца. «Открыть /
   создать привязку» выбирает эту точку; «Новая точка действия…» открывает
   отдельный мастер с выбором типа, не Modify существующего Level.
2. Выбрать игрока без привязки и завершить мастер. Появляется отдельная
   пустая точка. Повторить для другого игрока; прежняя ветка Level сохраняется.
   Занятые игроки недоступны, вторую точку Level Finish не принимает.
3. Изменить тип и отменить. Открыть New снова — тип сохранён, карта не менялась.
   Проверить EN/RU, Undo/Redo создания DKM и невозможность заменить уже
   открытый черновик новой командой.
4. Проверить смену/закрытие документа, вкладки, фокус, Tab и DPI100/125/150.
   Для native не ожидать отдельного упорядоченного списка пустых DKM points.

MC01–MC06 parent inventory закрыт по коду; I17 ещё требует исправления
конкретного оставшегося Things Manager coordinate callback106/107/186/187,
где текущий raw ввод вместо исходного раннего clamp описан в
[MANAGER_LIST_COMMANDS](MANAGER_LIST_COMMANDS.md). Это прежний scope I17.
Полный конечный перечень — [OPEN_FUNCTIONS_RU](OPEN_FUNCTIONS_RU.md).
