# Границы записей в игровых коллекциях

После этого этапа добавлены [общие physical layout guards](NATIVE_COLLECTION_GUARDS.md). Указанное ниже частичное отображение неподтверждённых полей описывает прежнее состояние; сейчас такие записи opaque и семантическое редактирование отклоняется.

Состояние на 25 октября 2026, этап `NativeCollectionLayouts-20261025`.
Это исправление части I04. Поддержка всех неизвестных layouts этим этапом
не объявляется завершённой.

## Причина и новое поведение

В игровых Players, Things, Triggers и Variables есть число записей и отдельное
поле размера payload. Чтение уже обходило записи по их числу и длине, но вставка
использовала размер payload как адрес конца коллекции. При устаревшем размере
новая запись могла попасть внутрь существующей записи или непрозрачного хвоста.
Удаление могло закончиться арифметическим переполнением, если из слишком
маленького беззнакового размера вычиталась длина записи.

Теперь чтение и определение места вставки используют один обход
`NativeCollectionEntries`. `NativeCollectionDataEnd` возвращает конец последней
учтённой записи, а для пустой коллекции — конец заголовка. Порядок существующих
записей сохраняется. Неучтённый суффикс остаётся после всей коллекции.

Изменены обычная вставка и дублирование, общее обновление заголовка при
вставке/удалении, пакетное добавление, удаление через менеджер и пакетное
изменение с переносом записей. Адреса переноса владельцев при пакетном изменении
вычисляются от фактического конца данных. Удаление отряда использует исправленное
общее обновление заголовка.

Размер из заголовка по-прежнему корректируется на разницу длин, если результат
помещается в DWORD. При отрицательном результате или переполнении записывается
фактическая длина учтённых записей, без непрозрачного хвоста. Файл не исправляется
при одном открытии: изменение заголовка происходит только вместе с разрешённой
операцией редактирования. Undo восстанавливает прежние bytes, включая старый
размер; Redo возвращает результат операции.

## Границы формата

| Коллекция | Signature | Заголовок | Обход записей |
|---|---|---|---|
| Players | B4 | 56 bytes | Число по +20, фиксированные 205 bytes |
| Things | BE | 56 bytes | Число по +20, длина записи — DWORD по +4 плюс 8 |
| Triggers | D2 | 60 bytes | Сумма чисел по +20/+24, длина записи — DWORD по +4 плюс 8 |
| Variables | E6 | 56 bytes | Число по +20, фиксированные 16 bytes |

Ограничения числа записей, проверки границ и декодирование полей перенесены
без изменения. Поля известной структуры с неподтверждённой длиной пока могут
отображаться частично. Единая политика отказа от её семантического редактирования
между inspector, полями, специализированными операциями и конвертацией остаётся
в I04; для definitions уже действуют отдельные
[guards](NATIVE_DEFINITION_LAYOUTS.md) и [walker](NATIVE_DEFINITION_TAILS.md).

## Проверенные данные и результаты

Инвентаризация 437 установленных файлов была только чтением. В 111 случаях
поле размера payload отличалось от длины учтённых записей. Например,
`3DLevelTriggers.kld` содержит размер 16 при 48 bytes записей. Также обнаружены
три ранее усечённых Variables-файла; они не изменялись и не использовались как
положительные примеры. Исходный `Files_Game.c` читает Things фиксированными
структурами; его ветви обхода и заголовки сохранены в доказательствах.

Семь новых групп до исправления завершились отказом, после исправления — успешно:

1. Добавление в четыре коллекции, включая условия и действия, с размером 0,
   увеличенным размером 96 и DWORD maximum.
2. Дублирование объектов и графов без перезаписи исходных записей.
3. Удаление с заниженным размером без unsigned underflow.
4. Пакетная вставка после прежних записей.
5. Пакетное удаление менеджером.
6. Пакетное изменение и фактические адреса переноса.
7. Удаление отряда.

Во всех группах проверены непрозрачный суффикс, точный Undo/Redo, настоящее
сохранение и повторная загрузка, а также неизменность исходных файлов.
Используется постоянное имя `DK2Preview_6a88240eaf814f78`.

Смежные проверки: 11 PASS и 2 FAIL. Успешны менеджер, пакетное изменение,
идентификаторы и layouts сценариев, отряды и шесть проверок официального
комплекта. Последние включают настоящий DKM, `level1`, все 1800 клеток,
упаковку definitions и повторное пересохранение в семь файлов.

Два отказа — `Direct native template differs from source compiler output`
и `Valid inserted graph has scenario semantic warnings` — отдельно повторены
на прежней опубликованной Core DLL с теми же сообщениями. Они предшествуют
исправлению; не объявляются исправленными и требуют классификации в I04/I18.
Полного прогона не было; исторические 1840 PASS / 63 FAIL не являются текущим
результатом. Все 41 проекта собраны без ошибок и предупреждений.

## Доказательства и остаток

В `artifacts/Evidence/NativeCollectionLayouts-20261025/` сохранены inventory,
исходные/итоговые логи с кодами завершения, ограниченный diff и
`source-boundary-proof.json`. Сравнение прежней DLL используется только как
доказательство: единый проект собирается из текущего `src/` без восстановления
кода из архивов. Свежая поставка и её хеши перечислены в `delivery.json`.

Осталось 6 кодовых пунктов и 23 ручные группы, всего 29. I04 открыт:
проверка заголовков и семантических размеров остальных коллекций, исторические
секции и общая таблица inspector/editable/conversion. Интерфейс, игра и Computer
Use не запускались. Решения пользователя о корректных shot-спиннерах, полном
Undo и горячих клавишах сохранены.
