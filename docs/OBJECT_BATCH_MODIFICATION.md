## Source and rules

Inspected `Source/Includes/Manager.h`, `Source/Sources/Things/Things_Manager.c:1314–2202`, the options/init/save routines at 2911–3250, preview decisions at 3685 onward, and source defaults in `Properties_Editor_Config.c:64–70`. The earlier partial notes in [the scope audit](OBJECT_BULK_EDIT_SCOPE.md) are historical, not the current implementation status.

- The ten source property masks use their literal original constants: coordinates, type/ID, owner, level, held gold, health, creature flags, hero flags, objective/area/enemy together, and noncreature union data. Unchecked fields retain the selected object's values. Flag updates can replace all bits or only a uint32 mask, including unknown bits.
- Creature coordinates support one common destination or translation relative to the selected minimum X/Y. Doors/traps and objects/special items force translation for groups. The minimum is calculated after excluding scenario-bound objects unless explicitly included; X/Y describes the new minimum, not a per-object displacement.
- Owner zero uses the source-projected terrain owner at each proposed position. Negative and outside coordinates are safely guarded; the source's invalid pointer access is not copied.
- Multiple-edit normalization clears hero options/objective/area/enemy on nonheroes when the source condition requires it, supplies hero objective 19 when absent, handles barricade locks and door/trap status conversions, checks spell-book IDs and clears inactive ordinary/special data. Warnings are separate from unknown-layout locks. Batch addition keeps its distinct accepted semantics.
- Preview rows expose **Keep / Remove source / Modify**, with locked destinations still permitting source removal. Existing overlaps follow first-door-before-trap and first-object-before-special priorities. Initially selected sources are considered vacating. Changing a source to Keep recalculates overlaps and resets a newly exposed replacement to Keep: the user must explicitly choose Modify again. Application independently rechecks that review; it never blindly deletes the initial worklist.

## Transactions, identities and scenarios

All modified records, approved source removals, approved overlaps and owned project binding changes are prepared before one `Edit` transaction. No per-record nested edit or repeated full-document snapshot is used. Independent preview fingerprints include tiles, definitions, entities and scenarios; foreign/stale or mutating-enumeration plans fail. Empty/byte-identical work preserves redo/history and does not silently upgrade sections. Actual multiple modifications append their selected sources in chosen order within each physical file, giving each destination family the source end-of-list order. Pure no-ops intentionally avoid the original list-order churn.

Stable project unique IDs and NODE linkage bytes are retained. Creature owner changes migrate native C7/C6/C8 layouts with the same scenario root and common reserved bytes. Same-layout changes preserve headers, padding, roots and hero band identity; unchanged inactive object slots remain byte-exact. A different layout cannot retain bytes that have no corresponding destination field; common reserved bytes at 16–19 and creature byte 21 are carried over. Unrelated files, native gaps/tails and events are retained. Shrinking native layouts use the shared understated-stored-size correction.

Object/special conversion remaps only the owned project binding's scope 128/256, retaining identity, root and graph. Retained branches are checked against the new event scope. Door-to-trap conversion loses a representable owner root; this requires the separate explicit **Allow detaching bindings** consent. Incompatible category-conversion branches likewise require this consent; events are kept, never silently deleted. Shared/ambiguous owners or an existing destination identity binding are refused rather than arbitrarily reassigned. Original UID-only/creature-only triggered filtering is deliberately replaced with actual binding detection.

Verified historical Things sections require explicit Things-only upgrade before modification; removal-only decisions still use their existing version. Unknown object/scenario layouts cannot be overridden by a warning checkbox. No whole-project upgrade occurs implicitly.

Document changes invalidate the selected physical records; the modification dialog must be reopened from the refreshed manager. Language changes retain draft values, masks, preview and decisions. Pending generic property commits invalidate an old preview before application. Closing/replacing the manager or document revokes its child callback. Terrain selection/copy buffers are not changed.
