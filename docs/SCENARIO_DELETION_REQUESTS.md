# Удаление точки, условия и действия

Этап ScenarioDeletionRequests-20261016, продолжение 17 октября 2026.
Единый основной код остаётся в `src/`, решение `DK2MapEditor.slnx`.

## Команды редактора

На вкладке сценариев удаление точки действия и удаление выбранной ветви
используют отдельные вопросы. Для пустой точки текст сообщает об удалении
пустой точки; для непустой — точки и всех её событий. При удалении условия
вопрос говорит о дочерних событиях, при удалении действия — об одном действии.
Следующие события условия или действия сохраняются.

В каждом вопросе «Да» — ответ по умолчанию. «Нет», Escape или закрытие окна
оставляют карту без изменений. «Запомнить Да» действует отдельно для точки,
условия и действия; установленный флажок блокирует «Нет», но сам по себе
ничего не запоминает. Закрытие окна с флажком не означает принятия «Да».
Вопросы центрированы относительно окна редактора.

Запомненный ответ переживает Undo/Redo, смену документа и Save/reopen в том
же редакторе. Он не записывается в карту или AppSettings и не переносится
в новый запуск. «Вернуть вопросы удаления сценария» сбрасывает только эти
три вида, не затрагивая вопросы удаления объектов/регионов.

Прежний обязательный флажок перед кнопкой удаления ветви заменён вопросом.
Полный современный Undo сохранён: одно принятое удаление — один шаг с
одним приростом счётчика команд. Удаление пустого native inherent root,
не имеющего отдельной сохранённой точки, сохраняет прежний accepted-no-change
контракт; это не создаёт искусственный Undo для отсутствующих данных.

Смена выбранного узла, в том числе другого отображаемого родителя общей
ветви, смена вкладки, документа или закрытие редактора отменяет старый запрос.
Переключение EN/RU восстанавливает тот же выбранный узел и не считается
пользовательской сменой выбора. Перед ответом проверяются также revision
и полное рабочее содержимое карты. Старый запрос не становится снова
действительным после Undo, даже если байты вернулись к прежнему виду.

## Границы удаления по исходнику

`Source/Sources/Triggers/Triggers_Select.c` содержит три команды:

| Команда | Что удаляет | Что сохраняет | Флажок RequestsFlags |
| --- | --- | --- | --- |
| Triggers_SelectKillPoint | TRIGGERLINK и весь достижимый граф AND/OR/next; освобождает ID физического владельца | Остальные точки/ветви | REQUEST_KILLPOINT 0x800 |
| Triggers_SelectKillTrigger | Условие и его AND-потомков, включая продолжения внутри дочерней ветви | OR/next продолжение самого выбранного условия | REQUEST_KILLTRIGGER 0x200 |
| Triggers_SelectKillAction | Одно действие | next продолжение | REQUEST_KILLACTION 0x400 |

Рекурсия Triggers_KillFromId и функции Unlink находятся в
`Source/Sources/Triggers/Triggers_Functions.c`. Для обычного дерева эти
границы уже были реализованы в DeleteEditorScenarioPoint и DeleteScriptBranch.
Их тела сохранены по смыслу; общая валидация выделена так, чтобы вопрос
показывался только для допустимой команды, а Apply проверял её ещё раз.

Современный редактор сохраняет проверки shared/cyclic/dangling/duplicate
графов и проверяет чужие ссылки до удаления. Это не имитация повреждения
данных исходником. В частности, исходный Triggers_UnlinkAction ищет
предшественников среди условий/действий, не среди TRIGGERLINK; современное
удаление сохраняет корректный splice корневого действия. Современный Undo
также остаётся доступен, хотя исходные три команды непосредственно его
не создают. Generic API удаления и его guards не заменены обходом.

## Реализация

EditorScenarioDeletionPolicy использует общий EditorRequestPreferences
ObjectManagerSession, независимые bits0x200/0x400/0x800 и общий single-active
lease с запросами объектов/регионов. BeginPoint/BeginEvent создают snapshot
документа, revision, fingerprint, точки или ID события, вида вопроса и числа
удаляемых событий. Это read-only подготовка: карта и её история не меняются.

Accept запоминает ответ вне Undo, затем вызывает прежнюю операцию удаления.
No/Dispose ничего не удаляют. При ошибке обработчика Changed после успешного
коммита запрос помечается принятым, освобождает lease и не предлагает
повторное удаление. Ошибки до коммита не объявляются успешным удалением.
Запоминание принятого ответа остаётся session state, включая отказ записи
после принятого ответа, как в source request/caller последовательности.

EditorWorkspace.ScenarioDeletion фиксирует не только EventID, но и
выбранные Incoming/ScopeRoot/identity. ScriptTreeControls явно различает
восстановление selection после перестроения дерева и пользовательский
выбор. RegionRemovalWindow использует общий оригинальный question icon,
default Yes, независимый remember, тексты EN/RU и centered placement;
чужой счётчик объектов в этом вопросе скрыт.

Новых игровых секций, полей или файлов нет. Семифайловый формат, UID/scopes,
orphan/empty metadata и прежний TestMap не меняют свой контракт.
