# Изменение региона двойным щелчком

RegionListModify-20261018. **MC02 внутри I17 закрыт по коду.** Фактическая
приёмка мыши, фокуса и оформления остаётся в M12/M20/M21/M23. MC03–MC06
по-прежнему открыты, I17 целиком не закрыт.

Вместо выпадающего RegionPicker теперь виден небольшой список с вертикальной
и горизонтальной прокруткой. Сохранились фильтр вида, «Все регионы», выбор,
подсветка, показ на карте, свойства, удаление и три входа создания из MC01.
В списке используется один выбор; пакетное удаление инспектора не изменено.

Двойной левый щелчок по строке открывает существующее общее окно свойств
именно этой записи. Кнопка «Свойства» использует тот же маршрут для выбранной
строки. Открытие и Cancel сами не меняют карту. Принятие использует прежний
RegionPropertiesSession и один Modify/Undo; новые сериализаторы не добавлены.

Обработчик извлекает ListBoxItem из OriginalSource и проверяет принадлежность
списку и текущей проекции. Он не берёт цель из чужого SelectedItem. Пустое место,
полоса прокрутки, правая кнопка и старая строка после обновления игнорируются.
Полный payload строки, владелец, контекст, ревизия и активный карандаш
проверяются до/после CommitFields и после смены выбора перед открытием.

Если уже открыт черновик этой записи, он активируется. Если открыт черновик
другого региона или создания, новый вызов показывает EN/RU сообщение
«Закройте открытый черновик региона перед изменением другой записи».
Первый черновик не подменяется и его данные не теряются. Смена/закрытие
документа и Unloaded по-прежнему закрывают принадлежащее ему окно.

## Опора и объём проверки

- Source/Sources/Things/Things_RectEx.c:194–196 — NM_DBLCLK вызывает
  RectEx_Modify; 640–717 — выбранная запись, частный ModifyContext и общий
  Undo/Apply. Создание исходного ListView — RectEx_Init.
- App/Editing/EditorWorkspace.xaml — ListBox и MouseDoubleClick;
  EditorWorkspace.Regions.cs — RegionList_DoubleClick, OpenRegionProperties,
  собственная копия payload для каждой строки и отдельная цель открытого окна.
- Новый WPF `--region-list-modify-only`: четыре подготовленных случая
  EN/RU × native/DKM. Для каждого вида по две записи, намеренно иной выбор
  перед double-click, button route, Cancel/Apply/Undo, отказ другого черновика,
  background/right/foreign/stale/raw events, active pen, скрытая вкладка и
  закрытие владельца. Старые WPF callers адаптированы к типу ListBox.

WPF случаи **только скомпилированы**, агент их не запускал. Физический double-click
и поведение фактических уведомлений не объявлены проверенными. Сборка и поставка
описаны в CURRENT_STATUS и artifacts/Evidence/RegionListModify-20261018.
Core, формат семи файлов и старые CLI checks не менялись; полный корпус не
повторялся. Последний полный Core-прогон RegionCreationDraft остаётся1829/63
на той же DLL, все63 отказа прежние; это не новый GUI-прогон.

## Ручная приёмка

1. В блоке регионов создать два региона одного вида с разными координатами.
   Выбрать первый, дважды щёлкнуть левой кнопкой по второму. Окно должно показать
   координаты второго. Проверить отдельно области, проходы и эффекты.
2. Закрыть без применения: карта прежняя. Через кнопку «Свойства» изменить
   выбранный регион, принять, сделать Undo/Redo. Соседняя запись не меняется.
3. Оставить черновик открытым и щёлкнуть другую запись: появляется сообщение,
   введённые значения первого окна сохраняются. Завершить/закрыть его и повторить.
4. Проверить пустое место, прокрутку, правую кнопку, смену фильтра, EN/RU,
   размеры блока и видимость выделения при DPI100/125/150. Выбор в списке
   должен по-прежнему подсвечивать соответствующую область на карте.
