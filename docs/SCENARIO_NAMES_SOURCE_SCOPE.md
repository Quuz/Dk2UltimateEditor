# Scenario variable/timer names: original workflow source scope

Read-only source audit, 2026-10-07, following explicit unused-event consent. The subsequent [named manager/property-choice implementation](SCENARIO_NAMES.md) now covers the tables/counts and guarded DKM/native alias persistence. This document retains source provenance; it does not establish full parity or claim that the original inline alias wizard/descriptive formatter is implemented.

## Stored and original editable data

`Source/Includes/Triggers.h:19–22` defines **129 variables / 17 timers**, each a **64-byte** editor alias. These are scenario names, not the separate 193 global map-variable values. KTRG reader `Files_Editor.c:1403–1405` copies the variable table followed by the timer table; its writer at 1767–1770 writes both tables after the link/condition/action records. `Triggers_ReleaseMemory` zeroes both arrays (`Triggers_Functions.c:45–46`); game loading calls it (`Files_Game.c:96`). The native compiler has no references to these alias arrays: names are editor metadata, not game event payloads.

The modern version-2/3 project reader already exposes all **146** rows as `Project.VariableNames` and `Project.TimerNames` with a 64-byte WesternAnsi `Name` field (`LegacyProjectEditing.cs:123–126`). They can already be edited through generic properties and saved losslessly. That is not the original named manager/usage display or alias-aware event picker. Native bundles have no such project table; do not guess a game-file slot, silently discard editor names or falsely claim the entire native/editor metadata problem solved. Older KTRG upgrades, native editor metadata persistence and saved editable-copy behavior need explicit acceptance.

## Actual source workflow

`Triggers_Variables.c:37–120` opens the 7001 dialog with separate variable/timer lists, enables rename for a selection, and invokes naming on double-click or the corresponding button. Initialization inserts all 129/17 indexed rows. `Triggers_VariablesSetInfo:238–295` displays index, alias/no-name, and source usage count. Display overrides variable **128** with Score and timer **16** with the time limit, even when their raw aliases contain data. The rename routine at 300–331 accepts the selected raw slot without excluding those indices, uses the 64-byte edit-buffer capacity, and increments map changes only after acceptance. Keep imported bytes/values; do not infer deletion of a hidden reserved alias.

The source reference counts are intentionally exact, not a generic operand scan:

- Timer: `TRIGGER_TIMER.param2` and `ACTION_SETTIMER.param1`.
- Variable: `TRIGGER_VARIABLE.param2`; additionally `param4` only when `param3 == 0x02`; `ACTION_SETVARIABLE.param1`; additionally `param5` only when `param2 == 0x0C`.

Both positions count separately when they reference the same ID; loops include **all** editing records, including unlinked events. The source timer manager does **not** count `ACTION_DISPLAYTIMER` although that action has an alias-aware picker. Do not silently broaden a value presented as the original usage count; an additional broader diagnostic would need a distinct label.

`Triggers_Triggers.c:836–873` populates condition variable/timer choices from aliases, numeric fallback and special Score/time-limit captions; variable condition operands both get choices. Its store at 1413/1435 writes nonempty edited alias text into the selected operand slot, with `CB_LIMITTEXT` capacity 63 at 1089/1117. `Triggers_Actions.c:1023–1059` populates both set-variable operands (including Score) but set-timer choices exclude time-limit index 16. Display-timer uses its own list; its store at 1757 also accepts alias text. Condition/action text formatting (`Triggers_Texts.c:982–1026`) uses a numeric ID for an empty/canonical numeric alias, otherwise quotes the alias. Other source operand modes remain part of the wider semantic-control audit, not yet covered by this note.
