# Непрерывная статистика при первом сохранении DKM

24 октября2026: [I16 закрыт конечной кодовой сверкой](I16_CODE_CLOSURE.md).12I/23M; ручная приёмка времени/окон остаётся. Датированные остатки ниже описывают прежние этапы.


23 октября 2026. ActivitySaveContinuation-20261023, конкретное исправление I16.

При первом Save As native-карты или AREA в DKM сохранялся новый файл, после
чего текущий документ заменялся загруженной DKM-копией. Такая загрузка заново
создавала временную сессию: TotalTicks становился сохранённым RealTicks,
а время записи/Flush выпадало из дальнейшего накопления. Дата и счётчики
в файле были правильными; ошибка относилась к продолжению текущей работы.

Теперь перед публикацией подготовленного файла новый документ получает
независимую копию живой статистической сессии: тот же исходный tick,
поставщики времени и неизменяемый текущий payload. После успешной публикации
эта сессия продолжает работу. Исходный объект документа сохраняет отдельные
счётчики; действия в новом документе их не изменяют. При ошибке публикации
рабочим остаётся исходный документ. Временное сохранение документ не заменяет.

Обычная загрузка файла по-прежнему начинает новый отсчёт с persisted RealTicks.
Не менялись KSTS codec/layout, форматы карты, правила writer для обычной,
неудачной и временной записи, поля статистики, Undo/dirty и игровые файлы.

Источник: Files_SaveMapQuick/Editor_GenerateFile не сбрасывают TickCount
при Save. Начало отсчёта устанавливают создание/загрузка; source KSTS load
копирует RealTicks в TotalTicks. TEMP восстанавливает только SavedTimes.
Точные source hashes и граница этого вывода записаны в
`artifacts/Evidence/ActivitySaveContinuation-20261023/source-scope.json`.

Доказательство дефекта и исправления — новый headless
ActivitySaveContinuationChecks. Часы управляются тестом; запись и Flush
сдвигают их отдельно, поэтому потерю времени нельзя скрыть допуском.
Для native и AREA проверены:

- Первое сохранение и принятие нового документа, точный payload и все opaque
  extension/tail bytes, tick wrap и SavedTimes UINT_MAX → 0.
- Учитываемое время записи/Flush, повторное Save и независимые счётчики
  прежнего и нового документа; продолжение часов даты компиляции.
- Настоящая повторная загрузка файла с прежним правилом RealTicks.
- Временная конверсия без принятия документа/цели и с восстановлением счётчика.
- Ошибки до создания output и после захвата статистики, отсутствие ложного
  успешного Save и успешная повторная попытка с непрерывным временем.

На прежнем коде новые случаи дали 4 FAIL / 2 PASS, exit1. После исправления
все6 PASS, exit0. Затронутая существующая группа EditorUnifiedSaveChecks
также прошла, exit0: DKM/MAP, native conversion, companion, повторные Save As,
ошибки записи, stale/disposed guards и autosave. Новые случаи используют
сгенерированные данные в уникальных временных каталогах; установленные карты
не редактировались. WPF и приложение не исполнялись.
