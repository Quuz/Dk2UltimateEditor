# Индикатор загрузки и сохранения

Этап DiskProgress-20261018, часть I17. Исходные callers перечислены в
`artifacts/Evidence/DiskProgress-20261018/source-scope.json` вместе с hashes.
Сверены `Files_Editor.c`, `Files_Game.c`, `Files_Text.c`, `Files_Load.c`,
`Windows_Disk.c`, `Global.h` и compile-time условие `Windows_Splash.c`/`Editor.h`.

## Пять исходных маршрутов

| Source method | Текущий маршрут | Наблюдаемые данные |
| --- | --- | --- |
| DISK_EDITORLOAD | OpenMap → NativeMapDocument.Load с observer → LegacyProjectEditing | KMAP, KSTS, KINF, игроки, things, регионы, bands, сценарии и definitions; проверка перед выдачей документа |
| DISK_GAMELOAD | Тот же OpenMap → native descriptor/reference files | Чтение descriptor и реально разрешённых файлов, тип данных, число завершённых чтений; проверка tile/records |
| DISK_TEXTLOAD | OpenMap → MAP parser → in-memory project sections | Чтение MAP, обработка созданных секций и проверка; корректный заголовок загрузки |
| DISK_EDITORSAVE | RequestSave после согласия → прежний EditorSaveSession | Подготовка, запись через прежнюю factory, фактически записанные байты, flush, проверка и принятие результата |
| DISK_TEXTSAVE | Тот же RequestSave для MAP; также явный TextExport | Нормальный MAP writer наблюдается через stream; дополнительный export показывает операцию записи комплекта |

В исходном Disk_Create нет отдельной инициализации DISK_TEXTLOAD, хотя
Files_Text вызывает этот метод и передаёт progress. В современном окне
заголовок и индикация MAP определены. Отдельный ошибочный исходный progress ID
при начале TextLoad не переносится как требование к UI.

## Текущее поведение

Окно показывает выбранный путь, текущую фазу и индикатор. Для известного числа
файлов/секций отображается счёт внутри этой фазы; неизвестный объём даёт
неопределённый индикатор. Число байт относится к текущему выходному потоку,
включая поток архива исходных данных, если он нужен. Это не процент времени
или оценка общей готовности редактора. Последовательные byte updates
объединяются; окно не накапливает бесконечный журнал.

Load/Save остаются синхронными, как исходные disk callers. Индикатор обновляется
на Render priority, с ограничением частоты в одной фазе; открытые окна
редактора на время операции отключены. Сообщения ввода и таймеров более низкого
приоритета не прокручиваются для обновления индикатора. Проверки контекста и
байтов перед публикацией сохраняются; программная смена карты по-прежнему
аннулирует старое сохранение. Новая загрузка принимается только при актуальном
контексте. Обёртка ничего не публикует и не повторяет неудачную запись.

Core Load имеет прежний overload без observer и новый явный overload с
Action&lt;EditorFileProgress&gt;. Без observer данные и порядок чтения прежние.
Завершение чтения в UI переводится в подготовку данных; «Операция завершена»
показывается после принятия документа/результата, а не при первом готовом buffer.
Неудача чтения сохраняет прежнюю карту, закрывает индикатор и показывает
прежний полный отчёт. Восстановление DKM использует тот же indicator.

Обычное сохранение начинает индикатор после выбора пути и всех подтверждений.
DiskProgressStream оборачивает существующую factory: array/span/byte writes,
позиция и владение stream сохранены. Flush исходного FileStream остаётся
durable. Успех и ошибка закрывают окно через Dispose; после успешного Save
оно остаётся видимым ещё250мс, как исходный DISK_TIMEOUT, без Sleep UI-потока.
Закрытие индикатора не прерывает запись посередине. Enabled states существующих
окон восстанавливаются. Programmatic nested load не заменяет внешний indicator.

Автосохранение остаётся без окна, включая временную запись с активным свободным
пером. Во время обычного disk operation оно заблокировано. Нового settings
переключателя нет: у HideDisk нет исходной команды изменения, default FALSE.
EN/RU labels, путь и счёт сохраняются при смене языка. Новых полей карты,
истории Undo или JSON нет. Окно компиляции описано отдельно в
[COMPILER_TASK_WINDOW](COMPILER_TASK_WINDOW.md).

## HideSplash

`Source/Includes/Editor.h:25` задаёт `SPLASH_DISABLED 1`. Единственное чтение
Config.HideSplash находится внутри `#if (!SPLASH_DISABLED)` в Splash_CreateWindow.
Таким образом, в имеющемся исходнике этот caller исключён при компиляции.
Это не незакрытая пользовательская команда; новый splash/settings UI не нужен.
Утверждение относится к Source, а не к неподтверждённому поведению каждого
исторического бинарного дистрибутива. Физическая сверка GUI остаётся M21.

## Доказательства и ручная приёмка

CLI проверяет точное совпадение загрузок DKM/KWD/MAP с observer и без него,
исходные hashes и missing references, реальные phase counts. Прерывание
observer не выдаёт Done и освобождает входной файл. Для stream проверены три
метода Write, фактические bytes/position/count, владение и Dispose. DKM/MAP
partial-write/flush failures сохраняют прежний target, историю и Save target,
не оставляют staging. Все выходы находятся в private temp; WPF не запускается.
WindowsSmoke дополнен actual Open/Save presenters, failure retention,
progress lifecycle и live EN/RU; эти UI cases только компилируются.

Ручные пункты M03/M20/M21/M23:

1. Открыть DKM, KWD и MAP: проверить путь, фазы, закрытие окна, результат.
   Затем открыть повреждённую копию и убедиться, что старая карта сохранилась.
2. Выполнить Save As DKM и MAP, отмену выбора пути и отказ от предупреждения.
   При отмене записи индикатор не должен начинать I/O. Ошибка доступа должна
   оставить прежний файл и доступный редактор.
3. Во время операции проверить блокировку редактирования и X индикатора,
   восстановление окон после успеха/ошибки и отображение конечного состояния.
   На больших файлах оценить фактическое обновление фаз; отзывчивость этой
   синхронной операции не доказывается сборкой.
4. Проверить восстановление и тихое автосохранение; во время явного Save
   второй Save/autosave не должен вмешиваться в файл.
5. Повторить в EN/RU, DPI100/125/150 и на другом мониторе. Физическое поведение
   окон и системных диалогов этим кодовым этапом не принято.
