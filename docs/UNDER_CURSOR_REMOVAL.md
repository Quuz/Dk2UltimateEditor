# Удаление объектов под курсором

16 октября 2026, UnderCursorRemoval-20261016. Текущие результаты сборки и
регрессии — в [CURRENT_STATUS](CURRENT_STATUS.md); вся задача и семь очередей
сохранены в [REMAINING_WORK](REMAINING_WORK.md).

## Как пользоваться

Наведите указатель на клетку открытой карты основного окна:

| Клавиша | Предпочтительная группа |
| --- | --- |
| Delete | существа |
| Shift+Delete | двери и ловушки |
| Ctrl+Delete | обычные и специальные предметы |

Если на клетке присутствует только одна группа, удаляется она независимо от
модификатора. Если групп несколько, используется предпочтительная группа;
при её отсутствии ничего не удаляется. Shift+Ctrl+Delete не запускает эту
команду. Удаляются все записи выбранной группы на клетке, включая стопки.
Области, ворота, эффекты и участники отрядов не являются этими предметами.

Двери обрабатываются перед ловушками; обычные предметы перед специальными.
Внутри списка сохраняется физический порядок. Для native это существенно:
BE-файл может содержать категории вперемешку, но команда следует исходным
раздельным спискам. Наличие только одной группы имеет приоритет над клавишей.
Вызов не зависит от выделения, активного brush template, paint terrain permission
или владельца клетки. Импортированный предмет на краю карты тоже доступен
команде; указатель за картой ничего не удаляет.

Редактор не перехватывает Delete при редактировании текстового поля/пароля.
Главное окно должно быть активно и доступно; указатель — над реальным Canvas,
в пределах его карты. Geometry-only preview, незавершённый штрих, правое
выделение и region pick не дают доступа к удалению. Alt/Windows модификаторы
не активируют команду. Правый клик продолжает выделять карту: исходный путь
удаления проходит через keyboard hook, а не MouseRightButton.

## Сценарный запрос и сохранение точек

Общего manager Yes/No с битом0x2 здесь нет. Используется только исходный safe
запрос существ с общим REQUEST_TRIGGERS0x100. Если на выбранной клетке есть
используемое в сценарии существо, открывается центрированный Yes/No/Cancel:

- Yes удаляет всех существ выбранной клетки.
- No оставляет всех с назначенным сценарным UID, удаляя только UID0.
- Cancel/закрытие оставляет карту и историю прежними.

Пустая явно созданная точка тоже считается используемой. Современный native
UID и orphan/empty state следуют [модели владельцев](NATIVE_OWNER_SCOPES.md).
DKM предикат использует creature operand всех TRIGGERLINK, как исходный
Triggers_GetFirstTrigger; node.type не служит дополнительным фильтром.

Двери/ловушки/предметы этого safe вопроса не задают. Их сценарные точки и
события после удаления остаются. Прямая команда не превращается в Delete Point.
Для продолжения работы с orphan/empty точками храните DKM и native-source ZIP.
Игровая карта остаётся ровно из семи официальных файлов.

Запомненное default Yes общее с manager remove/modify и used-area вопросами.
Отмена не запоминается; Undo не сбрасывает preference. Сброс вопросов объектов
или регионов очищает общий0x100. Посторонние биты сохраняются. При открытом
запросе другой policy не может перехватить его. [Общие правила](SHARED_SCENARIO_REQUESTS.md).
Клетка и состав выбора фиксируются **до** показа окна; движение указателя
к кнопке Yes, прокрутка окна или смена языка не выбирают другую клетку.

## Undo, счётчики и отказ

Source Things_RemoveAtMapPos/Things_RemoveAtMapPosSafe вызывает Undo_CreateEntry
и MapChanges++ отдельно для каждой физической записи. Команда повторяет этот
контракт: три удалённых существа означают три шага Undo, каждый восстанавливает
одного. Это отличается от одного родительского Undo менеджера. No с полностью
пропущенным набором и пустая клетка вообще не создают историю/счётчик/уведомление.
Согласованный пользователем полный Undo предметов сохранён: прежний порядок,
UID/точка и прежняя первая цель кристалла восстанавливаются вместе.

Source 32-bit MapChanges увеличивается на число удалённых записей и может
обернуться. Современные ChangeCount/EditRevision увеличиваются на то же число
с проверкой переполнения. Глубина0 не мешает редактированию; глубина1 оставляет
только последний шаг. Команда не добавляет usage paint/right-click counters.
Физическое принятие аппаратной клавиши и activity UI остаются ручной сверкой.

До изменения карты проверяются текущие schemas, все выбранные записи,
fingerprint, revision, layout ссылок и возможность выполнения каждой операции
на независимой копии. Если отказывает поздний шаг, исходные game/metadata
buffers, обе истории, memory budget и счётчики возвращаются целиком. При этом
уже запомненный Yes остаётся runtime preference, как в исходном запросе.

Запись остаётся по одному объекту и создаёт отдельные Undo, но уведомление
обновления UI отправляется после готовности всей серии. Observer не видит
частично опубликованную стопку; его ошибка после commit не объявляется отменой.
При Undo/Redo обычные уведомления происходят на каждом шаге. Generic DeleteRecord,
ApplyObjectRemoval и менеджерские counters/empty-parent policies не заменяются.

## Источник и проверка

Исходная цепочка: Main_Keyboard.c Keyboard_ProcessSpecialKeys(VK_DELETE)
→ Windows_MainWindowProc.c WM_KILLTHING → Map_Mouse.c
Mouse_RemoveThingUnderCursor → Things_Functions.c Things_RemoveAtMapPosSafe /
Things_RemoveAtMapPos → Map_Undo.c Undo_CreateEntry. Использование сценария
определяется Triggers_Functions.c. Source/ не изменён.

UnderCursorRemovalChecks проверяет48 сочетаний native/project × восемь
occupancy masks × три preference, source family order, несколько одинаковых
объектов, соседнюю неизменную клетку, empty/nonempty Yes/No/Cancel, shared0x100,
отсутствие общего0x2, no-op и No-all, per-record Undo/count, полные working+game
UndoRedo, depth0/1, uint wrap/long overflow, stale/pen/nested/bounds guards,
postcommit observer, DKM Save/reopen/compiler и семь игровых файлов.
Отдельная crystal проверка подтверждает цель9,9 → Undo4,5 и сохранение полного
порядка двух одинаковых кристаллов. WindowsSmoke содержит подготовленный
EN/RU × native/project маршрут с frozen tile/translation/Cancel/per-record Undo
и сохранением буфера/выделения; он только собран, не выполнялся.

Показ окна, реальная клавиатура/mouse, viewport clipping, focus, Enter/Escape,
системный звук, DPI и официальный редактор/игра требуют ручной приёмки.
Все реальные игровые проверки — DK2Preview_6a88240eaf814f78 через
DKII-DX.exe -q -level. Установленные карты и текущий TestMap не изменяются.

Открыты другие G/E участки: Inspector routing, manager category/detachment
semantics, полный Config preference lifecycle/persistence и прочие source
команды. Исторические/повреждённые layouts и compiler/definition/catalogue
проверки не объявляются закрытыми результатом этой команды.
