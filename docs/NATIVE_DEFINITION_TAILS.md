# Packed native-определения и непрозрачные хвосты

25 октября 2026. Продолжение I04. Чтение записей и выделение базовых
определений теперь используют общий `ScanNativeDefinitionSections`.

Раньше reader после известной секции пытался трактовать любые оставшиеся
56байтов как очередной header. Случайные длинные хвосты давали ошибку или
overflow. Copier отдельно определял packed только по второй известной
signature/version4: неизвестная секция между terrain и rooms могла скрыть
rooms, а при встрече непрозрачного хвоста поиск отсутствующего семейства падал.

Текущие правила:

- Проход идёт только по соседним ограниченным секциям. Старт непрозрачных
  данных завершает проход; поиска следующей signature внутри хвоста нет.
- Известный family header с распознаваемыми частями framing можно сохранить
  как неподтверждённый блок без fields. Unknown family frame требует
  согласованных version4/info/define markers. Это проверка framing, а не
  расшифровка его payload.
- Известная coherent секция, объявляющая больше bytes, чем осталось,
  отвергается как усечённая. Непрозрачный suffix не маскирует такой отказ.
- Семантические поля остаются доступны только после полного header guard
  предыдущего этапа. У неизвестного header count не используется для
  предположительного разбиения на editable records.
- Copier выделяет непрерывный физический фрагмент до следующего известного
  семейства. Неизвестные промежуточные frames и terminal tail остаются рядом
  с физически предшествующей секцией, а не выбрасываются.
- Future inner version можно сохранить в raw bundle, но нельзя выделить как
  standalone native-базис, который обычный reader не сможет открыть.

Opaque bytes не объявляются свойством последнего семейства. Сохранение рядом
с ним означает только сохранение непрерывного исходного фрагмента. Прежний
официальный packer явно отвергает фрагмент, выходящий за объявленную native
секцию: он не переносит непонятные bytes в другое место ради семи файлов.

При native→DKM неизвестные frames/хвосты и unsupported versions сообщаются
как `OpaqueDefinitionData` (**Loss**). Отказ от согласия не записывает DKM;
при согласии полный исходный Globals сохраняется в source companion.
Игровая пересборка поддержанных данных может исключить немоделируемые bytes,
поэтому их наличие больше не скрывается. Raw Save/reopen сохраняет все bytes
без такого преобразования. Неподтверждённые определения по-прежнему дают
`UnverifiedDefinitions` и запрещают семантическую конвертацию.

Подтверждены:

- Standalone suffix1/55/56/96/4096: редактирование известного поля, полный
  Undo, фактический Save/reopen с точными исходными bytes.
- Packed known/unknown/known +suffix; выделение настоящего rooms после
  unknown frame; сохранение промежуточных/terminal bytes при создании базиса.
- Future version как opaque; отказ недопустимого standalone extraction.
- Magic-only junk с embedded valid header не вызывает resynchronisation.
- Усечённая known секция остаётся отказом; loss consent/decline и source ZIP
  проверены настоящим Save.
- Полный девятисемейный базис включает официальный packer и подтверждает его
  отказ при suffix без опубликованного частичного каталога.

До правки:8FAIL/1PASS. После правки8 групп прошли; последний тест использовал
неполный базис и проверял loose Save вместо official packing. Фикстура отдельно
исправлена до полного девятисемейного набора, и её отдельный прогон прошёл.
Неизменённые восемь успешных групп ради этого не перезапускались. Полный
focus-01 ExitCode1 сохранён как промежуточный, не переименован в зелёный.
