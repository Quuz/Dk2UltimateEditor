# Сценарные точки регионов при обрезке карты

16 октября 2026. Окно свойств карты сохраняет сценарные точки областей,
удалённых при уменьшении размера. Это относится и к частично выходящим
областям, и к областям на фиксированной внешней рамке. Пустая явно созданная
точка сохраняется так же, как непустая. Ссылки событий на области, ворота
и генераторы эффектов остаются в данных.

Правило берётся из `Properties_RemoveRectEx` в
`Source/Sources/Properties/Map/Properties_Map_Global.c`: удалить MAPRECTEX
через `Undo_StoreEntry`, увеличить MapChanges и продолжить проход. Функция
не удаляет MapActionPoints, не меняет operands и не переадресует `nextid`.
После обрезки B в A → B → C связь A → B сохраняется как отсутствующая цель.
Обычная команда Delete имеет другое правило A → C и второй вопрос о
сценарии; её обработчик здесь не используется. См.
[удаление областей](USED_AREA_REMOVAL.md) и [патрульный Delete](AREA_REMOVAL_PATROL.md).

Source-флаг Nasty выставляется для используемой области, но полный
`Properties_MapOptions` его не читает: одно объявление и восемь передач адреса,
без последующего условия или показа окна. Поэтому обрезка не добавляет
второй вопрос Yes/No/Cancel или новое предупреждение о сценарной точке.
Существующее подтверждение обрезки в общем окне остаётся обязательным.

## Рабочая модель

Подготовка Apply работает с независимой копией. Оба этапа удаления — за
пределами нового размера внутри ResizeCore и на фиксированной рамке после
него — используют отдельную source-команду удаления проверенного региона.
Она сохраняет DKM TRIGGERLINK, а native GAMEAREA переводит в сохранённую
точку без физического владельца через D2AS/v1. Неизвестные layouts остаются
запрещены. Аргументы событий не исправляются автоматически.

Native DESTROYGATE по-прежнему использует проверенное преобразование цели:
отсутствующие ворота дают координаты(1,1), меняются только два соответствующих
WORD события. Рабочий ID сохраняется. Остальные event bytes и DKM operands
не переписываются. Пустые/orphan точки участвуют в истории, приватных копиях,
DKM/native-source архиве и дальнейшем повторном использовании ID области.
Их возможности и граница plain KWD описаны в [USED_AREA_REMOVAL](USED_AREA_REMOVAL.md).

Общий Apply имеет один Undo/Redo и одно уведомление. Исходный счётчик включает
настройки, изменение размера, каждое перемещение и каждую удалённую физическую
запись; сохранённая сценарная точка не считается ещё одним удалённым предметом.
Например, три региона, один удалён: без смещения получается3 увеличения
(настройки + resize + удаление), со смещением всех трёх —6.
Cancel и отказ от подтверждения обрезки сохраняют исходную карту и историю.
Undo/Redo возвращает целые game/working buffers вместе со счётчиками.

Низкоуровневые `Resize` / `PrepareMapProperties` сохраняют отдельные прежние
контракты. Generic native resize продолжает отказывать при входящей ссылке
на удаляемую область; исторический generic project resize сохраняет прежнее
удаление owned links. Source-поведение подключено к настоящему GUI через
`MapPropertiesWindow → PrepareEditorMapProperties → ApplyEditorMapProperties`.
Само окно этим этапом агентом не запускалось.

Быстрая команда Resize открывает это же общее окно. Старый отдельный диалог,
который вызывал generic resize и обходил source crop, удалён. Единственный
путь UI resize теперь использует общий черновик, подтверждение обрезки и Apply.

## Проверки и ручная приёмка

72 случая: native/project × область с пустой/непустой точкой, ворота или эффект
× три привязки × левая/правая рамка или выход за границу. Проверяются оба
этапа crop, полные event collections, сохранение обоих предшественников,
точек/operands, исходный счётчик, один Undo/notification, независимый preview,
Cancel, отказ подтверждения и целые Undo/Redo. Отдельно проверены пакет
трёх областей с разными точками, настоящие DKM Save/reopen, native-source архив,
first-free ID reuse, компиляция и семифайловый экспорт; прежние generic политики
проверены отдельно. Результаты конечной DLL и корпуса — [CURRENT_STATUS](CURRENT_STATUS.md).
Исходные тела и hashes: `artifacts/Evidence/RegionCropScopes-20261016/source-capture.json`.

Для ручной проверки на копии карты создайте область со сценарием у правой
границы и маршрут, ссылающийся на неё. Уменьшите карту через свойства так,
чтобы область попала под обрезку. Отказ подтверждения оставляет всё на месте.
После принятия область исчезает, её точка остаётся в дереве, а входящий
патрульный ID сохраняется. Проверьте Undo/Redo, DKM Save/reopen и EN/RU.
Новые ворота/области/эффекты не должны требоваться для завершения самой обрезки;
диагностика и политика компиляции отсутствующих целей остаются отдельными.
Игра — только `DK2Preview_6a88240eaf814f78` через `DKII-DX.exe -q -level`.

Это завершает source crop регионов. Для существ, дверей, обычных и специальных
предметов нужны отдельные working scopes/identity и source callers:
`Properties_RemoveThings → Things_RemoveAtMapPosEx` тоже сохраняет исходные
точки. Эти семейства остаются в очереди A/G, вместе с общим REQUEST_TRIGGERS,
прочими native metadata, compiler/historical policy и физической приёмкой.
Все23 области полной цели сохранены в [REMAINING_WORK](REMAINING_WORK.md).
