## Источник значений

`ReadCreatureLevelModifierDefaults` читает существующий загруженный
GlobalVariables.kwd либо его неизменную копию в native-source archive DKM.
В ядре нет скрытого чтения диска или догадок о процентах. Неоднозначный каталог
отклоняется; без полного effective набора частный контекст не открывается.

Перегрузка `CreateCreatureLevelModifierSession(defaults)` принимает явный
снимок другого каталога, например выбранного пользователем каталога ресурсов.
Входной список копируется. Сначала загружаются значения этого снимка, затем
существующие map tuples; последнее вхождение каждого `(type,statistic,level)`
задаёт текущий SHORT. Полные исходные DWORD остаются доступны для guards/no-op.
Неполный shared снимок допустим лишь тогда, когда недостающее уже есть в карте.

Дополнительное подтверждение чтения формата: [OpenKeeper KwdFile](https://github.com/tonihele/OpenKeeper/blob/master/src/main/java/toniarts/openkeeper/tools/convert/map/KwdFile.java)
читает ссылки по порядку и обновляет таблицы характеристик по ключу уровня и
характеристики. Стандартный descriptor нашего редактора ссылается сначала на
GlobalVariables.kwd, затем на map Variables.kld. Это подтверждение структуры
загрузчика, а не испытание оригинального игрового процесса. Необычные неоднозначные
наборы ссылок остаются в I01/I03; эта реализация не объявляет их закрытыми.

## Создание недостающих overrides

Частный session знает полные исходные значения, включая унаследованные.
Перед применением все changes проверяются: ключ, диапазон, source bits,
наличие captured default для нового ключа и текущие owner/revision/fingerprint.
Семантический no-op, в том числе ввод0 при исходных100, записи не создаёт.

В native карте новый16-byte tuple вставляется в map Variables.kld. Счётчики,
длины и opaque продолжение обновляются существующим bounded collection writer.
В SharedDefaults и установленном GlobalVariables.kwd ничего не записывается.

В DKM новые записи хранятся в отдельном частном разделе **D2LO v1**:

| Смещение | Размер | Содержимое |
| --- | --- | --- |
| 0 | 12 | signature0x4F4C3244/version1/payload length |
| 12 | 4 | count0…230 |
| 16 | 16×count | canonical type/statistic/value DWORD/level tuples |

D2LO содержит новые данные, созданные пользователем. Они не объявляются
исходными native records и не подмешиваются в immutable retained stream.
Правка уже существующих исходных записей по-прежнему использует D2LM с hash/
original bits/offset guards. Его версия и проверка архива не изменены.
D2LO проверяет shape/count/key/range/canonical signed bits, уникальность и
отсутствие коллизии с исходными retained keys. Смешанная операция обновляет
D2LM/D2LO в одной транзакции. Пустые разделы не сериализуются.

Новый DKM с D2LO не требует выдуманного исходного ZIP: его собственные typed
records находятся в самом проекте. Если у проекта уже был native источник,
Save/SaveCopy сохраняют прежний архив для восстановления остального содержимого.
При компиляции typed records добавляются после исходных retained records в
Variables.kld. Отдельных игровых файлов D2LM/D2LO нет.

## Reset и общая отмена

`DefaultValues` возвращает независимую страницу выбранной характеристики.
`ResetSelectedToDefaults` копирует все9+1 значений в private draft и проверяет
их целиком. Живой документ не меняется до Apply. У уже созданных overrides
reset заменяет значения на значения каталога и сохраняет записи карты.
При выборе другой страницы прежние правки остаются в том же контексте.

MapPropertiesSession теперь принимает проверенные level edits дочернего
контекста вместе с остальными настройками. В native коллекции допускаются
только DWORD последнего видимого вхождения и новые canonical visible keys.
Порядок/остальные bytes неизвестных записей и ранних дубликатов сохраняются.
В DKM допускаются проверенные D2LM/D2LO, а исходный retained stream и связанный
архив остаются прежними. Это разрешение конкретной подсистемы, а не общий
доступ дочерних окон к произвольным байтам.

Весь родительский Apply остаётся одним Undo; parent Cancel ничего не публикует.
Private buffers входят в fingerprints, clone, history и Save baseline.
Нехватка памяти после вставки возвращает весь прежний owner и оставляет session
открытым для повторного применения.
