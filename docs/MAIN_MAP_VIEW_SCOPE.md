# Original main-map view scope and remaining acceptance

Source audit, 2026-10-07. Physical glyphs and the eight object flags are covered by [main-map objects](MAP_OBJECT_DISPLAY.md); terrain resources, two-dimensional zoom and terrain visibility by [terrain/zoom](TERRAIN_ZOOM.md); camera icons/overlap, region labels, safe gate expansion, integer paths/colour and the six remaining flags by [map overlays](MAP_OVERLAYS.md). The source requirements below are now implemented by those separate checkpoints, not closed by this audit alone. Historical GDI raster/original GUI/hardware/DPI/game acceptance remains open. Main-map fidelity must not be replaced by invented creature sprites.

## Terrain images and zoom

`Map_Paint` in `Map_Display.c` uses four source image lists: World, Rooms, Gates and Walls. Room owners 1–7 select different lists. `Map_InitialiseZoom` in `Map_Setup.c` creates ordinary bitmap lists for World/Gates/Walls/Hero rooms, then `Misc_CreatePlayerImageList` for room owners 2–7. That routine scales the source room bitmap and a player frame bitmap, then combines them with **bitwise SRCPAINT**, not alpha tinting or a coloured modern border strip. Owner-frame resources are 932–937. Other lists use `ImageList_Add` with no mask. Unknown/native terrain projection and bitmap display identity must remain separate from editing bytes.

A comment-stripped join of `Datas_Map.c` and `Editor.rc` verifies 11 World / **23 active Rooms** / 6 Gates / 14 Walls entries. Distinct resource counts are 10 / 23 / 6 / 14; every resource mapping/file exists. The earlier count of 24 Rooms incorrectly included the commented-out Crypt row, which is not an active source capability. All six room owner-frame files exist too: 53 terrain BMP resources plus six frames. These preserved assets are reused without downloaded/generated replacements. The duplicated catalogue images do not remove variant/ID distinctions.

`Windows_ZoomButton.c` `Zoom_Change` exposes **11 original square presets: 10,16,20,32,40,48,60,80,96,100,128**. Its user option uses independently configured `Config.ZoomCX`/`ZoomCY`, default 64×64, and can be nonsquare. The modern canvas now supports these source presets and independent dimensions, with per-axis viewport navigation, visible-cell culling, object/region geometry, mouse-to-cell conversion, placement previews and selection. The former 2–48 scalar is no longer the implementation. Camera display is implemented in the overlay checkpoint; its historical/game acceptance remains open. The managed 2–512 bounds are a safety extension, not a recovered source restriction.

`MVF_TERRAIN` hides terrain by painting black, without automatically hiding independent object layers. The remaining source flags also include areas, gates, paths, effects, cameras and expanded gates. Eight physical object options are not all fifteen source menu flags.

## Cameras and region labels

`Map_Cameras.c` loads original 16×16 camera ICO resources 20–24; all five paths exist. `Map_DrawCameras` draws only five keeper cameras (source rows 2–6), skips explicit -1 camera coordinates, adds owner-coloured two-pixel ellipses of radius two cells and centred icons. Shared positions get source overlap offsets based on the number of other cameras and the keeper index. Project stored/default coordinates must not be conflated with compiler-resolved effective heart positions; historical readers ignore camera fields in older player sections. Existing [player geometry](PLAYER_GEOMETRY.md) already distinguishes these and retains malformed raw values. Ambiguous native player identities and out-of-map values need nonmutating guards rather than copied unsafe C indexing.

`Things_DrawAreas` / `Things_DrawEffects` call `Map_DrawRectangle`, which renders rectangle names with an outlined text colour before the clipped one-pixel boundary. The current generic region outline alone is not the complete source label/visibility workflow. Gate expansion must be derived from `Things_DrawGates` and `Things_ExtendGate`, including its boundary bug, before implementing a safe equivalent; a generated gate point and a terrain footprint are different identities. Source path-colour settings are also separate from camera/player colours.

Acceptance still required: preserved terrain/owner-frame and camera resources; independent pixel/ID checks, OR composition, source zoom presets/user dimensions and persistence; all fifteen source view flags wired to their actual layers; complete region/gate/camera display projection; EN/RU actual controls and rendered native/project checks; exact read-only selections/copy buffers/history; full regression/corpus gates; original-GUI/GDI/hardware/DPI/game verification. This audit closes no implementation requirement by itself.
