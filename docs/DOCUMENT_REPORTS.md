# Полные отчёты загрузки, проверки, сохранения и компиляции

17 октября 2026, DocumentReports-20261017. Устранено усечение предупреждений
компиляции до12 строк MessageBox. Добавлен общий отчёт с полным упорядоченным
списком, подробностями выбранной строки и переходом к её области на карте.
Повторяющиеся diagnostic codes не объединяются и не теряют отдельные строки.

## Сопоставление исходных callers

Source/Sources/Compiler/Compiler_Report.c, dialog6001, имеет два исходных
назначения: REPORT_LOADERROR только с Close и REPORT_COMPATIBILITY с
Save/Cancel. Load report вызывается после разблокировки карты в Files_Load.c,
включая список ошибок чтения. Compiler_ReportShow при выборе строки с x≠−1
переходит к указанной области. По закрытии снимается временная подсветка.
Cancel получает фокус; Enter не должен случайно разрешать запись.

| Современная команда | Текущий маршрут |
| --- | --- |
| Open успешно с диагностикой | Уже принятый документ/inspector остаётся открытым; Close-only отчёт показывает все строки инспекции |
| Open завершился ошибкой | Предыдущий документ сохраняется; Close-only отчёт содержит доступную диагностику инспекции и исключение загрузки. Новая карта не принимается частично |
| Явный Test/Validate карты | Существующий сценарный caller/cleanup consent выполняется как раньше; затем полный Close-only отчёт вместо одного summary MessageBox |
| Compile/подготовка Game Run: ошибки | Полный Close-only отчёт, без создания output и без запуска игры |
| Compile/подготовка Game Run: предупреждения | Полный список доступных diagnostics; Continue/Cancel перед записью. Информационные строки не становятся ошибками или отдельным обязательным подтверждением |
| Save/Save As | Существующий SaveConfirmationWindow с text losses/conversion issues/native-source retention сохраняется; выбранные version notices добавляются туда же, без второго запроса |

В отличие от исходного восстановления после неудачного Load, прежняя
современная атомарная замена документа сохраняется: отчёт не является
разрешением исправить или принять повреждённые данные. При успехе загрузки
Close — уведомление, а не возможность отклонить уже открытый файл.

## SaveReportFlags

Source/Includes/Files.h: Version=1,Warnings=2,Alerts=4,Infos=8. Default=14.
EditorReportRules объединяет исходный gate Files_Save.c и фильтрацию строк
Compiler_ReportInit. Для editor output выбираются только version rows и лишь
при включённом Version; для game/text — по severity. Temporary output не
создаёт compatibility report. Load и Compile/Test diagnostics этим фильтром
не скрываются.

MainWindow.SaveCompatibilityRows подключает существующие DK2 version notices
GameVersionCompatibility к реальному Save plan. DKM с default14 не получает
новый version prompt; MAP может показывать информационные notices. В текущем
сеансе доступно runtime-свойство SaveReportFlags, без нового settings dialog:
активной исходной команды настройки этого поля не найдено.

Фильтры управляют дополнительными compatibility notices. Они не выключают
действующее согласие на потери, запрет blocked conversion или обязательное
хранение native-source archive. И после ответа остаются прежние проверки
EditorSaveSession.IsCurrent(plan)/fingerprint/statistics/owner, проверки
компиляции и принятие точных сохраняемых bytes. Автосохранение не проходит
новый пользовательский отчёт и не получает разрешения на потери.

Это подключение существующих version diagnostics; полный перенос всех
исходных compatibility message generators/writer branches остаётся в I02.
Новый список не доказывает равенство ещё не сопоставленной семантики сообщений.

## Окно, навигация и lifetime

DocumentReportWindow хранит независимый массив диагностики. Severity, заголовки,
кнопки и подсказки локализованы EN/RU; сообщения используют существующие
Diagnostic translations, с исходным подробным текстом/code/path в деталях.
Неизвестные technical messages остаются в общем I13, не объявлены полностью
переведёнными благодаря новому окну.

Выбор строки с корректной областью перемещает курсор/viewport и временную
подсветку. Он не меняет выделение, данные, Undo и счётчики редактирования.
Metadata rows без координат, пустые/отрицательные/выходящие за карту области
не создают переход. Активный жест/region pick не прерывается навигацией.
После закрытия прежняя подсветка восстанавливается только для того же
документа; выбранное положение viewport сохраняется, как в исходнике.

Окно не может разрешить продолжение после смены/правки/закрытия документа.
Compile дополнительно перепроверяет собственный plan/current callback после
ответа. Read-only Load/Test не имеют разрешающего действия. При ошибке
Continue недоступно независимо от видимости других сообщений. Close/Cancel
— default action; смена EN/RU сохраняет выделенную диагностическую запись.

DocumentReportPresenter позволяет принять/отменить этот же оконный маршрут
при приёмке без открытия диалога. Существующие SaveNoticePresenter и
ScenarioNoticePresenter остаются override для Close-only сообщений: получают
весь список, никогда не разрешают Continue. CompileWarningsPrompt сохраняет
свой прежний контракт и precedence. Это обратная совместимость hooks, не
доказательство фактического отображения окна или работы мыши.

## Ручная M03/M04/M18/M20/M23

1. На собственной копии с диагностикой открыть карту; проверить Close-only
   список, все сообщения и детали. Для неудачной загрузки прежняя карта остаётся.
2. Выполнить явную проверку. Выбрать сообщение с областью: карта прокручивается
   и подсвечивается, прежнее выделение сохраняется; закрыть отчёт.
3. На карте с множеством compile warnings проверить сообщения после12-й строки,
   Cancel до output, затем Continue. При errors запись/запуск не разрешаются.
4. Выполнить Save As DKM/MAP с известными losses/version requirements: увидеть
   полный consent, отменить и проверить отсутствие новой записи. Затем принять
   и проверить результат на своей копии. Native-source retention сохраняется.
5. Проверить EN/RU с выбранной строкой, Enter/Escape/Tab, default Cancel/Close,
   длинные path/messages, прокрутку, DPI и закрытие владельца. Отдельно проверить
   недействительность согласия при изменённом документе в приёмочном harness.

Кодовые report routes I17 подключены в этом объёме. I17 не закрыт целиком:
