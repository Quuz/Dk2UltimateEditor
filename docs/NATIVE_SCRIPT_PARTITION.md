# Порядок условий и действий в native-сценариях

Последующий этап [packed inspector/suffix consent](NATIVE_PACKED_INSPECTION.md) закрыл описанные ниже packed-definition inspection и opaque collection suffix conversion. Остаются historical sections, unknown whole native companions и общая route matrix.

Состояние на 25 октября 2026, этап `NativeScriptPartition-20261025`.
Исправлен следующий конкретный дефект I04 после
[проверок физических layouts](NATIVE_COLLECTION_GUARDS.md).

## Формат и причина ошибки

`Game_ExtractTriggers` в исходнике сначала читает `dwTriggersCount` записей
с signature D5 и размером payload 16, затем `dwTriggersActionsCount` записей
D6 того же размера. Вместе с восьмибайтным префиксом запись занимает 24 bytes.
Заголовок D2 занимает 60 bytes; числа условий и действий находятся по +20/+24.
`Compiler_GenerateTriggersFile` также последовательно вызывает запись условий
и действий. Это два блока, а не произвольная смесь записей.

Раньше общая вставка дописывала условие после уже существующих действий.
Наш граф продолжал видеть его по signature, но исходный reader мог отвергнуть
такой файл. Теперь новое D5 вставляется по адресу `60 + 24 × conditionCount`,
перед первым действием. D6 добавляется после последнего учтённого действия,
до непрозрачного суффикса. Порядок внутри обоих блоков и event IDs сохраняются.
Поле размера payload по-прежнему не используется как адрес: в реальных файлах
оно бывает устаревшим, что уже учтено [предыдущим исправлением](NATIVE_COLLECTION_BOUNDARIES.md).

## Рабочие привязки и транзакции

Вставка условия сдвигает физические адреса действий. `RebaseNativeActionInsertion`
до переноса bytes сдвигает соответствующие `ActionOffset` в рабочей таблице
привязок ворот. Gate IDs, выбранный физический экземпляр и координаты не
пересчитываются по догадке. Это сохраняет выбранные вторые ворота при одинаковых
координатах, удалённую цель с ненулевым ID и отсутствие цели с ID0.

Рабочая таблица входит в общую транзакцию и Undo/Redo. При клонировании графа
новые IDs связей остаются согласованными, существующие действия сохраняют свои
цели. Вставка условия в продолжение действия уже обновляла владельца по event ID;
это поведение проверено и сохранено. Вставка выделения использует тот же общий
маршрут. После изменения коллекции внешний сохранённый `NativeRecord` может
устареть; текущую запись события следует получать по его ID.

## Неправильные входные файлы

Общий `VerifiedScriptPartition` проверяет signature каждой учтённой позиции:
первые conditionCount — D5, последующие actionCount — D6. Он обходит все
учтённые frames, поэтому неправильный порядок не скрывает последующее усечение.
Произвольный суффикс после объявленных записей не сканируется в поисках событий.

Неправильный порядок или разделение counts делает всю D2-коллекцию непрозрачной.
Инспектор и валидатор дают одинаковый DK2N047; поля не открываются для изменения,
добавление и DKM-проекция отклоняются. Обычная native-копия сохраняет исходные
bytes без перестановки и ремонта. Уже созданные неправильные файлы автоматически
не исправляются. Явный режим текстового MAP `OriginalNoScenarios` может исключить
такую коллекцию сценариев; обычный режим со сценариями её не пропускает.

Read-only инвентаризация 109 установленных `*Triggers.kld` не обнаружила
нарушений этого правила. Для каждого входа сохранён SHA256 до/после чтения.
Ни один установленный файл не записывался.

## Проверки

До изменения восемь новых групп завершились FAIL; после изменения все восемь
прошли. Независимый reader oracle использует буквальные D5/0x10 и D6/0x10 блоки
из `Files_Game.c`, а не production helper. Проверены:

1. Чередование добавления действий и условий, порядок внутри категорий,
   event IDs и настоящий raw Save/reopen.
2. Вставка условия после действия с обновлением переместившегося владельца.
3. Выбранные дубликаты ворот, удалённый target ID2 и missing ID0, включая
   native→DKM и точный Undo/Redo.
4. Дублирование смешанного графа с сохранением новых связей и целей ворот.
5. Устаревший payload size16, непрозрачный суффикс96 и точная история.
6. Три неправильных входа: перестановка блоков и два неверных split-counts;
   совпадающая диагностика, отказ без истории и точный raw copy.
7. Явная original no-scenario политика MAP.
8. Clipboard paste перед существующими действиями с сохранением выбранных ворот.

Смежный тест expansion сравнивал независимые компиляции побайтно вместе с
GAMEDATE. Это давало отказ на границе секунды. Тест теперь намеренно пересекает
её и исключает только 14 часово-календарных bytes каждого известного generated
GAMEDATE, включая семь editable frames внутри packed Globals. Шесть padding
bytes и все остальные данные сравниваются полностью. Наблюдавшиеся отличия
выведены со смещениями; даты отдельно проверены `CompilerGameDateChecks`.
Продуктовая генерация дат не менялась. Оба промежуточных отказа сохранены.

Логи и коды завершения находятся в `artifacts/Evidence/NativeScriptPartition-20261025/`.
Итоговые результаты, хеши DLL и пакетов перечислены в `source-partition-proof.json`
и `delivery.json`. Полного corpus-прогона и запуска GUI/игры не было.

I04 остаётся открытым для инспекции packed definitions, поддержанных исторических
секций и общей таблицы inspector/load/edit/export, включая явную политику
переноса непрозрачных суффиксов при конвертации. Это исправление не означает
завершения полной цели или 23 ручных групп.
