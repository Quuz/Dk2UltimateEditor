## Границы сравнения и сохранённые неудачные попытки

Первое подготовительное рисование совпало с прежней клеткой и было no-op;
после этого отдельная prepare.py применила отличающуюся terrain4. start.py не
повторяли и существующую тестовую папку не заменяли. Часть UI Automation индексов
системных дочерних окон не была доступна в cache; использовались свежие снимки и
координаты. Ввод пути исправлен через контекстное «Выделить всё», проверен до записи.

Первая чрезмерно строгая проверка fingerprint сразу после DKM Save против reopen
не прошла. У DKM это разные представления: SerializeLegacyProject пересоздаёт KMAP
из актуального TileFile; ProjectSavedActivity записывает runtime KSTS, сохраняя
imported section bytes в памяти. Отличались только main container, section-0 KMAP
и section-8 KSTS; остальные8буферов совпали. Это подтверждено исходным кодом
LegacyProjectEditing.cs и NativeMapDocument.ActivityStatistics.cs. Для проверки
результата запись сравнили с реальным массивом1672 клеток на диске и reopen всех
клеток, плюс остальными8буферами и точнымZIP. Не выдаём тот исходный assert за PASS.

При неуспешной записи сравнение полного editing fingerprint корректно: оно
проводится в одном документе, без сериализации/reopen, и прошло. Runtime counters
ActivityStatisticsSession отделены от undo-буферов и не входят в этот fingerprint;
BeginProjectWrite согласно исходнику сохраняет статистические эффекты попытки.
Их неизменность этим результатом не утверждается.
