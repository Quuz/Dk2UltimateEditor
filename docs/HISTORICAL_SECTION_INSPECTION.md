# Инспекция исторических секций и неизвестных native-файлов

Последующая [сверка I04](I04_CODE_CLOSURE.md) закрыла F01 descriptor header/metadata guard и весь кодовый scope I04. [Таблица](I04_FORMAT_MATRIX.md) теперь финальная; ручные проверки остаются.

Состояние на 25 октября 2026, `HistoricalSectionInspection-20261025`.
Текущий объём I04 сведён в [таблицу форматов](I04_FORMAT_MATRIX.md).

## DKM и AREA

Предпросмотр теперь разбирает не только внешний MAPF/AREA header, но и тот же
внутренний поток, что загрузчик. Он вызывает общий `FromLegacyProject` с
`initializeActivity:false`. Создаётся ограниченное представление контейнера,
без таймера статистики, поиска source archives или редактируемой сессии UI.
Проверяются KMAP, размеры известных секций, counts и alias table KTRG2/3,
KGBL flags/arrays и частные bounded level-modifier sections. Enhanced DKZ с
DKCP не принимается как обычный проект: для него сохраняется отдельный путь
«Загрузить DKZ в буфер». Предпросмотр сообщает реальные ширину и высоту.

Все 22 фиксированные схемы проверены в обоих контейнерах:

| Секция | Версии | Схема / граница |
|---|---|---|
| KINF | 1…7 | V1, V2 для2/3, V4, V5, V6, current; одна запись |
| KPLY | 1…3 | V1/V2/current, ровно семь positional rows |
| KTGS | 1…6 | V1, V2 для2/3, V4, V5, current; кратная длина |
| KREC | 1 | MAPRECTEX; кратная длина |
| KMTH | 1…5 | MTHBANDV1…V4/current; кратная длина |

Размеры и поля по-прежнему получаются из исходных C-структур через
`LegacyProjectSchemas`. Исторические KTRG1 остаются непрозрачными до явного
upgrade; этот этап не пытается раскрыть неизвестные bytes и не меняет рецепты
преобразования. Для KTRG2/3 проверяются три счётчика и полная таблица146×64;
для KGBL1 — семь optional arrays и точное окончание payload. Unknown flags,
будущие версии и неизвестные секции сохраняют `Project.Opaque` и DK2N008,
совпадающий с валидатором. Известная усечённая схема — ошибка в обеих точках.

Политики KSTS и source archives остаются отдельными. Известная секция статистики
может добавляться и обновляться при Save; это уже существующее поведение.
Новые проверки сравнивают все исходные секции и порядок побайтно и допускают
только одну добавленную KSTS, вместо неверного требования неизменности всего
контейнера. Предпросмотр не проверяет содержимое внешних source archives;
это выполняется при полном открытии, до восстановления native payloads.

## Целиком неизвестный native companion

Неизвестный signature version4 теперь виден как одна запись
`Opaque.NativeFile`, без полей. Инспектор и валидатор выдают одинаковый DK2N049.
Категория, предупреждение и loss message переведены на EN/RU. Raw native copy
сохраняет весь файл; DKM сообщает Loss `OpaqueNativeFile` и использует обычное
согласие на потери. До согласия файл проекта не создаётся; после согласия полный
companion остаётся в source archive. Игровая регенерация DKM не обещает включить
его в официальный комплект.

Обычный SetField и специализированный writer внутри общей транзакции не могут
менять неизвестный native-файл, даже если вызывающий код сконструировал поля.
Отказ восстанавливает bytes и не оставляет Undo. Future outer version остаётся
ошибкой. Ненулевой type в KWD reference теперь проверяется и при загрузке:
signature companion должен совпадать. Type0 сохраняет значение untyped packed
reference. Раньше эту проверку выполнял только инспектор.

## Результаты

Исходные восемь новых групп дали 8 FAIL. После подключения parser и opaque file
policy: 7 PASS / 1 FAIL, вызванный ошибочным full-container ожиданием от Save
с добавлением KSTS. Два дополнительных негативных случая — прямое изменение
неизвестного файла и typed-reference mismatch — воспроизведены отдельно.
Итоговые десять групп прошли после исправлений. Логи, коды и scoped diff сохранены
в `artifacts/Evidence/HistoricalSectionInspection-20261025/`; финальные числа
и хеши — в `source-section-proof.json` и `delivery.json`.

Проверены 44 положительных fixed-layout сочетания и44 их усечённых варианта,
обе версии KTRG2/3 в двух контейнерах, семь KGBL arrays, opaque retention,
inner framing, missing/duplicate KMAP, DKCP route и private sections. Смежные
проверки охватывают старые upgrades, DKZ, packed definitions, metadata bounds,
file-chooser previews, actual activity Save, native conversion и official bundle.
Все штатные семь игровых файлов и полные исходные inputs сохраняются.

Это структурная инспекция, не gameplay validation и не фактическая проверка
оригинального GUI. Полного corpus-прогона не было; старые1840/63 не выдаются
за текущий результат. Компьютерный интерфейс и игра не запускались.
