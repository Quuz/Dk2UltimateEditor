# Добавление и локальный Undo в менеджере объектов

17 октября 2026, ManagerCommandHistory-20261017. Внутри I17 реализованы
добавление из самого менеджера, его локальная отмена и double-click Modify.
Остальные source команды и Config не объявляются завершёнными.

## Исходные команды

Things_Manager.c: Things_ManagerProc case126 вызывает Add, case180 вызывает
Things_ManagerUndo, NM_DBLCLK списка вызывает Modify. ManagerUpdateUndo
увеличивает undocnt после принятых Add/Modify/Remove; Undo уменьшает локальный
счётчик и перестраивает список с прежними selection/onmap/sort preferences.
Закрытие менеджера не отменяет применённые изменения. Новый менеджер начинает
без права отменять шаги, сделанные до его открытия.

## Текущая реализация

Кнопка «Добавить объекты…» открывает существующее ObjectBatchWindow дочерним
окном, с соответствующей family, общими source templates/options/координатами.
Private Cancel остаётся без правки карты, явное применение использует прежний
batch insertion caller. Никакой второй реализации добавления не создано.
Double-click строки открывает тот же modification/request маршрут, что кнопка.

EditorObjectManagerHistory принадлежит одному открытому менеджеру. Выполнение
добавления/изменения в его дочернем окне и подтверждённого удаления регистрирует
точный новый root HistoryOperation. Кнопка Undo вызывает прежний document.Undo
только когда именно этот root находится наверху. Установка depth0 не создаёт
фиктивного локального Undo, trimming не даёт перескочить за удержанный стек.
Менеджер не отменяет чужую правку или шаг до своего открытия. Внешний Redo
не восстанавливает уже израсходованный локальный счётчик. Это guard современной
модальной интеграции; небезопасное применение source undocnt к чужому шагу
не воспроизводится. Согласованный полный Undo предметов сохраняется.

Перед Undo проверяются pending confirmation и canApply; после CommitFields
верхушка проверяется снова. Дочерние drafts закрываются, список перечитывается.
HistoryChanged обновляет доступность кнопки также при изменении depth/save.
Закрытие/смена документа освобождает обе дочерние формы и локальную authority.

При replay allocation failure локальная запись остаётся для повторной попытки.
При исключении observer после commit изменение уже выполнено: Execute
регистрирует этот root, а Undo потребляет его, если отмена уже состоялась.
Declined/stale removal не присваивает себе возможную чужую правку host.
Reentrant/несколько последующих root edits не присваиваются как один manager
command. Чужая операция блокирует локальную отмену, пока она сама не отменена.
Текущие request bits/preferences, форматы и число игровых файлов не меняются.

## Ручная приёмка M20

1. На своей копии сделайте обычную правку карты до открытия менеджера.
   Откройте менеджер: Undo пока недоступен. Отмена пустого добавления не
   должна его включить и не должна менять карту.
2. Через «Добавить объекты…» разместите один объект, примените, закройте
   дочернее окно. Undo менеджера включён. Нажмите его: добавление исчезает,
   прежняя правка карты остаётся. Ещё один локальный Undo недоступен.
3. Повторите с изменением и удалением объекта. Отказ от подтверждения не
   создаёт локального шага. Double-click строки и кнопка изменения открывают
   один и тот же запрос/редактор. Заголовок таблицы не должен открывать правку.
4. Закройте/откройте менеджер: старые изменения доступны в общей истории,
   но новый локальный счётчик пуст. Проверьте смену карты, EN/RU, Enter/Escape,
   focus/Cancel/Apply, разные DPI. Закрытие менеджера сохраняет применённое.

Эти шаги не выполнены агентом. Не исчерпывать память вручную: для fault cases
используется подготовленный harness. Игровые проверки по-прежнему только
DK2Preview_6a88240eaf814f78, ровно7 файлов, через DKII-DX.exe -q -level.

Things_ManagerIsThingInRect по включительным границам; это чтение кода,
не физическая приёмка списка. Полный перечень — OPEN_FUNCTIONS_RU.
