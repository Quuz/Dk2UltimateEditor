# Сценарная цель при редактировании native ворот

15 октября 2026. Прямое изменение геометрии ворот, общее окно свойств области,
его частная генерация и удаление ворот учитывают координаты зависимого действия
`ACTION_DESTROYGATE` (32). Изменение размера имеет отдельный маршрут:
[NATIVE_RESIZE_DERIVED_TARGETS](NATIVE_RESIZE_DERIVED_TARGETS.md).

## Основание в исходнике

В DKM действие хранит ID ворот в `param5`; `RectEx_Modify` меняет прямоугольник,
сохраняя этот ID. Writer получает текущую позицию через
`RectEx_GetRectLocation(&MapGates,Action->param5,axis)+1`.
При отсутствии ID функция возвращает0, writer записывает WORD `1,1`.
Удаление прямоугольников имеет собственный запрос использования в сценарии;
текущий native маршрут использует существующее подтверждение удаления записи.
Это не доказательство полного совпадения старых вопросов и их вариантов ответа.

При чтении native действия `Files_Game.c` вызывает
`RectEx_GetGateAtMapPos(X-1,Y-1)`. Поиск возвращает первый прямоугольник с точным
совпадением начальной позиции, в физическом порядке списка. Сердца определяются
по `bGateType == 14` и не попадают в MapGates. `bGateID` — игровой вид,
не уникальная ссылка: значения0,1 и другие импортированные значения не служат
основанием исключить обычные ворота из списка выбора.

Четыре исходных файла, reader/writer и полные функции сохранены в
`tests/DK2MapEditor.Validation/NativeGateMutationSource.json` и
`artifacts/Evidence/NativeGateMutation-20261015/source-capture.json`.

## Текущее поведение

Первоначальное разрешение native координат фиксирует физическую запись.
[Рабочая таблица](NATIVE_GATE_BINDINGS.md) сохраняет эту связь и между командами. При переносе меняются только WORD-координаты действия
по смещениям12/14. Тип14 после явного изменения или удаление выбранной записи
дают исходное значение отсутствующей ссылки `1,1`. Остальные параметры,
связи, повторные IDs и резервные байты действий сохраняются.

Две координаты прямоугольника изменяются как одна операция: промежуточная
позиция при записи X перед Y не захватывает действия других ворот.
Прямое редактирование поля также обновляет цель своей команды. Окно свойств
применяет геометрию и цели атомарно; частный preview/Cancel не пишет в карту.
При повторе вложенной генерации обновляются как импортированные действия,
так и ранее созданные этим черновиком. Общий Undo восстанавливает полные
файлы и счётчик; производные координаты не добавляют отдельных увеличений.

Равное принятие и негеометрические поля не нормализуют импортированные цели.
Загрузка, простое сохранение и диагностика не выполняют этот пересчёт.
Generic Resize сохраняет прежние raw payloads при удалении за границей.
Список ворот и выбор сохранённой цели используют тот же критерий типа и
первого точного совпадения, что reader.

## Что ещё не закрыто

Native формат хранит координаты, а DKM — ID. Совмещение и последующее
разделение разными командами теперь поддерживает [рабочая таблица](NATIVE_GATE_BINDINGS.md)
с Undo, частными копиями и DKM projection. При простом native reload действует
исходный координатный reader. [Source allocation/reuse](NATIVE_GATE_IDENTITIES.md)
реализованы отдельно. Варианты исходных запросов, порядок ворот после Undo
удаления и физическая приёмка остаются отдельными требованиями.

[Цели кристалла при командах объектов](NATIVE_CRYSTAL_MUTATION.md) теперь
пересчитываются в общей транзакции. Полная семантика компилятора для
отсутствующих проектных целей и все прочие исходные запросы
удаления и физическая приёмка остаются отдельными требованиями.
Значение `1,1` не делает отсутствующие ворота исправленной игровой целью;
предупреждение DK2N032 остаётся доступно EN/RU.

## Проверки и ручная приёмка

Новый модельный блок проверяет11 сочетаний прямой геометрии, полей и общего
окна; пять случаев удаления/смены типа; физические дубликаты, вид ворот0/77/99,
сердца, промежуточное совпадение, полные action bytes, точные счётчики,
Undo/Redo/save/reopen, равное принятие, нулевую историю, повторные IDs,
сырой generic crop и общий replay с импортированным и новым действием.
Результаты исполнения — в [CURRENT_STATUS](CURRENT_STATUS.md).
Тест фактического класса RegionPropertiesWindow EN/RU подготовлен;
сборка этого теста не подтверждает его исполнение.

Для ручной проверки на копии карты выберите ворота в действии уничтожения,
перенесите ворота через свойства области и проверьте цель, общий Undo/Redo,
Cancel и сохранение. Повторите с вложенной генерацией. После удаления
используемых ворот проверьте предупреждение и задайте существующую цель.
Игровая проверка использует ровно семь файлов `DK2Preview_6a88240eaf814f78`
и команду `DKII-DX.exe -q -level DK2Preview_6a88240eaf814f78`.
Агент не запускает окна, WPF, рендерер, официальный редактор, звук или игру.
