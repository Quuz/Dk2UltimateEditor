# I04 закрыт по коду: границы форматов и их инспекция

25 октября 2026. [20 строк форматов](I04_FORMAT_MATRIX.md) сопоставлены с текущими
reader/edit/copy/conversion providers. Последняя F01 закрыта
[общим guard KWD](DESCRIPTOR_HEADER_GUARDS.md); проверены version, length,
count и непрозрачные данные на заявленных маршрутах. Это закрытие кодового пункта
I04, а не завершение редактора или ручной приёмки.

Поддержка теперь описана конечными уровнями: подтверждённые raw fields,
более строгие named catalogue tools, непрозрачное сохранение и явный отказ
от неподтверждённого редактирования/пересборки. Произвольный неизвестный формат
не получает выдуманных полей. Неизвестные native-файлы и хвосты сохраняются в
raw-копии либо исходном архиве с нужным Loss/Error, без скрытого ремонта.

Закрыты конкретные найденные расхождения:

- единые header/stride/catalogue guards семи семейств,44/46 creature variants,
  adjacent packed frames и хвосты без поиска signatures внутри opaque bytes;
- вставка коллекций по учтённым записям, безопасное обновление устаревших размеров,
  D5 перед D6 и перенос private action bindings с точным Undo/Redo;
- согласованные inspector/load policies для native, DKM/AREA и opaque companions,
  включая22 historical fixed layouts и отдельный enhanced DKZ путь;
- явное согласие на исключение неизвестных данных из DKM-пересборки при сохранении
  полного source snapshot; общая проверка KWD metadata prefix;
- родительская проверка переменных использует тот же безопасный metadata fallback,
  что дочерний writer, и не блокирует согласованную операцию.

Сверка использует сохранённые датированные проверки и новую проверку последнего
изменения. Она не объявляет весь старый набор текущим зелёным. Исторический full
1840 PASS / 63 FAIL не пересчитывался. Частные regression results и SHA указаны
в `artifacts/Evidence/DescriptorHeaderGuards-20261025/`:
`source-descriptor-proof.json`, `i04-closure-proof.json`, `delivery.json`.

Границы остаются явными: metadata-only preview требует tile file для редактирования;
source archive проверяется при полном Open; raw native file не сериализует все
частные рабочие IDs; KSTS меняется по штатным правилам Save; дефекты и неоднозначные
owners/identities относятся к I18. Фактическое отображение и запуск карт — ручные
M01/M04/M11/M15/M16 и другие M-группы. Входные карты не исправлялись.

После I04 остаётся **5 кодовых пунктов: I07, I08, I09, I10, I18**, а также все
**23 ручные группы**, всего28 пунктов работы. Следующий кодовый участок — I07:
конечная сверка кисти/заливки/одиночных объектов и их source call paths.
