## Existing copy-buffer replacement consent

`Map_Select.c` `Select_CopyRequest` returns immediately when `MapCopy.Map` is empty. With an existing buffer it asks Yes/No using `szCopyRequest`, the REQUEST_COPY preference, MBF_AUTOREPLY and default gadget 1. `Select_Copy` invokes this request **before** allocating/copying/cutting. `Select_Load(ToCopyMemory)` parses the DKZ and object section first, then asks before releasing the existing buffer. Declining leaves the old buffer and map unchanged; direct selection insertion (`ToCopyMemory=false`) does not replace the internal buffer. The source internal buffer is not the Windows clipboard.

This source workflow is now implemented in actual menus, shortcuts and DKZ import, with EN/RU consent, original default/preference behavior, canceled/stale Cut preservation and persisted suppression. Trusted scripted APIs remain nonmodal, while human commands always use the guarded request route. See [implementation and acceptance](COPY_BUFFER_CONFIRMATION.md); this section retains source provenance rather than claiming the workflow still absent.

## Unused scenario event cleanup during compilation

The [Core analysis/transaction prerequisite](UNUSED_SCRIPT_REMOVAL_CORE.md) and subsequent [actual human Test/Compile workflow](UNUSED_SCRIPT_REMOVAL.md) are now implemented with EN/RU candidates, Keep/Remove/Cancel, live one-step Undo/Redo and full terminal gates. Automatic validation remains read-only. The paragraphs below retain source provenance, not a claim that this functional workflow is still missing; whole-editor/original-GUI/game acceptance remains open.

`Compiler_Compile.c` `Compiler_TaskTestTriggers` (1070–1154) visits **all MapActionPoints link roots**, marking reachable conditions/actions in the high node.type byte. It follows condition OR and AND links and action next links using signed project event IDs. If validation has not failed, it counts unmarked conditions/actions, reports both counts and asks `szCompilerUnusedEvents` Yes/No. With explicit Yes it deletes unmarked nodes from both MapTriggers and MapActions and reports REPORT_UNUSEDREM. It subsequently resets the temporary marks on reachable events. This is actual mutation of the source editing lists, not only suppression in the generated native output and not a general invented orphan sweep over physical entities.

`Compiler_TaskTestTrigger` / `Compiler_TaskTestAction` reject missing links; an already-marked node also produces the source emergency repair question and a failed check. The recursive source conflates shared acyclic branches with loops and is unsafe for large depth. Modern shared/cyclic graph safety must not reproduce that unsafe recursion or silently run the repair branch that removes all non-area owner bindings. Cleanup authority should be based on a bounded iterative analysis with all real root bindings, explicit unsupported/ambiguous/missing-reference guards and a read-only preview, followed by a fresh confirmed atomic deletion with exact Undo. Native action reserved ChildAnd bytes are payload, not another graph edge. A graph reachable from an imported unresolved physical-owner binding must not be discarded merely because the owner is unresolved: original traversal starts from the link, not successful owner resolution.

The audit baseline had scoped binding/branch deletion and orphan-head display but no compiler cleanup question. Complete action traversal, Test/Compile/Run call order and all-entry export inclusion are read in the [follow-up source scope](UNUSED_EVENT_SOURCE_SCOPE.md): explicit original Test also offers cleanup, and No compiles all unused entries unchanged. The implemented workflow retains unrelated event bytes, IDs/scopes, owners, opaque tails and bound topology, without repairing imported dangling graphs. Its acceptance includes Core graph/layout/action/byte/save cases and actual native/project EN/RU decisions, pending/stale/closed guards, Keep-versus-Remove compilation and terminal regression/corpus gates. This does not prove full original GUI/game compatibility.
