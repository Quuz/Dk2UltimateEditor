# Рабочие связи native ворот

15 октября 2026. При редактировании native карты выбранные ворота сохраняются
между командами, даже если две записи временно стоят в одной точке.
Показательный случай: действие выбрало вторые ворота; их совместили с первыми,
затем передвинули первые. Действие остаётся привязано ко вторым.

## Три вида данных

В исходном проекте DKM действие уничтожения хранит ID ворот в `param5`.
Изменение прямоугольника сохраняет этот ID. Writer получает координаты
выбранного прямоугольника и добавляет1. В игровом KWD/KLD остаются только
эти WORD-координаты; исходный ID не записывается в действие.

Импорт обычного native файла воспроизводит reader: первая физическая запись
с точной позицией `(X-1,Y-1)`. Сердца типа14 исключаются; bGateID не считается
уникальным идентификатором. После такого первоначального разрешения рабочая
модель сохраняет конкретную запись и не ищет её заново по совпадающим координатам.

Рабочий проект DKM сохраняет выбранные ворота как отдельный проектный ID.
Обычный игровой KWD при повторном открытии снова использует координатный reader,
как исходный редактор. Для сохранения неоднозначного редакторского выбора
используйте рабочий DKM. Игровой комплект остаётся ровно из семи файлов.

## Представление в текущем коде

`NativeGateBindings.cs` хранит ограниченную таблицу D2GB/version2 в отдельном
внутреннем NativeFile с суффиксом `#GateBindings`. Это элемент транзакции,
не файл из коллекции `Files`, не ссылка KWD и не дополнительный игровой файл.
Таблица участвует в снимках истории, fingerprint, частных копиях и проверках
устаревания. В защищённый native-source ZIP рабочего DKM она попадает вместе
с остальными исходными данными; путь служит меткой и не извлекается на диск.

Запись действия адресуется физическим файлом и смещением, независимо от ID
сценария. Ворота адресуются файлом и порядком записей GAMEGATE, включая сердца
при подсчёте порядка. Удаление обычного предмета или отряда перед воротами
поэтому не меняет их рабочую ссылку. При удалении ворот переадресуются более
поздние порядковые номера; при удалении событий — их физические смещения.
Копирование графа переносит ссылку явно, а не восстанавливает её из координат.

Пара исходных WORD-значений позволяет отличить сохранённую связь от явно
изменённых сырых операндов. Непосредственное изменение координат действия
разрешает новую координатную цель; равный числовой ввод сохраняет выбор.
Таблица не использует словарь ID событий, поэтому повторные ID не скрывают
другие физические действия. Размеры/версия/счётчик/адреса таблицы проверяются.

Для таблицы повторно используется исходный parser двух native коллекций.
Его тело вынесено без изменения правил и сравнено с предыдущим пакетом;
глобальные каталоги при обновлении связей не разбираются.

## Команды и история

Перемещение области, прямые поля X/Y, общее окно свойств и вложенная генерация
переносят только координаты зависимого действия. Раздельная запись X, затем Y
не захватывает действия других ворот в промежуточной точке. Повторные команды,
Undo/Redo и нулевая глубина истории сохраняют выбранную запись.

Выбор вторых ворот в той же точке может изменить только рабочую ссылку,
оставив все игровые байты прежними. Это реальное изменение параметра:
общая операция даёт один Undo и одно увеличение счётчика. Принятый пользователем
современный Undo параметров сценария сохраняется. Равный повтор Save остаётся
прежним принятым действием без нового Undo.

Мастер сценария разрешает менять только связь редактируемого события;
другие рабочие связи защищены проверкой частного черновика. Общий resize,
частное окно области и генерация переносят таблицу вместе с остальными снимками.
Конвертация в DKM использует рабочую ссылку для выбора проектного ID,
вместо поиска первого прямоугольника по координатам.

Удаление выбранных ворот или смена на сердце оставляет отсутствующую рабочую
ссылку и исходный writer fallback `1,1`, сохраняя ID цели. Она не становится
ссылкой на другие ворота только из-за появления записи в этой точке. Повторное
использование освободившегося ID восстанавливает её независимо от координат.
Неизвестная цель0 остаётся неизвестной. DK2N032 проверяет рабочую
цель и соответствие её координат; предупреждение не исправляет карту.

## Границы подтверждения

[Выделение, освобождение и повторное использование ID](NATIVE_GATE_IDENTITIES.md)
реализованы в NativeGateIdentity-20261015, включая DKM/compiler/generator,
предел255 и чтение прежней версии1. [Удаление DKM ворот](PROJECT_GATE_REMOVAL.md)
с входящим действием разрешено; [общее подтверждение/remember](REGION_REMOVAL_CONFIRMATION.md)
добавлено. Специальные решения об используемых областях и порядок регионов
после Undo остаются отдельными требованиями.
[Пересчёт первого кристалла](NATIVE_CRYSTAL_MUTATION.md)
для полей/менеджеров/рисования/выделения теперь включён в общую транзакцию.
Полная политика compiler tasks/writer, прочие native metadata и физическая
приёмка. Все семь очередей и23 исходные области остаются в [REMAINING_WORK](REMAINING_WORK.md).

Модельные проверки охватывают совмещение/разделение, выбор вторых ворот без
изменения игровых байтов, отдельные X/Y, полные Undo/Redo и нулевую историю,
удаление предмета/ворот/события, клонирование и удаление неиспользуемого графа,
мастер и общий resize, настоящий DKM Save/reopen, ID2 при одинаковой позиции,
семь точных игровых имён и исходный native reader при повторном открытии.
Фактические результаты и сохранённые неудачные попытки — в [CURRENT_STATUS](CURRENT_STATUS.md).
WPF-тест класса окна EN/RU подготовлен и собран; его исполнение не заявляется.

Для ручной приёмки выберите вторые ворота в совпадающей позиции, передвиньте
первые и проверьте цель/Undo/Redo. Сохраните рабочий DKM, откройте его снова
и разделите ворота. Экспортируйте игровой комплект и проверяйте только
`DK2Preview_6a88240eaf814f78` через
`DKII-DX.exe -q -level DK2Preview_6a88240eaf814f78`.
Агент не запускает редактор, WPF, рендерер, официальный редактор, звук или игру.
