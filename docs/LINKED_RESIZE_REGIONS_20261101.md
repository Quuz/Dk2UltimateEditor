## Разобранные расхождения проверки

Первое сравнение Undo действия ошибочно использовало снимок до ручного
раскрытия ветки. Побайтный разбор нашёл только TRIGGER.expanded, short по+14.
Это описанное в [SCENARIO_EXPANSION](SCENARIO_EXPANSION.md) состояние дерева:
раскрытие пишется без отдельного Undo. С правильным снимком после раскрытия
Undo/Redo действия полностью точны. Игровые параметры и связи не расходились.

Клиент один раз повторно использовал устаревший handle после Undo; после
нового records_list чтение продолжено. Первые предположения клиента о поле
типа действия и нулевой базе raw-координат исправлены по исходнику.
Это ошибки проверки, а не исправления продукта. В script-resize-live.py
пустая категория Project.SCRIPTNAME не считается доказательством имён:
имя подтверждено настоящим деревом после открытия и отдельной проверкой
сохранённых DKM. Неиспользуемые события ради компиляции не удалялись.

Во время прохода кратковременно сработала квота автоматического рассмотрения
записей. После указанного времени обычный запрос одобрен; обход не применялся.
UI Automation позднее возвращала старое дерево главного окна: переходы на
вкладки и языки проверялись по свежим скриншотам, модальные поля — по их
собственным свежим окнам. Старые индексы главного окна больше не использовались.
