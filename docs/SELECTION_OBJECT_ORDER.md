# Порядок объектов выделения

12 октября 2026. Исправлено CopySelection: раньше оно оставляло порядок физических
записей файла, который мог отличаться от обхода исходного редактора.

Select_Copy обходит Y, затем X. В каждой клетке Things_CloneAtMapPos последовательно
вызывается для MapCreatures, MapDoors, MapTraps, MapObjects, MapMagicalObjects.
Внутри категории сохраняется её список; List_AddEntry добавляет запись в конец.
Areas_WriteThings для обычного прямого выделения использует тот же порядок клеток
и категорий, но берёт первый noncreature элемент категории в клетке. Буфер
FromCopyMemory записывает готовый список всех элементов без пересортировки.
Разделение этих writer routes исправлено14 октября:
[DIRECT_SELECTION_EXPORT](DIRECT_SELECTION_EXPORT.md). Далее описана исходная
правка порядка CopySelection, до добавления direct first-member projection.

Текущее CopySelection использует устойчивую сортировку по Y/X/категории. Native
keeper/hero/neutral относятся к общей категории существ; GAMEOBJECT IDs75–81hex
относятся к специальным предметам, как в исходном импорте. Проект использует
node.type0–4. Остальные поля, record payloads, identity, root/scopes и графы сценариев
сохраняются. Сортировка не меняет рабочие файлы, dirty, revision, Undo/Redo или
Changed. Маска защиты и фильтрация внешних объектов продолжают действовать.

Преобразование уже созданного буфера двигает координаты, сохраняя его порядок.
SelectionFile не сортирует заново такой буфер при Save. В текущем DKCP5 остаются
точные raw records и terrain cells; смена версии для этого исправления не нужна.

## Проверка

SelectionObjectOrderChecks независимо создаёт native/project карты с перемешанным
порядком добавления, несколькими клетками, всеми пятью категориями, двумя
существами в одной клетке, внешним объектом и двумя прикреплёнными сценариями.
Ожидаемый порядок IDs/category bytes задан буквально. Проверяются сериализация,
повторное открытие, Mirror/Rotate без пересортировки, paste с сохранёнными событиями,
источник/история/уведомления и импортированные дубликаты обычных объектов.
До правки первая проверка отказала; после прошла. Доказательства:
`artifacts/Evidence/SelectionOrder-20261012`.

## Границы

Исходный Select_Copy копирует все записи категории. Однако прямой Areas_WriteThings
для doors/traps/objects/magics записывает только первую запись в клетке, тогда как
Areas_GetThingsSize считает все: при импортированных дубликатах исходная запись
файла может стать несогласованной. Наш единый путь копирования/экспорта сохраняет
все записи, не повторяя эту потерю/ошибку размера. Для обычной карты без таких
дубликатов порядок соответствует исходному прямому экспорту; точное повторение
повреждённого файла не заявляется. Установленные карты не исправляются.

Физическая проверка Copy/Save/буфера, оригинального GUI, старого реального DKZ
corpus и игры остаётся отдельной. Это не закрывает все требования FEATURE_PARITY.

Текущая full regression:1799 passes/63 failures, terminal exit1; все63 сообщения
совпадают буквально и в полном порядке, предыдущие1798 passes сохранены.
Все41 проекта собраны без warnings/errors; focus5selection groups, archive31 и
native retention/conversion/activity checks exit0. Source/Binaries1006 и
installed4453 неизменны. Physical GUI/game acceptance не выполнялся.
