## Analysis and authority

`PlanUnusedScriptRemoval` produces immutable candidate IDs, separate condition/action counts, retained count and explicit blockers. It starts from every actual serialized root, including all nine project scopes, duplicate bindings and bindings without resolvable physical owners. It never uses the successful owner resolver as a root filter. Conditions follow OR/AND; actions follow next only. Native action ChildAnd remains untouched reserved payload.

Iterative colour/exit traversal recognizes reachable cycles without treating a shared acyclic branch as a loop. Missing retained edges/roots, zero/duplicate IDs, wrong project signed categories, unverified roots/layouts/types, native category counts and scenario versions prevent removal authority. Known old/future opaque sections require the established explicit upgrade/verification workflow; they are not guessed. Verified unreachable unknown event types, dangling components and cycles can appear in the deletion preview; none are silently repaired.

Reachable actions receive the original coordinate, area/camera-path, crystal-object, release-band and pet-band option checks. Crystal requires ordinary object ID 28; band zero is valid; the pet option is project Options2/native bMainOptions2 bit 0x20. Physical targets are indexed once rather than rescanned for every action. Negative coordinates are rejected as well as the original upper-bound check; ambiguous targets are not arbitrarily resolved. This is not full compiler/non-script validation: the future explicit Test/Compile integration must gate that separately and revalidate the retained/generated result.

`NativeMapDocument.EditRevision` advances before notifications on committed outer Edit, Undo and Redo. It is never rolled back with the reversible history counter. Explicit no-op edits do not advance it. Plans capture owner identity, this revision and SHA-256 over length-delimited paths and complete file bytes. Wrong-document, nested, stale edit+Undo, raw-byte-mutated or blocked plans are rejected before writes; current analysis is rechecked rather than trusting mutable record offsets supplied by callers.

## One real editing operation

`ApplyUnusedScriptRemoval` removes only the proved candidate records inside one atomic document Edit. It does not filter the compilation output or alter owner/root bindings. Bounded per-file byte removal keeps retained record order, complete payloads, IDs, links, project previous-ID words, aliases and opaque native tails. Source cleanup does not normalize retained backlinks merely because an unlinked component previously pointed into the retained graph.

Project KTRG condition/action counts and strict section size change; link count and 146-entry alias table remain intact. Native condition/action counts and stored sizes change with preserved deltas. If an understated native size would underflow, generic size becomes the actual new file length and event-payload size the actual remaining record bytes (excluding opaque trailing bytes); no missing data is invented. One Undo/Redo restores all bytes, including old size metadata/tails. Empty cleanup consumes no edit, history or notification.
