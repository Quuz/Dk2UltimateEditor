# Named map level options

Source-derived implementation, 2026-10-07. The [original scope audit](MAP_LEVEL_OPTIONS_SOURCE_SCOPE.md) identifies real game metadata, four original scalar ranges, twelve checkbox meanings (including inverted possession) and six reward slots. This component does not close the separate speech/text-browser or whole-editor/game requirements.

## Actual human workflow

The Properties-tab Level options button opens a modeless EN/RU tool with four numeric inputs and synchronized bounded sliders, twelve named flags and three previous/three next reward selectors. Rewards contain None plus all **48 source entries**, in original order, using explicit reward IDs rather than list ordinals or ordinary type IDs. Each entry has its original source bitmap and bilingual name; imported unknown rewards remain selected with a distinct label. Unknown/out-of-range raw values remain visible and unchanged during unrelated edits. Sliders clamp their visual positions only, never silently rewriting raw input.

Apply commits a complete available-field draft as one operation with exact Undo/Redo. Discard/refresh drops only the draft; Close/Escape do not apply it. Language switching retains invalid/pending numeric and reward/flag inputs. Actual pending generic-property edits are committed before application and invalidate old authority, with their separate edit retained. Raw changes without notifications, edit+Undo, document/workspace replacement and closed-shell lifetimes also invalidate drafts; stale Apply is disabled until refresh. Source flags are displayed semantically, including the inverse Options 0x04 possession checkbox.

Unknown flag bits are preserved with known masks **Options 0xFC / Options2 0x3F**; the original dialog's clear-and-rebuild data loss is not reproduced. Its unreachable secret-number reset is not inferred as an active rule. An imported Options2 0x40 bit does not erase a explicitly selected secret-level number.

## Formats and atomicity

These values update the original DKM metadata or native GAMEINFO bytes, not a new editor companion. Native mappings use the preserved compiler assignments; record/field availability is verified before writes. Project versions 1–3 expose none of these fields, **V4 exposes only Options**, and V5–7 expose all twelve storage fields (four scalars, six rewards, two flag bytes). The historical partial panel enables exactly its six Options checkboxes, not guessed padding aliases; other controls remain disabled. Existing explicit project upgrade introduces missing fields with exact undo. Unknown project versions retain opaque bytes and refuse panel editing; the native loader rejects future versions, and a separate panel guard also handles in-memory descriptor-version mutation.

Strict changed-value ranges are talisman pieces 0–4, game ticks 1–50, soundtrack 1–3 and secret-level number 0–16. Unknown rewards/flag bits may be retained but not invented through named controls; raw generic editing remains available. Baseline ownership, monotonic edit revision and a complete bounded document fingerprint protect prepared drafts. Preflight failure is read-only; a nested mixed metadata/game failure rolls back bytes and preserves redo. Same-value Apply creates neither history nor notification; zero history disables tracking, not edits.
