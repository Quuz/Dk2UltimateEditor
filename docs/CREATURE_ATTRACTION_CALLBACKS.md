# Привлечение существ: зависимые списки и количество

Исправление 13 октября 2026 касается страницы Parameters в общем окне
определений существ. Источник поведения — Properties_GlobalParamsProc,
Properties_GlobalSetAttractions и Properties_GlobalSaveChangesCr в сохранённом
`Source/Sources/Properties/GlobalVariables/Properties_Global_Creatures.c`.

## Исправленное поведение

Если в строке черновика сохранено количество 37, пользователь набрал 123 и затем
сменил второй тип привлечения, оригинальный обработчик заново выводит 37 из
приватной строки. Ранее современное окно сохраняло ещё не применённое 123 между
формами. Теперь смена второго типа сбрасывает этот локальный ввод, а смена первого
типа оставляет количество второго без изменений.

У типа «Нет» список ID и текст количества пусты и отключены. У золота/маны
список ID пуст и отключён, количество доступно. У комнаты/существа список
содержит соответствующий каталог. При отсутствии сохранённого ID в новом
каталоге видна первая строка, как при исходном CB_SETCURSEL(0).
Показ первой строки сам по себе не записывает её ID: сохранённый ID остаётся
в приватном вводе до пользовательского выбора или предусмотренной очистки.
Явное сохранение страницы очищает ID/количество по исходным правилам для «Нет»,
золота и маны. Отмена окна не применяет такую очистку к карте.

Неизвестные импортированные типы сохраняют прежнее диагностическое отображение
и значения. Новая логика не угадывает ветвь оригинала для такого типа и не
ремонтирует импорт автоматически. Смена языка не считается сменой типа и
не сбрасывает набранное количество.

## Реализация и проверка

В Core добавлены read-only правила CreaturePageControls.ChangeAttractionType,
AttractionSelection и AttractionAmountText. Они работают с локальным вводом,
не меняя документ, историю или счётчики. CreaturePageWindow использует их
в реальном обработчике выбора и при построении элементов страницы. После
частного Apply окно обновляет исходную строку для следующих переключений.
Общее окно по-прежнему применяет все страницы атомарно одним Undo.

CreatureAttractionChecks включён в существующую группу CreaturePageChecks.
На native и DKM проверены десять сочетаний типов, исходные первые ID каталогов,
перезагрузка количества, сохранение скрытого ID, пустые отключённые поля,
очистка только при явном сохранении, отсутствие изменений карты во время
работы с черновиком, частный/общий Apply, один Undo и отмена. Проверка читает
сохранённый оригинальный обработчик и сверяет его исходные контракты.
Неверный текст количества от предыдущей формы отбрасывается при её смене,
а не блокирует новую форму. Неизвестный импорт остаётся неизменным.

## Ручная проверка

На рабочей копии тестовой карты откройте определения существ → Parameters.
Выберите для второго привлечения комнату, задайте количество 37 и примените
страницу и общее окно. Повторно откройте страницу, наберите 123, затем выберите
«Существо»: количество должно снова стать 37. Выберите золото/ману: ID пуст и
отключён. Выберите «Нет»: оба зависимых поля пусты. Пока не нажата кнопка
применения, возвращение к комнате/существу снова выводит 37.

Отдельно убедитесь, что смена первого типа не сбрасывает набранное количество
второго, а смена EN/RU сохраняет локальный ввод. При переходе к каталогу, в
котором нет прежнего ID, сравните отображение первой строки и реакцию на
пользовательский выбор с оригинальным редактором. Для этого сравнения отмените
черновик, чтобы не сохранять неподтверждённый ID.

Проверьте отмену страницы и общего окна, затем отдельное применение «Нет» и
один Undo общего изменения. Тест игры выполняется только на
DK2Preview_6a88240eaf814f78 через DKII-DX.exe -q -level DK2Preview_6a88240eaf814f78.
Полное соответствие всего редактора этим исправлением не объявляется.
