# Main-window startup crash evidence

Read-only Windows Application event inspection on 2026-10-07 found an application crash on 2026-10-05 at 11:43:03 (local time), event 1000, record 70619. The application is `DK2MapEditor.App.exe` from this repository's Debug `net10.0-windows` output, with exception code `0xe0434352` and KERNELBASE offset `0x5fe4c`. The user screenshot has the same application and exception code, and its exception address ends in `5fe4c`; this is consistent with that incident, though the screenshot itself supplies no timestamp or report ID.

The associated .NET event 1026, record 70618 at the same time, identifies a `System.Windows.Markup.XamlParseException` assigning `System.Windows.Media.GeometryDrawing.Pen`. Its inner `ArgumentException` says `#2B251F` is not a valid `Pen` value. The stack reaches `MainWindow.InitializeComponent`, its constructor and `App.OnStartup`. Record 70620 at 11:43:33 reports the same XAML/Pen failure from a `dotnet.exe` launch. This is specific evidence for a historical startup cause, not merely interpretation of the generic CLR exception code.

The current `MainWindow.xaml` uses a nested real `<Pen Brush="#2B251F" Thickness="1" />` in `GeometryDrawing.Pen`, not a colour string as its value. The existing `CheckMainWindow` test constructs and lays out the complete main window in EN/RU with settings persistence disabled, finds the actual `DrawingBrush`, and asserts that its line geometry has that real brush colour and thickness. It runs in both full Debug/Release UI gates. Thus the observed historical XAML cause is corrected and directly regression-tested in current builds.

No new code change was necessary during this event-log audit. Passing offscreen construction does not claim manual visible-window/hardware/DPI or whole-editor acceptance, nor rule out different future failures. The application crash record and its inner-exception evidence were read without changing event logs, original source or maps.
