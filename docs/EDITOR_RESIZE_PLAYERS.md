# Камеры и области ИИ при изменении размера карты

15 октября 2026. Общее окно свойств применяет исходные правила
`Properties_UpdateProperties`: сдвигает геометрию только компьютерных
хранителей 3–7. Геометрия героя, нейтрального игрока и хранителя-человека
сохраняется побайтно. Флаг компьютера берётся из общего частного черновика,
поэтому его изменение в том же окне учитывается при последующем resize.

| Хранимое значение проекта | Исходное поведение |
| --- | --- |
| `PlayerCameraX == -1` | Не сдвигать ни X, ни Y камеры |
| `PlayerCPUAreaX1 == -1` | Не сдвигать все четыре координаты области ИИ |
| Остальные X | Прибавить смещение ко всей паре/области, включая вторичные значения `-1` |
| Отрицательные или выходящие за размер значения | Сохранять результат 32-битного LONG, не обрезать координаты |

В native файле координаты имеют ширину WORD. Исходный игровой reader загружает
их в LONG как неотрицательные числа: `65535` не является проектным `-1`.
У компьютерного хранителя такое число сдвигается и затем сохраняется
в 16-битной проекции. Обычный общий Resize сохраняет прежнюю политику:
сдвигает поля всех игроков, обрезает их границей и отдельно сохраняет FFFF.
Эта совместимая политика общего API не применяется к оконному исходному маршруту.

Проектные версии настроек игроков V1/V2 требуют отдельного обращения:
их старые readers задают камеру по умолчанию, а игнорируемые сериализованные
поля камеры V2 и сердца V1 не должны становиться активной геометрией.
Редактор сохраняет эти байты, обновляет только поддержанную область ИИ
и не повышает версию секции автоматически. Неоднозначные native IDs
компьютерных хранителей не дают полномочий угадывать владельца координат.

Перенос выполняется в независимой копии при подготовке плана. Preview и Cancel
не меняют живую карту или частный черновик. Общее применение сохраняет один
Undo и исходный счётчик свойств/resize; отдельного увеличения на каждого
игрока нет. Undo/Redo восстанавливают полные буферы и счётчики.

## Предупреждения исходного компилятора

`Compiler_TaskTestPlayers` сообщает о правой/нижней границе через warnings:

- `DK2N030`: камера любого хранителя 3–7, включая человека. X и Y проверяются
  независимо; для каждого проектный `-1` исключается из этой проверки.
- `DK2N031`: область строительства только компьютерного хранителя. Проверяются
  все четыре координаты, даже если X1 содержит проектный признак по умолчанию.

Это предупреждения EN/RU, а не ошибки, блокирующие компиляцию.
Диагностика не изменяет карту и работает также при проверке без сценариев.
Для native она оценивает сохранённую WORD-проекцию: полный исходный LONG
по одним игровым байтам не восстанавливается.
Она воспроизводит исходные верхние границы и не подменяет полную проверку
игрового поведения. После предупреждения пользователь может выбрать новые
координаты или отменить изменение размера.

## Код и проверки

Основные файлы: `EditorResizePlayers.cs`, `PlayerGeometryDiagnostics.cs`,
`NativeMapDocument.cs`, `LegacyProjectEditing.cs`, `MapPropertiesSession.cs`.
Семь исходных файлов, полный обработчик переноса и проверки компилятора
зафиксированы в `EditorResizePlayersSource.json` Validation и
`artifacts/Evidence/ResizePlayers-20261015/source-capture.json`.

54 модельные матрицы покрывают native/project × три изменения размера × девять
привязок и семь игроков в каждой карте. Независимые буквальные примеры проверяют
32/16-битное переполнение, парные признаки, native FFFF и смешанные вторичные
значения. Дополнительно проверяются старые версии, полный Undo/Redo,
save/reopen, общий Cancel, частное переключение человека в ИИ перед resize,
неоднозначный ID, нулевая глубина, неизменённый общий API и неблокирующие warnings.
Результаты исполнения — в [CURRENT_STATUS](CURRENT_STATUS.md).
WPF-проверка фактического окна EN/RU подготовлена и собрана; автоматически
окна, рендерер, официальный редактор, звук и игра не запускаются.

## Ручная последовательность

1. Создайте копию карты 32×30 с двумя хранителями. Первый — человек, второй —
   компьютер. Явно задайте обоим камеру (8,9) и одинаковую область ИИ.
2. В общем окне свойств увеличьте карту до 36×34, выбрав нижнюю правую привязку.
   Камера компьютера должна стать (12,13), все координаты его области —
   увеличиться на 4. Геометрия человека должна остаться прежней.
3. Проверьте один общий Undo/Redo и общий Cancel. Повторите после смены
   управления с человека на компьютер в том же частном окне.
4. Уменьшите карту так, чтобы явная камера или область оказалась за правым/
   нижним краем. Проверьте соответствующее предупреждение EN/RU и сохранение
   координат; затем задайте корректную геометрию перед игровой проверкой.
5. Проверяйте игру только на семифайловом комплекте
   `DK2Preview_6a88240eaf814f78` через
   `DKII-DX.exe -q -level DK2Preview_6a88240eaf814f78`.

Другие вычисляемые native сценарные координаты, исторический бинарный корпус
и физическая приёмка всех workflows остаются отдельными требованиями.
