# Живые проверки размера, буфера и общих свойств — 1 ноября 2026

Этап LiveResizeClipboard-20261101 продолжает предыдущий
[проход MCP и GUI](MANUAL_MCP_ACCEPTANCE_20261101.md). Это новый прогресс,
не повтор прежних успешных проверок. Весь goal остаётся активным.
Полная ручная приёмка и переход на KWD без DKM/ZIP не завершены.

## Изменения редактора

- MCP получил24-й read-only инструмент dk2_map_fingerprint.
  files и orderedSha256 описывают загруженные файлы в их порядке;
  documentSha256 включает все буферы TransactionFiles, в том числе отдельные
  служебные метаданные редактора и идентичности путей. Содержимое буферов
  не выдаётся. Буфер копирования, история, настройки и runtime-счётчики
  активности в этот hash не входят. Это не hash всего процесса/диска.
- Для проверки обнаружения метаданных создана настоящая typed DKM override
  характеристики уровня: обычные Files не изменились, documentSha256
  изменился, Undo вернул исходный hash. Чтение fingerprint не меняет token.
- В настоящем окне свойств при125% обнаружено обрезание подписей ширины/
  высоты. Ширина этих двух блоков увеличена с95 до120. Последняя публикация
  проверена визуально EN/RU: подписи помещаются.
- Исправленный ранее контраст hover кнопок теперь подтверждён визуально
  на включённой кнопке вложенных параметров и Creature modifiers.

Файлы реализации: Core/Automation/AutomationTools.cs и EditorAutomation.cs,
Core/Editing/UnusedScriptEditing.cs, App/Editing/MapPropertiesWindow.cs.
Единый проект не разделялся; новых проектов/сетевых зависимостей нет.

## Вход и границы опыта

Исходная тестовая карта32×24 с колдуном не перезаписывалась.
Через Export создана отдельная копия:
artifacts/McpWorkspace/LiveResizeClipboard-20261101/DK2Preview_6a88240eaf814f78.dkm.

Экспорт не является буквальной файловой копией: штатный SaveCopy записал
текущую статистику KSTS. Размер обоих DKM31372;12 отличающихся байт находятся
только в KSTS31168..31371. Все остальные секции совпадают побайтно.
Время записи исходного файла предшествует первому запросу этого прохода.
Ошибочное первичное ожидание полного равенства DKM исправлено после разбора,
не исправлением карты. Подробности — input-preservation.json в Evidence.

Все мутации выполнены на этой отдельной копии в настоящем открытом WPF.
Установленные игровые файлы в этом проходе не заменялись. Source, Binaries,
fixtures и исходный пользовательский проект не редактировались.

## Подтверждённые результаты

### M09: девять привязок и обрезка

Для каждой привязки0..8 карта32×24 увеличена до36×30.
Ожидаемые смещения вычислены независимо:
X=0/2/4, Y=0/3/6. Все1080 клеток сверены с ожидаемым переносом,
заполнением землёй и фиксированным краем. Все поля колдуна совпали
с исходными, кроме ожидаемых X/Y.

После каждого применения в истории ровно один корневой шаг.
Undo вернул полную documentSha256, включая служебные буферы;
Redo точно вернул hash применённого состояния. Финальный Undo каждого
случая снова вернул исходную карту.

Для уменьшения16×14 с нижней правой привязкой:
отказ без разрешения удаления не изменил живую карту;
preview с одним Project.MAPTHING и Cancel не изменили её;
Apply без согласия на crop отказал без правки;
Apply с согласием удалил ровно это существо.
Undo/Redo восстановили соответствующие полные hashes.

Принята отдельная36×30 копия с нижней правой привязкой:
сохранение и повторное открытие дали те же клетки и поля существа;
компиляция создала ровно семь файлов в Maps.

### M07: выделение с объектом

- Copy6×3 включил одно существо и0скриптов. Paste перенёс его из(3,6)
  в(12,13), назначил другую уникальную идентичность и сохранил остальные поля.
  Undo/Redo совпали по полным hashes.
- CopyRotated создал буфер3×6 с существом; Paste дал ожидаемую(12,15).
  Undo восстановил все буферы.
- Cut удалил существо. Undo вернул прежние поля, порядок и идентичность,
  Redo повторил полное состояние вырезания.
- Вставка у(29,21) обрезалась картой. Защищённые крайние строки/столбцы
  сохранились; существо, попадающее в защищённый X31, не вставилось.
  Undo восстановил полный исходный hash.

### M14/M09: настоящие вложенные окна и общий владелец

Через Computer Use открыто реальное общее окно свойств на копии36×30.

Во вложенном окне GameTicks изменён4→5 и нажат внутренний Apply.
После закрытия и нового открытия дочернего окна видно5:
правка действительно вошла в частный документ.

Общая отмена родителя отклонила имя, размеры и уже применённую дочернюю
правку. Вся fingerprint-структура совпала с состоянием до окна,
revision остался0, карта36×30 чистая. Следующее дочернее окно показало4.

Затем в настоящем окне приняты вместе:
имя M14 applied parent,38×32, нижняя правая привязка,
дочерний GameTicks4→6. Нажат именно общий Apply all.
Через живой MCP прочитаны новые имя/GameTicks и колдун(9,14);
в истории ровно один шаг. Один Undo восстановил все исходные буферы,
Redo вернул весь результат, финальный Undo снова оставил чистую36×30.
