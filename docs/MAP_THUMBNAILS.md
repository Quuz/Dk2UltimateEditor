# Original map-thumbnail controls and BMP export

The Map tab now opens a separate English/Russian Map thumbnail tool. Its preview uses the preserved original terrain palette, with nine world visibility toggles and four independent categories for each of seven owners (37 controls). The owner/category matrix exposes all original choices at once instead of hiding them behind an owner picker. It has hidden RGB colour input, original-background colour-key compositing, shared minimap proportions, both source sizes, Refresh and Save new BMP. These are view/export settings, never map edits.

## Preserved source rules

`Windows_Thumbnail.c` supplies 144/96 previews, options, refresh and save. `Thumbnail_GenerateExt` filters World/Rooms/Gates/Walls according to `Config.h` flags. Closed mana uses Neutral rooms; hero gates use Heroes portals; both wall and claimed-path cells use their owner's Walls category. Hearts and the normal/mercenary portals use independent owner categories. Unknown terrain/owners/variants use the same read-only source conversion fallback as the minimap; stored bytes are not normalized. All unexposed bits in both flag words survive checkbox edits and settings serialization.

`Config_SetToDefault` first zeroes Config, sets both thumbnail flag words to 0xFFFFFFFF and enables MinimapKeepProps. Thus hidden colour defaults to black, colour-key is disabled and all categories show. KeepOldBitmap is original allocation ownership, not an editable map option, so it is replaced by managed immutable raster lifetime. The owner-picker index is unnecessary because all seven owners are visible. Original window position and native allocation/registry layout are not copied.

The source has one verified wrong-word defect: Heroes-heart filtering reads `WorldFlags & TOF_SHOWHEROESHEARTS` (0x80), while the actual heart checkbox changes `PlayersFlags`. World bit 0x80 is the unclaimed-terrain checkbox. Modern filtering deliberately reads the correct PlayersFlags heart control; an independent regression proves hearts are no longer coupled to unclaimed ground. This is an intended control fix, not a claim of pixel equivalence to that defect.

The original background resource 996 (`Source/Bitmaps/Interface/Carte - Fond.bmp`) is embedded unchanged and decoded as its original 144 × 144, uncompressed 24-bit bottom-up bitmap. Aspect-retaining rendering centres the map over this background; stretched rendering fills the square. With colour-key enabled, every pixel matching the selected hidden colour (including a visible palette colour collision) is replaced by the background. Output remains opaque: the BMP never has an alpha channel. The modern renderer uses deterministic nearest-neighbour sampling and a minimum one-pixel extent for extremely narrow maps; historical GDI rounding/native hardware equivalence is a separate acceptance scope.

The original 144 × 144 preview **exports as 128 × 128**; 96 exports as 96. `Thumbnail_GenerateFile` writes a 14-byte BMP file header, 40-byte info header, 24-bit BI_RGB and bottom-up BGR rows. Modern export follows that structure, with zero resolution/palette fields and correct image/file sizes. It also handles row padding in the general encoder. Preview dimensions and export dimensions are explicitly named in both UI languages.

## Export, drafts, settings and lifetime

Save commits/validates the hidden-colour input before opening the native file picker. Invalid drafts have an inline translated error, leave the last valid preview/options unchanged and create no output. Valid colour text is RGB `#RRGGBB`, encoded explicitly as Windows COLORREF; it accepts the optional leading # and normalizes display after Apply/Refresh/Save. Switching language retains pending text and active flags. File-selection cancellation does not create a file.

`MapThumbnail.SaveNewBmp` prepares bytes, refuses an existing file/directory or missing parent, writes and flushes a GUID-named sibling staging file, then publishes with no-overwrite File.Move. Failure cleans up only that staging file; existing files and map inputs remain intact. The dialog does not authorize replacing existing files. The actual UI uses the same public SaveTo operation tested without native dialogs, and reports failures inline.

The live thumbnail subscribes to its document and refreshes after edits/undo/resize, retaining current settings and pending colour text. Closing clears document/raster/image/export authority and unsubscribes from the source and language event. Workspace replacement/close/unload closes its active tool. Reopening keeps session options. The source-identity callback prevents an obsolete tool from updating a different current map's settings.

Thumbnail options are included in the existing modern JSON AppSettings. MainWindow applies them at startup and captures them with ordinary settings saves/close; test shells use persistSettings:false. Missing old settings use original defaults; invalid saved preview sizes fall back to 144 and colour is bounded to 24 bits, retaining valid flags/key/proportions. JSON/settings-shell tests exercise persistence without writing actual user settings. Shared Keep proportions changes affect both minimap and live thumbnail. Other view preferences (minimap size/show-hide, zoom, entity layers) still need persistence; thumbnail settings do not imply they are complete.

## Verification

`MapThumbnailChecks` independently inspects source BMP/size/key/default statements, flag defines and catalogues. It verifies all nine world and 28 owner/category masks, all terrain bytes × nine valid/invalid owners × five variants against independent filtering logic with each flag both isolated and cleared. It reproduces the Heroes-heart defect and checks the intended fix. Landscape, portrait, square and extreme aspect fixtures independently verify both preview/export sizes, stretch/proportions/key states, every composed background/pixel and bottom-up header/BGR encoding. Native/project fixtures check exact source/history/redo/notifications, all catalogue entries, filtered pixels, saved/reopened document output, duplicate/missing-parent refusal and staging cleanup. Unknown flags and reserved bytes remain retained.

Four `ThumbnailSmoke` EN/RU × native/project actual-window cases exercise every checkbox, live preview pixels, COLORREF/RGB, key, both directions of the shared proportions setting, preview96/file96 and preview144/file128, Windows BMP decoder acceptance, pending invalid-colour refusal, no-overwrite, live translation/draft retention, edits/undo/resize refresh, session reopening and source/closed-map cleanup. JSON and never-shown MainWindow shells check saved options and malformed-setting fallback. Rendering found dark owner/category labels; the tool now explicitly supplies light foreground/dark background, and tests assert readable owner/header text. The four PNGs in `Test/Thumbnail-20261007-b` were rendered from actual controls; English-project and Russian-native were inspected. Native file-dialog cancellation/confirmation, hardware/DPI, historical GUI and in-game thumbnail acceptance are not automated.
