# Удаление областей со сценарными точками

16 октября 2026. Команда удаления регионов повторяет два вопроса исходного
`RectEx_RemoveRects` / `Triggers_IsUsed`. Первый — общий Yes/No для выбранных
областей, ворот или генераторов эффектов, с запоминанием Yes в бите0x10.
Если среди выбранных областей есть используемая, открывается второй вопрос:

| Ответ | Результат |
| --- | --- |
| Да / Yes | Удалить все выбранные области, сохранив их сценарные точки и события |
| Нет / No | Сохранить используемые области и удалить остальные выбранные |
| Отмена / Cancel, Escape, закрытие | Оставить карту без изменений |

Второй вопрос запоминает только Yes, отдельно в бите0x100. Пока флажок включён,
No и Cancel отключены; крестик/Escape продолжают отменять без запоминания.
Ответ первого вопроса уже принят: его запоминание сохраняется, даже если второй
отменён. Настройки действуют между картами текущего рабочего окна, находятся
вне карты и Undo. Сброс подтверждений удалений очищает оба бита и не меняет
остальные биты. Общий вопрос размещается у курсора, второй центрируется
относительно владельца. Интерфейс и новые подписи имеют EN/RU переводы.

В исходнике REQUEST_TRIGGERS0x100 также используется при удалении/изменении
существа со сценарием через Things_Functions/Things_Manager. Текущая политика
здесь охватывает удаление регионов; общая доставка этого решения между
остальными обработчиками остаётся отдельной задачей очереди G.

## Что исходник считает использованием

`Triggers_GetFirstTrigger` ищет сохранённый Action Point по полю `area`.
Пустая точка с `trigger=0` тоже считается использованием. При Data=0 область
не считается используемой. В исходнике при поиске проверяется `area` без
проверки `node.type`; этот случай сохранён для импортированных DKM.

Ссылка только из аргументов события не вызывает второй вопрос: исходный
`Triggers_IsUsed` находит её, но не присваивает `Used=TRUE` перед `goto Done`.
У ворот и эффектов нет собственного сохраняемого scope такого вида, поэтому
второй вопрос для них не открывается. Подтверждённая команда сохраняет аргументы
событий и цели существ; не обнуляет их при удалении региона. Native-цель
уничтожения ворот продолжает использовать [рабочий ID](NATIVE_GATE_IDENTITIES.md)
и существующее координатное преобразование. Отсутствующая цель может вызвать
диагностику или отказ последующей компиляции: политика writer остаётся отдельной
очередью B. Установленные карты не исправляются автоматически.

Пакет обрабатывается в порядке списка. После удаления области меняется только
первый оставшийся патрульный предшественник, как описано в
[AREA_REMOVAL_PATROL](AREA_REMOVAL_PATROL.md). Весь пакет даёт один шаг истории
и одно увеличение счётчика. Даже No, сохранившее все выбранные области, принимает
исходную команду с пустым шагом Undo и одним счётчиком. Глубина0 отключает
хранение шага. Поздний отказ откатывает буферы и сохраняет оба стека истории;
запомнённый ответ остаётся вне Undo.

Низкоуровневый `DeleteRecord` сохраняет отдельную защиту ссылок. Source-политика
применяется только внутри проверенного подтверждённого удаления регионов;
неизвестные layouts остаются запрещены. Выбор фиксирует canonical records,
поля, ревизию и fingerprint. Устаревший второй вопрос не получает права на
удаление или запоминание после изменения карты/выбора.

## Native: точка переживает удалённую область

Native GAMEAREA хранит `wAreaTrigger` в самой записи. После удаления области
такого места хранения больше нет; исходный редактор при этом оставляет
MapActionPoints. Поэтому рабочий документ дополнительно хранит таблицу
`#AreaScopes` с сигнатурой D2AS, версия1: заголовок16 байт, строки20 байт.
Строка содержит индекс BE-файла и порядковый номер GAMEAREA, ID области,
корень события и служебные слова. Адрес(-1,-1) означает сохранённую точку
удалённой области. Повторные ID импортированных точек сохраняются без
назначения произвольного владельца. Версия, размер, адреса, повторы живых
адресов и резервные байты проверяются.

Ненулевые импортированные корни создают рабочие точки. Явно созданная пустая
точка получает отдельный признак существования; импортированное нулевое поле
само по себе таким признаком не является. Очистка корня сохраняет существование
точки, а команда удаления точки/связи удаляет и признак. Удаление области
переводит её точку в orphan, сохраняя root; обычное создание региона с повторно
занятым ID снова получает её корень. Дублирование области с собственной точкой
сохраняет эту точку у копии: непустая ветка клонируется, пустая получает явный
marker. Более старая orphan при этом сохраняется отдельно и не подменяет сценарий
копии. Физические адреса точек остаются уникальными; неоднозначные логические ID
не исправляются молча. Не следует путать рабочую таблицу с дополнительным
игровым файлом.

Точки без владельца отображаются в дереве как «Удалённая область / Deleted area».
Они остаются корнями графа для очистки unused, проверки входящих связей,
переименования event ID, вставки событий через мастер, перемещения связи к
другой области и явного удаления сценарной точки. Они не предлагаются как
существующие физические владельцы. История и приватные копии включают таблицу;
обычные свойства карты сохраняют её и запрещают произвольную правку сценариев
через свой черновик.

Преобразование в DKM записывает и живые, и пустые, и orphan Action Points.
Живые точки сохраняют прежний физический порядок native вещей относительно
корней существ и отрядов; точки без физической записи добавляются отдельно.
Native-source архив рядом с DKM включает проверенную рабочую таблицу;
старые архивы без неё читаются. После успешного сохранения обновляется baseline
dirty-state. Компилятор сохраняет editor-таблицу в возвращаемом рабочем документе.

Экспорт Maps содержит ровно7 файлов. Пустые и orphan точки не имеют отдельного
представления в игровых GAMEAREA, поэтому простое открытие экспортированной KWD
не восстанавливает эти editor-only точки; связанные события остаются в данных.
Для продолжения редактирования таких точек нужен DKM и его native-source архив.
Это граница игрового формата, а не восьмой файл карты.

## Проверки и ручная приёмка

Core-проверки покрывают оба формата, пустые/непустые точки, Yes/No/Cancel,
оба бита и их сброс, отмену после запоминания первого Yes, all-skipped и history0,
устаревший второй вопрос, action-only ссылки областей/эффектов/ворот,
wrong-scope area operand и area ID0. Сравниваются полные game/working buffers,
Undo/Redo, сохранённые точки, ID reuse, event identity remapping, запрет удаления
входящего события, unused plan, явное удаление точки и handoff владельца.
Проверены приватный мастер вставки, clone/Cancel/Apply resize, DKM Save/reopen,
архив/компилятор и семифайловый экспорт. Фактические terminal results текущего
блока включают четыре empty/nonempty × orphan/free-ID случая дублирования
с полной проверкой Undo/Redo и независимым сохранением обеих точек. Результаты
блока и границы полного корпуса фиксируются в [CURRENT_STATUS](CURRENT_STATUS.md).

WPF harness содержит EN/RU × native/project случаи перехода между двумя
окнами, No и Cancel и отключения кнопок при remember. Harness только собирается.
Агент не запускает редактор, renderer, исходный GUI или игру. Для ручной проверки
на копии карты создать две области: одну с пустой/непустой точкой, другую без.
Выбрать обе и проверить второй No: первая остаётся, вторая удаляется.
Undo возвращает обе. Второй Cancel сохраняет карту. Второй Yes удаляет обе,
но сохраняет точку в дереве; Undo/Redo и DKM Save/reopen должны её сохранять.
Проверить EN/RU, remember/reset, фокус, Escape и DPI. Игровое имя только
`DK2Preview_6a88240eaf814f78`, запуск `DKII-DX.exe -q -level DK2Preview_6a88240eaf814f78`.

Обрезка регионов подключена следующим этапом:
[REGION_CROP_SCOPES](REGION_CROP_SCOPES.md). В ней сохраняются точки/operands,
но не переадресуется nextid и не открывается второй вопрос.
Остальные native owners/metadata, compiler/historical policy, все23 области
FEATURE_PARITY и физическая приёмка не объявляются завершёнными этим блоком.
Полный [остаток](REMAINING_WORK.md) и согласованный [Undo](EDIT_HISTORY.md) сохраняются.
