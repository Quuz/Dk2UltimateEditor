## Подтверждённое поведение официального редактора

Статически исследован обычный `Data/editor/DK2 Editor.exe`, SHA256
`f5cbbb05b3f78a1d13d0ff0c9600e6e4b231f7a81c3817cafd22368dcb175125`.
EXE не запускался. Функция `004aa6e0` формирует коллекцию E6 версии4;
циклы `004ab0be..004ab10f` и `004ab10f..004ab152` записывают:

| Поле | Обычные уровни | First Person |
| --- | --- | --- |
| Тип | 0x41 | 0xE0 |
| Характеристика | 0…31 | 0…31 |
| Уровень | 2…10 | 10, сохранённый последней обычной итерацией |
| Число записей | 288 | 32 |
| Значение | Знаковый SHORT расширяется до DWORD | То же |
| Ноль | Записывается 100 | Записывается 100 |

Ноль не исключает запись: обе ветви соединяются перед вызовом записи16 байтов.
Отрицательное −1 записывается как `FF FF FF FF`, −10000 — `F0 D8 FF FF`.
Внутренние offsets от объекта `0054f550`: `0xf5c` для первого уровня2,
`0x119c` для First Person; они совпадают с ранее подтверждёнными массивами UI.
Границы ввода остаются −10000…10000.

Вызывающий маршрут `0047d0c0` затем пишет секцию Things через `004ab210`.
У исследованного GlobalVariables.kwd E6 занимает9992 байта, после неё находится
секция0xBE версии4 длиной3644 байта. Раньше эти3644 байта были известны только
как непрозрачное продолжение. Новый writer сохраняет их буквально и не делает
дополнительные записи Things редактируемыми.

Это другой маршрут, чем запись семифайловой карты: `0047d510` объединяет11
семейств определений в Globals.kld и напрямую не вызывает `004aa6e0`.
Поэтому данные общего каталога нельзя автоматически считать частью map
Variables.kld. Политика shared/map override и reset ещё требует сопоставления.
Никакие установленные файлы в этом этапе не менялись.

## Реализация

`CreatureLevelModifierWriter.EncodeEditedValue` проверяет диапазон и формирует
подтверждённый DWORD с правилом ноль→100. `CreateRecord` формирует16 байтов
для видимого ключа официального окна; скрытые характеристики не создаются.

`PatchCollection` принимает исходный буфер и список `CreatureLevelModifierChange`.
До формирования результата проверяются layout/count/длина E6, уникальность
ключей запроса, видимые IDs/уровни, диапазон всех значений, наличие каждого ключа
и точное совпадение исходных DWORD. Отсутствующий ключ не вставляется: такая
вставка требует отдельного плана на основе подтверждённого effective source.

Изменяется только DWORD значения последнего существующего дубликата ключа.
Ранние дубликаты и порядок записей, скрытые/неизвестные записи, headers/count,
остальные поля и продолжение остаются побайтово прежними. Результат — отдельный
массив, ссылка на исходные данные не сохраняется. Равное signed значение не
нормализует верхние bits. Если ввод0 сохраняет существующие100, байты также
остаются прежними: это семантический no-op. Явное изменённое значение0 при
другом исходном значении при повторном чтении даёт100, как официальный writer.

Метод не получает NativeMapDocument, file path, EditorSourceArchive или права
записи в источник. Он не изменяет immutable retained variables. Нельзя просто
передать его результат в исходный архив DKM: прежняя проверка provenance
сохранена и по-прежнему требует точного совпадения с исходным bundle.

## Проверка и границы

Новый CLI `--creature-level-writer-only` использует буквальные signed DWORD
ожидания, все видимые страницы реального каталога и цикл draft→write→read.
Проверяет ноль→100, крайние значения, последний дубликат, непрозрачный хвост,
hidden/unknown bytes, независимость результата, stale/duplicate/missing/invalid
batch и отсутствие частичной записи. Установленный источник сверяется по SHA.
Терминальные результаты сборки и запуска находятся в evidence этого этапа.

Прежние Core/App sources не менялись: добавлен один независимый Core файл,
