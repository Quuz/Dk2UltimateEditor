# Числовые параметры вложенных окон ловушек и выстрелов

ProjectileChildInputs-20261019, часть открытого I11. Изменён ввод в
GlobalTrapOptionsWindow (trigger/shot), GlobalSpellOptionsWindow (Shot/Upgrade),
CreatureSpellOptionsWindow и общей встроенной панели параметров выстрела.
Пять исходных форм имеют номера0–4; FF не имеет параметров.

| Исходный обработчик и поле | Edit / spin | Диапазон целой части |
| --- | --- | --- |
| TypeProc: TriggerData |101 /102 |0…32767, unsigned |
| ShotProc: первый числовой параметр форм0/1 |101 /104 |0…32767 либо −32768…32767 по Ctrl1Signed |
| ShotProc: второй числовой параметр формы0 |103 /105 |0…32767 либо −32768…32767 по Ctrl2Signed |
| ShotProc: количество существ формы2 |203 /204 |0…100, unsigned |
| ShotProc: золото предмета формы4 |205 /206 |0…80000, unsigned; доступно только для предмета ID1 |

В форме3 вид существа и уровень остаются именованными выборами. Для форм2/4
цель также выбирается из прежнего каталога. Числовые шаги не получают доступа
к этим спискам и к отсутствующему второму полю формы1/FF.

## Два согласованных исправления исходника

Пользователь19 октября выбрал «Сохранить корректное поведение»:

- Исходный UDN105 вызывает helper для control101. Наш второй спиннер меняет
  своё второе поле, оставляя первое прежним.
- Исходный signed EN_CHANGE при нижней границе вызывает SetDlgItemInt с FALSE
  и выводит4294934528. Наш нижний clamp выводит−32768.

Решение сохранено в artifacts/Evidence/ProjectileChildInputs-20261019/user-decision.json.
Это явные согласованные отличия, а не заявление побайтового повторения дефектов.
Верхние границы, signed/unsigned getter и остальные шаги сопоставлены с source.

## Поведение текущего ввода

GlobalProjectileInputs использует прежний SourceIntegerInput: ведущая целая
часть, prefix/partial ввод, ноль при переполнении getter, signed/unsigned LONG
и unchecked шаг. Выход за границы сразу заменяется целым граничным текстом.
Дробь внутри разрешённой целой части остаётся в поле; строгий Apply всё ещё
требует целое число. Пустое поле остаётся пустым до шага; увеличение даёт1.

Три дочерних класса и общая панель используют RepeatButton−/+ и Up/Down без
модификаторов. Шаг меняет текущий TextBox, сохраняя кнопку и форму. Проверяются
владелец, editable/current baseline, зарегистрированный контрол, доступность
поля, числовая форма и gold mask. При загрузке и смене языка TextChanged
подавляется: импортированные числа не исправляются автоматически.

Каталоги, подписи EN/RU, fallback цели/уровня, принятый non-gold clear,
typed drafts, private parent Apply и компилятор не менялись. Native storage
остаётся WORD: source UI допускает золото до80000, но native Apply явно
отказывает выше65535 без записи части операции. DKM сохраняет80000.
Отказ/Cancel дочернего окна не меняет карту; общий родитель публикует один Undo.
CrSpells относится к CreatureGlobalsSession, а Traps/Spells — к GlobalVariablesSession.

## Проверки и границы

CLI `--projectile-child-input-only` проверяет source controls и диапазоны,
пустой/частичный/whole-part ввод, integer clamps, signed/unsigned wrap,
оба согласованных исправления, запрет named/inactive numeric API. Native/DKM
через четыре места хранения проверяют независимые значения и signed WORD bits,
частные черновики, соответствующие общие контексты, один Undo/Redo, Cancel
и native WORD preflight при сумме80000. Writer/codec не переписывались.

Подготовлены4 WPF suites EN/RU×native/DKM: три настоящих дочерних класса,
trigger, четыре слота общей панели, TextBox/RepeatButton identity, изменение
второго поля отдельно, signed минимум, gold mask, язык и устаревший владелец.
Они только скомпилированы. Старый UI invalid case101 заменён на `invalid`:
101 теперь должен ограничиваться до100 при вводе.

GUI, renderer, Computer Use, игра и аудиоустройство не запускались.
Полный корпус без изменений файловых алгоритмов не повторялся; прежние
1840 PASS/63 отказа относятся к Core этапаCreatureLevelModifierWindow,
а не к новой DLL. Source/Binaries, tests/Fixtures и игровые карты сохранены.

## Ручные шаги

1. В параметрах trigger введите32768: должно получиться32767. Очистите поле
   и увеличьте —1. Проверьте удержание−/+, Up/Down, Tab/каретку и resize/DPI.
2. В форме с двумя числами задайте9 и4; увеличьте второе: должны остаться9 и5.
   Кнопка и поле не должны пересоздаваться после каждого шага.
3. Для signed параметра введите−32769: получите−32768. Для количества существ
   введите101: получите100. Проверьте оба языка и все четыре места хранения.
4. Для предмета ID≠1 сумма отключена. При ID1 она доступна: DKM принимает80000,
   native выше65535 должен показать ошибку и сохранить всю операцию неизменной.
5. Отмените дочернее/общее окно, затем повторите с принятием и общим Undo.
   Открытие и смена языка не должны записывать импортированные значения.
