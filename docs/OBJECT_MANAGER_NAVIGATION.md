# Навигация и выбор точки в менеджере объектов

[Первый настоящий native RU125% проход 3 ноября](MANAGERS_LIVE_20261103.md): менеджер/навигация и часть статистики; остальной конечный объём открыт. Координаты назначения нормализуются исходными callback: X999→43, нечисловой токен читается как0, поэтому прежнюю фразу о запрете любого неверного X/Y следует читать с этим уточнением.

17 октября 2026, ManagerNavigation-20261017. Подключены три конкретных
исходных маршрута внутри I17: показать выбранный объект, показать X/Y
назначения, выбрать точку на карте. Реальное взаимодействие остаётся в M20.

## Исходные правила

Things_Manager.c: case157/CenterView берёт один выбранный объект; кнопка
недоступна при нескольких строках. Case108 показывает106/107 (X/Y) через
Map_ScrollToPoint(SHOW_CURSOR). Things_ManagerShowWindow скрывает менеджер,
даёт окно возврата, затем показывает менеджер снова. ShowProc располагает
возврат у правого верхнего края главного окна с коррекцией рабочей области.

Case109/ChoosePoint передаёт X/Y в Map_ChoosePointEx(MAP_CHOICELMBPOINT).
Map_Choice.c копирует координаты в отдельный Context: LMB меняет только его;
лишь OK возвращает значения caller, Cancel/Escape оставляет прежние. Правый
клик в point mode ничего не принимает и не отменяет. Это не мгновенная запись
по щелчку. В текущем App сохранены private preview/OK/Cancel и этот RMB режим.

## Реализация

ObjectManagerWindow.Navigation.cs добавляет общие X/Y сеанса, три кнопки и
временный сеанс навигации. EditorWorkspace.ObjectManagerNavigation.cs использует
существующий Canvas/ScrollViewer: показывает нужную вкладку, центрирует клетку,
переносит cursor и временно подсвечивает её. Показ имеет окно возврата;
выбор использует тот же canvas point gesture с отдельным черновиком и кнопкой
«Использовать точку». После клика можно выбрать другую клетку или отменить.
Нажатие Enter на холсте также подтверждает; Escape отменяет выбор.

Координаты попадают только в ObjectManagerSession и родительские поля после
подтверждения. Добавление/многообъектная правка используют тот же общий draft;
после закрытия дочернего окна координаты менеджера перечитываются. Координаты теперь ограничиваются при вводе: [ManagerDestinationCoordinates](MANAGER_DESTINATION_COORDINATES.md).
Промежуточный raw text допустим в поле, но session/show/Add используют принятое
число. Picker остаётся private до OK, Cancel не меняет родительские координаты.
Новая карта и отдельный workspace не получают чужие экземпляры record/plan.

MapCanvas.NavigateCursorTo отделён от PaintObjectAt: не размещает предмет,
не рисует и не меняет ordinary copy selection. Начатый до навигации штрих
завершается своим обычным маршрутом; если это изменило revision, запрос
навигации отклоняется. Обычные click-statistics во время выбора не пишутся.
Исходный одноаргументный BeginRegionPick сохранён; только этот picker
использует дополнительный internal режим игнорирования RMB.

## Закрытие, отмена и модальность

Менеджер временно скрывается. Hide завершает старый WPF ShowDialog frame;
возврат в прежний модальный режим ставится в ContextIdle после завершения
старого handler. Modeless вызов возвращается modeless. Для просмотра окно
возврата модально, для выбора оно оставляет доступ к главному холсту.
Окно возврата использует Win32 bounds/monitor work area и существующий clamp,
не предположение об одном основном мониторе.

Document reference, revision и navigation token проверяются перед принятием.
Смена/закрытие документа, внешняя правка, Cancel и закрытие менеджера завершают
выбор; старый callback не применяет координаты и не открывает новое окно.
Снимаются RegionPicked/RegionPickCanceled/PreviewKeyDown, временная подсветка
возвращается, queued restore проверяет token и владельца. Map selection,
данные карты и Undo не используются для хранения X/Y/preview.

При неожиданном исключении во время скрытого состояния выполняется cleanup,
исходная ошибка передаётся дальше. В частности, typed history allocation error
при завершении старого pen не оставляет скрытый активный picker и сохраняет
доставку через прежний центральный history notice. Обычный OOM не называется
ошибкой Undo. Вложенные Add/Modify и destructive Apply/Undo недоступны во время
навигации. Root menus при выборе всё ещё принадлежат главному окну; их действие
не разрешает старому picker пережить изменение документа.

## Ручные шаги M20

1. На своей копии выбрать одну строку менеджера и «Показать выбранный объект».
   Менеджер скрывается, карта центрирована на клетке, видна подсветка и окно
   возврата. Вернуться: тот же менеджер снова работает в прежнем режиме.
   При двух выбранных строках показ недоступен.
2. Ввести допустимые X/Y и показать точку назначения. Проверить подсказку,
   cursor, прокрутку и возврат; неверные/выходящие за карту X/Y не показываются.
3. «Выбрать на карте…»: щёлкнуть первую, затем другую клетку. Родительские X/Y
   ещё не меняются. Правый клик не завершает выбор. «Использовать точку»/Enter
   переносит последнюю клетку; новое добавление открывается с этими X/Y.
4. Повторить с Cancel/Escape: прежние X/Y, карта, выделение и Undo сохраняются.
   Проверить закрытие редактора/смену карты во время выбора: окно не возвращается,
   жесты не остаются активными, старый callback ничего не применяет.
5. Повторить на EN/RU со сменой языка в открытом выборе, на другом мониторе/DPI.
   Особенно проверить возвращение настоящего модального менеджера после обоих
   способов навигации; prepared smoke не заменяет этого пользовательского ввода.

Агент GUI/редактор/игру не запускал. Остальные options/preview/Config маршруты
I17 и весь OPEN_FUNCTIONS_RU сохраняются. Все игровые проверки по-прежнему
