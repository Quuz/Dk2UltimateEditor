# Общая проверка заголовка KWD

25 октября 2026, `DescriptorHeaderGuards-20261025`. Закрыта последняя строка
F01 в [таблице I04](I04_FORMAT_MATRIX.md).

Открытие KWD и предпросмотр используют `NativeDescriptorReferences.HeaderProblem`.
Проверяются DC/version4, information header DD/28, parameters marker DF и границы
параметров. Минимальный блок параметров — 2304 bytes с позиции56, до байта2360:
Unicode name64, description1024 и author64. Таблица ссылок не считается частью
метаданных, даже если её физические bytes заполняют отсутствующий префикс.
Неверные DD/size, DF и усечённый префикс одинаково отклоняются.

Сохранена поддержка полного исходного layout, минимального префикса и
дополнительных bytes в блоке параметров. Открытие минимального префикса не
объявляет отсутствующие поздние поля известными; named tools видят частичный
набор. Устаревший общий размер файла0/12/56 остаётся metadata warning, а не
адресом конца данных. Фактические bounds, таблица ссылок, безопасные пути,
explicit/fallback precedence и signature typed companions проверяются отдельно.

Предпросмотр показывает физически доступные name/author даже у ошибочного
файла, но не разрешает открытие и не следует неправильным ссылкам. Диагностика
DD/DF/prefix дополняет сохранённый DK2E113 таблицы, как прежде. Синтетический KWD
только с метаданными может быть структурно пригоден для просмотра без размеров
карты; для редактирования нужен реальный tile companion. Это явная граница
preview/Open, а не расхождение проверки одного layout.

Read-only инвентаризация580 дескрипторов нашла один штатный вариант:
v4/DD/28/DF, parameter payload25683. Все входные SHA совпали после чтения.
Это ограниченная проверка нового header-контракта, не полный corpus-прогон.

## Согласование переменных со свойствами карты

Смежная проверка обнаружила старое ожидание отказа при удалении переменной
из native-коллекции с заниженным payload size. Дочерний writer уже использовал
[согласованный безопасный fallback](NATIVE_COLLECTION_BOUNDARIES.md), а родитель
в `VerifyPropertiesVariableCollection` продолжал вычислять checked unsigned
вычитание. Новый отдельный позитивный тест воспроизвёл переполнение.

Родитель теперь проверяет тот же `AdjustedNativeStoredSize`, с фактической длиной
учтённых записей без хвоста. Старое ожидание отказа заменено проверкой применения,
точного Undo/Redo и сохранения исходных padding/opaque bytes. Остальные guards
свойств карты не менялись. Пройден полный целевой `MapPropertiesSessionChecks`
и headless caller-тест свойств карты. Попытка сравнить весь старый набор на
перенесённой DLL остановилась раньше из-за относительного пути к ресурсу;
этот лог не используется как доказательство совпадения ошибки. Отдельный
позитивный тест подтвердил реальную продуктовую ошибку до исправления.

## Проверки и доказательства

Исправленный descriptor fixture сравнен с прежней опубликованной DLL:
3 PASS / 3 FAIL; новая версия — 6 PASS. Исходный промежуточный fixture для
metadata-only preview случайно находил рядом tile fallback; он перенесён в
изолированный каталог. Все промежуточные логи сохранены. После добавления
позитивного случая переменных итоговый focus содержит7 успешных групп.

Смежные проверки ссылок сначала выявили регрессию показа текста/диагностики;
исправлено поведение продукта, исходный тест не переписывался. Проверены
поддержанные/ошибочные bounds и ссылки, CP1252, явный приоритет путей, historical
inspection, предпросмотр, реальный DKM/level1,1800cells/711payloads и семь файлов.
Уже успешные группы на предыдущем build этого же этапа не повторялись после
единственного изменения родительской формулы; их DLL-хеши явно сохранены.

`artifacts/Evidence/DescriptorHeaderGuards-20261025/source-descriptor-proof.json`
разделяет финальные текущие проверки и смежные проверки предыдущего build.
`i04-closure-proof.json` связывает все20 строк с текущими providers и датированными
доказательствами. Поставка и каждый ZIP entry проверены отдельно в `delivery.json`.
GUI/WPF/game/Computer Use не выполнялись; все23 ручные группы остаются.
