# Исторические объекты в выделении

12 октября 2026. Найдена и исправлена ошибка совместимого KTGS6-представления:
SelectionFile копировал только совпадающие имена полей старой записи. В KTGS1–3
поле options поэтому терялось вместо перехода в herosoptions; отсутствовали
исходные defaults поведения/цели героя. Для ловушек KTGS1–4 не задавался charge4.
Преобразование старого выделения в native также пропускало эти правила.

## Правила из исходного Editor_ExtractThings

| Исходный KTGS | Преобразование в текущий MAPTHING |
|---|---|
| 1 | options→herosoptions; для существа creaturesoptions=9, для героя objective=19 и enemy=0; trap shots=4; отсутствующие поля нулевые |
| 2–3 | Те же правила; area/uniqueid сохраняются, старый objective не переносится |
| 4 | Составные flags, objective, area, uniqueid, enemy сохраняются; trap shots=4 |
| 5 | Все описанные поля сохраняются; нового goldheld ещё нет |
| 6 | Текущие поля сохраняются; прежние pointer bytes не экспортируются как ссылки памяти |

Бинарные смещения взяты из Includes/Things.h, Compatibility.h и32-bit NODE из
Global.h. Никакие старые pointer значения не разыменовываются. Сериализованные
координаты совместимого блока становятся относительными к выделению.

## Текущая реализация и обратная совместимость

UpgradeHistoricalThing — общий исходный recipe для явного UpgradeLegacyProject
и независимого selection projection. Последний не меняет документ, историю или
старые записи: результат вычисляется в отдельном буфере. Native conversion
использует тот же recipe перед переводом текущих полей в native типы.

Этап исправления записей ввёл **DKCP4**. Его payload/provenance/mask такой же, как в DKCP3;
версия обозначает новое правило формирования совместимого KTGS6. В расширении
хранится целиком исходная историческая запись, включая поля, которые старый
Editor_ExtractThings не переносит. Базовый KTGS6 получает правильные значения
для исходного редактора. Это не изменение семифайлового формата игровых карт.

DKCP1/2/3 читаются с прежней проверкой их совместимого блока. Последующее исправление
клеток ввело DKCP5, включающее исправленное KTGS-представление и полный raw tile
vector; DKCP4 также читается. См. [terrain projection](SELECTION_TERRAIN_PROJECTION.md).
Несогласованный
совместимый блок по-прежнему отвергается. Нельзя применять новые defaults к
проверке старого DKCP3: это ошибочно отвергло бы ранее сохранённые файлы.

## Проверка и границы

HistoricalSelectionChecks создаёт36 независимых fixtures: все6 KTGS versions,
пять категорий и оба владельца существа. Ожидаемые64 bytes записаны по literal
source offsets отдельно от продуктового recipe. Проверяются совместимый блок,
целый современный roundtrip, старое DKCP3-представление/повторная запись,
native поведение/цель/флаги/заряды и неизменность исходного документа/Undo/Redo.
До исправления v1 hero projection завершался с exit1; после исправления группа
завершилась с exit0. Сырые логи: `artifacts/Evidence/HistoricalSelection-20261012`.

Нормализация клеток и copy-order проверены отдельными source-backed группами.
Direct first-member rule и полный raw snapshotDKCP6 исправлены14 октября:
[DIRECT_SELECTION_EXPORT](DIRECT_SELECTION_EXPORT.md). Исторические реальные DKZ, физическая проверка
буфера/вставки/официального GUI и игровой цикл ещё не подтверждены. Оригинальный
Areas_ExtractThings сам читает старые версии через sizeof(MAPTHING); источником
проверенных переходов между layout служит Editor_ExtractThings, а не небезопасный
старый pointer walk. Полное историческое соответствие этим тестом не заявляется.

Полная текущая регрессия:1797 passes/63 failures, terminal exit1; все прежние63
сообщения буквально совпадают в полном порядке, предыдущие1796 passes сохранены.
Промежуточный64-failure report сохранён: его единственный дополнительный отказ
был старым future-version assertion для4. После перехода assertion на неизвестную5
пройдены focused и полный повторный run. Защита неизвестных layouts не ослаблена.
