## Территория и владелец

На страницах «Содержимое области» (TRIGGER_AREACONTENT) и «Изменить клетку карты»
(ACTION_CHANGESQUARE) выбор территории теперь управляет владельцем. Исходные
обработчики LVN_ITEMCHANGED в Triggers_Triggers.c/Triggers_Actions.c устанавливают
combo501/303 и блокируют его для следующих типов:

| ID территории | Выбор владельца после выбора территории |
| --- | --- |
| 1–7 и 31 | Neutral / Нейтральный, исходный ID2; список отключён |
| 35 | Heroes / Герои, исходный ID1; список отключён |
| Остальные допустимые строки | Список включён, текущий выбор сохраняется |

Это номера из сценарного Terrain, а не номера ресурсов изображения, номера строк
или индексы комнат в глобальном каталоге. Source combo начинается с ID1 без Auto;
Store добавляет единицу к выбранному индексу. Поэтому исходный индекс1 означает
ID2, а индекс0 — ID1. На странице условия есть29 типов; на странице действия27,
поскольку исходный список действия исключает портал и сердце.

Изменение территории и зависимого владельца остаётся в приватном вводе до Apply
или общего Finish мастера. В Core отдельный UpdateScenarioTerrainSelection
составляет обе величины через существующий проверенный черновик. App применяет
ту же зависимость к видимому списку и повторно проверяет её при подготовке Apply.
Прежние общие sparse/raw API не получили автоматической нормализации владельца.

Простое открытие, Reset или смена языка не переписывают импортированный владелец.
Для известной принудительной территории такой выбор отображается отключённым;
новое исходное значение задаётся при выборе территории. Неизвестная импортированная
территория сохраняется и не предоставляет права выбора владельца до замены на
допустимую строку. Исходный ParamsCheck восстанавливает combo из сохранённого
param2 после инициализации; физический порядок Win32 уведомлений отдельно не
проверен. Сохранение импортированных данных при просмотре — явная граница
современного поведения.

## Число и переменная в ACTION_SETVARIABLE

В исходном ParamsCheck вторичная combo214 сначала выбирает переменную0. Только
режимы 0x0C/0x14/0x24 восстанавливают из param5 номер исходной переменной.
Режимы 0x0A/0x12/0x22 оставляют этот скрытый выбор0: их param5 является числом.
Числовое поле210 при этом всегда получает сохранённый param5.

Ранее современное окно заполняло скрытый номер переменной числовым значением.
Например, открытие «присвоить число42» и переключение на переменную показывало
переменную42. Теперь первоначально показывается переменная0. Числовое поле
сохраняет42; после явного выбора переменной8 возврат к числу показывает42,
а обратный переход к переменной сохраняет8 в текущем окне.

InitialSecondaryID в неизменяемом Core draft задаёт только первоначальный выбор
контрола; хранимый param5 от чтения свойства не меняется. Для уже открытого
режима переменной сохраняется её исходный ID, включая неизвестный импорт.
Неизвестный режим также сохраняет числовые биты при no-op; его скрытый исходный
список начинается с0. Общая отмена, кэш имён слотов, CP1252, одновременная запись
операндов/псевдонимов, родительский repeat и один Undo остаются прежними.

## Проверки

Независимый source capture сохраняет пять хешей исходников,29/27 допустимых
территорий, исходные уведомления, принудительные индексы владельца и шесть
режимов инициализации вторичного списка. Проверены все56 типов ×8 владельцев,
включая импортированный255, ×2 формата:896 случаев. Сравниваются полные буферы,
неизменность базового черновика, один Undo/Redo, счётчик и уведомление. Также
проверены сохранение приватного владельца после разблокирования, неизвестный
тип, недопустимый выбор, stale/foreign/raw/future/nested guards.

Для вторичного списка —42 случая на формат: шесть режимов и неизвестный режим,
значения0/1/42/128/255/0xFFFFFFFF, точный no-op, сохранение числовых битов и
исходных ID. Эти модели включены в прежние группы полного Validation. WPF
проверки именованных страниц/пространственного мастера/псевдонимов обновлены
и собраны, но не исполнялись; сборка не доказывает их физическое прохождение.

## Ручная последовательность EN/RU

1. На рабочей копии карты откройте «Изменить клетку карты». Выберите обычную
   территорию, например казну, затем Хранителя1. Выберите воду: владелец должен
   стать «Нейтральный», список — отключиться. Выберите логово героев: владелец
   «Герои», список отключён. Вернитесь к казне: список доступен, выбор «Герои»
   сохраняется. Повторите на странице условия «Содержимое области».
2. Переключите EN/RU в таком черновике. Территория, владелец и доступность списка
   должны сохраниться. Cancel не меняет карту; Apply сохраняет обе величины
   одной операцией Undo. Повторите в мастере создания, включая Back/Next и Cancel.
3. Откройте «Задать переменную» с режимом присвоения числа42. Переключитесь на
   присвоение переменной: первоначально выбирается0. Выберите8, вернитесь к числу
   (42 сохраняется), затем снова к переменной (8 сохраняется). Повторите EN/RU.
4. Отмените окно, затем повторите с Apply и Undo. Для игрового сравнения используйте
   только DK2Preview_6a88240eaf814f78 и обычный семифайловый экспорт; команда
   `DKII-DX.exe -q -level DK2Preview_6a88240eaf814f78`.
