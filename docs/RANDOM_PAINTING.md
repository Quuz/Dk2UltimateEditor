# Source-shaped ordinary and random map painting

## Original requirements and managed implementation

`Source/Sources/Map/Map_Mouse.c::Mouse_LeftButtonUp` maps Shift at release to five modes: random line, outlined/filled rectangle and outlined/filled circle. `Map_Display.c::Map_PaintElement` samples each corrected bounding-rectangle cell in row-major order, BEFORE shape and protected-cell tests. Zero samples paint the single selected translated terrain/owner/variant; this is not a randomized palette. `Properties_Editor_Config.c` initializes frequency to 2, giving probability 1/2. The source audit found no separate general painting-frequency control, so no unverified original UI/range is claimed.

`PaintEditorGesture` now accepts random mode, positive frequency and an optional sampler. The Windows interactive editor uses source GDI masks for both ordinary and randomized shapes. `OriginalPaintRaster` reproduces `Map_PaintTemporaryElement`'s white zero-width cosmetic pen, white/black brushes, Polyline/FillRect, ellipse degeneracies, LineTo endpoint plus SetPixelV, and one-cell special case. It uses a private local top-down 32-bit DIB, flushes and reads its BGR pixels, restores selected objects and releases handles. It does not open a native window, capture the screen, load old editor DLLs or access installed game files. The Core raw `MapDrawing` algorithms remain unchanged; non-Windows gesture fallback retains those managed algorithms, not a claim of GDI-equivalent cross-platform rendering.

The old managed ellipse approximation differed from the independently recreated source masks in **360 tested cases**. It is no longer the Windows interactive mask. Sampling still consumes every bounding cell, including cells outside the shape or modern selection and protected edge cells. After sampling, mask/selection/protection and source owner/variant normalization determine writes. Ordinary shapes bypass sampling. Brush, fill, sample, selection and geometry picking retain their separate behavior.

Source special footprints force fully filled rectangles even with random mode/Shift. All eight verified heart/portal/gate footprint entries are tested, including both directional gate variants and unlimited dimensions. Invalid unknown variants are not assigned guessed catalogue footprints. Failed initial/final footprint checks consume no samples and do not partially paint.

The default sampler is a fresh managed PRNG per gesture. This reproduces probability and per-gesture reseeding intent, not the exact historical Borland PRNG seed/sequence. A positive frequency and in-range sampler outputs are validated when random drawing is actually active; disabled random modes do not read irrelevant sampler/frequency settings. Lazy random enumeration occurs inside the atomic map transaction. Mid-sampling exceptions restore every earlier write and retain prior history. No-op draws retain redo; Undo/Redo reuse exact stored bytes and never resample. Changed random operations have bilingual history names.

## Actual editor controls

The existing line/rectangle/ellipse tools accept Shift when the mouse is released. A bilingual “Random (or Shift)” checkbox adds an equivalent accessible session mode; it is deliberately not presented as an original separate toggle. Its checked preference survives language and document changes but is disabled without a document, during geometry picking, for unrelated tools and for forced special footprints. Ending/canceling a geometry pick refreshes placement-control availability. This fixes the stale disabled-control state uncovered by integration tests.

Tooltip instructions explain the 1/2 probability, Shift-release timing and unaffected tools/special footprints. There is no map edit merely from choosing the mode or changing language. Selection and copy buffers are retained. Closed documents cannot draw or sample. Native physical mouse/keyboard/DPI and historical executable interaction are separate acceptance work; offscreen tests do not claim hardware input automation.

## Verification and current gate state

The independent `OriginalGdiReference` uses an absolute-coordinate full-map monochrome DDB and GetPixel, unlike production's relative-coordinate 32-bit DIB/Marshal.Copy. It recreates source drawing primitives directly. **1602 masks** compare exactly: all five shapes, sizes 1–12 on each axis, both directions, and an additional reversed diagonal line sweep. GDI-resource counts are checked after the sweep (at most one initial process cache handle; no per-operation accumulation).

`RandomPaintChecks` reads source Shift mappings, default frequency and ordering evidence. Native/project fixtures check independent expected complete buffers for all five shapes/directions, selection/edge clipping, frequencies 1/2/3/17/Int32.MaxValue, exact sample counts, atomic/no-op events/history, Undo/Redo without resampling, saved copies, project-to-native terrain compilation, invalid/throwing sampler rollback, all eight special footprints, unchanged brush behavior, repeatable 1/2 probability and an actual default-sampler nontrivial subset. Native corpus checks additionally perform all five seeded draws on each successfully loaded map and compare full buffers with independently encoded source masks after exact undo. Inputs are not written.

Four actual WPF EN/RU × native/project cases bind the real tools/palette/checkbox and shared Shift-release operation, compare complete bytes with the independent masks, verify source frequency/order, history labels, Undo/Redo, language/input/selection/clipboard retention, special/brush/picking behavior and closed-source guards. The first UI fixture accidentally selected only the interior of an outlined rectangle; exact bytes were correct and the draw was correctly a no-op. Its selection was corrected to exercise boundary writes; the explicit empty-mask/no-op checks remain. The next run found and fixed the stale control state after geometry picking. Artifact set `Test/RandomPaint-20261007-b` has four actual-control renders; Russian-native and English-project layouts were inspected. The shown subset uses a deterministic injected fixture sampler, not a screenshot of a historical PRNG sequence.

Focused Core and all four WPF cases pass in Debug/Release; both solution builds have zero warnings/errors. Full Debug synthetic regression is terminal with **68 groups / zero failures** (`random-paint-debug-20261007.json`). Both complete WPF configurations are terminal with **184 passing cases each**, exit 0. The expanded 578-map Release corpus is terminal (`expanded-corpus-random-paint-20261007.json`, exit 1): **1717 passes / 94 failed checks**, including 68 synthetic, 560 native, 530 supported-text and 559 original-policy text passes. Its complete ordered failure array exactly matches the history baseline. This includes all five real-map random-paint/undo projections within each successful native check. Whole-editor parity and historical/hardware/game acceptance remain incomplete.
