# Что OpenKeeper даёт для нашего редактора

Проверка 22 октября 2026: актуальный `master` совпадает с уже использованным коммитом `59c1966b80b589cf397476b421fd779527b8e2c4`. Сохранены 786 файлов исходников и лицензий, включая весь `src`; дополнительно просмотрены потребители полей в `game` и `view`. Исходники не исполнялись и не добавлялись в приложение редактора.

OpenKeeper — важная основа для структуры файлов, но его игровая реализация не является полной спецификацией оригинала. Имена и формулы из неё остаются отдельным уровнем доказательств; проверенные отличия конкретного EXE имеют приоритет.

Последующее native-уточнение Effects/EffectElements находится в `EFFECTS_RUNTIME_RU.md`: оно имеет приоритет над предварительными подсказками по формулам ниже. Там проверены условия CUBE_GEN, 16-битные поля, режимные значения SPRAY/GOLD_COST/TEST_3 и цепочки элементов.

Для Effects сохранены 13 интерпретаций отдельных полей со смещениями и первичными ссылками. В частности, `MinHp/MaxHp` в ремейке задают время жизни в тиках 20 Гц; это не здоровье существа. Горизонтальные диапазоны появления пересчитываются как `raw*23/4096`, вертикальные — `raw*16/4096`; углы используют 2048 единиц на оборот. Эти конкретные коэффициенты пока не объявлены подтверждёнными по оригинальному EXE.

## Где нельзя считать реализацию полной

1. **Shots:** `ShotsController.createShot`, строки 66–83, реализует четыре процесса: CREATE_CREATURE, CREATE_OBJECT, POSSESS_CREATURE, MODIFY_HEALTH. Остальные попадают в предупреждение о нереализованном типе. Наш SHOT_PARAMETERS.md отдельно содержит разбор 39 процессов оригинального движка.
2. **Порядок исследований:** KwdFile.java:2966–2976 читает тип 17 как `UNKNOWN_17`. PlayerResearchControl.java:119–156 строит собственную последовательность: заклинания → двери → ловушки → комнаты, улучшения после новых открытий. Такой алгоритм нельзя использовать вместо native ResearchOrder из Variables. Его обработчик `0x51DB00` разобран отдельно.
3. **Атаки существ:** CreatureController.java:668–674 содержит TODO по alternative shot и временному применению ShotData1 как урона. Это не основание подписывать все Data1 как Damage: назначение зависит от процесса/типа урона.
4. **Уровень открытия заклинания:** CreaturesController.java:705 использует сравнение `levelAvailable >= level`. Направление этого сравнения нельзя автоматически переносить в редактор как правило оригинальной игры; здесь зафиксировано только состояние исходника.
5. **Триггеры:** в TriggerControl.java:289–323 есть TODO для CollapseHeroGate, SetCreatureMoods, SetSystemMessages, ChangeRoomOwner, SetSlapsLimit, SetTimerSpeech. Разбор бинарных параметров и выполнение действия — разные степени готовности.
6. **Цепочки эффектов:** VisualEffect.java:156–159 запускает NextEffect сразу, с TODO по времени запуска. Это не подтверждает тайминг оригинального движка.
7. **Неизвестные поля:** поиск по 501 Java-файлу `game`/`view` не нашёл вызовов 35 объявленных `getUnk*`/`getUnknown*` в моделях 11 каталогов. Это лексический поиск, без Java type resolution; он показывает отсутствие дополнительной помощи в этих потребителях, а не неиспользуемость байтов оригинальной игрой.

Ранее установленные отличия тоже сохраняются: поле Creatures +0xF20 читается игрой как unsigned угол, а не `short/4096`; Level содержит 20 сообщений по 512 UTF-16 символов; ordinal AnimationType не равен игровому номеру слота шагов. Для WALK нужен игровой слот 1.

## Дополнительная сверка с движком

По подсказкам OpenKeeper дополнительно сохранены `0x440720` (выделение массива определений Effects), `0x4407D0` (вставка/загрузка определения), `0x4358C0` (перенос в runtime), `0x4347E0` (создание эффекта), `0x434E80` (обновление).

- Effects выделяет `N` записей runtime размером `0x94`; это не размер записи на диске (`246` байт).
- Raw `MinHp` +0xBA и `MaxHp` +0xBC переносятся в +0x86/+0x88 определения. Создание эффекта выбирает значение в диапазоне min..max включительно и сохраняет в +0x10B экземпляра; обновление уменьшает положительное значение при активном +0x145. Это подтверждает роль счётчика времени, но ещё не коэффициент 20 Гц для всех путей вызова.
- У Mass +0x8C, скоростей +0x9C..0xA8 и масштабов +0xAC/+0xB0 исходные 32 бита проходят через intermediate, а runtime хранит 16 бит. Полный raw сохранять: размер runtime не меняет формат файла.
- 12 хвостовых u16 по raw +0xDA передаются в intermediate, а runtime loader заменяет соответствующий слот только при ненулевом значении. Это условие обновления определения, а не разрешение удалять нулевые поля из файла.

В `scalar-storage-paths.json` теперь 242 буквальных скалярных пути для девяти семейств, включая 21 путь Effects. Циклы, ресурсы, getter-вызовы и весь control flow этим консервативным извлекателем не покрываются; отсутствие пути ничего не доказывает об использовании поля.

## Воспроизводимость

- `sources/openkeeper-head-check.json`: дата и результат сверки master с закреплённым коммитом.
- `sources/openkeeper-source-snapshot.json`, `openkeeper-source-manifest.json`: происхождение архива и SHA-256 сохранённых файлов.
- `openkeeper-audit.json`: результаты поиска, 16 выдержек с номерами строк/URL и 13 интерпретаций полей. `audit_openkeeper.py` пересобирает аудит без сети.
- `sources/openkeeper-59c1966b80b5/`: локальные исходники с исходными лицензиями.
- `ghidra/game-effect-*.txt`: новые первичные декомпиляции. `PHASE4_FINDINGS_RU.md` связывает их с остальным продолжением исследования.
