# Objects: полная загрузка, цвет света и деление Speed

Дополнение этапа110: цепочка сырой записи до полного Object tick и обработчика StartState теперь проверена отдельно; см. `OBJECT_STATES_RU.md`. Для точного DX установлены заполненные состояния0–58 и отложенный небезопасный dispatch значений вне них. Справочное перечисление не заменяет проверку конкретного EXE.

Этап71, 27 октября2026. Полные native initializer/converter/loader двух предоставленных игровых EXE проверены в86 успешных сценариях; ещё четыре сценария ожидаемо останавливаются на делении при нулевом TPS. Визуальный resource provider равен null, звук представлен адаптером захвата аргументов. Это работа в памяти эмулятора, не запуск изменённой игры.

Размеры десятичные: исходная запись894 байта, intermediate1022, runtime definition285. Смещения далее hex относительно указанной структуры. Точный профиль выбирается по SHA из `native_object_loading.py`; папка старого EXE не удостоверяет розничную версию1.3.

## Неизвестное34C и непереносимые байты

Полная цепочка подтверждает WORD raw34C → intermediate3CC с presenceDWORD50 → definitionWORD106. Все16 бит сохраняются, включая8000/FFFF. При presence0 остаётся прежнее слово;2/FFFFFFFF считаются присутствием. Скрытая подпись GUI «Mana Gen» не превращена в доказанный игровой эффект.

Три raw-байта341..343 converter не переносит. У intermediate есть соответствующий по положению, но отдельный физический участок3C1..3C3: изолированный converter оставляет его прежнее содержимое, полный initializer очищает все1022 байта. В12 полных цепочках замены raw-участка на00/FF/шаблон дают одинаковые intermediate и definition при фиксированных профиле/глобальном флаге. Другие потребители и исторический смысл глобально не исключены; исходные raw-байты сохранять.

Converter устанавливает32 DWORD признаков присутствия, копирует девять84-байтных ArtResource,24 байта Light и scalar поля. Обе строки имеют bounded strncpy32 с принудительным последним NUL. Flags преобразуются через `midDWORD3C4 |= rawDWORD344`. Грязный промежуточный буфер сохраняет прежние биты; initializer полной цепочки это устраняет. Включённая статическая assembly parser56D880 подтверждает initializer перед преобразованием очередной записи, но filesystem parser и вставка в мировой каталог новым этапом не исполнялись.

## Цвет устанавливает Light Flags bit0

При ненулевом presence30 loader сначала копирует все24 байта Light из intermediate394 в definitionD8. Затем выполняет:

```text
runtimeLightFlagsDWORD E8 |= int(any(mid3A8, mid3A9, mid3AA))
```

Это raw color bytes328/329/32A. Любой ненулевой из трёх устанавливает младший бит. Если все три нулевые, существующий bit0 не очищается. Остальные flags сохраняются. Четвёртый байт32B копируется в структуру и участвует в checksum, но сам по себе не включает bit0. Проверены каждый из трёх байтов отдельно, только четвёртый, flags0/80000000 и чёрный цвет с исходными flags1.

Результат не объявляется подтверждением фактического свечения, цвета на экране или полного renderer. В DX копирование/условие Light находится вне глобальной ветки пропуска visual/checksum/sound.

## Speed и нулевой TPS

При присутствующем Speed loader выполняет unsigned DIV исходного DWORD338 на runtime TPS, сохраняет low16 частного в definition100. Если уже суженный результат0, а rawSpeed ненулевой, заменяет его на1. Проверены0/1/19/20/65535/1310720/1310740/FFFFFFFF при TPS20. В частности,1310720/20=65536, low16=0, поэтому получается1. Это правило хранения, а не доказательство всей физики движения.

В обоих EXE DIV выполняется **до** проверки rawSpeed на ноль. При TPS0 и присутствующем Speed даже rawSpeed0 останавливается на инструкции DX49DE1F/old494F36. Четыре ожидаемых fault-сценария фиксируют отсутствие возврата, точный PC и ошибку EmulatorHelper `Remainder by 0`. Это не зарегистрированный Windows crash и не доказательство доступности нулевого TPS в обычной сессии.

Если presence44=0, DIV пропускается; прежний WORD100 сохраняется даже при TPS0. API возвращает ValueError для предсказуемо аварийного контракта вместо имитации успешной загрузки.

## Сумма и звук

DefinitionDWORD F0 — сумма всех1022 беззнаковых intermediate байтов. Старый loader считает её всегда; DX — при globalDWORD6FCDCF==0, иначе оставляет прежнее значение. Это не поле checksum, физически записанное в raw894.

Тот же DX-флаг пропускает разрешение звука. При наличии строки и разрешённой ветке настоящий strncpy копирует32 байта в глобальный буфер, byte31 обнуляется. Audio vslot1C получает native-префикс GLOBAL\ и имя; token сохраняется в definition10E. Адаптер фиксирует указатель префикса, все32 байта и количество вызовов, возвращая A1B2C3D4. Поиск реального ресурса, воспроизведение и обработка ошибок не проверялись.

## Воспроизводимость и комплект

Среди86 успешных сценариев:6 initializer,12 converter,18 loader,50 полных init→converter→loader цепочек. Наблюдатель сравнивает целиком894 raw,1022 intermediate и285 definition байт,32 байта звукового буфера и40 байт захвата вызова. EAX/EBP финального результата относятся к наблюдателю. Четыре DIV0-сценария его не достигают: для них не заявляется успешное сравнение выходных буферов.

Исполнялись восемь полных native-функций: initializer/converter/loader/strncpy каждого EXE. После исполнения считаны15 code extents: восемь исполнявшихся функций, статический parser и шесть контекстов ложных начал. Отдельно сверены два префикса звука и20-байтная switch table. Все байты совпали с исходными PE; provider-код не перекрывает native инструкции.

На84 файлах с11756 Objects выполнены23512 новых точечных пересборок в памяти: отдельно три color bytes328..32A и DWORD LightFlags324. Весь контейнер совпадает с ожидаемой единственной правкой; остальные байты сохраняются. Сохранность неизвестного34C ранее проверена этапом62 и не пересчитывается как новая работа. Четыре исходных EXE неизменны; игровые данные и параллельный редактор не менялись.

Схема `object-loading-semantics.json` вложена в `object-property-semantics.json.phase71_loading`; пакет остаётся67 компонентов. Итоги — `phase71-validation.json`. Воспроизведение: `emulate_object_loading.py`, `prepare_object_loading_primary.py`, `ghidra_probe.py phase71-primary-queries.json`, `build_object_loading_semantics.py`, `build_format_package.py`, `audit_object_loading.py`.

API `native_object_loading.py` требует явных предыдущих буферов и точного EXE-профиля. Runtime definition не заменяет raw-запись при сохранении. Неизвестные назначения Objects34C, Traps204, Doors236 и других существенных полей остаются в общей очереди анализа.
