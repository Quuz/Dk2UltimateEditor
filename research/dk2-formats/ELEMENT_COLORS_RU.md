## Структура полей

Запись EffectElements —182 байта. Не смешивать raw-смещения с определением игры и экземпляром эффекта.

| Поле | Raw | Intermediate игры | Runtime definition |
|---|---|---|---|
| Color, byte0 | +0xAE | +0x11A | +0x4A |
| Color, byte1 | +0xAF | +0x11B | +0x4B |
| Color, byte2 | +0xB0 | +0x11C | +0x4C |
| RandomColorIndex | +0xB1 | +0x11D | +0x4D |
| TableColorIndex | +0xB2 | +0x11E | +0x4E |
| FadePercentage | +0xB3 | +0x11F | +0x3D |

Все шесть полей — физические байты. У экземпляра packed-color находится в+0x6E, оставшееся время жизни в+0x109, вычисленный порог прозрачности в+0x10D. Указатель+0x4E экземпляра — ресурс для рендера, а+0x4E определения — TableColorIndex: это разные структуры.

## Начальный цвет: приоритет трёх веток

Initializer0x435F20, участок0x43630B..0x4363B4:

1. При resource type1, baseline-имя SPRITE, цвет равен255/255/255 и alpha255. Эта ветка имеет приоритет даже над PLAYER_COLOURED.
2. Иначе при resource flags&2 берётся цвет игрока, каждый канал увеличивается как минимум до48, alpha255.
3. Иначе используются три raw-байта Color, alpha255.

Resource type в файле расположен по+0x70, флаги ресурса — DWORD+0x60. Их нельзя подменять флагами самого элемента по+0x9C. В loaded-ресурсе type —+0xA, flags —+0xB.

Выбор player color зависит от сравнения owner с локальным игроком: в просмотренной ветке вызывается bridge+0x298(0) либо bridge+0x290(owner,0). Read-only API принимает уже разрешённый цвет; полную систему палитр игроков он не моделирует. Эмуляции проверяют обе ветки с разными подставными цветами и минимумом48.

Упаковка соответствует порядку байтов: `byte0 | byte1<<8 | byte2<<16 | alpha<<24`. API не переставляет каналы по предположению о формате графического API. Итоговое смешивание с framebuffer не исследовалось.

## Порог alpha и FadePercentage

При инициализации сначала выбирается целое H из MinHp..MaxHp, затем вычисляется:

```text
T = H - trunc(H * FadePercentage /100)
```

T сохраняется как DWORD в instance+0x10D. Для имеющихся u16 H и u8 процента произведение помещается в signed32. Это число тиков, а не дробное значение /4096.

| H | FadePercentage | T |
|---:|---:|---:|
| 128 | 0 | 128 |
| 128 | 25 | 96 |
| 128 | 70 | 39 |
| 128 | 100 | 0 |

При FadePercentage100 порог равен0, и **ветка обновления alpha не выполняется**. Это не отключает отдельное RGB-затухание. Значения больше100 дают отрицательный signed-порог; API сохраняет его DWORD-представление, не ограничивает процент автоматически диапазоном0..100.

## RGB и alpha обновляются по разным правилам

Tick0x436430 сначала вычитает elapsed ticks из H, затем один раз выполняет fade-блок. Общий gate — element flags&8, baseline-имя FADE, и H!=0.

**RGB:** если H не больше максимума трёх текущих каналов, каждый канал становится:

```text
new_channel = low8(trunc(((H-1) * current_channel) / H))
```

В native-коде произведение сужается до32 бит и применяется signed IDIV. Изменение использует текущий цвет. Это не прямое умножение исходного RGB на H/initialH и не формула через FadePercentage. При H больше максимального канала RGB в этом обновлении вообще не меняется. При H=1 каналы становятся0; при H=0 весь fade-блок пропускается.

**Alpha:** записывается только при T!=0 и signed H<signed T:

```text
alpha = low8(unsigned32(low32(H *255)) / unsigned32(T))
```

Здесь native DIV **unsigned**, хотя сравнение H с T signed. При H==T обновления alpha нет. Если alpha записана и resource type равен2/3/5, устанавливается bit0 instance renderer flags+0x81; остальные биты сохраняются. Для других типов эта ветка флаг не меняет.

Гейт проверяет H!=0, а не H>0. При отрицательном оставшемся времени формула может увеличивать каналы или давать low8-перенос. Такой случай проверен эмуляцией, но его видимость на экране до удаления экземпляра не установлена. Read-only модель воспроизводит арифметику и не добавляет отсутствующее в этом участке ограничение H≥0.

Fade выполняется один раз за вызов, перед возможным циклом физики. Например, для текущего канала100 и lifetime10 при FADE: один вызов с elapsed2 даёт87, два вызова с elapsed1 — сначала88, затем77. Поэтому пакетное обновление времени нельзя объявлять равнозначным нескольким единичным обновлениям цвета.

## Что найдено в корпусе

В80 файлах карт проверены47224 записи EffectElements. Повторяющиеся определения разных карт учитываются отдельно.

- В31593 записях включён element FADE.
- FadePercentage100 встречается47144 раза;70 —80 раз.
- Все80 записей с процентом70 — ID294, Blood Pool Element. MinHp=MaxHp=128, Color=(10,10,10), resource type2, поэтому T=39. При H38 alpha получается248; при H1 —6. Изменение alpha в H0 в этом блоке не выполняется.
- Единственный resource type1 в каждом наборе — Crap Effect Element, ID49. Его raw RGB подчиняется приоритетной белой ветке, если экземпляр создаётся этим initializer.
- Оба палитровых индекса равны0 **во всех47224 записях**. Успешная эмуляция цвета с индексами255 показывает лишь отсутствие влияния в изолированном initializer-color участке; глобальную неиспользуемость не доказывает.

`element-color-semantics.json` включена в общий пакет как `element_color_semantics`. `native_element_colors.py` предоставляет `record_view`, `initial_color`, `alpha_threshold`, `fade_after_lifetime_update` и `update_projection`. Исходные записи не меняются.

```python
from native_element_colors import initial_color, alpha_threshold, update_projection
color = initial_color(2,0,[10,10,10])
t = alpha_threshold(128,70)
assert t['signed'] ==39
step = update_projection(color['channels'],39,1,t['unsigned'],8,2)
assert step['channels'][3] ==248
```
