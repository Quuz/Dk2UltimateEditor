# Variables: нулевые элементы и порядок игроков

14 ноября 2026. Дополнение к [первой player-ветви](../variables-player-writer/README_RU.md).
Замороженный индекс205 и прежние доказательства не меняются.
[Сцены и подробности](PLAYER_ORDER_RU.md), [личная приёмка](coordinator-validation.json).

Координатор повторил четыре подготовленные CPU-сцены оригинальных4937C0/4943C0,
счётчика48CA00/48CF50 и аксессора488830. Весь JSON совпал с сохранённым отчётом;
запуск без записи сохранил хеши всех трёх файлов. Счётчики196+2/196+2/196+2/196+1,
новые записи, заголовки, META и нетронутый хвост буфера совпали с ожиданиями.
Байты и PC проверены от начал функций; аксессор включает полный RET4.

В этих сценах нулевой value не создаёт записи и не увеличивает count. Два других
элемента одного игрока сохраняют порядок. Для двух разных игроков записи следуют
массиву указателей: перестановка[P0,P1]→[P1,P0] меняет порядок двух уникальных
kind/key/value в выходе. Игрокkind2 пропускается, обход продолжается к kind3.
Все новые16байт выводятся из входов; скалярные хвосты полного сравнения остаются
воспроизведением наблюдённого entry-scratch, независимый оракул для них не заявлен.

Индекс1 подтверждён сочетанием посещений циклов, уникального результата второго
указателя и контрольной перестановки. Отдельной трассы значения аргумента нет.
Это не заявление о GUI, настоящем файловом сохранении, игровой загрузке или
произвольных player/pool/availability-ветвях. Прочие циклы при пустых данных
проходили, но их непустая семантика не разобрана. Type77=0, Globals29/186/113/114
и отложенный Crypt не получают новых трактовок.

## Воспроизведение

Нужен исходный стенд Tools/dk2-format-research с хелперами снимка и предыдущим
variables-player-writer, локальными Pro EXE/Terrain.kwd и существующими
Python/pefile/Capstone/Unicorn указанных в проверке версий. Игровые файлы и
зависимости не включены; один checkout без этого стенда CPU-сцены не выполняет.

`python -B Tools/dk2-format-research/variables-player-order-audit/audit_player_order.py --no-write`

Ожидаетсяoverall=PASS и четыре сцены, приFAIL код возврата ненулевой. Baseline
регистры, CFile/vtable/heap/IAT и наблюдающие hooks — объявленная фикстура.
Оригинальные инструкции не заменялись, новых пер-инструкционных hooks нет.
Исходные игровые файлы только читались.
