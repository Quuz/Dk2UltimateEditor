# Variables: пропуск нулевого value и порядок между игроками (ветка `4943C0`)

14 ноября 2026. Профиль `DK2 Editor pro.exe`, SHA-256 `989c45df779bccfc9a9e509b2ad0224a9bd269629f74792adc0320fa4b99fb09`. Дополнение к принятому аудиту `variables-player-writer`: закрываются только два оставленных им пробела — пропуск элемента `player+0x4C` с нулевым value и индекс игрока > 0 (порядок между игроками, `Map+0xA64`/`+0xA68`). Файлы: `audit_player_order.py`, `player-order-results.json`.

## Что исполнено

Оригинальные инструкции без изменений: `4937C0`, ветка `4943C0` (вызов из `0x49386D`), счётный проход `48CA00` (`0x4937D0`), его счётчик `48CF50` (`0x48CA36`) и аксессор `488830` (`0x4943E8`, `0x48CA25`, `0x48CA6F`, а также `0x49389D` — другой цикл по игрокам в `4937C0`, который здесь не интерпретируется). Переиспользованы без правок `emulate_editor_variables_writer.build()` и `native_editor_variables_writer_cpu.run()`.

Добавлены только данные: массив указателей `0x17790000`, отдельный объект игрока `i` по `0x177A0000 + i*0x1000` и отдельный массив `{key,value}` по `0x177B0000 + i*0x1000`. Так два игрока не могут перекрываться. Остальные поля игрока (pool/availability) — нули; `Type77 count 110 = 0`; локальные/глобальные списки пусты.

## PC-доказательства (наблюдённые посещения, не только статический дизассемблер)

Пропуск нулевого value (writer): `0x494414` (`JZ 0x494437`) посещается на каждый элемент выбранных игроков — 3/2/2/2; `0x494434` (вызов sink) — только ненулевые 2/2/2/1; `0x494437`, `0x49443A`, `0x49443D` — все элементы 3/2/2/2. Счётчик: `0x48CF6F` (`JE`) — 3/2/2/2, `0x48CF71` (`INC EAX`) — 2/2/2/1, `0x48CF50` и `0x48CA36` — число выбранных игроков 1/2/2/1.

Порядок и индекс: `0x4943E5` (`PUSH EBP`), `0x494449` (`INC EBP`), `0x49444A`, `0x49444C` (`JB`) — по числу игроков 1/2/2/2. Аксессор: валидный путь `0x488843`/`0x488849`/`0x48884C` — 4×игроков (4/8/8/8), выход за границу `0x48883E` — 0. Четыре места вызова аксессора на игрока: `0x49389D`, `0x4943E8`, `0x48CA25`, `0x48CA6F`.

Сцена kind2→kind3: `0x494414` = 2, а не 3 (элемент kind2-игрока не посещён), `0x494434` = 1, `0x48CA36` = `0x48CF50` = 1, при этом `0x49444C` = 2 — обход продолжился к следующему игроку.

Границы доказательства индекса 1: неизменённый раннер отдаёт только счётчики PC и итоговую память, аргумент аксессора не трассируется. Поэтому индекс 1 подтверждается косвенно и ограниченно: четыре входа в валидный путь на игрока, число итераций цикла игроков, уникальные kind/key/value второго указателя и контрольная сцена с обратным порядком указателей. Отдельного трассирования значения аргумента нет.

## Хеши и проверки

- EXE закреплён; `source_exe_sha256` в каждом результате, `code_substitutions = 0`, запись в код/read-only запрещена раннером.
- `4943C0` (`0x4943C0..0x494464`): `643e727f1becbdbc312ba0a211efe463ce250f00184106d02d33e6ede27034fe` — совпадает с `bytes_sha256` из `phase199-editor-Variables-writer-primary.json`. `48CF50`: `e3bd419c984952ed6a0863d72cbf5e72e8ab7ba71503ce69d0f3ffd1e16ddf61`; `488830` (`0x488830..0x48884F`) и `48CA00` — в JSON (`source`).
- Хеши helper-файлов, включая принятый `variables-player-writer/audit_player_writer.py` (`c029ce36129d8bfa8f15d6708c3146ab3c6c4d284e4b28214cc35f008dcdaf3f`), и digest входного fixture каждой сцены — в `player-order-results.json`.
- Заголовок: сигнатура `0xE6`, версия 4, size = 56+16·count, тег `0xE7` по +12, count по +20, тег `0xE8` по +48, 16·count по +52. `META = (3+count, OUTPUT+size, 0)`; неиспользованный хвост `OUTPUT` — `0xA5`. Временные/датовые поля заголовка наследуются от оригинальных clock/text-вызовов и здесь не пересчитываются.
- `audit(write=False)` возвращает отчёт и ничего не пишет; `--no-write` — то же из CLI; при FAIL код возврата ненулевой (наблюдалось при промежуточной проверке).
