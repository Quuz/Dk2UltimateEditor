# KeeperSpells: реальные проверки перед применением заклинания

Этап 152, 31 октября 2026. Исследован точный `DKII-DX.exe` с SHA256
`d7a8b854e4e4f02709eba271bead6fe2307dd6e332b5a96e70857e5b0e19fb8a`.
Машинная схема: `keeper-validation-semantics.json`, компонент пакета
`keeper_validation_semantics`.

Теперь выполнены оригинальные проверки возможности применить заклинание,
которые в старых опытах с созданием Shot были явными заглушками. Это расширяет
подтверждённое использование полей `CastRule`, `TargetRule`, стоимости и
перезарядки. Назначение неизвестного `+0xC8` по-прежнему не установлено.

## Связь с файлом и оригинальным кодом

| Поле | В 406-байтной записи KWD | В 122-байтном определении игры |
|---|---:|---:|
| CastRule, BYTE | EF | 76 |
| TargetRule, BYTE | DA | 77 |
| ManaCost, DWORD | 11C | 58 |
| RechargeTime, DWORD | CC | 3E |
| Неизвестное C8, DWORD | C8 | 3A |

В каждом сценарии исполняются настоящие конструктор `4F7C70`, инициализатор
промежуточной записи `56B990`, конвертер `56BAB0` и загрузчик `4F7CE0`.
Далее настоящие `5174A0` и `517580` создают таблицы правил. Полная проверка
координаты — `4BB8A0`, полная проверка цели-существа — `4BBA40`.
Существование определения и поиск по ID проходят через оригинальную таблицу
виртуальных методов World и настоящие `50DE50`/`50DD60`.

`CastRule` выбирает одну из шести строк по 17 байт в таблице `6FCDD8`.
`TargetRule` выбирает одну из семи строк по 18 байт в `6FCE40`.
Сами callback-указатели записывает код инициализации; нули BSS в сохранённом EXE
не означают отсутствие обработчиков во время игры. Все указатели сверены
после настоящей инициализации.

## Местность: названия редактора не исчерпывают условия

Проверенные клетки имеют RoomID0. Владельцы в подготовленной сцене: игрок7,
другой игрок8; отношение к игроку8 переключалось в настоящей таблице отношений
игрока. Бит3 NAV-клетки задавался явно; оригинальный World сам его читает.

| CastRule | Подтверждённое поведение |
|---|---|
| 0, NONE | Нет callback; диспетчер возвращает0. |
| 1, OWN_LAND | Принимает свою **и союзную** землю. Несоюзную отклоняет. Есть отдельное исключение настроенного нейтрального владельца. |
| 2, OWN_AND_NEUTRAL_LAND | Использует тот же положительный тест отношения владельца; своя/союзная принимаются. Отдельной проверки «не нейтральный», как в режиме1, нет. |
| 3, ENEMY_LAND | Принимает несоюзного владельца, отклоняет своего/союзного. |
| 4, ANY_LAND | В проверенных сценах не зависит от отношения и владельца. |
| 5, ANYWHERE | Сам callback безусловно возвращает1; внешние проверки продолжают действовать. |

Для режимов1–4 оригинальный NAV-тест требует, чтобы бит3 был сброшен.
Режимы1–3 дополнительно содержат ветки для некоторых типов комнат; эти ветки
здесь не исполнялись. Не следует переносить результат RoomID0 на все комнаты.

Для режима2 название про нейтральную землю само по себе не доказывает результат:
он зависит от настоящей таблицы отношений игрока к её владельцу. Подготовленный
нейтральный Player и этот вариант отношения в новом наборе не исполнялись.

В исходных 1066 записях: CastRule1 — 639, CastRule2 — 1, CastRule4 — 171,
CastRule5 — 255. Единственный режим2 найден у **Heal ID10 в Secret1Globals.kld**.
Его точная исходная запись успешно прошла настоящий загрузчик и полную проверку
своего существа. CastRule3 проверен на диагностических копиях исходной записи.

## Цели и вселение

| TargetRule | Подтверждённое поведение |
|---|---|
| 0, NONE | Нет callback; возвращает0. |
| 1, OWN_CREATURES | В обычной ветке проверяет равенство владельца существу и игроку, а также отсутствие `IS_HORNY` (4000). |
| 2, ENEMY_CREATURES | Проверяет неравенство владельцев и исключает настроенного нейтрального. В этом callback нет проверки союза между игроками. |
| 3, ALL_CREATURES | Принимает своих и чужих существ, исключает настроенного нейтрального. |
| 4, LAND | Проверка координаты с ветками комнат. В выполненных RoomID0-сценах принимает точку. |
| 5, ALL | Callback возвращает1. Полный wrapper существа всё равно до этого проверяет существование тега и тип Actor0. |
| 6, POSESSION | Отдельные ограничения на возможность вселения, см. ниже. |

У TargetRule1 статически видны дополнительные ветки с владельцем переносчика
и комнаты. Они пока не исполнены. Формулировка про обычную ветку существенна.

Для настоящей исходной записи Possession, CastRule5/TargetRule6, подтверждено:

- обычное своё существо разрешено, чужое и настроенное нейтральное отклонены;
- `IS_HORNY` в определении существа запрещает вселение;
- runtime-флаги Actor `8000` или `8` по отдельности запрещают вселение;
- ненулевые WORD Actor `3CB` и `44B` по отдельности запрещают вселение;
- состояния ActorDWORD25E `D1`, `FF`, `100`, `101`, `C1`, `116`, `117`, `118`
  по отдельности запрещают вселение; контрольное обычное состояние17 разрешено;
- отсутствующий тег и Actor другого типа отклоняются полным wrapper до callback.

Это **runtime-смещения**, а не смещения в Creatures.kwd или Things.kld.
Новые смысловые названия неизвестным состояниям/WORD по одной этой проверке
не присвоены. Статически видимая специальная ветка объекта типа2 с ID9 здесь
не исполнялась: полный wrapper существа отвергает тип2 раньше.

## Два бита аргумента вызова

Третий аргумент полных функций проверки — отдельные флаги вызова. Связь этого
аргумента с сохранённым `KeeperSpells.Flags` по смещению DC здесь не установлена.

| Бит аргумента | Подтверждённое действие |
|---|---|
| 2 | Для CastRule2/3/4 требует runtime cellWORD8&2000. Режим1 этого дополнительного условия не требует. |
| 4 | Для TargetRule1 выбирает чужую/ненейтральную цель; для TargetRule2 вызывает проверку своей цели с удалённым битом4. |

Бит cell2000 пока не переименован в видимость/туман войны: проверено условие
на конкретный runtime-бит. Его связь с непрозрачным байтом карты не доказана.

## Мана, перезарядка и C8

Реальный `4C1740` проверяет стоимость0 отдельно, затем делает знаковое сравнение
стоимости с PlayerDWORD82. При исходной цене Sight5000 проверены отказ4999 и
успех5000. Не вводится новое правило нормализации всего DWORD стоимости.

Нулевой timestamp в состоянии заклинания обходит проверку перезарядки. При
ненулевом timestamp сравниваются текущий tick Session минус timestamp и
загруженный RechargeTime. При TPS20/raw4096 получено20 ticks: интервал10
отклонён, интервал20 разрешён. При timestamp0 диагностический rawFFFFFFFF
не препятствует проверке. Ранее установленное усечение low32 произведения
rawRecharge*TPS перед сдвигом12 сохраняется.

Сделаны 10 граничных сценариев C8 для Sight/Possession. Все82 принятые трассы
не содержат чтения runtimeDWORD3A..3D. Значения C8 проходят реальные загрузчики;
проверки доступа, стоимости и перезарядки читают другие поля.
**Это ограниченный отрицательный результат.** Другие состояния, функции,
сборки игры или DLL могут иметь потребителей C8; глобальное неиспользование
не доказано. Поле остаётся неизвестным и должно сохраняться побайтно.

## Доказательства и воспроизведение

82 сценария: 42 полных координатных проверки и40 полных проверок существа.
Два исходных файла дают четыре неизменённых примера записей: Sight, Possession,
Call to Arms и Heal Secret1. Остальные различия — явные диагностические копии
в памяти или подготовленное состояние сцены.

10 независимых CPU-прогонов Ghidra сравнивают260 областей, всего599450 байт,
с результатами первого эмулятора. Сверены32 диапазона оригинального кода,
1407 уникальных исполненных PC и2 блока данных. У `517800` в Ghidra остаётся
неполное однобайтное описание функции. Его ошибочный листинг не использован:
точка входа установлена настоящей записью callback, 12C байт отдельно считаны
из Ghidra, сверены с EXE и декодированы от этой точки. Два независимых прогона
Ghidra успешно исполняют соответствующие ветки. Сервер не перезапускался,
настройки разрешения Java-скриптов не менялись.

Подготовлены World/Player/Actor/NAV и одиночный массив определений. Выполняются
настоящие игровые функции, исходные инструкции и виртуальные таблицы не
заменяются. Единственный внешний адаптер возвращает дескриптор звука загрузчику;
графический провайдер NULL. Живая игра, фабрика нового Shot, применение урона,
нормальный World scheduler и все специальные ветки комнат здесь не исполнялись.

`validate_keeper_validation_api.py` делает246 точных правок CastRule/TargetRule
на копиях82 контейнеров с1066 записями. Проверены обратные правки, сохранение
C8/остальных байтов, полная пересборка контейнера и публичный decode→rebuild.
Значение255 сохраняется даже при отказе нативного диспетчера: неизвестное
значение в исходном файле не является основанием молча его переписывать.
Исходные310 файлов и7 EXE сохранены по SHA256.
