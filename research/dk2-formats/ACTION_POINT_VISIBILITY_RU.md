## Флаг10 раскрывает включительный прямоугольник

Путь из файла ранее установлен: FlagsWORD raw12 → runtimeBYTE32 с game mask3D. Панель редактора привязывает маску10 к Reveal Through Fog Of War. Теперь проверен настоящий игровой потребитель — фрагмент50C05D..50C170 в функции50B5B0.

Он берёт первый tag из worldWORD12, разыменовывает global6EE540, затем переходит по APWORD08. Это связанный список; AP ID37 не является индексом обхода. При worldBYTE7239 &40 весь проход пропускается. Назначение этого мирового флага отдельно не установлено.

Для каждой AP с runtime32 &10 нативный код перебирает **X от x0 до x1 включительно, Y от y0 до y1 включительно**, беря unsignedWORD координаты38/3A/3C/3E. Равные углы дают одну клетку, а не пустую область. Ограничения размером карты здесь нет: адрес клетки вычисляется по world width9E6 и base9EE. Безопасный диагностический API отклоняет упорядоченные области за картой; это ограничение API, а не оригинального кода.

Это16-байтовые **runtime tiles**, не физические4-байтовые клетки Map.kld. Бит2000 ниже нельзя записывать в raw флаг map-клетки.

## Что делает454B80 с клеткой

Полная функция454B80 выполнялась оригинальными инструкциями:

1. Если tileWORD08 уже имеет2000, ничего не меняет и не вызывает дальнейшие callbacks.
2. Иначе смотрит low12 tileWORD02 как room tag. Если у найденного room его definitionBYTE452 равен3,4 или8, передаёт обработку4E8B80. Эта вызываемая функция заменена fixture, поэтому реальное раскрытие всей комнаты не заявляется. Вызов возможен для каждой подходящей клетки, пока внешняя функция не изменила её состояние.
3. Для остальных клеток устанавливает WORD08 |=2000, сохраняя прочие биты. Формирует16-байтовое событие `(packedXY, 1, 0, 3)`, вызывает оригинальный forwarding helper517480 и затем update451C60(x,y).

Координаты события helper вычисляет от global6DA49C/base и6DA490/width. В проверенных fixtures они совпадают с world map. Совпадение этих globals во всех реальных состояниях игры отдельно не доказано.

После каждой подходящей AP world-фрагмент отправляет событие `(packedStartXY, packedWidthHeight, 0, 6)`. Width/height — low16(end-start+1). Этот вызов остаётся даже при обратной оси, когда перебор клеток пуст, и когда все клетки уже имеют2000.

Поэтому две перекрывающиеся области дают событие клетки только при первом переходе бита, но по одному событию области на каждую AP. Порядок cell events — построчно Y, затем X. Числа3/6 — проверенные коды структуры события; полный обработчик событий не анализировался в этом проходе.

## Tool Box: последняя подходящая точка

Полная функция510E20 обходит тот же owner-список. Начинает с результата0 и при каждой AP с runtime32 &20 заменяет результат на её ID37. Возвращается **последняя подходящая точка по runtime linked-list**, не первая и не обязательно последняя в файле. Более поздняя AP с ID0 заменяет прежний ненулевой результат на0. Порядок создания и размещение toolbox этим этапом не проверялись.

## Границы доказанного и проверки

`action-point-visibility-semantics.json` — компонент56 пакета; `native_action_point_visibility.py` — проекция runtime tiles/events и выбора ID. Физические C5 править через `native_action_points.patch_raw`, сохраняя полный FlagsWORD и остальные байты.

36 native cases:30 фрагментов world reveal с полной454B80/517480 и6 полных510E20. Проверены точки, строки/столбцы, прямоугольник, обратные оси, отдельные flags04/08/10/20/40, world gate, уже раскрытые клетки, перекрытие и повторение области, room types1/2/3/4/5/8/9, поздний toolbox ID0/255. Сравнивается весь16384-байтовый объединённый буфер: tile bytes, записи событий, renderer calls и room counter.

Это не исполнение всей50B5B0: начало до50C05D и конец после50C170 пропущены memory-only jumps. Session handler527150, update451C60 и room4E8B80 — явные fixtures. Реальный event forwarding517480 выполняется. Циклы списков/выход за карту не запускались; видимый результат рендера не наблюдался.
