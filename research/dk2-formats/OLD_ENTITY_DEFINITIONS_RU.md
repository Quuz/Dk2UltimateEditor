# Старый EXE: типы сущностей и указатели на определения, этап62

Уточнены адреса полей экземпляров Traps, Doors и Objects в предоставленном старом EXE. Найденные совпадения смещений проверены по native-классам, конструкторам, цепочкам создания и источникам указателей. Игровое назначение неизвестных `Traps +204` и `Objects +34C` не установлено.

Все смещения ниже шестнадцатеричные. Старый EXE определяется SHA-256 `93e826a142f677ef5120699feddb0572799d93399167ef1d05ec4b48a8b2a342`; текущий DX — `d7a8b854e4e4f02709eba271bead6fe2307dd6e332b5a96e70857e5b0e19fb8a`. Название папки `DKII 13` не удостоверяет розничную версию. Размеры и числа проверок в тексте — десятичные.

## Поля экземпляров различаются между EXE

| Семейство | Старый ID | Старый указатель definition | Текущий ID | Текущий указатель definition |
|---|---:|---:|---:|---:|
| Traps | `F5` | `F6` | `F6` | `F7` |
| Doors | `F5` | `F6` | `F6` | `F7` |
| Objects | `12B` | `12C` | `12C` | `12D` |

Это адреса **runtime-структур**, не смещения в KWD/KLD. Из таблицы нельзя выводить сдвиг всех остальных полей или переносить профиль на другой EXE.

В старом EXE `CTrap`, `CDoor`, `CObject` подтверждены native RTTI, locator, vtable и полными конструкторами. Отдельно сохранены фрагменты фабрики, которые передают один и тот же объект от соответствующего конструктора в initializer и записывают BYTE ID. Initializers запрашивают definition через world-vslots `160`, `138`, `188` и сохраняют возвращённый указатель в указанных полях. Общий helper переносит kind 3/4/2 в DWORD экземпляра `+12`.

Конструкторы, initializers и эти фрагменты проверены статически. Полный жизненный цикл создания с allocator и регистрацией в мире здесь не исполнялся. Текущие поля унаследованы из отдельно подтверждённых `structure-overlay-semantics.json` и `placed-object-semantics.json` с контрольными SHA файлов доказательств.

## Поиск в старых каталогах

Полностью исполнялись старые getters `502300` (Traps), `5020A0` (Doors), `502560` (Objects). Их массивы используют прежние размеры definition 209/181/285 байт и ID по `B4`/`AD`/`113` соответственно. Проверено 21 native-вызов на пустых таблицах, нулевом ID, разреженных ID, отсутствующей записи, повторном ID, старших битах аргумента и несортированном тестовом массиве.

Алгоритм берёт `key = argument & 255`, начинает с `min(key−1, count−1)` и идёт назад. Равный ID возвращает запись; меньший ID или исчерпание поиска возвращают null. В частности, ID0 не находится даже при физической записи0. Несортированный тестовый массив может скрыть существующий ID; это не доказательство несортированности обычных таблиц после вставки движком.

Порядок runtime-массива не требует менять физический порядок записей файла. Обычный codec продолжает сохранять исходную последовательность.

## Две отклонённые зацепки Traps +204

Старое чтение WORD `[ECX+97]` в `58ACC5` относится к ветке kind4 функции `58ACA0`, то есть к **Door Height**. Указатель `+F6` общий по смещению у двух разных классов. В ветке kind3 эта функция читает Trap Height из definition `+A0`, а не неизвестное `+98`.

Десять полных native-вызовов helper подтвердили формулы: Trap — unsigned Height WORD +512; Door — unsigned Height WORD +2048, дополнительно +2200 при ненулевом DWORD экземпляра `+10C`. Прибавка сохраняется в context `+14` и добавляется по модулю 2³² к двум Z по `+2D` и `+39`. Два одинаковых Trap-контекста при Height100 и разных unknown WORD `0000`/`FFFF` дали полностью одинаковый результат. Это доказательство конкретного потребителя; не всей графики, физики или неиспользования поля игрой.

Другая зацепка, `4ED876` в функции `4ED3B0`, получает WORD `+98` из отдельного конфигурационного буфера. Callback `512D00` копирует 158 байт с входного `+28` во временный стековый буфер и передаёт его через `4B22D0` объекту по owner `+1005`. Код включения того же объекта ставит owner BYTE `+FFE`, а независимый native-диагностический текст называет `+FFE` **ComputerPlayerOn**. Поэтому это путь конфигурации компьютерного игрока, а не подтверждённое чтение definition Traps. Название самого WORD конфигурации здесь не присваивается.

## Objects +34C и граница подтверждения

Полные старые converter `563920` и loader `494E80` статически подтверждают путь WORD `raw +34C → intermediate +3CC`, presence DWORD `+50`, затем `definition +106`. Это соответствует ранее найденной ширине хранения. Полный старый Objects loader в этом этапе не эмулировался. Подпись Mana Gen в интерфейсе оригинального редактора остаётся свидетельством интерфейса; активный игровой потребитель неизвестного WORD не установлен.

## Поиск с проверенными смещениями

Итоговый `phase62-old-typed-consumer-leads-v3.json` содержит 408 исходных точек и 5966 состояний анализа; ограничение количества состояний не достигнуто. Получено 10 зацепок: чтения известных ManaUsage/Health и пересечение Door Height с числовым смещением неизвестного Traps. Нового игрового назначения неизвестных полей этот проход не дал.

Версии v1/v2 сохранены как диагностика. Первая ошибочно использовала текущие поля `F7/12D` для старого EXE; вторая использовала правильные поля, но включала чтения аргументов через ESP. В v3 эти стековые чтения исключены. Только v3 входит в итоговое доказательство. Поиск по-прежнему не разрешает динамические индексы, все косвенные возвраты, произвольные указатели через аргументы или числовые границы циклов; глобальное отсутствие потребителей не доказано.

## Проверки и включение в пакет

31 native case исполняет четыре полные функции: три getters и helper `58ACA0`. Целиком сравниваются исходные массивы/контексты; оригинальные инструкции не подменяются. Финальные EAX/EBP отражают проверки наблюдателя, возврат getter проверяется отдельно. Сверены 19 полных функций и 16 отдельно помеченных диапазонов данных/фрагментов кода. Функция включения с дальним tail-jump не объявляется одним непрерывным полным телом только потому, что Ghidra присоединила целевой код.

Побайтовый round-trip выполнен для 84 файлов; 13 705 точечных пересборок проверили сохранность остальных байтов: 1293 Traps, 656 Doors, 11 756 Objects. Менялись только заранее выбранные поля в памяти; исходные игровые файлы и четыре EXE не изменены.

Схема `entity-definition-semantics.json` вложена в `trap-semantics.json.phase62_old_entity_definitions`; Doors и Objects ссылаются на неё с SHA-256. Пакет остаётся из 67 компонентов. API — `native_entity_definitions.py`, проверки — `audit_entity_definitions.py`, итоги — `phase62-validation.json`. Неизвестные игровые назначения остаются открытыми.
