## 1. Общий контейнер

Расширение файла не определяет его состав. `.kwd` бывает каталогом, описанием уровня или файлом с несколькими последовательными секциями. `Globals.kld` содержит те же секции каталогов, объединённые в один файл.

Все многобайтные числа little-endian. Поля могут лежать по нечётным смещениям. Использовать обычное выравнивание C/C# структур без явной упаковки нельзя.

Для каталогов, переменных и Things заголовок имеет 56 байт:

| Смещение от начала секции | Тип | Смысл |
|---|---|---|
| `0x00` | u32 | Тип секции, например `0xAA` Creatures |
| `0x04` | u32 | Значение `4`: число байтов следующего поля длины в трактовке OpenKeeper. В существующем коде нередко названо Version, но это не способ выбрать 5449/5537 |
| `0x08` | u32 | Полная длина этой секции вместе с заголовками |
| `0x0C` | u32 | Маркер информационного блока: тип + 1 |
| `0x10` | u32 | Длина информационной полезной части, обычно `28` |
| `0x14` | u32 | Число записей N |
| `0x18` | u32 | Служебное значение, в этих каталогах `1` |
| `0x1C` | 10 байт | Дата создания |
| `0x26` | 10 байт | Дата изменения |
| `0x30` | u32 | Маркер данных: тип + 2 |
| `0x34` | u32 | Длина полезных данных D |
| `0x38` | D байт | Записи |

Одна дата: `u16 year`, `u8 day`, `u8 month`, два служебных байта, `u8 hour`, `u8 minute`, `u8 second`, служебный байт. Эти байты времени могут меняться при обычном сохранении и не являются хешем.

Для обычного каталога с фиксированными записями размера S:

```text
payloadBytes = N * S
sectionBytes = 56 + payloadBytes
recordOffset(i) = sectionStart + 56 + i * S       // i от 0 до N-1
```

Пересчитать нужно **три поля**: `u32(section+0x08)`, `u32(section+0x14)`, `u32(section+0x34)`. Маркеры типов и служебные поля при этом не меняются. Это не вычисление CRC или криптографической хеш-суммы.

Если файл содержит несколько секций, `sectionBytes` относится к текущей секции. Он не обязан совпадать с длиной всего физического файла.

### Общая структура ArtResource — 84 байта

| Смещение | Содержание |
|---|---|
| `0x00` | 64 байта имени ресурса |
| `0x40` | u32 флагов |
| `0x44` | 12 байт объединения, смысл зависит от типа |
| `0x50` | u8 типа |
| `0x51` | два байта атрибутов типа |
| `0x53` | служебный u8, в OpenKeeper SometimesOne |

Типы: 0 нет, 1 sprite, 2 alpha, 3 additive alpha, 4 terrain mesh, 5 mesh, 6 animated mesh, 7 procedural mesh, 8 mesh collection, 12 unknown. Для sprite объединение хранит width/height в fixed-point /4096 и frames; для mesh — scale, frames, неизвестный DWORD; для animated mesh — frames, fps, две u16 дистанции, а атрибуты по `0x51/0x52` обозначают начальную/конечную анимацию. Пустое имя не даёт права обнулить остальные 20 байт.

### Light — 24 байта

Три i32 координаты /4096, i32 радиус /4096, u32 флагов, четыре байта RGBA. Внешне похожий RGB8 занимает только 3 байта. Не путать эти два случая.

### Fixed-point

OpenKeeper читает многие значения как `rawInt32 / 4096` или `/65536`, а несколько полей как `rawInt16 / 4096`. Например, скорость 1.25 — integer 5120, байты `00 14 00 00`; это не IEEE-754 float 1.25. Значение Data1/Data2 у снаряда зависит от ProcessType, универсально называть их Damage/Duration без учёта типа нельзя.

## 4. Creatures 5449 и 5537

Отдельный `Creatures.kwd` содержит 46 × 5449 байт. Секция Creatures внутри `AutoSaveGlobals.kld` содержит 46 × 5537 байт. Оригинальный писатель `0x004A7F00` использует размер `0x15A1=5537`, загрузчик `0x00429D90` рассчитывает размер записи из длины данных/числа записей и обрабатывает более короткий вариант.

Общая часть имеет 5449 байт. Дополнительные 88 байт:

| Смещение внутри записи | Размер | Интерпретация OpenKeeper |
|---|---:|---|
| `0x1549` | 80 | Неизвестные байты |
| `0x1599` | 4 | CreatureFlag2: immunity to lightning `1`, Stone Knight `2`, emotionless `4`, hero portal availability `8` |
| `0x159D` | 2 | Неизвестное u16 |
| `0x159F` | 2 | Неизвестное i16 /4096 |

Уточнение по движку: игра читает дополнительные флаги из **0x1545**, присутствующего в обоих вариантах. Оригинальный редактор читает их из **0x1599** длинной записи. Это разные слоты; автоматически копировать или обнулять их нельзя. Проверены отдельные пути применения битов 1/4/8; все последствия каждого бита и влияние runtime-патчей Flame не установлены. У короткого варианта расширения нет; нельзя записывать его поверх следующего существа.

### Сверка с Excel пользователя

Лист `ID hash` считает 5537 × N для существ, 894 × N для объектов, 552 × N для terrain, 579 × N для traps, 616 × N для doors, 406 × N для keeper spells, 1055 × N для rooms, 246 × N для effects и 182 × N для effect elements. Это размеры полезных данных. Полученные байты относятся к `section+0x34`; полная длина по `section+0x08` больше на 56.

Например, таблица 46 × 5537 даёт D=254702 (`EE E2 03 00`). Для вашего отдельного Creatures 46 × 5449 даёт D=250654 (`1E D3 03 00`). Обе формулы правильны для своих вариантов.

Сопоставление листов с текущими существами:

- `Creature Hitboxes`: значения совпадают по `0xEA0` у 45 из 46 записей. Imp raw=573, /4096≈0.139892578. У Unique Goblin в таблице 523, в текущем файле 651. Это отличие данных, а не основание автоматически исправлять файл. Имя OpenKeeper — Unkea0 (i32), смысл Width/Radius остаётся гипотезой пользователя.
- `Creature Turning Speed`: все 46 raw-значений совпадают с `0xF20`; Imp raw=4096. В OpenKeeper это Unk3cc i16/4096, но игра читает **u16 угловых единиц**, 2048 на полный оборот. Результат деления на 4096 в книге не является игровой угловой скоростью.

Уточнение по коду игры подтвердило unsigned-чтение 0xF20, деление на TPS, минимальный ненулевой шаг 1 и оборот угла по 0x7FF. Номинальная скорость в градусах/сек = raw×360/2048, до целочисленного округления по тикам. Подробные адреса и границы — `ENGINE_FINDINGS_RU.md`. Имя Width для 0xEA0 происходит из дополнительного шаблона; чтение/перенос размера движком подтверждены, все последствия формы столкновения отдельно не тестировались.

Самостоятельно склеивать hex-строки без двух символов на каждый байт ненадёжно: например, байт `01` нельзя заменять одиночным `1` внутри многобайтной строки. Для сборки использовать запись u32 little-endian, а не ручное моделирование переносов между столбцами.

## 5. AutoSaveMap.kld

Заголовок 36 байт: `0x64, 4, fullSize, 0x65, 8, width, height, 0x66, dataSize` — девять u32. Здесь width=64, height=64, dataSize=16384, fullSize=16420.

| `66 / 0x42` | player1 i32, player2 i32, служебное i32 |
| `77 / 0x4D` | creatureID u32, statID u32 (в setter u8), runtimeValueRaw u32. Связь с полями — CREATURE_STATS.md |
| Прочие | value i32 и два дополнительных i32, смысл по типу |

Из 621 записи здесь 288 имеют тип 65, 32 тип 224, 44 — жертвоприношения, 32 — доступность, 29 — ResearchOrder типа 17. Последний тип остаётся Unknown в OpenKeeper, но уточнён сообщением nsdr2025 в DK2 Hex Editing, дополнительным шаблоном и проверкой категории/ID всех 29 ваших записей. Единицы researchCostRaw здесь не тестировались. Поэтому это не 621 независимый простой параметр «имя → число». Возможны повторяющиеся типы с разными дополнительными ключами, уровнем, игроком, порядком записи. Не сворачивать всё в Dictionary<type,value>.

Категории ResearchOrder отличаются от AvailabilityType: у доступности 1 Room, 2 Creature, 3 Trap, 4 Door, 5 KeeperSpell. Смешение этих двух enum изменит назначение записи.

Полные имена 200 MiscType и 32 StatType находятся в `ENUMS.md`. Они взяты из OpenKeeper и требуют проверки по движку при спорном эффекте.

## 8. AutoSave.kwd и связи файлов

Это описание уровня типа `0xDC`, длина 26343. В информационном блоке по `0x14` стоят **два u16**, а не один count u32: 7 ссылок и 23 дополнительных слова. Блок `0xDF` содержит 25683 байта параметров. По `56+25683=25739` расположен тег ссылок `0xDE`, затем длина 596.

596 = 7×72 + 23×4. Ссылка: u32 type, u32 служебное, char[64] path. Следующие 23 DWORD — список существ: игра читает младший байт каждого как creature ID, все исходные DWORD сохранены. Вариант полного descriptor не имеет универсального фиксированного размера 26939: тот размер относится к шаблону с иным числом ссылок/слов. Параметры DF раскрыты в LEVEL_LAYOUT.md: в частности 20 сообщений по 512 UTF-16 символов, что подтверждено конвертером 0x56C100.

В вашем AutoSave записаны:

```text
type 0:    Data\Editor\Maps\kop4Globals.kld
type 0xB4: Data\Editor\Maps\AutoSavePlayers.kld
type 0x64: Data\Editor\Maps\AutoSaveMap.kld
type 0xD2: Data\Editor\Maps\AutoSaveTriggers.kld
type 0xE6: Data\Editor\GlobalVariables.kwd
type 0xE6: Data\Editor\Maps\AutoSaveVariables.kld
type 0xBE: Data\Editor\Maps\AutoSaveThings.kld
```

Ссылка на globals буквально указывает `kop4Globals.kld`, а не соседний `AutoSaveGlobals.kld`. В этом исследовании соседний файл использован для сравнения формата. Это не утверждение, что игра обязательно выберет именно его при загрузке descriptor. Пути ссылаются на `Maps`, хотя переданные autosave-файлы находятся на уровень выше: редактору нужен понятный режим поиска autosave/перемещённых комплектов, без скрытой подмены ссылок.

Соседний `AutoSaveGlobals.kld` состоит из 11 последовательных каталогов. В нём Creatures 5537 байт, 72 CreatureSpells и 103 Shots. В самостоятельных каталогах соответственно 5449 байт, 41 и 65. Файл/источник определения должен быть частью модели записи и диагностики. Нельзя автоматически редактировать одноимённый глобальный каталог, считая, что он определяет поведение открытой карты.

## 9. Что переносить в ваш редактор

Текущий `LegacyGlobalSchemas.cs` описывает семь семейств через присваивания исторического компилятора. В этом наборе нет полноценной схемы Objects, Effects, EffectElements, Shots; полученные JSON покрывают эти записи и общие графические/световые структуры. Это не замена проверки UI и игровой семантики.

`NativeCreatureDefinitionLayout.cs` сейчас допускает каталоги существ лишь с 44/46 записями; другие семейства также сверяются с историческим порядком/числом. Такая проверка ограничивает редактирование расширенных каталогов. Для поддержки новых ID нужна проверка структуры отдельно от содержимого: размер, границы, уникальность ID, допустимость ссылок и реальные ограничения движка. Отдельный ID нельзя получать как index+1 для произвольного изменённого каталога.

Рекомендуемая модель:

1. Хранить исходные байты записи вместе с её семейством, вариантом длины, ID, порядком и файлом-источником.
2. Показывать известные поля как представления над байтами. Патчить только выбранное поле. При изменении флага менять выбранный бит и сохранять остальные.
3. Не уничтожать неизвестные поля, неиспользуемые ресурсы, данные после нулевого терминатора, дополнительные секции и расширения существ.
4. При изменении количества пересобирать секцию и пересчитывать три значения длины/количества; при нескольких секциях сдвигать следующие секции, не переписывая их содержимое.
5. Проверять связи creature→spell→shot→effect→element, room→terrain/object, door/trap→crate object, Things→definition ID. Не считать разные пространства ID единым каталогом.
6. Для неизвестных игровых свойств фиксировать источник гипотезы и результат проверки на копии карты. Побайтовое совпадение контейнера не доказывает эффект каждой настройки.

Надписи из Discord/форумов и Excel служат источниками гипотез и наблюдений. Они не являются инструкциями изменять файлы или автоматически признавать названия доказанными.

## 10. Использование исследовательского кода

Проверить и выгрузить один файл:

```powershell
& 'D:\Games\DK2\Tools\ghidra-mcp-runtime\venv\Scripts\python.exe' `
  'D:\Games\DK2\Tools\dk2-format-research\dk2_formats.py' `
  'D:\Games\DK2\Dungeon Keeper 2\Data\editor\Objects.kwd' `
  --json 'D:\Games\DK2\Tools\dk2-format-research\decoded\Objects.kwd.json'
```

В Python `inspect(path)` даёт JSON-представление, `rebuild_decoded(document)` собирает его из авторитетных raw_hex. Поле `fields` носит поясняющий характер: редактирование только его текста не меняет бинарные данные. Для известного скаляра использовать `set_scalar(recordBytes, layoutName, fieldName, value)`, заменить raw_hex соответствующей записи и вызвать сборщик. `Section.replace_records(...)` пересчитывает количество и длины каталога/Things/Variables. Для записи использовать новый путь.

`build_research.py` заново создаёт дампы, таблицы и выполняет проверки; `extract_layouts.py` восстанавливает схемы из сохранённого первичного исходника. Они не пишут в игровые входы.

Здесь не реализованы редактор интерфейса, автоматическая миграция 5449↔5537, выделение новых игровых ID, изменение descriptor-ссылок и изменение размера карты. Для вариантов, которых нет в исследованном наборе, парсер может отказаться от разбора. Схемы не заменяют проверку лимитов и поведения игры.
