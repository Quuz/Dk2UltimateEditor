# Пол геройского аванпоста

14 ноября 2026. Дополнение к Terrain35, не меняющее физическую схему KWD.

**Static:** в DKII-DX.exe строка `hero_outpost_floor` находится по69FF24, ссылка —4C28C7 в4C2880. Функция сначала очищает пять слотов через vslot2B0, затем при разрешении по существующей таблице загружает `hero_outpost_floor0..4` через ресурсный сервис с type4 и сохраняет результат в эти слоты. Суффикса владельца в этой функции нет. Это отдельная загрузка, а не имя из пустого CompleteResource записи Terrain35.

**Seen (данные):** штатная Terrain35 (`Hero Lair`) содержит пустой CompleteResource, флаги OWNABLE и CONSTRUCTION_TYPE_QUAD. В Meshes.WAD существуют все пять KMF: части0..3 используют Hero_Outpost, часть4 —Hero_Outpost_64. Поэтому отсутствие CompleteResource не доказывает отсутствие игровой модели.

**Editor verified:** добавлена резервная привязка для Terrain35 с пустым именем — `hero_outpost_floor`, без owner-суффикса. Непустые пользовательские определения сохраняют прежний путь. Используется имеющаяся сборка четырёх четвертей по соседям. Smoke `--hero-floor-only <копия KWD> <папка игры> <папка PNG>` проверяет5×5 двух владельцев, изолированную клетку, обе текстуры, Paint/Undo и побайтовую сохранность исходного документа. Источник: tests/DK2MapEditor.WindowsSmoke/NativeLightingSmoke.cs. Утверждение относится к рендеру редактора.

**Unknown/unverified:** полная естественная цепочка выбора объекта аванпоста в работающей игре и визуальная сверка той же сцены с игрой не исполнялись. Привязка функции к типу аванпоста дополнительно согласуется с локальным SingleQuadConstructor OpenKeeper; сторонний код — ориентир, не доказательство исполнения игры. Исследование не назначает новое физическое поле и не меняет байты KWD; новые raw-пересборки неприменимы.

Профиль EXE и хеши первичных файлов приведены в semantics.json/manifest.json. Первичные инструкции и декомпиляция сохранены рядом. Замороженный основной пакет форматов не изменён.
