## Что исполнялось

Цепочка исходных функций: `56CBD0 → 5716E0 → 521790 → 51DB30 → 50F7E0`, затем `5133A0 → 4F1600 → 4F1660 → 4F1780`. Для золота вызываются `4BA420 → 4B7A90`, для обычного объекта — `4B7A90`. Конструктор, initializer, выделение памяти и регистрация созданного Object выполняются исходным кодом.

В двух сценариях прочитана полная первая секция исходного GlobalVariables.kwd: **621 запись**, включая **44 рецепта** и остальные типы Variables. Её 9992 байта совпадают с исходником. Второй вариант — первая секция копии после добавления рецепта: **622 записи**, 10008 байт. В этих сценах исполнены все callbacks секции, не только type43.

Остальные14 сценариев используют секцию, содержащую44 неизменённых исходных рецепта и диагностические добавления. Приём исходных bytes происходит через настоящие MyFile/Disc/stream и игровой parser; чтение Win32 обслуживает явный файловый провайдер в памяти. Следующая секция0xBE и загрузка всего уровня в эти запуски не входят.

| Сценарий | Наблюдаемый результат |

Последние два пункта уже имели отдельное подтверждение в этапе89; здесь они подтверждены внутри полной файловой композиции. Это не новые общие правила экономического баланса. Сокровищницы с реальным содержимым не исполнены.

Владельцы намеренно различаются: комната принадлежит8, глобальный Object-owner равен7. Созданный объект принадлежит7; прямое зачисление при нулевой координате меняет `owner8+7E`. Универсальное правило «вся награда принадлежит хозяину храма» такой результат не подтверждает.

Для комнаты задан конечный список из двух клеток: место жертвы и доступное место награды. Родной `4E4D90` выбирает позицию; factory получает центр выбранной клетки и устанавливает z1000. Это подготовленный runtime-контекст, а не построение комнаты из KLD.

## Как собрать файл

Рецепт занимает16 байт. Для копии исходного файла добавление одной записи даёт:

| Поле | Смещение | Было | Стало |
|---|---:|---:|---:|
| Размер секции S | 8 | 9992 | 10008 |
| Число всех Variables-записей N | 20 | 621 | 622 |
| Размер данных D | 52 | 9936 | 9952 |

Запись вставляется после старого тела секции; следующая секция сдвигается на16 байт и сохраняется полностью. Проверены отдельные вставки gold5000 и Object17, точное совпадение с независимой вставкой, parse→pack и обратное удаление до исходного файла. Никакой дополнительный CRC или криптографический хеш не вводится. N считает все записи, не только рецепты.

Исходные44 рецепта содержат ингредиенты Creature. Диагностические Spell9→gold/Object не выдаются за штатные рецепты или за доступные опции оригинального GUI.
