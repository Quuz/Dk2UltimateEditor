# Effects: генерация в четырёх соседних позициях

Этап 158, 31 октября 2026. Профиль `DKII-DX.exe`, SHA-256
`d7a8b854e4e4f02709eba271bead6fe2307dd6e332b5a96e70857e5b0e19fb8a`.

Подтверждён оригинальным кодом `GenerationType=2`, обработчик `4376E0`.
Справочное имя — ADJACENT_EXPLOSION; native-название не установлено.
Правила относятся к генерации дочерних Effects/EffectElements.

**В 30 207 исходных записях Effects из 82 контейнеров режима 2 нет.**
Поэтому выполненные сцены — диагностические копии исходного ID1 с явно
изменёнными полями, а не воспроизведение исходной карты с этим режимом.

## Подтверждённые правила

Родитель — подготовленный экземпляр CEffect. Его определение и определения
детей загружаются настоящими initializer/converter/loader. При положительном
времени жизни родителя проверяются четыре центра в следующем порядке:

```text
[X,        Y + 4096, Z]
[X,        Y - 4096, Z]
[X + 4096, Y,        Z]
[X - 4096, Y,        Z]
```

Координаты Q12: 4096 единиц равны одной клетке. Каждая позиция проходит
оригинальную проверку `447A70`. В принятых положительных сценах все четыре
разрешены явно подготовленными внешними ответами engine.

Радиусы, высота и разброс родителя в этих сценах равны нулю, поэтому дети
создаются точно в указанных позициях, с прежним Z. Изменение координат при
ненулевых диапазонах и арифметические крайние значения здесь не проверены.

N — unsigned BYTE `ElementsPerTurn`, raw `F3` → definition `8A`.
**На каждую разрешённую соседнюю позицию приходится N партий.** При обычном
выборе каждая партия обходит все восемь физических GenerateIds в порядке
`7,6,5,4,3,2,1,0`. Нулевые ID пропускаются, повторения сохраняются.

Для обычного выбора число запросов:

```text
разрешённые позиции × N × число ненулевых слотов
```

Это число запросов. Отказы CBridge/аллокатора и цепочки NextEffectId
отдельно определяют число созданных экземпляров. При N=0 соседние позиции
проверяются, но запросов создания нет. Неположительное время жизни
пропускает соседнюю генерацию.

## Выбор каталога и настройки

| Настройка | Подтверждённое поведение режима 2 |
|---|---|
| Флаг `40h` | Выбирает создание Effects |
| Флаг `40h` снят | Создаются EffectElements, в том числе при снятом `80h` |
| Оба `40h/80h` | Создаются Effects |
| `4000h`, коэффициент `69752C` = 50/255 | В проверенных ветках не масштабирует N |
| `400h` | Вызывает native-подбор `435E30`; проверены восемь одинаковых ID1 |

Два полных опыта с `4000h`, N=2 и коэффициентами 50/255 дали одинаковые
результаты во всех подготовленных областях, кроме самого входного байта
коэффициента. Ни одного чтения, перекрывающего этот байт, в 16 путях нет.
Формула адаптивного количества из режима 4 на режим 2 не переносится.

Общий закон случайного распределения по разным ID/нулевым слотам в новом
этапе не устанавливается. Контроль с восемью ID1 подтверждает прохождение
случайной ветви и один запрос ID1 на партию в этом частном случае.

## Настоящие фабрики и цепочки

Effects создаются через исходную CBridge vtable:
`43A8E0 → 440420 → 440350`, с настоящими конструкторами и регистрацией.
Для EffectElements исполняется `4352E0 → 435E70/435F20`.

В дочерних исходных определениях сохранены NextEffectId `1→143` и `2→221`.
Поэтому четыре запроса ID1 создают восемь Effects. Слоты
`[1,0,3,0,0,0,0,4]` дают на каждую позицию запросы `4,3,1`, а создание
идёт `4,3,1,143`. Порядок глобального списка обратный порядку создания,
поскольку каждый новый экземпляр вставляется в голову.

| Сцена | Запросы CBridge Effects | Входы в `440350` | Создано Effects |
|---|---:|---:|---:|
| Один ID1, N=1 | 4 | 4 | 8 |
| Один ID1, N=2 | 8 | 8 | 16 |
| ID1 только в восьмом слоте | 4 | 4 | 8 |
| Слоты `4,3,1`, N=1 | 12 | 12 | 16 |
| Tile flags = 0 | 4 | 0 | 0 |
| Пул 1080 байт | 4 | 4 | 3 |

В сцене tile flags=0 проверка `447A70` всё ещё разрешает позиции при
заданных внешних ответах. Четыре запроса достигают `440420`, который
отказывает **до** `440350`. Этот отказ нельзя считать отсутствием запросов
генератора или отказом предыдущей проверки соседней позиции.

В пуле 1080 байт помещаются `1,143,1`. Свободных байтов остаётся ноль;
ранее созданные экземпляры сохраняются. Проверены действительные списки
used/free, полное покрытие арены, защитные байты и отсутствие отката.

В двух отдельных сценах без `40h` загружен настоящий Element294:
с флагами 0 и `80h` создано по четыре EffectElements.

У созданного Element подтверждены отдельные runtime-поля:

| Поле | Смещение |
|---|---:|
| ElementId WORD | `101h` |
| Definition pointer DWORD | `103h` |
| OwnerTag WORD | `107h` |
| ParentTag WORD | `111h` |
| XYZ, три signed DWORD | `D6h` |
| Собственный tag WORD | `F2h` |

В стенде OwnerTag=7, ParentTag=2. `4352E0` передаёт оба значения из
разных полей родителя, `435F20` сохраняет их раздельно. Это смещения
экземпляра в памяти, не новые смещения KWD.

## Что осталось неизвестным в EE/F0

Два WORD сохраняются по пути raw `EE/F0` → intermediate `1A2/1A4` →
definition `4B/4D`. В 16 новых полных путях они не читаются из определения.
Две пары меняют их у родителя и у всех шести дочерних определений:
различаются только соответствующие raw/MID/definition-копии. Дети, PRNG,
арена, списки и прочая подготовленная память совпадают.

**Игровое назначение EE/F0 остаётся неизвестным.** Сохранять исходные
значения; отсутствие чтений здесь не доказывает неиспользование во всей игре.

## Улучшение поиска указателей

Новый анализатор сохраняет числовые локальные переменные на стеке и
учитывает подтверждённую очистку аргументов при возврате. Для 52 функций
использованы полные ранее сверенные Ghidra-листинги и оригинальные байты RET.
Шесть косвенных мест вызова связаны с исходными vtable в пределах принятых
стендов. Для неизвестного вызова знания сбрасываются консервативно.

Автоматически исключены шесть ложных Misc-цепочек и три ложных чтения
GenerateRandomness за границей массива. Восстановлено настоящее чтение
флагов `4378C2`: native CPU подтвердил 60 обращений к definition `+5F`.

Поиск: 54 начальные подсказки, 12 204 состояния, 20 контекстов вызовов.
Семь начальных путей и один контекст ограничены. Новые сохранённые указатели
позволили исследовать больше путей; число ограничений не означает уменьшение
области поиска. Общая ABI-корректность всех косвенных вызовов не утверждается.
