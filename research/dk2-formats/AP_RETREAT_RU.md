# Hero Lair в выборе точки отступления: этап64

Подтверждён новый игровой потребитель флага ActionPoint **Hero Lair, маска01** в exact `DKII-DX.exe` SHA256 `d7a8b854e4e4f02709eba271bead6fe2307dd6e332b5a96e70857e5b0e19fb8a`. Выполнены23 полных вызова `4611D0` и настоящий getter времени `517490`. В native diagnostic path присутствует `FightWithDrawState.cpp`; source code игры не использовался.

Это дополнение к ранее проверенным геометрии/загрузке C5, patrol, visibility, toolbox и TriggerGeneric predicates. Назначения **AP04/08 в целом остаются открытыми**. Сама подпись RC3 Hero Gate для08 по-прежнему является доказательством интерфейса редактора, а не полного игрового механизма.

## Что делает исследованная ветка

Полный `4611D0` имеет несколько путей. Здесь проверена ветка, в которой WORD владельца creature+28 совпадает с globalWORD6F254C. В предоставленной карте символов последний назван `g_goodPlayerId`; native-сравнение не зависит от доверия к этому имени. Дополнительно требуется creatureBYTE46F bit10.

1. Из worldWORD12 берётся head списка ActionPoint. Указатели разрешаются через global tag table6EE540, next — APWORD08. Это тот же тип списка, который независимо подтверждён AP creator, reveal и toolbox consumer.
2. Кандидатом становится только точка с APBYTE32 bit01. Флаги04/08 не заменяют01.
3. Целевая позиция: `X=(unsignedWORDstartX38<<12)+2048`, `Y=(unsignedWORDstartY3A<<12)+2048`, Z=0. Это центр **начальной** клетки. EndX/EndY, WaitDelay, NextWaypointId, TriggerId и ID не выбирают положение в этой ветке.
4. Для каждой подходящей точки вызывается4D0E60 с creature, адресом позиции и аргументом0. **Первая** точка с ненулевым результатом выигрывает. Это не поиск ближайшей и не последняя точка списка. Реальный расчёт доступности задан внешним fixture, поэтому полный navigator не объявлен выполненным.
5. Затем проверяется состояние через478050. Если возвращается не16hex, делается запрос476D30(C7,0); отказ прекращает продолжение. При успехе движение запрашивается через471890 к выбранной позиции с10A/E8, а после отказа —10A/68. Два отказа возвращают0.
6. При удачном запросе вызываются4887D0(creature,1,0) и audio virtual20. Native-код сохраняет возвращённый sound handle в creatureDWORD2E. Само движение, изменение state и проигрывание звука заменены явно заданными поставщиками и не симулируются как настоящая игра.

Порядок **runtime списка** не объявляется равным физическому порядку записей файла. Циклы списка не исполнялись; исследовательская проекция отвергает цикл, не приписывая это поведение native-коду.

## Отдельная особенность сохранённого состояния существа

После успешного продолжения, если CreatureIdBYTE36F!=1, код пишет в52A и52C **одно и то же** `low16(signedentityX1A>>12)`. Второй source load46180B тоже использует+1A, а не+1E. Затем настоящий517490 читает clock через world+4→clock+4 и записывает52E.

Проверены разные X/Y, отрицательный X и CreatureId1, который пропускает эти записи. Установлены инструкции и байты состояния; намеренность, роль52A/52C и видимые последствия не доказаны. Это не основание объявлять ошибку редактора или менять координаты в исходных KWD/KLD.

## Исправление инструмента статического поиска

На этом этапе обнаружен конкретный пробел: **Capstone5.0.7** для некоторых `TEST memory,register` возвращает memory operand `access=0`. Прежнее условие `access & CS_AC_READ` пропускало такие чтения. Примеры: DX510E36 `test byte ptr [ecx+32],dl` и old423645 `test dword ptr [ebp+686],edx`.

Новый `native_memory_access.py` учитывает явные чтения TEST/CMP, отдельно исключая LEA и косвенные CALL/JMP из поиска data fields. Семь настоящих инструкций сверены с PE и Ghidra; есть положительные и отрицательные примеры. Полнота всех метаданных всех x86-инструкций не заявляется.

Перезапущены четыре указанных прохода; результаты и hashes — `memory-read-policy.json`:

| Проход | Результат после исправления |
|---|---|
| Old Creature, передача ECX/stack arguments | 822 корня,14506 состояний,356 чтений контрольных полей вместо335. Добавились21 TEST флагов; AbilityJump/PickUpPriority purpose не установлен |
| Old Trap/Object pointers | 408 корней,5966 состояний,10 кандидатов; список не изменился. Единственное пересечение204 остаётся Door Height из этап62 |
| Keeper alias CFG | 45 корней,838 состояний,0 чтений C8,9 передач указателей; purpose не установлен |
| DX AP getter/tag-table pointers | 2623 корня,135454 состояний,274 кандидата вместо272. Восстановились два пути к уже независимо native-проверенному Toolbox TEST20 |

У последнего прохода **8 корней и28 контекстов callees достигли ограничений**. Global tag-table/vslot корни сами по себе нетипизированные: численное совпадение32 не доказывает ActionPoint. Статическая идентичность и полное native-исполнение нового Hero Lair consumer проверены отдельно. Старые snapshot-поиски остаются историческими; нельзя объявлять исправленными все прежние сканеры автоматически.

Предыдущие результаты native-эмуляций не зависели от metadata access и не отменяются этим дефектом. Однако любые прежние формулировки «не найдено чтений» нужно понимать с дополнительным ограничением инструмента. Отсутствие найденного потребителя никогда не было доказательством глобального неиспользования.

Дополнительно проверены396 совпадений предполагаемых WORD/DWORD смещений в initialized non-executable data двух exact EXE. DWORD75C/6EB не обнаружены; единственное WORD75C находится внутри значения размером указателя. Отдельный неизвестный purpose из этих совпадений не назначен. Runtime-built, byte-encoded и embedded-in-text tables этим проходом не исключены.

## Воспроизводимость и сохранность файлов

Полные функции4611D0 (1654 байта) и517490 (7 байт) сверены с исходным PE. Семь отдельных калибровочных инструкций и source path перечислены **как фрагменты/данные**, не как дополнительно исполненные полные функции. Native-код двух выполняемых функций в эмуляторе не подменён.

В23 сценариях сравниваются все16 байт controller,1536 creature,32 world,16 clock,2304 definition, все64-байтные AP узлы и512 байт наблюдений. Native return0/1 сохраняется до сравнительного наблюдателя. Поставщики навигации, состояния, движения, post-success update и audio — local EmulatorHelper fixtures, их реальные побочные эффекты за рамками доказанного.

106 источников содержат3501 ActionPoint;46 имеют raw bit01. Используется сохранённый snapshot AutoSaveThings этап47, поэтому число отличается от исторического3429 в этапе45; исходный файл не откатывался. Смена каждого из01/04/08 проверена во всех3501 записях: **10503 точечные пересборки всего контейнера в памяти**, без изменения остальных байтов. Все четыре исходных EXE неизменны.

Машинная схема `ap-retreat-semantics.json` полностью вложена в `action-point-semantics.json.phase64_retreat`; пакет остаётся67 компонентов. Search-review SHA-ссылка добавлена в unresolved-field-traces и creature-version-layout schemas. Скрипты: `emulate_ap_retreat.py`, `prepare_ap_retreat_primary.py`, `build_ap_retreat_semantics.py`, `audit_ap_retreat.py`, `audit_memory_read_policy.py`. Счётчики — `phase64-validation.json`. Общая цель и оставшиеся unknown gameplay fields остаются открытыми.
