# Objects34C: индексированные чтения и восстановленные переходы

Обновление этапа100: шесть оставшихся неиндексированных anchored-кандидатов разобраны и отвергнуты по настоящим границам инструкций; пять switch arms восстановлены. См. `UNKNOWN_BOUNDARIES_RU.md`. Другие кандидаты и общее назначение Objects34C остаются открытыми.

Этап70, 27 октября2026. Проверено происхождение новых кандидатов в предоставленном старом EXE SHA93e826a142f677ef5120699feddb0572799d93399167ef1d05ec4b48a8b2a342. Название папки `DKII13` не удостоверяет розничную версию. Никакого нового имени игрового эффекта Objects34C не присвоено.

Физический путь остаётся прежним: WORD raw34C → intermediate3CC → definition106. Родной редактор связывает его со скрытым контролом «Mana Gen». Это подпись интерфейса и перенос данных, не доказательство генерации маны в игре. Исходные два байта сохраняются независимо от знания назначения.

## Что изменено в поиске

Исторический проход этапа61 исключал индексированные memory operands. Новый проход использует общую исправленную политику чтения TEST/CMP, включает индексы и декодирование вокруг displacement-байтов. Исторический JSON не переписывается.

Из780881 декодированной инструкции получено146 кандидатов пересечения WORD106, включая стек и ложные начала. Относительно прежнего набора есть24 новых адреса:17 индексированных WORD и7 прочих anchored-кандидатов. Это не146 потребителей Objects: происхождение указателя и граница каждой инструкции требуют отдельной проверки. В данном наборе новые адреса появились от индексов/anchored-декодирования; включение исправленного read policy само по себе не означает нахождения новой настройки.

## Куда указывают17 новых WORD-чтений

Они читают signed WORD по адресу `table +105 +2*index`. Базовый указатель происходит из globalDWORD6CF048. В проверенном инициализаторе он получает **фиксированный адрес6DD5D8** по4FE595. Предшествующий цикл заполняет9-WORD строки значением100; при сбросе global pointer очищается по4FEDFA.

В контекстах чтения используются byte402 уровня и WORD698 определения существа. Здесь важен подтверждённый отдельный источник таблицы: он не получается из указателя на определение Objects. Из числового пересечения105/106 нельзя делать вывод о Mana Gen. Назначение каждой строки таблицы и полные игровые последствия всех этих функций новым этапом не переименовываются.

Прослеживание17 указателей выполнено по графам11 нативных контекстов. MOV из6CF048 создаёт alias таблицы; MOV между регистрами его переносит; записи в регистр удаляют; CALL сбрасывает EAX/ECX/EDX и использует обычный x86 ABI для сохраняемых регистров. Результат ограничен этими путями и контрактом инициализации, а не произвольно повреждённой памятью.

Первоначальный nearest-call hint для чтений4710BA/49FA90 был отвергнут проверкой полных тел. Реальные следующие входы —470E50/49F510; исходные предположения сохранены как `superseded_function_hint`. Само наличие call target перед инструкцией не доказывает принадлежность той же функции.

## Два вычисляемых перехода

Ghidra после создания функции4EFB70 не включила в body все arms двух switches. Переходы4F007B/4F01D5 используют таблицы4F0A08/4F0A18 по4 targets. Native AND EAX,3 и CMP EAX,3 ограничивают индекс0..3.

Все8 targets прочитаны из PE и живого Ghidra program, ветки восстановлены до обычного потока. Дополнительно покрыто130 инструкций. После этого анализ посетил4883 состояния, не оставив неразрешённых indirect jumps в выбранных контекстах; во всех достигнутых состояниях17 чтений сохраняют установленный источник таблицы.

Последняя по адресу инструкция этого body —4F0A01 JMP4EFC46, то есть внутренняя обратная ветвь, а не завершающий RET. Поэтому диапазон явно помечен как code extent с восстановленными switches. Нельзя считать недекодированную ветку отсутствующим исполняемым кодом или требовать RET последним по адресу во всякой функции.

## Ложный префикс и оставшиеся кандидаты

Кандидат42F0F1 начинается внутри настоящей инструкции42F0F0. Её байты — `66 8B 81 06 01 00 00`: префикс66 задаёт WORD. Если начать со следующего байта, получается вымышленное DWORD-чтение. Настоящий getter уже связан native RTTI с CEEffectElement этапом61, а не с определением Objects.

Шесть других новых anchored-кандидатов остаются неклассифицированными. Прежние wide/byte/alias-кандидаты также не объявлены исчерпанными. Новые17 чтений не подтверждают потребителя Objects106; это не доказательство глобального неиспользования поля.

Выполнен статический анализ, **новых native-эмуляций и raw-пересборок нет**. С Ghidra повторно считаны11 code extents:10 обычных полных тел и один диапазон с отдельно восстановленными switch arms. Все байты сопоставлены с исходным PE. Дополнительно сверены32-байтные jump tables и два явно помеченных фрагмента setup/reset. Полные constructor/destructor и игровая сессия не исполнялись.
