## Сначала экранный реестр

Реестр расположен в `769A78`, запись16 байт:

| Смещение | Runtime-значение |
|---|---|
| 0 | centerX, float |
| 4 | centerY, float |
| 8 | квадрат экранного радиуса, float |
| C | указатель примитива |

Счётчик находится в реестре+1000. В статически проверенных производителях
`580EC0`/`584900` есть ограничение256 записей; заполнение до границы здесь не
исполнялось. Это структура движка, не заголовок KWD.

`588A60` идёт от переданного индекса и возвращает следующую запись, для которой
`(screenX-centerX)^2 + (screenY-centerY)^2 < radiusSquared`. Сравнение строгое.
При квадрате радиуса100 и запросе0,0 центр9,0 допускается,10,0 уже исключён,
20,0 также исключён. Возвращаемый индекс сдвигается к следующей записи.
Предварительной сортировки по глубине в этом запросе нет.

## Два прохода внутри основного поиска

Первый проход вызывает virtual0C каждого допущенного кандидата с аргументом1.
Это точная проверка по треугольникам. Возвраты обработчиков объединяются OR.
Если хотя бы один вернул ненулевое значение, запрос возвращает выбранный токен
и записывает1 в выходной **BYTE**.

Если все обработчики вернули0, реестр обходится заново с аргументом0. Теперь
обработчики сравнивают глубины преобразованных центров моделей. Выходной BYTE
остаётся0, хотя возвращаемый токен может быть ненулевым.

Общая переменная глубины начинается с float1e30. Новый результат заменяет
старый только при строго меньшей глубине. Поэтому при равенстве побеждает
более ранняя запись реестра. В сценах с разной глубиной перестановка реестра
сохраняет выбор более близкой модели.

Важный контроль: **дальняя модель с точным попаданием выигрывает у ближней,
в треугольник которой курсор не попал**. При наличии точного попадания второй
проход вообще не исполняется. Это другой механизм, чем запасной клеточный
`44DEC0` этапа153, где первое подходящее существо получает преимущество.
Полный caller5992B0, решающий дальнейшие действия, здесь остаётся статическим.

Выходной параметр меняется только на один байт: остальные три исходных A5
сохранились. Возвращаемое EAX — токен примитива, который в подготовленной сцене
является указателем Actor9/10. Динамический обработчик берёт его из primitive4C,
анимированный — из primitive50. Физическое поле KWD этим не объявляется.

## Треугольники и глубина

Для динамической модели выполнены настоящие преобразования матрицей модели,
смещение XYZ примитива, преобразование камеры, перспективная проекция и три
проверки ориентированных рёбер треугольника. Оригинальный порог этих проверок
равен float0. Проверена смена порядка вершин: обратная ориентация исключает
точное попадание, после чего работает проверка центра.

Глубиной точного кандидата служит **арифметическое среднее трёх глубин вершин**.
Это не вычисленная глубина пересечения луча с поверхностью. Контрольная модель
с глубинами вершин1/4/4 проигрывает модели2/2/2, несмотря на свою ближайшую
вершину1. Это наблюдение относится к выполненному алгоритму выбора.

Глубины ниже float0.001 заменяются этим значением; исходные биты порога
`3A83126F`. В контрольной сцене отрицательные глубины центров−1/−2 превращаются
в равные, и остаётся первая запись. Из этого не следует корректность всей
отсечки геометрии за камерой: нормальная графическая подготовка сцены не
выполнялась.

Для анимированной модели настоящий `57E5B0` распаковывает 10-битные координаты
и исполняет интерполяцию. В стенде заданы два одинаковых подготовленных кадра,
выбран кадр0. Вызовы этой функции и дальнейшая проверка треугольников реально
исполнены; нет утверждения о проверке настоящей анимации из файла или всех
сочетаний кадров/матриц.

## Что стало известно о Priority и Jump

После реальных raw-загрузчиков подтверждены доступные игре значения:

| Поле | Raw | Runtime definition |
|---|---:|---:|
| Creature Pick-Up Priority | F55, BYTE | 6EB |
| Creature Ability Jump | EE0, DWORD | 75C |
| Object PickUpPriority | 35D, BYTE | 112 |

В27 новых трассах нет чтения этих runtime-полей. CreaturePriority-пары0/255,
255/0,1/40, Jump80000000/FFFFFFFF и ObjectPriority0/255 не меняют выбор ближней
подготовленной модели. Это дополняет результат запасного клеточного поиска.

**Глобальное неиспользование полей не доказано.** Не исполнен производитель
Actor/RenderInfo→примитив. Если поле используется там для вычисления матрицы,
геометрии или другого параметра, готовый примитив мог бы уже содержать результат.
Следующий конкретный участок — оригинальное создание динамических/анимированных
моделей и передача данных из RenderInfo (`59D010`, `59CCF0`, `59C880` как зацепки).
Нативная подпись Ability Jump (Tiles) сама по себе также не доказывает игровой
потребитель или единицы реального движения.
