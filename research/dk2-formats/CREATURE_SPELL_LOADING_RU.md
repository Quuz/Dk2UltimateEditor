Этап55,27 октября2026. Проверяется точный DX EXE с ранее зафиксированной SHA-256. Продолжение `SPELL_ALTERNATIVES_RU.md`; новые данные встроены в существующий компонент `spell_alternative_semantics`, число компонентов пакета остаётся65.

Заменена только низкоуровневая функция чтения: она берёт байты из ограниченного буфера памяти, проверяет длину не больше266 и конец потока до REP. Массив определений уже выделен; графический/resource provider равен0. Настоящая загрузка мира, выделение памяти и файловая система не исполняются.

Полный путь подтвердил границу прежнего вывода: rawE8/E9 не становятся самостоятельными полями70-байтного определения и не сохраняются callback в отдельный массив альтернатив. При gate6FCDCF=0 они влияют на checksum определения и, при вставке, на общий аккумулятор. При gate!=0 не меняются даже эти значения. Обновление существующего ID проходит через настоящий getter и loader, сохраняя count и общий аккумулятор. Игровое правило замены Shot/Room этим не установлено; сохранять эти raw-поля обязательно.

RawEE — другое поле: оно переносится в definition45 и выбирает проверку пригодности цели. Подмена этого поля альтернативным ID была бы ошибкой.

Одна и та же intermediate заново инициализируется для каждой записи. После загрузки в ней остаются данные последней записи; это не самостоятельное постоянное хранилище для всех заклинаний.

Важное перекрытие: парсер Traps `571040`, инструкция `57117A`, использует **747103 как начало своего intermediate** и вызывает `570B60`. Последний обнуляет747 байт:42 DWORD признаков присутствия и579 байт данных. Два дополнительных опыта сначала выполняют полный парсер CreatureSpells, затем намеренно вызывают именно этот инициализатор Traps на штатном адресе. Все747 байт обнуляются; Alternative Room теряется, а70-байтные определения и CWorld остаются прежними. Проверены также все346 байт прежнего intermediate. Это доказывает возможность перезаписи scratch, а не безусловный порядок загрузки каталогов в каждой карте.

Всего18 итоговых v3 прогонов:12 основных (два режима checksum, вставка/обновление, три пары альтернатив) и6 дополнительных (дубликаты, ID0, заполненная ёмкость, другой raw-хвост, два перекрытия). В каждом по3 входных записи и7 вызовов getter. Сравниваются210 байт определений,41932 байта CWorld,346 intermediate, исходный поток и состояние чтения. У дополнительных опытов с header callback вместе выполняются native counting и record callback — это явно заданная комбинация теста, не утверждение об однопроходном выделении мира. Основные12 опытов используют null header callback и заранее известную capacity, как проверенная регистрация record-прохода.

Статические правила сортировки, ID0, дубликатов и тихого пропуска при заполненной ёмкости из `CATALOGUE_LOADING_RU.md` теперь проверены исходным машинным кодом именно для CreatureSpells. Не переносить этот объём исполнения на все остальные семейства. Пропуск записи при capacity overflow возвращает успех; структурная корректность файла не гарантирует наличие всех определений в памяти.

Все12 полных функций (включая статически просмотренные регистрации и Traps parser) перечитаны после эмуляции и совпали с PE. Наличие функции в этом списке не означает, что исполнены все её ветки. Xrefs показывают только один зарегистрированный прямой вызов converter56A560 — из этого parser, и два вызова loader4F7860 — обе ветки51FE00. Это проверка известных ссылок, не доказательство отсутствия любого косвенного вызова.
