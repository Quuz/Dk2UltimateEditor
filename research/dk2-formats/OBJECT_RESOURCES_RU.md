# Ресурсы Objects: native-привязки и конфликт имён

Актуализация этапа121: прежняя неизвестность Objects+0xC8 ниже закрыта — это ресурс иконки объекта на карте оригинального редактора, подпись Object Icon. Суффикс #N задаёт номер в атласе; подтверждены исходные getter, расчёт, потребитель карты и writer. Используйте `EDITOR_OBJECT_ICONS_RU.md` и `effective_object_resource_bindings`; историческая таблица ниже сохранена как состояние этапа10. Ресурс170 по-прежнему отдельный In Hand Icon.

23 октября 2026. Исследованы предоставленные `DK2 Editor pro.exe` и `DKII-DX.exe`; SHA-256 закреплены в `object-resource-bindings.json`. Новые выводы получены из PE-ресурсов, MFC message map, конвертеров, модели, writer и игрового загрузчика через Ghidra.

## Результат

Ранее неизвестный ArtResource **Objects+0x170** связан с native-контролом **In Hand Icon...**. Это подтверждённая подпись исходного редактора. Игра отдельно загружает этот ресурс в `MyObjectDataObj+0x1B`, второй `CWorldEntry`. Полное поведение изображения при подборе/отрисовке пока не прослежено, поэтому подпись GUI не объявляется доказательством всех игровых применений.

Есть конфликт с baseline: поле **InHandIconResource** в исходной схеме находится по **+0xC8**, а не +0x170. Оно сохраняется отдельно. Нельзя переадресовать имя на другой слот, синхронизировать их или удалить один из них.

## Физическая раскладка

Смещения raw отсчитываются от начала одной записи Objects длиной894 байта. Каждый ресурс занимает84 байта. Смещения intermediate, editor model и runtime относятся к разным структурам в памяти.

|---|---|---|---|---|---|
| 0x020 | MeshResource | Mesh...,1590 | 0x0A0 | 0x0C8 | 0x51 |
| 0x074 | GuiIconResource | GUI Icon...,1589 | 0x0F4 | 0x010 | 0x00 |
| 0x0C8 | InHandIconResource | привязка не установлена | 0x148 | 0x06C | загрузка из этого слота в0x49DD60 не найдена |
| 0x11C | InHandMeshResource | In Hand Mesh...,1595 | 0x19C | 0x1C8 | 0x36 |
| 0x170 | kUnknownResource | **In Hand Icon...,1587** | 0x1F0 | 0x16C | **0x1B** |
| 0x1C4 | AdditionalResources[0].resource | Additional 1...,1591 | 0x244 | 0x224 | 0x6C |
| 0x218 | AdditionalResources[1].resource | Additional 2...,1592 | 0x298 | 0x280 | 0x87 |

Все восемь перечисленных кнопок **скрыты в PE-шаблоне диалога327**. Их подписи и обработчики установлены; динамическая видимость не исследована. Нельзя обещать, что они доступны в текущем окне Editor Pro. Статическое отсутствие загрузки +0xC8 в одной исследованной функции не доказывает отсутствие всех потребителей во всей игре или редакторе.

## Цепочка доказательств для +0x170

1. Ресурс диалога327 содержит control1587 с подписью `In Hand Icon...`.
2. По VA`0x5117A0` находятся шесть DWORD MFC-записи: `0x111,0,1587,1587,12,0x45B410`. Это WM_COMMAND, код0, диапазон одного ID и handler`0x45B410`. Генератор проверяет эти24 байта непосредственно в EXE.
3. Handler`0x45B410` получает модель из panel+`0x100`, вызывает getter`0x45BA00` и передаёт результат в resource dialog`0x433120`.
4. Getter возвращает model+`0x16C`. Конвертер редактора`0x42D570` переносит84 байта raw+`0x170` в intermediate+`0x1F0`; callback`0x4A1D80` переносит этот ресурс в model+`0x16C`.
5. Writer`0x4A9390` получает ресурс из model+`0x16C`, копирует21 DWORD в `auStack_228`. Начало записи — `uStack_398`, разность смещений равна`0x170`. В поток уходит запись`0x37E` байт. Соседний model+`0x1C8` независимо сериализуется в raw+`0x11C`.
6. Игровой конвертер`0x56D620` также переносит raw+`0x170` в intermediate+`0x1F0`. В загрузчике`0x49DD60` по`0x49DF84` берётся этот адрес, по`0x49DF8D` вызывается resource service vtable+`0x54`, затем по`0x49DF9A` ECX устанавливается в runtime+`0x1B` и по`0x49DF9D` вызывается`0x504D80`.

Последняя assembly-проверка нужна из-за неполного восстановления соглашения вызова в ранней декомпиляции: один текстовый вызов `FUN_00504d80(...)` без ECX не доказывал адрес назначения.

Игровая загрузка условная: наличие intermediate-флага, ненулевой resource service и ненулевой type. Общий режим `DAT_006fcdcf !=0` пропускает обычный путь загрузки ресурсов. Основной mesh имеет дополнительную ветку подстановки имени для отдельных типов объектов. Эта схема не эмулирует такие подстановки, ресурсный менеджер или отрисовку. CWorldEntry имеет размер27 байт; helper заполняет его поля, а Start/End handles загружаются отдельными ветками по флагам.

## Реальные записи

Проверены три отдельные области: самостоятельный Objects.kwd, Objects внутри AutoSaveGlobals.kld и внутри указанного в descriptor maps/kop4Globals.kld. В каждой по145 объектов.

У **одного** объекта в каждой области type ресурса +0x170 ненулевой: ObjectId10 **Call To Arms**, имя ресурса `gui\spells\call_to_arms`, type1. У +0xC8 type ненулевой в109 записях; например, Gold содержит `ObjectIcons#2`, Chicken — `ObjectIcons#9`. Это наблюдение по данным, а не самостоятельное доказательство назначения поля.

Ненулевые типы для девяти слотов в каждой из трёх областей:125,22,109,13,1,20,6,5,1 соответственно порядку таблицы. Непустое имя не всегда означает ненулевой type: у +0xC8 есть110 непустых имён при109 ненулевых типах. Не стирать ресурс только на основании одного из этих признаков.

## Использование и проверка

`object-resource-bindings.json` добавлен в общий пакет как20-й компонент. Идентификация слота в API идёт по физическому смещению, чтобы исключить неоднозначность имён:

```python
from native_object_resources import object_resources, set_object_resource

views = object_resources(record)
edited = set_object_resource(record, 0x170, replacement_84_bytes)
# Меняется только диапазон0x170..0x1C3; +0xC8 остаётся прежним.
```

`object_resources` показывает baseline-имя, native-подпись, исходные84 байта и разобранное представление ArtResource. Setter принимает ровно84 байта и только одно из девяти допустимых смещений; не назначает новый type, не меняет flags и не копирует соседние ресурсы самостоятельно.

`build_object_resource_bindings.py` повторно сверяет восемь MFC-записей с EXE и подписи с извлечёнными диалогами. `audit_object_resources.py` проверил34 граничных случая и3915 замен ресурсов реальных записей с пересборкой секций, повторным чтением, сохранением остальных записей и байтов. Проверены34 выдержки первичных доказательств. SHA-256 всех17 основных входных файлов и обоих EXE совпадают с закреплёнными значениями.

Назначение Rooms+0x1C4, игровых неизвестных скаляров и полного применения Objects+0xC8 остаётся открытым. Игровые файлы и исходники вашего редактора не изменены. Изменённые ресурсы в игре или Editor Pro не запускались.
