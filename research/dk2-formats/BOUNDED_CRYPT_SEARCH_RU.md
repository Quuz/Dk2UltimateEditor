# Crypt: поиск с проверкой границ циклов

Этап 157, 31 октября 2026. Точный `DKII-DX.exe`, SHA-256
`d7a8b854e4e4f02709eba271bead6fe2307dd6e332b5a96e70857e5b0e19fb8a`.

**Нового бонуса Crypt не установлено.** Раскрыты прежние восемь групп;
десять счётчиков `108A`, `108B`, `1092`, `1093`, `1096`–`109B` остаются
без подтверждённого игрового назначения. Этот этап исправляет поиск,
проверяет ещё одну ложную зацепку и сохраняет воспроизводимые границы вывода.

## Что изменилось в поиске

Прежний анализатор следовал за смещениями указателей, но не ограничивал
циклы по значениям числовых счётчиков. Поэтому он мог дойти до Crypt-поля
за пределами настоящего массива. Старый анализатор и его результаты сохранены.

Новый вариант отдельно отслеживает известные целочисленные значения и
флаги сравнения. Ветвь отсекается только при доказанном результате.
Чтение памяти считается неизвестным; смещение относительно указателя
не выдаётся за числовое значение самого указателя. Неописанная запись
в регистр сбрасывает соответствующее известное значение.

Поддержано ограничение через `CMP` и через `DEC/INC` с условным переходом.
При частично известных флагах используются только флаги, нужные этому
переходу: например, для `JNZ` достаточно ZF, даже если CF неизвестен.
Это ограниченный анализатор, а не модель всего процессора.

В расширенный поиск добавлены общая таблица объектов по tag и 20 подсказок
вычисления адреса с шагом CPlayer `1125h`. Такие указатели не считаются
автоматически указателями владельца: каждое новое совпадение требует
проверки типа по первичным инструкциям.

| Результат | Количество |

| Начальные подсказки | 3 171 |
| Прежние подсказки, сохранённые в новом поиске | 539 |

Ограничения не скрываются: 43/49 относятся к расширенному поиску, а не к
шести контекстам прежнего поиска. Более широкая область поиска добавила
свои ограниченные контексты; эти числа нельзя сравнивать как один процент покрытия.

## Прежняя ложная зацепка теперь исключается автоматически

Функция `4C7360` читает только owner `+E97`, `+EB0`, `+EC9`.
Новый анализатор получает ровно этот набор и завершает контекст за
28 состояний. Двенадцать цепочек, ошибочно связывавших инструкцию `4C7368`
с owner `+108B`, исчезли без ручного удаления результатов.

Ранее восемь исполнений оригинального кода и четыре контроля Ghidra уже
проверили эту границу. Их доказательства сохранены и используются как
эталон; повторно выполненными опытами этого этапа они не считаются.
Подробности прежнего исполнения — `UNKNOWN_SEARCH_REVIEW_RU.md`.

## Ещё один массив: 46 записей, не Crypt

Расширенный поиск вывел на `4DC7E0`. Его полный код проверен в Ghidra и
исполнен в 11 сценариях. Он работает с подготовленным буфером владельца:

1. Берёт младший байт аргумента и записывает его в owner `+B47`.
2. Проверяет ровно 46 байтов по `B57 + 18 × i`, где `i = 0…45`.
3. При совпадении записывает DWORD `A000h` по `B65 + 18 × i`.
4. Остальные байты не меняет.

| Граница | Смещение |
|---|---:|
| Первое сравнение | `B57` |
| Последнее сравнение | `E81` |
| Последняя возможная запись DWORD | `E8F` |
| Предполагаемое поле Crypt | `108B` |

Чтобы чтение стало `108B`, понадобился бы индекс 74:
`B57h + 74 × 12h = 108Bh`. Настоящий цикл заканчивается на индексе 45.
Граница через `DEC ECX / JNZ` теперь также учитывается анализатором;
его контроль получает ровно 46 адресов и завершается за 281 состояние.

Проверены отсутствие совпадений, первое/среднее/последнее совпадение,
все 46, чередование, аргументы 0/255 и аргумент `12340022h`, действующий
как байт `22h`. Изменение Crypt `108B` на 1/255 не меняет обращений функции.
Во всех случаях сохранены прочие байты полного буфера и 32 внешних защитных байта.

Пять независимых полных контролей Ghidra сравнили 15 областей, 22 130 байт.
Всего в новых native опытах выполнено 506 сравнений записей. Подмен
оригинального кода, vtable или I/O нет.

В статически проверенном вызывающем `45A0D0` передаётся CreatureType из
байта существа `+36F`, а указатель владельца получается через его tag
WORD `+28` и таблицу `6EE540`. Сам вызывающий здесь не исполнялся.
Более широкое назначение этой 46-записной таблицы и её связь с сырыми
параметрами файлов на этом этапе не устанавливаются.

## Что можно заключить о десяти неизвестных группах

Все оставшиеся найденные чтения этих десяти счётчиков находятся внутри
уже исследованного `4D8E60`, который меняет счётчики. Нового игрового
потребителя бонуса не подтверждено. Назначать новое имя группе по факту
такого чтения нельзя.

Это не доказательство глобальной неиспользуемости. Остаются неизвестные
косвенные вызовы, возвраты указателей, индексированные диапазоны, строковые
операции, ограничения состояний и глубина прямых вызовов 3. Старое
ограничение модели стека после CALL также не исправлено этим этапом.

Отдельно пересмотрена прежняя информация о CreatureSpells `E8/E9`:
обычная загрузка не переносит эти ID в постоянные смысловые поля
70-байтового определения. Это прежнее доказательство этапа 55, а не
новая расшифровка или основание повторять уже завершённые выстрелы.

## Пакет и воспроизведение

Новый компонент — `bounded_crypt_search_semantics`, файл
`bounded-crypt-search-semantics.json`. Пакет содержит 136 компонентов;
прежние 135 схем сохранены побайтно. Новых правок raw-формата и новых
названных неизвестных свойств — ноль. Codec, enums и effective-представления
не изменены. Сохранены SHA-256 420 источников и семи путей EXE.

```text
python -X utf8 scan_bounded_crypt_pointers.py
python -X utf8 emulate_owner_table_boundary.py
python -X utf8 crosscheck_owner_table_boundary.py
python -X utf8 prepare_bounded_crypt_primary.py
python -X utf8 build_bounded_crypt_search.py
python -X utf8 publish_bounded_crypt_search_docs.py
python -X utf8 audit_bounded_crypt_search.py
```

Три диапазона первичных функций покрывают все 11 новых исполненных PC;
два диапазона относятся только к статическому анализу. Общая оценка
готовности остаётся около 75%, цель по 15 семействам открыта.
