# Структурный реестр форматов DK2

14 ноября 2026. [Матрица](format-registry.RU.md), [машинный реестр](format-registry.json),
[проверка координатора](coordinator-validation.json).

Реестр извлекает12схем каталогов для11ID,6классов контейнеров и2варианта Level,
присутствующие только в coverage. Для схем указаны размеры записей, число полей,
границы байтов и точные JSON-ключи исходных полей. Массивы всех1208полей повторно
не дублируются: смещения, ширины, kinds и исходные имена доступны по schema_source.
Все182ссылки компонентов и85строк precedence снабжены ключами/хешами исходников.
Компоненты, упомянутые в precedence, найдены по тексту; это не доказанный граф вызовов.

Координатор независимо воспроизвёл весь JSON и Markdown без записи, проверил
digest и непрерывность1208полей. Четыре отрицательных контроля замечают изменение
размера записи, числа непрозрачных байтов, строки Terrain и ID каталога.
В Terrain18исторических непрозрачных строк:1+16+1. Прежнее число19 было ошибкой
ручного подсчёта; на19не строится никакой процент.

Это обзор **замороженного снимка205**, а не измеренное современное покрытие.
Ссылки на effective views и semantic corrections сохраняются, имена из baseline
не становятся доказанной игровой семантикой. Одинаковый effective view двух
Creatures-схем не устанавливает правило выбора версии для произвольного файла.
Кодировки отдельных полей, дополнительные потребители и сохранение произвольных
версий этим генератором не проверяются. Пробел ключа в реестре не доказывает,
что соответствующий факт неизвестен в остальных компонентах исследования.

## Воспроизведение без игры

Из корня этого репозитория, Python3.12+, только стандартная библиотека:

`python -B research/dk2-formats/format-registry/build_format_registry.py --research-root research/dk2-formats --no-write`

`python -B research/dk2-formats/format-registry/build_format_registry.py --research-root research/dk2-formats --self-test`

Ожидается0ошибок,12/11/6/2, Terrain18. Хеши четырёх исходных JSON закреплены:
изменённый вход требует нового осознанного снимка, он не принимается молча.
CLIпо умолчанию только читает. В опубликованном checkout следует всегда указывать
`--research-root`, поскольку исторический default предназначен для исходного стенда.
Явный `--write` создаёт ровно два файла рядом со скриптом и отказывает при
несогласованности. Для проверки и использования готового реестра запись не нужна.
