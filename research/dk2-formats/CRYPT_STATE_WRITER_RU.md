# Crypt: счётчики в потоке состояния CPlayer

Этап190, 4 ноября2026. Предоставленный `DKII-DX.exe`, SHA256 `d7a8b854e4e4f02709eba271bead6fe2307dd6e332b5a96e70857e5b0e19fb8a`.

**Подтверждён ещё один общий потребитель счётчиков: исходный метод записи CPlayer передаёт их в поток вместе с остальным состоянием владельца.** Это не новые игровые бонусы и не новые поля Creatures.kwd. Десять игровых назначений счётчиков остаются неизвестными.

## Как установлен тип владельца

Исходная RTTI-цепочка `.?AVCPlayer@@` ведёт через type descriptor `69F330` и COL `67D900` к vtable `66D99C`. В этой первичной таблице два метода: deleting destructor `4C1FB0` и writer `4B8D40`. Она не содержит дополнительных виртуальных getters Crypt.

В проверках выполняется полный оригинальный конструктор `4B8450`. Он сам устанавливает vtable, регистрирует tag1 и создаёт встроенный под-объект через `506120`. Это подготовленный пустой CPlayer, не полная инициализация игрока из уровня. Другие прямые методы, вторичные контексты и возвраты указателей этой таблицей не исчерпываются.

## Настоящая цепочка записи

`CPlayer4B8D40 →5B3EE0 → MyFile vslot0C/5B6EC0 → Disc vslot08/5FFFF0 → исходный IAT WriteFile66C1D0`.

Тела игровых функций, IAT и исходные vtable сохранены. Только внешний адрес Windows WriteFile `28CF36` обслуживается объявленным адаптером: байты попадают в исследовательский буфер памяти. Настоящий файл сохранения Windows-игрой не создаётся.

Первые части фрагмента CPlayer:

| Относительное место в потоке | Размер | Источник runtime CPlayer |
|---|---:|---|
| 0 |1 | BYTE10FC; имя raw-поля этим не назначается |
| 1 |2 | WORD4/tag |
| 3 |4136 (`1028hex`) | Сплошной блок76..109D |

Внутри последнего блока сохраняются **все20 байт108A..109D**. Первые18 имеют ранее установленное соответствие группам регистрации; назначение двух хвостовых слотов109C/109D не установлено. Считать их двумя новыми группами нельзя.

Для отдельно начатого с позиции0 фрагмента эти20 байт находятся по `1017hex` (4119) и заканчиваются перед `102Bhex` (4139). Это **относительные смещения данного фрагмента**, не абсолютные смещения в KWD или полном SAV.

Далее writer выдаёт заголовки собственных массивов и их элементы. Контроль с одним подготовленным9-байтовым элементом проверил обе отдельные4-байтовые записи этого элемента. Обычный пустой фрагмент занимает4184 байта, с одним таким элементом —4192. Названия всем массивам и полный формат сохранённой игры этим этапом не назначаются.

## Битовая сохранность и ошибки IO

Четыре проверки с полной записью сохранили нули, последовательные маркеры и комбинации00/01/7F/80/FF без нормализации всех20 байт. Значения80/FF — диагностика сохранности битов, а не утверждение, что штатный setter допускает такое число участников.

| Условие внешнего WriteFile | Фактически записано | Возврат CPlayer writer |
|---|---:|---:|
| Полная запись, пустые массивы |4184 |1 |
| Полная запись, один элемент |4192 |1 |
| Не более17 байт за вызов |65 |1 |
| BOOL0, bytesWritten0 при каждом вызове |0 |1 |

На уровне проверенного `4B8D40` возврат1 не доказывает полноту потока. `5B3EE0` формирует результат0/1 по фактическому количеству байтов, а вызывающий writer проверяет его как неотрицательный. Поведение внешнего игрового механизма сохранения, возможная дополнительная проверка и реакция интерфейса не исполнены; общий баг всех сохранений из этого не выводится.

Исходный объект после writer побайтово совпадает с отдельным снимком, сделанным после конструктора и подготовки массива. Защитные байты выходного буфера, источника и журнала, а также исходные IAT/vtable проверены целиком.

## Почему старые пробы исключены

В раннем стенде буфер вывода31040000 размером131136 байт перекрывал служебное состояние31050000 и начало журнала31060000. Сравнение только записанного префикса этого не замечало; полная проверка защитных байтов отвергла пробы. Ещё одна ранняя проба массива не объявляла его диапазон источником внешнего IO.

Исправленный выходной буфер расположен31400000..31420040. В native и независимом Ghidra-драйвере добавлено обязательное непересечение всех областей. Все12 прежних exploratory-файлов сохранены и явно исключены из принятых доказательств; новые прогоны имеют другие ключи входа и прошли полную проверку.
