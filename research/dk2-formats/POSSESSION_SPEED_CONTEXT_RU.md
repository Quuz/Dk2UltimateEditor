# Скорость: файловые параметры, HP и поверхность

Этап 201, 11 ноября 2026. Профиль DKII-DX.exe, SHA-256 `d7a8b854e4e4f02709eba271bead6fe2307dd6e332b5a96e70857e5b0e19fb8a`. Компонент `possession_speed_context_semantics`, схема `possession-speed-context-semantics.json`. Переносимый расчёт — `native_speed_context.py`.

Это расширение этапа **92**, где уже подтверждены базовая формула Stat21, выбор режима и альтернативный флаг. Новые результаты соединяют свежую загрузку Creature definition с настоящим Variables-reader, проверяют ранения, поверхность, их порядок и сужение скорости при загрузке. Ранее закрытые формулы вселения не пересчитываются как новые открытия.

Новая Creature definition действительно создаётся и загружается из изменённой в памяти исходной записи. Внешние file/TLS и null-resource/sound/graphics поставщики объявлены отдельно. Исходные функции, IAT и игровые vtable не заменяются. Живой игровой процесс, rendering и движение по кадрам не исполнялись.

Файловый вход — односекционный E6-файл в памяти с настоящими заголовками и записью `(224,21,200,10)` из GlobalVariables.kwd либо её диагностической копией. В двух случаях перед ней добавлена запись роста HP `(65,1,125,2)`. Полный Level/reference проход этапа198 здесь не повторялся.

## Сначала скорость загружается с сужением

| Скорость | Raw Creature | MID | Runtime definition |
|---|---:|---:|---:|
| Walk | EB4h | 12A4h | 5B4h |
| Run | EB8h | 12A8h | 5B8h |
| Shuffle | D37h | 1127h | 5BCh |

У всех трёх полей путь `492320` выполняет unsigned DIV на TPS, оставляет младшие 16 бит и при ненулевом исходном значении поднимает нулевой результат до 1:

```text
r = u32(raw)
q = (r // u32(TPS)) & FFFFh
loaded = 1, если q == 0 и r != 0; иначе q
```

Хранилище runtime имеет размер DWORD. Само начальное значение после этой операции сужено. Историческое отображение raw как signed Q12 не описывает unsigned DIV в этом потребителе; исходные 32 бита должны сохраняться.

| Raw, TPS=20 | Загруженная базовая скорость |
|---:|---:|
| 0 | 0 |
| 1 | 1 |
| 1310720 = 20×65536 | 1 |
| FFFFFFFFh | 52428 |
| 2000000000 | 57600 |

Это не ограничение всех будущих runtime-записей. Другие пути вроде Variables77 могут присваивать значения отдельно; они в этом расширении не исследованы. TPS=20 задан явно; другие делители и ошибки деления этими 32 сценами не проверены.

Режим getter: 1 выбирает Run, 2 — Shuffle, остальные значения — Walk. У всех этих режимов модификатором в `48ABB0` служит Type224 Stat21. Stat22 для этого getter не подставляется.

## Порядок множителей и округлений

Первой идёт проверка ранения, затем поверхность, затем Stat21. На каждом шаге выполняется своя 32-битная арифметика и целочисленное деление.

Если бит0 definitionDWORD686h снят, максимум для этой ветки берётся из definitionWORD692h при уровне1 либо вычисляется как `trunc0(s16(коэффициент роста HP) × definitionHP /100)` для других уровней. Порог — `u32(maxHP ×20)//100`. Текущее DWORD HP40h сравнивается с порогом **со знаком**. Только при строго меньшем HP скорость становится `u32(S×20)//100`.

Далее настоящий World508FE0 получает 16-байтную клетку по текущим Q12 XY. Её byteAh выбирает Terrain definition через таблицу6DA4A8. При результате Actor vcall88, равном0:

- Terrain DWORD17Bh bit80h, историческое имя WATER: `S = u32(S×50)//100`;
- иначе bit100h, историческое имя LAVA: `S = u32(S×150)//100`.

При обоих битах выбирается первая ветка, 50%. Terrain flags заданы в подготовленной runtime definition; загрузка самого Terrain.kwd и естественный переход между клетками здесь не выполнялись.

Последней идёт ранее известная ветка Type224:

```text
p = s16(Stat21 WORD)
Actor DWORD3E6h bit80h установлен:  S = u32(S × (100+p)) //100
иначе Actor DWORD3EAh bit8 установлен: S = u32(S × (100+p)) //200
иначе S не меняется
```

Первый флаг имеет приоритет. Поставщик второго флага в обычном игровом пути здесь не прослежен. Минусовые коэффициенты проходят через младшие32 бита произведения и unsigned деление: их нельзя просто ограничивать нулём или считать отрицательной возвращаемой скоростью.

Для базовой скорости **109**, HP=199, definitionHP=1000, WATER и Stat21=200:

```text
109 → floor(109×20/100)=21 → floor(21×50/100)=10 → 10×300/100=30
```

Одно объединённое деление дало бы 32. Поэтому объединять множители в одно вещественное выражение для точного повторения нельзя.

| Подготовленный случай | Результат getter |
|---|---:|
| HP199, WATER, Stat21=200 | 30 |
| HP200, WATER, Stat21=200 | 162 |
| HP199, LAVA, Stat21=200 | 93 |
| WATER без двух последних флагов, HP1000 | 54 |
| LAVA без двух последних флагов, HP1000 | 163 |
| WATER и LAVA вместе без последних флагов | 54 |
| HP199, WATER, только альтернативный флаг | 15 |
| HP199, WATER, Stat21=75 | 17 |
| HP199, WATER, Stat21=−100 | 0 |

При definitionHP=1000 порог равен200: HP199 включает штраф, HP200 уже не включает. После загрузки Type65 Stat1/Level2 со значением125 порог равен250: HP249 даёт30, HP250 —162 при остальных тех же условиях. Это прямая композиция файловой таблицы роста с потребителем скорости.

## Числовые ветки флагов

В обычной проверенной vtable `66D524`, слот88 указывает на `48ED40`. Он возвращает ненулевое значение только при одновременных definition686h bit0 и Actor3E6h bit100h. Для этой реализации:

| Definition bit0 | Actor bit100h | Низкое HP | Поверхность |
|---|---|---|---|
| 0 | 0 или1 | Проверяется | Применяется |
| 1 | 0 | Проверка пропущена | Применяется |
| 1 | 1 | Проверка пропущена | Пропущена |

Состояние definition bit0 получено изменением raw Flags+EFCh bit0 и настоящим конвертером/loader. Не присваивается новое игровое имя этим числовым условиям. Используется подготовленный обычный CCreature; выбор подкласса при естественном создании существа с изменёнными Flags и другие реализации виртуального слота остаются отдельным вопросом.

HP=0 в одной сцене всё равно даёт30 от getter. Это не доказательство движения мёртвого существа: смерть и выбор движения могут проверяться внешним кодом, который здесь не исполнялся. Полученные числа — внутренние значения функции, не измерение tiles/sec или кадровой скорости.

## Сохранность и реализация

Type22421 записывает младший WORD по адресу6F288Dh и читается со знаком. Старшие16 бит ValueRaw и последний DWORD записи не входят в эту арифметику, но World callback учитывает полную MID-запись в signed-byte checksum. Они сохраняются в исходном файле, включая `(224,21,200,10)` и проверенный вариант ValueRaw=`ABCD00C8h`.

`native_speed_context.py` содержит независимый от игры расчёт: `load_base_speed`, `regular_actor_v88` и `speed_terms`. Его результаты сопоставлены со всеми32 нативными композициями. Для других подклассов передавайте в `speed_terms` фактический результат vcall88; предположение из `regular_actor_v88` имеет указанный профиль vtable.

Проверены **32** композиции, 34 Variables-записи, 2118449 исходных инструкций; **8** полных Ghidra-сравнений, 440 областей, 1209160 байт. Все3485 различных исполненных исходных PC покрыты78 полными байтовыми диапазонами функций. Отчёты: `phase201-speed-context-emulations.json`, `phase201-speed-context-crosschecks.json`, `phase201-speed-context-primary.json`.

19 точечных DWORD-правок настоящих Creatures.kwd и GlobalVariables.kwd обратимы и сохраняют заголовки, соседние поля, неизвестные байты и остальные секции. Проверки включают три speed-поля, Flags bit0 и ValueRaw Stat21. Все420 исходников данных и7 EXE сохранили хеши; codec и178 прежних компонентов не изменены. Проверка — `phase201-validation.json`.

Глобальные параметры и общая цель не завершены. Значения29/186 не переименованы, оценка общей готовности не повышена. Открыты другие скаляры/потребители и ветви Variables writer; затем идут резисты и флаги существ. Crypt остаётся отложенным.
