# Variables74: запас до предела переносимого золота

Этап193, 9 ноября2026. Подтверждение относится к предоставленному `DKII-DX.exe`, SHA-256 `d7a8b854e4e4f02709eba271bead6fe2307dd6e332b5a96e70857e5b0e19fb8a`.

**Историческое имя `GAME_TICKS` у Variables74 неверно для проверенного потребителя.** Полная оригинальная функция `464360` использует значение как вычитаемый запас до предела переносимого золота. Подтверждённое имя для нашего редактора — `GOLD_CAPACITY_MARGIN`, «Запас до предела переносимого золота». Это уточнение смысла существующего DWORD, новых полей в файле нет. Историческая базовая таблица сохранена; актуальный смысл задаёт компонент `gold_capacity_margin_semantics` в пакете.

## Точная формула

Функция получает контекст ИИ с указателем на Creature по `+8` и один аргумент. При нулевом аргументе она проверяет только `переносимое золото != 0`; предел и Variables74 в этой ветке не читаются. Любой проверенный ненулевой аргумент включает расчёт:

```text
base = unsigned16(CreatureDefinition+69C)  // исходный Creatures+F1E, MAX_GOLD_HELD
if CreatureLevel == 1:
    capacity = base
else:
    coefficient = signed16(VariablesBase+13B+2*CreatureLevel)
    capacity = trunc0(base * coefficient / 100)
threshold = wrap_u32(capacity - Variables74)
return unsigned32(Creature+3FB) >= threshold
```

Уровень — BYTE Creature+403. Коэффициент роста поступает через настоящий callback `51DC40` записи Variables65/Stat6. Усечение деления происходит к нулю. Сравнение переносимого золота с порогом **беззнаковое**, результат вычитания **не ограничивается нулём**.

| Подготовленные условия | Порог | Результат |
|---|---:|---|
| Вместимость6000, запас340, золото5659 | 5660 | Ложь |
| Вместимость6000, запас340, золото5660 | 5660 | Истина |
| База6000, уровень2, коэффициент150, запас340 | 8660 | На8660 истина, на8659 ложь |
| Вместимость6000, запас6000 | 0 | Даже нулевой переносимый остаток проходит |
| Вместимость6000, запас6001, золото6000 | 4294967295 | Ложь вследствие переполнения вычитания |
| Вместимость100, запас340, золото100 | 4294967056 | Ложь вследствие переполнения вычитания |

Поэтому редактору нельзя молча заменять машинную формулу на `max(0, capacity−margin)`: это изменит поведение проверенной игры. Коэффициент150 в таблице подготовлен явно для проверки арифметики, он не выдаётся за текущее общее значение. Отрицательные битовые значения и отрицательный коэффициент роста включены как диагностика представления; их допустимость в обычном игровом интерфейсе не установлена.

## Источник и запись в файл

В текущем `GlobalVariables.kwd` записи74 нет. Неизменённая запись со значением340 взята из **соседнего `Data/editor/AutoSaveVariables.kld`**: индекс468 (от нуля), начало записи7544, Value7548, размер записи16 байт. Raw: `4a000000540100000000000000000000`.

Это не доказательство фактической загрузки данного соседнего файла картой AutoSave. Текущий дескриптор `AutoSave.kwd` ссылается на общий `Data\Editor\GlobalVariables.kwd` и на **отсутствующий `Data\Editor\Maps\AutoSaveVariables.kld`**. Точные текущие ссылки и хеш дескриптора сохранены в `phase193-gold-storage.json`. Порядок разрешения ссылок/общих и уровневых замен этим этапом не исполнен.

Восьми значениям Value соответствуют точные правки только четырёх байтов `record+4`. Заголовки, Extra1/Extra2, остальные записи, секции и хвосты сохраняются; обратная правка возвращает исходный файл побайтово. Соседний Variables-файл проходит физическую и декодированную пересборку. Прежние15 пересборок семейств унаследованы от этапа192 с повторной проверкой хешей источников; они не считаются15 новыми прогонами. API: `native_gold_margin.view`, `patch_bits`, `project`.

Приняты16 native-сцен и6 независимых Ghidra-контролей полных контекстов:240 областей,671172 байта.
