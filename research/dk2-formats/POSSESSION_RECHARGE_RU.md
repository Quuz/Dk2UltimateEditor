# Вселение: длительность перезарядки способностей

Этап96, предоставленный `DKII-DX.exe`, SHA-256 `d7a8b854e4e4f02709eba271bead6fe2307dd6e332b5a96e70857e5b0e19fb8a`.

**Подтверждены два регулятора перезарядки при вселении:** запись GlobalVariables type224/StatId31 и отдельная скалярная запись type210. Настоящие функции расчёта интервала, готовности и прогресса выполнены в38 сценариях. В пяти из них выполнена также полная загрузка сырой записи CreatureSpells до игрового потребителя.

Схема — `possession-recharge-semantics.json`, компонент `possession_recharge_semantics`. Точная целочисленная проекция — `native_possession_recharge.py`. Старые74 компонента пакета сохранены побайтово.

## Какие поля редактировать

| Источник | Физическое поле | Как использует проверенный путь |
|---|---|---|
| GlobalVariables, type224, StatId31 | DWORD значения по+8 | Загрузчик сохраняет low16, getter читает signed16; текущее значение25 |
| GlobalVariables, type210 | DWORD значения по+4 | Загружается только low8; текущее значение100 |
| CreatureSpells | DWORD по+EA | Исходная длительность Q12; загрузчик переводит её в игровые тики |

В текущем GlobalVariables проверены неизменённые записи `[224,31,25,10]` и `[210,100,0,0]`. Индекс31 и type210 — разные записи. Последний DWORD10 в type224 не является уровнем существа в этом загрузчике.

Для type210 значение256 действует как0, `ABCD0064h` — как100. Редактор обязан сохранять полный32-битный DWORD и остальные8 байт записи, хотя этот потребитель использует только байт. API `patch_scalar210(raw,value_bits)` меняет именно DWORD+4.

Базовое имя Stat31 — `MELEE_RECHARGE_TIME_SECONDS`, а type210 — `FIRST_PERSON_RECHARGE_MODIFY_PERCENTAGE`. Эти имена взяты из базового перечисления. Нативный `4F7AB0` получает определение CreatureSpell и локально не проверяет, является ли оно атакой ближнего боя; проверены lookup для ID1 и7. Смысл установлен по потребителям, а не только по имени.

## От сырого времени до интервала

Физическая цепочка:

```text
CreatureSpells raw DWORD_EA
 → converter56A560: intermediateDWORD13A
 → loader4F7860: definitionDWORD2D
 → 4F7AB0: интервал с поправками
 → 48C800: готовность / 48C8B0: прогресс
```

Загрузчик вычисляет:

```text
baseTicks = low32(rawTime * ticksPerSecond) >> 12   # логический сдвиг
```

Сначала получается32-битное произведение; заменять его неограниченным64-битным умножением нельзя. При raw4096 и TPS20 база равна20; при TPS25 —25. Raw6144 и TPS20 дают30.

Пусть `B` — база в тиках, `P` — signed16 из type224/31, `C` — low8 из type210. Для обычных небольших положительных значений приблизительная запись формулы:

```text
без обоих флагов:      B
со вселением:          B * (100+P)/100 * C/100
только соседний бит08: B * (100+P)/200
```

Вторая строка использует **сам процент C**, без добавления100. При обоих флагах приоритет имеет вселение. Соседний флаг выставлен настоящей `4BFD00`, исследованной на этапе95; новый стенд использует существ в одной XY-клетке, чтобы вызвать её настоящий путь.

Реальный код работает через Q12 и округляет на промежуточных шагах. Точная последовательность и signed/unsigned правила записаны в схеме и API. Простое вычисление формулы через float не воспроизводит все значения.

| Условия, база20 | Интервал |
|---|---:|
| Обычное существо | 20 |
| Вселение, P25, C100 | 25 |
| Соседний флаг08, P25 | 12 |
| Вселение, P25, C50 | 12 |
| Вселение, P25, C0 или256 | 0 |
| Вселение, P25, C255 | 63 |
| Вселение, P0, C100 | 20 |
| Вселение, P100, C100 | 40 |
| Вселение, PFFFFh/signed−1, C100 | 19 |

При C100 и текущем P25 проверенный интервал вселённого существа увеличился20→25. Это результат данного getter. Полный боевой цикл, анимация и остальные временные модификаторы в этой новой композиции не исполнялись, поэтому итоговую частоту всех атак в игре только по этой таблице утверждать нельзя.

## Готовность и прогресс — разные функции

`48C800` получает слот способности, сужает его до low8 и через настоящий `4943F0` находит запись в определении существа. Нулевой ID или слот вне числа способностей даютfalse. Настоящий World lookup `50DFA0` получает70-байтовое определение CreatureSpell.

Для существующей способности последнее использование хранится в `actorDWORD41B + 4*slot`. При0 функция сразу возвращаетtrue. Иначе:

```text
denominator = low32(actorDWORD3AF + actorDWORD3B3)
deadline = low32(lastUse + low32(interval << 12) / unsigned(denominator))
ready = unsigned(deadline) < unsigned(currentTick)
```

Назначение полей3AF и3B3 этим этапом не именуется; подтверждено их участие в этой арифметике. При нулевом знаменателе и ненулевомlastUse код содержит DIV0; такой сбой не исполнялся и не объявляется ошибкой редактора.

Сравнение строгое. Для интервала25, lastUse100 и знаменателя4096:

| Тик | Готовность `48C800` | Прогресс `48C8B0` |
|---|---:|---:|
| 110 | false | 40 |
| 125 | false | 100 |
| 126 | true | 100 |

`48C8B0` считает прогресс по разности времени и интервалу, не читая3AF/3B3. Поэтому в подготовленном примере с обычной базой20, знаменателем8192, lastUse100 и tick111 готовность ужеtrue, а прогресс55. Это различие двух настоящих функций; состояние специально задано стендом и не доказывает ошибку отображения в живой игре.

При lastUse0/tick0 проверка готовности далаtrue, а прогресс0. Для подготовленного времени до lastUse getter вернул rawDWORD `FFFFFFFCh` (signed−4), без ограничения снизу. Как такой результат отображается настоящим интерфейсом, здесь не наблюдалось.

## Проверки и сохранность данных

38 новых native-сценариев: состояния без флагов/вселение/соседний/оба, проценты, low8/low16 и старшие биты, текущие записи, граница времени, нулевое последнее использование, сужение слота, отсутствие способности, другой SpellID и переход счётчика времени через DWORD-границу.

Пять raw-CreatureSpell композиций выполняют настоящие initializer56A490, converter56A560 и loader4F7860, затем все три потребителя. Сравниваются полные266raw,346intermediate,70definition и64 защитных байта после каждого. Явный gate1 и нулевой поставщик ресурсов исключают визуальную/checksum-ветки. Сырой parser и включение в массив мира заново не запускались — массив подготовлен, lookup настоящий.

Пересборка файлов проверена отдельно:

- 557 ранее принимаемых Variables-контейнеров:475 записей type210,3325 точечных пересборок с заменой только DWORD+4.
- 82 CreatureSpells-контейнера:3535 записей,14140 пересборок с заменой только DWORD+EA через прежний API `native_spell_writer.patch_raw`.

Все хеши исходников и обратная сборка сверены; заголовки, порядок, неизвестные поля и соседние записи сохранены. Старые24 отказа строгого Variables-parser не исправлялись. Исходные игровые файлы не перезаписывались.

162 полных диапазона функций и9 PE-блоков сверены с оригинальным EXE; это включает прежние и статические зависимости, а не исполнение всех162 функций. Актёр и второй источник подготовлены на основе нативного снимка этапа90. Новых выделений, снимков живого процесса или подмен игровых функций/vtable нет. Ленивая CRT-регистрация getter способности пропущена через явно подготовленное уже инициализированное состояние и нулевой fallback.

Для forensic-входов проверены переполнение сырого времени и сдвига базы; необычные результаты не являются рекомендуемыми значениями для редактора. Исключительные деления, все ветки смерти, полный Shot26/control, смысл98/113/114 и остальных stat-полей остаются открытыми.

Воспроизведение: `prepare_recharge_primary.py`, `ghidra_probe.py phase96-primary-queries.json`, `emulate_possession_recharge.py`, `build_possession_recharge.py`, `build_format_package.py`, `audit_possession_recharge.py`. Пакет содержит75компонентов; общая цель по15семействам не завершена.
