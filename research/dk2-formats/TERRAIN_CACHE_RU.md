# Terrain: перечисление ID, глобальный кэш и выбор определения для света

Этап74. Проверены исходные инструкции `DKII-DX.exe` и предоставленного старого EXE из папки `DKII 13`. Профили выбираются по SHA-256, а не по имени папки. Неизвестные Terrain `+0x198` и `+0x224` не получили игрового назначения.

Все смещения ниже шестнадцатеричные; размеры структур и число проверок — десятичные. Буферы мира и определений заранее подготовлены исследовательским стендом. Новые проверки не исполняют allocator, parser, GUI или renderer.

## Три разных способа получить Terrain

| Операция CWorld | DX | Старый EXE | Результат |
|---|---|---|---|
| vslot `60` | `50CEB0` | `501900` | ID по порядковому номеру среди непустых слотов |
| vslot `70` | `508DD0` | `4FD7F0` | Адрес прямого слота `array + 460 × (argument & 255)` |
| vslot `74` | `508DF0` | `4FD810` | DWORD счётчика загрузок `world+15AC` |

Массив находится в `world+15A4`, его граница — `world+15A8`. Перечислитель начинает со слота1 и останавливается перед этой границей. Он пропускает слоты с нулевым BYTE ID в `definition+1C4`. Аргумент порядкового номера используется как полный DWORD; результат имеет смысл в AL. Старшие24 бита EAX не следует считать частью возвращённого ID.

Таким образом, слот0 никогда не перечисляется, даже если его ID ненулевой. При capacity1 перечислитель не увидит физически существующий слот1. В неконсистентном массиве, где слот1 содержит ID7, он вернёт7; последующий прямой getter вернёт слот7, а не первоначальный слот1.

Ранее статически установленный allocator выделяет `sum_header_counts + 1` элементов: см. `catalogue-loading.json`. Он здесь заново не исполнялся. Нельзя заменять capacity счётчиком уже загруженных записей.

## Заполнение глобальной таблицы указателей

Полные функции `455D40` / `44E7E0` очищают256 DWORD глобального кэша `6DA4A8` / `6CD1A0`. Затем выполняют число итераций, взятое из `world+15AC`. На каждой итерации получают ID перечислителем и записывают указатель прямого слота в `cache[ID]`.

Если итераций больше, чем доступных непустых слотов, перечислитель возвращает0. В кэш тогда записывается `cache[0] = адрес слота0`. Остальные невыбранные элементы остаются null. Это проверено при двух непустых слотах и счётчике4; причина расхождения счётчика в реальной игровой загрузке здесь не воспроизводилась. Предыдущий этап58 отдельно подтвердил, что повторный ID увеличивает счётчик загрузок, хотя заменяет прежнее определение.

Есть ещё разделение источников: перечисление берёт CWorld из глобального указателя `6DA4A4` / `6CD19C`, а count и прямой getter вызываются у мира, переданного аргументом. По одному сценарию на EXE проверено с разными мирами: ID берутся из глобального мира, адреса определений — из переданного. Это не доказывает, что обычная игра действительно передаёт разные миры.

Исследованные82 файла содержат3306 записей Terrain. В каждом набор положительных ID равен1..N, нулевых и повторных ID нет:62 файла по41 записи,19 по38, один42. Это наблюдение над данным корпусом; порядок и неизвестные байты других файлов нельзя автоматически исправлять по этому образцу.

## Выбор определения перед подготовкой света

Полные helpers `452DC0` / `44B910` читают указатель из кэша по BYTE клетки `+A`. Их bool-результат и выходной указатель — отдельные результаты. Native caller `441CD0` проверяет bool перед использованием выбранного определения и подготовкой каналов света.

- Если `WORD клетки+2 & FFF` ненулевое, helper требует `BYTE клетки+C == FF` и флаг определения `10000000`. При успехе пишет текущий указатель и возвращает1; при отказе сохраняет прежний выходной указатель.
- Если младшие12 бит равны0, бит20 в клетке+9 выключен и бит40 в клетке+B включён, выбирается текущее определение при его флаге `01000000`; иначе вызывается настоящий getter с ID38. Указатель записывается всегда, а bool равен биту28 флагов выбранного определения.
- В остальных случаях требуется флаг `10000000`, затем вызывается `global_world.vslot21C(x,y,0)`. Нулевой результат запроса и повторная проверка флага разрешают запись текущего указателя и возврат1. При отказе прежний указатель сохраняется.

Два вида сценариев в обоих EXE подтвердили **запись указателя при bool=0**: выбор текущего определения и выбор fallback ID38. Это контракт helper, а не доказательство ошибки редактора. ID38 не получает нового смыслового названия лишь из-за этого использования.

Vslot21C представлен явным адаптером: проверяются ECX, все три аргумента и число обращений; задаётся результат0,1 или FFFFFFFF. Настоящий геометрический запрос и итоговое изображение не проверялись. Все входные указатели кэша валидны; поведение при отсутствующей записи не установлено этим набором успешных случаев.

## Новый поиск неизвестных полей

Добавлены два пути поиска для каждого EXE: возвраты getter/vslot70 и чтения глобальной таблицы указателей. Поиск отслеживает постоянные смещения, копии регистров, ESP/EBP spill и передачу через ECX/первые восемь возможных аргументов до трёх уровней прямых вызовов.

Всего561 исходная точка,11173 состояния,24 контекста callee. Получено469 контрольных зацепок по флагам и соседнему полю raw19A; новых потребителей `definition+183` или `+1B5` не установлено. Один callee в DX-поиске от getter достиг лимита. Косвенные вызовы и возвраты, указатели через выходные параметры, динамические индексы и другие бинарники остаются за пределами такого поиска. Нулевой результат не доказывает, что поле не используется вообще.

## Проверки и интеграция

44 полные native-композиции:18 заполнений кэша и26 выборов определения. После заполнений выполнено ещё90 полных вызовов перечислителя с захватом AL. Настоящие enumeration/getter/count исполняются; их код не заменён адаптерами.

Сравниваются все1024 байта кэша, весь5888-байтный world, полные массивы460-байтных определений, клетки, результаты и таблицы виртуальных функций. EAX выбора сохраняется до наблюдателя; финальные EAX/EBP означают результат сравнений. Для функции заполнения кэша не объявляется публичное возвращаемое значение.

После исполнения11 полных функций, включая10 исполнявшихся и одного статического caller, и6 диапазонов vtable повторно прочитаны из Ghidra и сопоставлены с PE. Хеши82 входных файлов и четырёх EXE не изменились. Новых raw-патчей нет: текущие операции читают готовые runtime-данные; прежние точечные пересборки этап58 остаются отдельным доказательством.

`terrain-cache-semantics.json` вложен в `terrain-lighting-semantics.json.phase74_cache`; пакет сохраняет67 компонентов. `native_terrain_cache.py` предоставляет исследовательские проекции `enumerate_id`, `cache_ids`, `light_selection`. Проверки: `phase74-validation.json`, `phase74-primary-manifest.json`, `phase74-terrain-cache-emulations.json`, `audit_terrain_cache.py`.
