## Что строится

Настоящая59F760 инициализирует24записи `(индексA, индексB, requiredMask)` по795720h. Функция59F3C0 создаёт сетку3×3×3, то есть27точек. По X/Y шаг0,5; основание берётся через native floor от преобразованных координат. Координатный wrapper сначала прибавляет знаковые смещения RenderInfo51/53/55 и переводит Q12 в float.

Сам селектор3 передаёт сетке константу Z=−2. В проверенном обычном режиме уровни Z примерно−1,55/−1,30/−1,05. При global759AE8=1 — примерно−2,05/−1,55/−1,05. Два других проверяемых кодом global759AD0/75AEAF здесь нулевые; их игровых названий нет.

Ребро выбирается по условию:

```text
(requiredMask & (RenderInfo.DWORD5B & 255)) == requiredMask
```

Таблица обходится с конца. Биты01/02/04/08 по отдельности дают по2сегмента; полный1Fh —24. Бит10h требуется вместе с боковыми битами для верхних и вертикальных сегментов; один10h ничего не рисует. Маска0 тоже не создаёт геометрии.

Для каждого сегмента вызывается оригинальная59DD30 с толщиной float32≈0,03. Она выделяет **два меша**, каждый8вершин/4треугольника, через57CEB0, конструктор588190 и очередь571AE0. В полном каркасе получается48мешей. Это геометрия в очереди движка; GPU и конечные пиксели не проверены.

Текстурный ID берётся из GFX DWORD8Eh, затем используется его low16. Подтверждённый статический engine-init5983C0 загружает туда asset `Cursor`. Число3 в аргументе загрузки этой текстуры — отдельный аргумент графического API, его нельзя отождествлять с процедурным селектором3 только по совпадению числа.

## Настоящие потребители Terrain

Загружена исходная запись `Claimed Path`, TerrainId8: настоящий constructor4F6570 → initializer56EB60 → converter56ED20 → полный loader4F66E0. Loader получает null graphics provider для ресурсов Terrain; это не доказательство всей графической загрузки каталога. Далее исходные виртуальные методы World читают клетки и определение через таблицу6DA4A8.

| Поле raw Terrain | Runtime definition | Выход59E210 |
|---|---|---|
| WibbleH, BYTE1CE | BYTE1A1 | DWORD `u8 <<7` |
| WibbleV, BYTE1D2 | BYTE1A5 | DWORD `u8 <<7` |
| LeanH[0..2], BYTE1CF..1D1 | BYTE1A2..1A4 | float32 `u8 /512`, по трём слоям |
| LeanV[0..2], BYTE1D3..1D5 | BYTE1A6..1A8 | float32 `u8 /512`, по трём слоям |

Обработчик создаёт27записей по20байт: два DWORD диапазонов, два float наклона и последний DWORD, который он не назначает. В отдельной композиции предсказаны все540байт, включая сохранение неназначенного хвоста; дополнительно проверены64защитных байта.

**Важно: Lean действительно float.** Декомпилятор показал целочисленные приведения, но59E324/59E338 выполняют `FSTP float`. Значение255 становится0,498046875, а не0. Поэтому здесь нет доказанного «сломано из-за округления в целое».

Выбор Wibble из Terrain зависит от **runtime WORD+8 клетки**, бита2000h. При дополнительном8000h диапазоны Wibble обнуляются. Без2000h берутся глобальные DWORD6F25F9/6F25FD, в стенде они явно нулевые. Их связь с конкретными GlobalVariables здесь не расшифрована. Lean выбирается по2000h без этого дополнительного8000h-условия. Не переносите эти биты на Flags сырой Terrain-записи или байты raw Map без отдельной цепочки доказательств.

59ED80 использует настоящий PRNG5558D0 и масштаб1/131072:

```text
X/Y: (rand(WibbleH <<7) − (WibbleH <<7)/2) /131072
Z:    rand(WibbleV <<7) /131072
```

При нулевом диапазоне соответствующий PRNG-вызов пропускается. Это внутренние смещения перед дальнейшим сочетанием с интерполяцией и базовой волной; нельзя выдавать формулу за прямое окончательное перемещение любой вершины.

В одинаковой подготовленной сцене изменение только WibbleH изменило X/Y всех27точек, сохранив Z. Только WibbleV изменило Z всех27точек, сохранив X/Y. Lean0/255 меняет точные float-выборки, но в однородном окружении с занятыми соседями итоговая геометрия совпала.59F4B0 применяет наклоны через условия заполненности и интерполяцию; смешанные границы остаются открыты. Глобальная неработоспособность Lean не доказана.

## Проверки и ограничения второго CPU

Приняты28native-композиций общего wrapper и2отдельные полные цепочки rawTerrain→59E210. Выполнены536сегментов/1072меша. Для всей сложной деформированной геометрии математическая модель не заявляется.

Четыре контроля Ghidra совпали по всем подготовленным выходным областям, кроме стека: **238областей /1587972байта**. Это два целочисленных не-деформированных кадра и две отдельные цепочки загрузчика Terrain/59E210. Внутри этих областей исключений байтов нет.

Сохранены два результата, которые **не считаются пройденными**:

* На дробных `(2,25;3,75)` native floor выбирает `(2;3)`, а Ghidra даёт расхождение heap. В установленном x86 Sleigh `FRNDINT` реализован как безусловный `round(ST0)`, без учёта FPUControlWord. На целых координатах это различие не проявляется. Отдельно сохранены первые различающиеся байты.
* Полный включённый кадр Ghidra останавливается по59E5E3: неподдержанный `fsin`. Его инструкции не заменялись. Полный кадр исполняется в Unicorn; Ghidra подтверждает только отдельную выборку до этой операции.

Исходный FPUControlWord37F/Status0 задан явно в обоих CPU. Ранний диагностический запуск Ghidra с нулевым control word входил в путь floating exception и также не принят как доказательство игры.
