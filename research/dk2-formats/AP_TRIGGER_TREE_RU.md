# Action Point: дерево триггеров, ссылки и повторы

Этап 156, 31 октября 2026. Профиль — точный `DKII-DX.exe`, SHA-256
`d7a8b854e4e4f02709eba271bead6fe2307dd6e332b5a96e70857e5b0e19fb8a`.

Подтверждено исполнением оригинальных инструкций: 33 сценария, 99 полных
вызовов обновления AP, 33 привязки триггера, 93 проверки условий и 57 действий.
Двенадцать полных цепочек независимо выполнены в Ghidra: совпали 98 областей,
358 952 байта. Подмен функций, таблиц виртуальных методов и внешних I/O нет.

Подготовлены runtime World, AP и массивы триггеров. Парсер KLD, загрузчики
этих массивов, выделение AP и нормальный планировщик World здесь не исполнялись.
Проверки показывают поведение полного AP-обхода на заданных входах.

## Файл и память игры

Триггер хранится как оболочка `tag:u32, payloadBytes:u32` и 16 байт payload.

| Смещение в payload | Поле | Тип |
|---:|---|---|
| `00` | Parameters | 8 байт |
| `08` | Id | u16 |
| `0A` | NextId | u16 |
| `0C` | ChildId | u16 |
| `0E` | Type | u8 |
| `0F` | RepeatTimes | u8 |

В подготовленном runtime узел занимает 20 байт. DWORD `+10h`, бит `01`,
обозначает активность узла; он не входит в 16-байтовый payload файла.
Остальные биты этого DWORD сохраняются при отключении.

Массив условий: World `+7308h`, число WORD `+7314h`.
Массив действий: World `+730Ch`, число WORD `+7318h`.
Все эти смещения относятся к памяти игры.

## Переходы и поиск ID

Цепочка: `4B0C90` привязывает триггер; `4B05E0` обновляет AP;
`4B0CC0` обходит дерево; `4B0D70` проверяет условие;
`518AD0` исполняет действие.

Обход трактует ссылки как **signed16**: ноль завершает цепочку,
положительное значение выбирает массив условий, отрицательное — массив
действий. В файле сохраняется исходный 16-битный рисунок; например,
`FFFFh` в этой логике означает `−1`.

Геттеры `518090` и `5180F0` ищут первое совпадение ID. При дубликатах
выигрывает ранний узел. При отсутствии ID они возвращают базу массива.
В проверенных непустых массивах это приводит к исполнению первого узла:

- ссылка на отсутствующее условие `1777` выполнила первое условие с ID `7`;
- ссылка на отсутствующее действие выполнила первое действие.

Вариант с нулевым числом элементов также возвращает базу по листингу,
но его исполнение не проверялось. Поведение NULL-указателя не установлено.

Ненулевой аргумент привязки сохраняет ID в AP `+34h` и копирует байт
RepeatTimes найденного условия в AP `+36h`. Нулевой аргумент ничего не
очищает: прежние ID и кэш сохраняются. У изначально нулевого ID обновление
дерево не вызывает.

## Как работают повторы именно у AP

Неактивный узел пропускается, затем обход переходит по NextId.
Истинное условие вызывает ChildId и передаёт **свой** RepeatTimes.
Успешное действие при переданном значении `1` очищает собственный бит
активности. Затем вызывается его ChildId с тем же значением, после него — NextId.

| RepeatTimes родительского условия | Действий за три обновления AP |
|---:|---:|
| `0` | 3 |
| `1` | 1 |
| `2` | 3 |
| `255` | 3 |

Собственный RepeatTimes действия здесь не определяет отключение:
действие с байтом `255` отключилось при родительском `1`, а действие с
байтом `1` оставалось активно при родительском `2`.
Вложенное условие передаёт собственное значение: родитель `1`, вложенное
условие `2` дали три исполнения действия.

Причина видна в оригинальном коде. После рекурсивного обхода условие
могло бы вызвать `508640` — уменьшение RepeatTimes с отключением при нуле.
Однако вызов зависит от ненулевого результата рекурсии, а все обычные
возвраты `4B0CC0` проходят через `XOR EAX,EAX` по `4B0D69`.
В 99 обновлениях вызовов `508640` нет; байты RepeatTimes не меняются.

Таким образом, в этом AP-обходе `2` не задаёт лимит «два запуска».
Вывод ограничен обычными путями данной функции и данным EXE. Другие
обходчики триггеров и версии игры могут вести себя иначе.

## Узлы из настоящего 3DLevelTriggers.kld

Три сценария используют неизменные 16-байтовые payload исходных узлов:

- условие ID `1`, Type `34` (справочное имя LEVEL_TIME), сравнение `4`,
  значение `0`, ChildId `FFFFh`, RepeatTimes `1`;
- действие ID `FFFFh`, Type `45` (SET_SYSTEM_MESSAGES), available `0`,
  RepeatTimes `0`.

К payload добавлен отдельный подготовленный runtime DWORD активности.
AP и Session подготовлены явно. Это исполнение настоящих узлов через
AP-обход, а не доказательство их естественного AP-вызова на карте 3DLevel.

`518270` сравнивает параметр DWORD `+4` с DWORD времени из Session `+4`,
полученным через настоящую `517490`. Сравнение знаковое:

| DWORD времени | Результат «больше 0» | Изменение World `+72A1h` |
|---:|---|---|
| `0` | ложь | `A7h` сохраняется |
| `1` | истина | `A7h → A5h`, один раз |
| `80000000h` | ложь | `A7h` сохраняется |

В выбранном обработчике преобразования через TPS нет. Внешние настройки
единиц времени и нормальный ход часов этим экспериментом не проверяются.

Дополнительно исполнены ветви действий `44`, `45`, `51`, записывающие
маски `01`, `02`, `04` в World `+72A1h` с сохранением остальных битов.
Имена SET_SYSTEM_MESSAGES / SET_TIMER_SPEECH остаются справочными:
конечные потребители сообщений и речи на этом этапе не прослежены.

## Неизвестные флаги AP 04h и 08h

Матрица 16 сценариев — флаги `00/04/08/0C` и повторы `0/1/2/255` —
прошла три полных обновления на каждый вариант. Ни одного чтения AP `+32h`
в этих путях нет; флаги сохраняются, результаты совпадают.

**Назначение 04h и 08h остаётся неизвестным.** Это проверка выбранного
полного обхода, а не доказательство неиспользования во всей игре.
Прежние факты сохраняются: writer Pro ставит 04h при наличии NextID;
RC3 подписывает 08h как Hero Gate. Эти факты не задают игровую семантику.

## Пересборка и подключение к своему редактору

852 новые точечные пересборки выполнены только в памяти:
428 правок RepeatTimes в 107 непустых Triggers и 424 правки флагов в
106 контейнерах AP. Две пустые секции Triggers проверены тождественно.
Всего просмотрено 25 588 узлов и 3 501 AP. AutoSave AP проверяется по
явно указанному замороженному снимку этапа 47, а не по живому автосохранению.

Сохранены все остальные байты: заголовки, счётчики, ссылки, порядок,
padding и неизвестные биты. Обратная правка восстановила исходный контейнер;
публичный decode→rebuild прошёл для каждой изменённой секции.

Для редактора:

- сохранять RepeatTimes как исходный байт; правила AP не заменяют общую
  семантику всех триггеров;
- сохранять неизвестные флаги AP;
- показывать диагностику отсутствующих ссылок, дубликатов и циклов;
  автоматическое переназначение ссылок меняет поведение;
- не записывать runtime DWORD активности в файл.

Новый компонент: `ap_trigger_tree_semantics`, файл
`ap-trigger-tree-semantics.json`. Пакет содержит 135 компонентов;
прежние 134 схемы сохранены побайтно. Исторические layouts, codec и
effective-представления не изменены. Подтверждена сохранность 420 источников
и семи EXE. Существенные неизвестные остаются, общая оценка около 75%.
