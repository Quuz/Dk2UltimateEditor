## Что показывает оригинальный редактор

В интерфейсе диапазон каждого канала0..511. Getter вычисляет `byte + 256 * bit`. Например, исходная Water имеет RGB-байты100/44/250 и дополнительный бит G: в редакторе это100/300/250. Lava содержит44/100/20 и дополнительный бит R: в редакторе300/100/20.

Полные нативные setter/getter функции `420320/420350`, `420370/4203A0`, `4203C0/4203F0` проверены исполнением. Setter берёт младшие16 бит аргумента, записывает младшие8 и устанавливает внутренний флаг800/1000/2000, если unsigned WORD больше255. Getter гарантирует значимые младшие16 бит результата; верх EAX не следует трактовать как результат.

Диапазон GUI и поведение низкоуровневого setter различаются:512 превращается в байт0 с установленным битом, читается как256;65535 читается обратно как511; DWORD65536 обрезается до WORD0. Эти примеры не означают, что GUI разрешает такие значения.

Статическая цепочка GUI подтверждена по первичным инструкциям:

- `46D3B0`: шесть DDV проверок0..1FF. RGB controls1054/1055/1056 и2043/2046/2049, чекбоксы2040/2041. Ресурсы диалогов143/320 имеют подписи Terrain Light/Ambient Light.
- `46DEB0`: заполнение панели из моделей цвета `2E0/2FC` через три getter, enable BOOL из `3C8/3CC`.
- **`46E410`**: фактический commit панели через шесть setter и копирование enable BOOL. Ранее сохранённый файл с именем `editor-phase8-terrain-panel-save.txt` содержит `46E350`, освобождающий объект панели; его нельзя использовать как доказательство commit.
- `49F5E0`: промежуточные RGB-байты сначала передаются setter, затем decoder `425640` восстанавливает биты цвета из Flags.
- Writer `4A7690` копирует байты модели `2F8..2FA` и `314..316` в raw RGB и получает raw Flags через `4254C0`.

Эти большие UI/callback/writer функции статически изучены и сверены с EXE; целиком в этом этапе они не исполнялись.

## Что загружает игра

В проверенном `DKII-DX.exe`, фрагменте `4F69A0..4F6AB6` функции `4F66E0`, правило отличается:

1. Если presence соответствующего канала ненулевой, BYTE промежуточной записи копируется в runtime WORD с расширением нулями.
2. При установленном дополнительном бите к runtime WORD добавляется **255**, а не256. Сложение выполняется по модулю65536 и не зависит от presence канала или общего enable группы.

| BYTE | Дополнительный бит | Getter редактора | WORD после полной загрузки игрой |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 255 | 0 | 255 | 255 |
| 0 | 1 | 256 | 255 |
| 44 | 1 | 300 | 299 |
| 255 | 1 | 511 | 510 |

Таким образом, реальные Water/Lava имеют канал300 в редакторе и299 в загруженном определении игры. Это сравнение чисел определения, **не измерение конечного изображения**. Дальнейшие ветвления освещения, преобразования каналов и renderer в этом этапе не проверены исполнением. Нельзя автоматически менять исходные байты, пытаясь компенсировать расхождение.

Terrain RGB проходит через mid293/294/295, presence8C/90/94, в runtime WORD1AF/1B1/1B3. Ambient: mid2B9/2BA/2BB, presence9C/A0/A4, runtime1B9/1BB/1BD. PresenceB0 заменяет runtime Flags17B на mid248; при отсутствии этого presence используются прежние флаги.

При частичном обновлении, если канал отсутствует, но его дополнительный бит включён, повторный вызов снова прибавляет255 к прежнему WORD. При полном обновлении presence каждого канала сначала восстанавливает исходный BYTE, накопления нет. В промежутке между тройками presence98 управляет копированием mid2DC в runtime1B5; назначение этого соседнего DWORD остаётся неизвестным.

Статические потребители `441CD0` и `43E440` связывают эти WORD с Terrain light и ambient путями. Первый имеет условную замену RGB глобальными значениями, второй в одной ветке сужает WORD до BYTE. Поэтому loaded WORD нельзя без дополнительного анализа выдавать за итоговую яркость пикселя. Кандидат `4FF5C0` с совпавшим смещением1B9 относится к таблице процентов уровней существ и исключён.

## Почему нужно сохранять исходные Flags

Полные decoder `425640` и encoder `4254C0` проверены вместе в38 нативных случаях. Для **decoder→encoder без GUI commit**:

- прямые биты сохраняются по маске `0x3187FFFF`;
- дополнительные Terrain RGB биты сохраняются только при enable `0x10000000`;
- дополнительные Ambient RGB биты сохраняются только при enable `0x20000000`;
- `0x00400000/40000000/80000000` не имеют представления в этой модели и теряются.

Максимальная выходная маска `0x3FBFFFFF`. Это не полный цикл GUI: `46E410` дополнительно безусловно обнуляет model384, соответствующий raw флагу `0x10`, и меняет другие свойства. API `flags_projection` воспроизводит только decoder→encoder, а не весь GUI.

В3306 исходных записях из82 файлов этот decoder→encoder флаги не изменил. Но это не делает преобразование безопасным для иных входов: синтетические единичные биты подтвердили потери. Расширенные RGB-биты присутствуют в160 записях:82 Terrain R,78 Terrain G; остальные четыре канала с установленным битом в этом корпусе не встретились. Их реализация подтверждена машинным кодом, а не частотой встречаемости.

## Интеграция и проверки

`terrain-lighting-semantics.json` — компонент59 пакета `editor-format-package.json`. `native_terrain_lighting.py` предоставляет:

- `view(raw552)` — исходные флаги/байты, диапазон редактора и WORD после полной загрузки каждого канала;
- `patch_channel(raw, "terrain"|"ambient", channel0..2, value0..511)` — один RGB-байт и один соответствующий бит; enable и все остальные данные сохраняются;
- `flags_projection(flags)` — отдельная, явно вызываемая нативная decoder→encoder проекция;
- `game_colour_fragment(mid736, previous460)` — проверенный фрагмент загрузчика с presence и16-битным сложением.

`phase48-validation.json`:99 нативных случаев (21 setter/getter,38 flag codec,40 loader fragment),9361 API проверка,24 дополнительные partial-presence проверки,216 точечных пересборок контейнеров в памяти,82 полных побайтовых roundtrip.17 полных диапазонов функций сверены с повторной дизассемблировкой, памятью Ghidra и исходными PE. Сравниваются весь28-байтовый объект цвета, весь3D4-байтовый объект модели либо все460 байт runtime определения, в зависимости от случая.
