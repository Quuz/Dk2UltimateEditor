# Старый EXE: CreatureSpells, состояние Action Point и Variables

27 октября 2026, этап52. Продолжение проверки неизвестных игровых полей после RC3. Новый компонент63 — `version_crosscheck_semantics` в `editor-format-package.json`.

Старый EXE определяется SHA-256 `93e826a142f677ef5120699feddb0572799d93399167ef1d05ec4b48a8b2a342`. Он предоставлен в папке `DKII 13`, но ресурс версии отсутствует: происхождение именно от retail1.3 этим исследованием не доказано. Текущий DX определяется SHA-256 `d7a8b854e4e4f02709eba271bead6fe2307dd6e332b5a96e70857e5b0e19fb8a`. Выбирать смещения по имени папки нельзя.

## CreatureSpells: одинаковый converter, разное условие контрольной суммы

| Путь | Старый EXE | Текущий DX |
|---|---:|---:|
| Инициализатор346 байт |5607D0|56A490|
| Converter raw266 → intermediate346 |5608A0|56A560|
| strncpy |627CD0|6361A0|
| Loader definition70 байт |4EC440|4F7860|
| Ticks per second |6DD618|6F2590|

Полные198-байтовые инициализаторы побайтно одинаковы. В полных360-байтовых converters отличается только displacement одного CALL; обе254-байтовые реализации вызываемого strncpy побайтно одинаковы. Это равенство конкретных полных функций, не утверждение о равенстве всего EXE или всех путей чтения файлов.

Старый loader4EC440 **безусловно** обнуляет DWORD definition+1B и суммирует unsigned bytes всех346 байт intermediate. Текущий4F7860 выполняет это при global6FCDCF==0, а при ненулевом значении оставляет предыдущую сумму. Изменение TPS не меняет этот принцип; TPS участвует отдельно в преобразовании времени. Проверка старого loader варьировала также адрес переключателя DX, но в теле старой функции такой проверки нет.

Сумма definition+1B — игровое значение в памяти. Это **не поле checksum внутри raw266** и не сумма сырых байтов файла. Для совместимого воспроизведения нужны результат converter, фактический intermediate346 и состояние загрузчика.

Шесть initializer-прогонов и12 converter-прогонов сравнивают все346 байт при seeds00/A5/FF и хвостах00/FF.36 полных loader-прогонов сравнивают все70 байт: два EXE, gate0/1, три пары AlternativeShot/Room0/0,36/4,255/255 и TPS0/20/FFFFFFFF. Resource provider равен null, ветви успешной загрузки ресурсов не проверялись.

В обоих просмотренных loaders mid138/139 — rawE8 Alternative Shot ID иrawE9 Alternative Room ID — не назначаются смысловым полям70-байтового определения. Их изменение влияет на пересчитываемую сумму. **Игровой механизм замены Shot по этим двум ID остаётся неизвестным.** Отдельный rawEE predicate с этим не смешивается; см. `SPELL_ALTERNATIVES_RU.md` и `SPELLS_RUNTIME_RU.md`.

## Action Point: runtime64 и локальное состояние9 — разные уровни

В старом EXE найдена цепочка RTTI `.?AVCActionPoint@@` → vtable65E73C → методы сериализации. У DX соответствующий vtable66D7BC. Оба RTTI-описания, complete object locators и таблицы виртуальных функций считаны из Ghidra и сверены с PE.

Старый factory4AEA80 передаёт allocator размер40hex/64, вызывает constructor4AE070 с присвоением vtable65E73C, затем init4A6F60. Четыре полных исполнения проверяют два успешных варианта с seeds00/A5, выключенный gate и отказ allocator. Сравниваются все64 байта, запрошенный размер, выходной указатель и счётчик creator+32. Base constructor, base init и allocator заменены стендовыми функциями; реальная регистрация в игровом мире не воспроизводилась.

| Локальное runtime-поле | Смещение | Ширина | Native diagnostic label |
|---|---:|---:|---|
| Счётчик прохождений |2E|WORD|CreaturesPassedThrough|
| Ожидание |30|WORD|WaitTimer|
| Флаги |32|BYTE|Flags|
| Следующая точка |33|BYTE|NextWaypointId|
| Корень триггеров |34|WORD|TriggerRoot|
| Повторение корня |36|BYTE|TriggerRootRepeatCount|

Имена взяты из строк, на которые ссылаются реальные диагностические методы old4A7700 иDX4B0B90;18 строк проверены непосредственно в PE. Название диагностического счётчика само по себе не заменяет проверку всех его игровых потребителей.

State writers old4A6FB0 иDX4B0460 записывают IDBYTE37, четыре байта верхнего левого угла38, четыре байта нижнего правого3C, вызывают base writer, затем копируют **все9 байт2E..36**.12 полных исполнений сравнивают18 локально переданных байт, четыре обращения к I/O и неизменность всей64-байтовой модели. Base writer и I/O подставлены: полный формат savegame этим не расшифрован.

State readers old4A70A0 иDX4B0550 сначала вызывают base reader. Если тот возвращает0, локальное чтение и post-load не выполняются. При успехе копируются9 байт2E..36, затем вызывается post-load с позицией1A/1E и Z=0.12 полных исполнений сравнивают все64 байта и число локальных чтений/post-load. Base reader, I/O и post-load — подстановки; пространственная регистрация не проверена.

В локальном state-пути нет маскирования Flags: бит08 и остальные биты байта сохраняются. Оба отдельно просмотренных setter08 используют runtime32. Это усиливает доказательство хранения флага, но **не устанавливает игровой эффект Hero Gate08**.

RawC5 карты имеет56 байт полезной части, FlagsWORD18 и ожиданиеWORD16. RuntimeAP64 имеет FlagsBYTE32 и ожиданиеWORD30, уже после преобразования времени. Локальные9 байт сохранённого состояния нельзя копировать в rawC5. Различия runtime-смещений Creature из этап47 не означают такой же сдвиг у Action Point.

## Variables61–64: старый обработчик тоже пустой

Полные initializers old50E860 иDX51AA90 проверены в эмуляторе: четыре20-байтовые строки таблиц содержат61/62/63/64, callback и три нуля. Старые строки начинаются697914, текущие6A611C.

Callbacks old511940 иDX51DC20 читают три DWORD intermediate+10/+14/+18 и вызывают old4EB320 либоDX401200. Обе вызываемые функции — единственная инструкция `RET`. Шесть полных callback-прогонов сохраняют32-байтовый вход и возвращают1 без подстановки этих helpers. Поэтому поиск через старый EXE не дал здесь нового назначения. Это относится к четырём callbacks двух точных EXE; удалять соответствующие записи Variables из файлов нельзя.
