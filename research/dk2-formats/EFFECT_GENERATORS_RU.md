# Things CB: генератор эффектов

Этап37, 26 октября 2026. Расшифрованы загрузка, область появления, четыре слота эффектов, частота и сохранение генераторов. Первичные источники — код предоставленных `DKII-DX.exe` и `DK2 Editor pro.exe`; их хеши закреплены в `effect-generator-semantics.json`. Полный игровой запуск с изменёнными данными не выполнялся.

## Физическая запись

В секции Things190 после заголовка56 идут записи с envelope8: `tag:u32=203 (CB)`, `payloadBytes:u32=36`, далее payload. Все смещения таблицы относятся к payload; целая запись занимает44 байта.

| Смещение | Байт | Хранение | Подтверждённое назначение |
|---|---:|---|---|
| `00` | 4 | DWORD | X клетки; позиция игры `(X<<12)+2048`, с переполнением32 бит |
| `04` | 4 | DWORD | Y клетки; такое же преобразование |
| `08` | 4 | DWORD | Неизвестное Z: попадает в intermediate/checksum, но placement задаёт Z=0 |
| `0C` | 4 | DWORD | Неизвестные флаги: converter переносит через OR; данный callback игры их не применяет |
| `10` | 2 | unsigned WORD | Width: ширина области появления, в клетках |
| `12` | 2 | unsigned WORD | Height: высота области появления, в клетках |
| `14..1B` | 8 | 4 unsigned WORD | Четыре слота Effect ID, включая нулевые |
| `1C` | 1 | BYTE | Frequency: множитель global ticks-per-second для следующего deadline |
| `1D` | 1 | BYTE | ID генератора |
| `1E..23` | 6 | raw bytes | Неизвестный хвост; назначение не установлено, нули не гарантированы |

Диагностика игры `4B1CF0` прямо подписывает runtime WORD40/42 как Width/Height, BYTE3A как Frequency, DWORD3C как Active, BYTE3B как Flags, BYTE44 как Id. Runtime Flags3B не следует отождествлять с raw DWORD0C: проверенный загрузчик этого не делает.

## Путь загрузки

Парсеры игры `570630` и редактора `430DB0` при наличии callback всегда запрашивают36 байт, независимо от envelope payloadBytes. Проверки с declared35/37 использовали безопасный буфер36; поведение реального усечённого файла не исполнялось. Наш codec требует точную длину и envelope, чтобы не воспроизводить это чтение за объявленной границей.

Intermediate76 содержит10 DWORD признаков наличия, XYZ по28/2C/30, flags34, width38, height3A, effects3C..43, frequency44, id45. Raw хвост1E..23 туда не копируется; последние6 intermediate bytes остаются от инициализации. Converter редактора `42FB50` сам не очищает их и выполняет `midFlags |= rawFlags`; оба полных parser сначала обнуляют весь intermediate.

Game callback `521380` сначала передаёт intermediate76 в checksum helper, затем создаёт69-байтовый генератор через `4B81E0`, `4B7560`, `4B19A0`. X/Y становятся центром клетки Q12, Z=0. Width/height остаются исходными WORD; active=1, deadline=0, runtime flags=0. После успешного создания копируются четыре effect WORD и frequency BYTE. Raw DWORD0C не отключает генератор. Это вывод о конкретной цепочке загрузки; историческое назначение rawFlags остаётся неизвестным.

## Что происходит при обновлении

Полная функция `4B1B60` проверена с контролируемыми внешними вызовами.

1. Если Active=0, возвращается без обращения к часам.
2. Проверяется **unsigned `now > deadline`**. Равенство не запускает попытку; при начальном now=0 и deadline=0 эффекта ещё нет.
3. Выбирается случайный индекс0..3. Если выбранный Effect ID=0, попытка заканчивается, deadline не меняется. Ненулевые слоты не собираются в отдельный список; одинаковые ID могут занимать несколько слотов.
4. К базовым X/Y прибавляются `random(width*4096)` и `random(height*4096)`. Это область в положительном направлении от центра исходной клетки, а не симметричный радиус. Сложения32-битные.
5. Вызов world virtual20C проверяет позицию. Ненулевой результат отменяет попытку без изменения deadline. Назначение проверки не подменено предположением о конкретном типе поверхности.
6. Выбирается угол0..2047; world virtual38C получает Effect ID WORD, owner WORD из global6F2548, позицию и указатель на угол.
7. Даже если создание вернуло ошибку, функция назначает `deadline = now + Frequency * globalTPS` по модулю2^32. Возврат создания не проверяется.

Поэтому Frequency задаёт задержку после прохода до вызова создания, но не гарантирует строго периодическое появление. Пустой слот и отклонённая позиция оставляют таймер просроченным. Frequency=0 допускает новую попытку только при строго большем now, а не повторно на том же значении часов.

Отдельно проверен настоящий RNG `5558D0`: при bound=0 он пишет диагностическое сообщение и возвращает0 без сдвига seed. Это позволяет нулевой ширине/высоте давать нулевое смещение в исследованном пути. Для ненулевого bound, при выключенном debug switch, используется LCG `seed*1664525+1013904223`, ROR13 и unsigned остаток от деления. В тестах tick RNG заменён управляемым provider; реальный RNG имеет пять отдельных проверок.

## Что меняет Editor Pro

Callback `491F20` и настоящий конструктор `41F810` проверены вместе с setters. Модель48: X4, Y8, ID18, frequency20, width22, height24, effects26..2D. Z не переносится в модель этой цепочкой. Flags setter `401A50` — только RET4, getter `41FA70` всегда возвращает0.

Width setter `41F990` сравнивает signed32 `(X_DWORD + requested_WORD)` с zero-extended low16(mapWidth). При меньшем значении сохраняет requested; иначе сохраняет low16(mapWidth-low16(X)-1). Height `41F9E0` аналогичен. При обычных координатах это ограничивает размер значением `dimension-origin-1`. Для координат вне карты возможен wrap до65535: это не универсальный clamp к нулю. Наш lossless loader не применяет эту нормализацию автоматически.

Writer `4947C0`, участок4950C9..4951BB, пишет X/Y, **Z0 и flags0**, четыре эффекта, width/height, frequency и ID. Шесть байт хвоста в цикле CB не назначаются. Шесть прогонов полного writer при прочих количествах типов0 подтвердили сохранение seed00/A5/FF в этих байтах. Это ограниченный факт о данном пути и начальном scratch; другие предшествующие записи могут оставить иной хвост.

## Наблюдения по файлам и проверка

В109 Things файлов карт и AutoSaveThings проверено80 генераторов, все payload36. Raw Z/flags у всех0. Frequency:1 у65 записей,7 у2,10 у4,15 у9. У32 генераторов width=height=0. У78 есть одновременно пустые и непустые слоты; всего232 нулевых слота из320. Игра сохраняет их участие в выборе.

Ненулевой хвост найден у14 записей:11 содержат `12 00 00 00 00 00`, ещё три имеют другие значения. Всего пять вариантов хвоста. Это основание сохранять его целиком; сами ненулевые значения не доказывают игровое назначение. В картах с найденными парными Map-файлами проекция bounds setters не изменила наблюдаемые width/height.

`phase37-validation.json` фиксирует:

- 62 эмуляции:8 parser,3 converter,4 game callback/create/init,6 editor callback/constructor,14 tick,16 bounds setters,5 RNG,6 полного writer.
- 1137 проверок API и границ,2880 точечных изменений в памяти с точным сравнением всего контейнера,110 точных parse→pack файлов Things.
- 1703 инструкции первичного assembly,23 повторных disassembly и23 диапазона live Ghidra memory, совпавших с исходными PE.
- Хеши всех прежних17 основных входов и двух EXE совпадают. Изменённые игровые файлы не создавались.

В эмуляции заменены I/O, выделение памяти, base initialization, регистрация в мире, checksum и фактическое создание визуального эффекта. В editor callback заменены base constructor, координатные virtual setters, parent provider и map insertion; генераторный constructor/bounds/effect setters исполнялись настоящие. Полный writer проверяет payload CB; прочие count/date/file helpers заменены. UI-диапазоны Frequency/ID и полный gameplay этим этапом не подтверждены.

## Для нашего редактора

Машинная схема — `effect-generator-semantics.json`, компонент48 пакета `effect_generator_semantics`. `native_effect_generators.py` разделяет `record_view`, `intermediate`, `runtime_projection`, `tick_projection`, `editor_extent`, `writer_payload` и `patch_raw`. Обычное сохранение должно использовать исходные44 байта и точечные изменения выбранных полей. `writer_payload` воспроизводит описанное поведение Editor Pro только при явном выборе совместимости и явно заданном шестибайтовом scratch.

Неизвестными остаются историческое назначение DWORD08/DWORD0C и хвоста, правила уникальности ID и другие потребители runtime Active/Flags. Сохранение поля и проверка конкретной ветви не означают, что вся система эффектов полностью расшифрована.
