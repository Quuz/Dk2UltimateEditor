Этап54 проверяет полные функции DX `4B7CD0 → 4B7D60 → 4AAC90` и их вызов из обеих функций применения KeeperSpells. В этапе53 сама фабрика была тестовой заменой; теперь исполняются исходные фабрика, конструктор и инициализатор. Замены остаются у базового объекта, выделения памяти, мира, графики, движения и звука. Это исполнение машинного кода в памяти Ghidra, без запуска игры.

Усиленный KeeperSpell сохраняет основной тип создаваемого Shot. Выбор BonusShotId используется для проверки ненулевого ID и предварительного lookup, но фабрика получает основной ID. Инициализатор снова запрашивает описание по этому основному ID и сохраняет указатель в объекте. Затем функция заклинания подставляет выбранные Data1/Data2. При реализации редактора нельзя автоматически копировать BonusShotId в основной ShotId.

|---|---|
| Размер выделения фабрики | `0x173` = 371 байт |
| Тип объекта | Основной ID → `Shot BYTE124` |

Смещения в таблице — смещения памяти, не KWD. В файле Shots Data1/Data2 расположены по `0x98/0x9C`, ProcessType по `0xC7`; описание значений обработчиков уже вынесено в `shot-semantics.json`. У KeeperSpells основной ID — raw `0xF0`, дополнительный — `0x113`, основные параметры — `0xD0/0xD4`, дополнительные — `0x114/0x118`. Каждое поле сохраняется отдельно вместе с неизвестными байтами.

В составных опытах указатели основного и дополнительного описаний различаются. Для основного задан ProcessType9, для дополнительного0. После применения указатель объекта остаётся основным, хотя Data1/Data2 заменяются дополнительными. Это подтверждает источник описания. Сам callback ProcessType здесь не вызывается; результат его игрового действия этим опытом не установлен.
