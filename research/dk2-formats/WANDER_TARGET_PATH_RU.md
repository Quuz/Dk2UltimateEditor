# Выбор цели блуждания и принятие пути в состоянии 87

Этап 144, 31 октября 2026. Выполнены оригинальные `4808E0` и `480A00`, запросы CWorld/CMap, нативная инициализация NAV и принятие пути через `471890 → 4D0F60`. Исследован точный предоставленный `DKII-DX.exe`, SHA-256 закреплён в `wander-target-path-semantics.json`.

**Байт размещения с native-подписью WanderRadius по-прежнему не получил подтверждённых игровых единиц или назначения.** Новый результат отделяет его от действительно работающего выбора радиуса в состоянии 87.

## Радиус состояния 87

Оригинальный initializer `47BBE0` регистрирует callback `4808E0` для состояния 87, категория 0. В новых сценариях callback вызывается непосредственно с подготовленным встроенным AI-контекстом `Actor+24E`. Обычный World AI scheduler не исполняется.

Перед поиском вызывается `496D00`: при DWORD `Actor+3A9`, отличном от 0 и `15h`, callback сразу возвращает true, не расходуя RNG. Назначение всех возможных значений этого DWORD здесь не переопределяется.

В рабочей ветке:

1. `RNG(4)+4` выбирает радиус 4–7 клеток. Это константное правило кода, не значение WanderRadius из Things.
2. Helper `480A00` ищет цель на кольце. Если не нашёл, callback уменьшает радиус и повторяет поиск до 1 включительно.
3. Если все попытки неудачны, берётся текущая позиция существа.
4. `RNG(9)` выбирает внутриклеточные смещения 682/2047/3412 по каждой оси.
5. Исходный `471890` запрашивает движение. На открытой карте настоящий path controller принимает маршрут и AI переходит из 87 в 6; состояние продолжения сохраняется как 87.

Успешный поиск возвращает центр выбранной клетки с Z=0. При запасном варианте сохраняется исходное Z существа. Координаты Actor в этих опытах остаются прежними: проверены выбор цели, маршрут и переход состояния, **не шаг перемещения, анимация или достижение конечной точки**.

Один общий RNG хранится по `CWorld+15A0`. Выбор радиуса, helper и jitter расходуют один поток. Выражение `World+568` в старой декомпиляции содержало DWORD-указатель: машинные инструкции и наблюдение аргумента `5558D0` подтверждают именно байтовое смещение `15A0`. Это не второй RNG по байтовому адресу568.

## Порядок клеток helper480A00

В проверенной ветке список комнат владельца пуст, поэтому дополнительный путь выбора комнаты не даёт цели. Helper всё равно выполняет предусмотренный RNG(8), затем берёт начальный индекс `RNG(8*r)`.

Для центра `(cx,cy)` и шага от 0 до `2*r-1` четыре стороны вычисляются так:

| Сторона | X | Y |
|---:|---|---|
| 0 | cx+step−r | cy−r |
| 1 | cx+r | cy+step−r |
| 2 | cx+step−r | cy+r |
| 3 | cx−r | cy+step−r |

В выбранных обычных координатах перебор идёт от случайного индекса до конца и не возвращается к началу. Например, при центре(10,10), r=4 и старте4 единственная открытая клетка(7,6) не проверяется. Это не равномерный выбор из всех доступных точек кольца.

При старте0 северо-западный угол(6,6) встречается дважды, а юго-восточный(14,14) не встречается. Контроль с единственным открытым юго-восточным углом вернул отказ. Контроль с открытым повторяющимся углом после старта4 получил его при обходе четвёртой стороны. Полные последовательности запросов границ записаны наблюдателем исходного `509090` и сопоставлены с независимой проекцией.

Это точная особенность выбранной ветки. У helper есть дополнительная ветка для специального сочетания координат, а также поиск по непустому списку комнат; они новыми сценариями не покрыты.

## Фильтры и запасной вариант

Исполняются настоящие запросы CWorld:

- `509090`: проверка границ по размерам карты.
- `509200`: чтение NAV bit8; установленный бит исключает кандидата.
- `509230`, `508FC0`: наличие комнаты и получение клетки.
- Сравнение младших 12 бит owner WORD клетки с владельцем существа; флаг `Actor+3E6`, маска4000, допускает обход этого сравнения.
- `453600`: проверка цепочки объектов клетки на блокирующий объект.

В новых fixtures нет room tags и блокирующих объектов: ветки их успешного обнаружения не исполнены. На чужой земле без флага4000 все кольцевые попытки отказали. После этого callback выбрал jitter внутри текущей клетки и path controller принял этот запасной маршрут. Следовательно, отказ кольцевого фильтра владельца не равен отказу всего callback.

На полностью заблокированной NAV callback также дошёл до запасного запроса, но native preflight его отклонил, состояние осталось87. На открытой карте семь принятых запросов в девяти callback-сценариях дали состояние6. Один callback вернулся раньше поиска из-за DWORD3A9; ещё один получил отказ NAV.

## Граница WanderRadius из файла

Прежние этапы подтвердили raw-байт Neutral C6 `+17`, Good C7 `+1D` и тот же байт внутри32-байтовых Good-слотов C9. Он сохраняется в DX Actor BYTE418; старый точный профиль использует BYTE417. Новые сценарии начинают с подготовленного Actor, а не повторяют полный raw Things loader/factory.

В новой полной паре изменён только Actor418:0→255. Выбранная цель, RNG, NAV, path controller, переход87→6 и все остальные подготовленные области памяти совпали. Среди всех17 принятых путей чтений этого байта не обнаружено. Это усиливает границу доказанного для состояния87, **но не доказывает глобальную неиспользуемость байта**. Его нельзя автоматически считать числом клеток, приравнивать к hardcoded4..7 или нормализовать0 как «отключено».

Актуальное `effective_thing_layouts` сохраняет физические поля и их исторические имена, добавляя native-подпись и явную отметку неизвестных единиц/эффекта. Аннотации даны для C6, C7 и16 слотов C9; новых игровых имён неизвестным полям не присвоено.

## Проверки и пределы

- 17 различных native-запусков:8 полных helper-сценариев и9 полных state87-сценариев. Семь native path requests приняты.
- 6 независимых Ghidra CPU контролей:326 областей,930082 байта совпали, включая настоящий return корневой функции.
- Полная пара Actor418:54 области/187838 байт; различается только сам байт.
- 60 полных диапазонов исполнявшихся оригинальных функций/8535 разных PC, две native vtable и две switch-таблицы сверены с PE/Ghidra. Полное тело функции не означает исполнение каждой её ветки.
- 102 точные пересборки Things-контейнеров в памяти:29 C6,68 C7,5 занятых слотов C9. Меняется только выбранный raw-байт на53; все остальные байты сохраняются, обратная правка восстанавливает исходную запись.
- Ещё7 файлов из109 не содержат поддерживаемого занятого носителя этого байта: они проверены на сохранность, но не посчитаны успешными правками.
- Общий список SHA-сохранности теперь309 источников и7 путей EXE. Добавлены109 Things-файлов с историческими хешами этапа75; прежние200 источников сохранены.

Для callback-наборов исполняются исходные AI initializers4798F0/47BBE0 и NAV setup4CE690/4CE740/4C8F30/4CEF20 для32×32. AI-таблицы целиком совпадают с независимыми проекциями. NAV buffer имеет2048 элементов,59396 байт плюс64 защитных байта; защитный хвост сохраняется. CWorld и Creature vtables оригинальны; внешнего исполняемого кода в принятых путях нет.

Ранняя проба без инициализации NAV остановилась на4C9934 с отсутствующей памятью. Она исключена из принятых17 сценариев и не интерпретируется как ошибка игры. Подготовленные Actor/definition/World/карта — отдельное ограничение: новые raw Creatures/Things loaders, полный KLD bootstrap и обычный scheduler не исполнялись.
