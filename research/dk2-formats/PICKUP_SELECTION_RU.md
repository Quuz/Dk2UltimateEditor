# Creatures и Objects: запасной выбор кандидата под рукой

Этап153, 31 октября 2026. Машинная схема — `pickup-selection-semantics.json`,
компонент общего пакета — `pickup_selection_semantics`.
Точный исследованный DX EXE:
`d7a8b854e4e4f02709eba271bead6fe2307dd6e332b5a96e70857e5b0e19fb8a`.

Выполнена настоящая функция `44DEC0`, которую вызывает путь определения
содержимого под рукой `5992B0`, если требуется запасной поиск по клеткам.
Это конкретный путь проверки предполагаемого назначения Pick-Up Priority.
Сам **приоритет пока не расшифрован**: найденный алгоритм его не читает.
Главный графический поиск `572820` остаётся отдельным, ещё не выполненным путём.

## Связь с файлами

| Поле | Сырая запись | Определение игры | Что установлено новым этапом |
|---|---:|---:|---|
| Creature Pick-Up Priority | F55, BYTE | 6EB, BYTE | Не читается запасным поиском44DEC0. |
| Creature Ability Jump | EE0, DWORD | 75C, DWORD | Не читается этим путём; смысл прыжка не установлен. |
| Object PickUpPriority | 35D, BYTE | 112, BYTE | Не читается запасным поиском44DEC0. |
| Object Flags | 344, DWORD | F4, DWORD | Ветка объектов проверяет бит100 `CAN_BE_PICKED_UP`. |

Подписи первых двух полей взяты из оригинального редактора на прежних этапах.
Новая проверка не превращает название интерфейса в доказанную игровую формулу.

В каждом из34 сценариев выполнены **два полных Creature raw→definition** и
**один Object raw→definition**. Для существ использована исходная запись ImpID1
с явно заданными диагностическими значениями Priority/Jump. Для объектов —
настоящие записи Gold1, DoorKey17 или DungeonHeart13. Исходники на диске не
меняются. В памяти проверены rawF55→definition6EB и rawEE0→definition75C,
сумма промежуточной записи и полный результат объектного загрузчика.

Это устраняет неоднозначность «возможно, значение приоритета просто не было
загружено». Оно загружено настоящим кодом и доступно функции, но функция его
в выполненных ветках не читает.

## Обход кандидатов

Настоящий World возвращает размеры карты и указатели клеток через оригинальную
виртуальную таблицу. Проверяемая функция берёт целые координаты сдвигом12,
обходит включительно center−1..center+1 и ограничивает диапазон границами карты.
Обход: **Y по возрастанию, затем X по возрастанию, затем связный список клетки**.

Список задаётся WORD0 runtime-клетки; это тег первого экземпляра. Следующий тег
берётся из ActorWORD0C и разрешается через таблицу `6EE540`. Порядок подтверждён
по фактическим чтениям координат каждого кандидата в `44DFBC`, а не только
ожидаемому результату выбора. Проверены перестановка списка, конкурирующие
клетки и оба края карты.

Runtime-клетка занимает16 байт. Её список и смещения экземпляра **не являются
схемой четырёхбайтной клетки KLD**; неизвестный байт карты здесь не переименован.

## Метрика и пороги

Из разниц координат вычисляется:

```text
d = max(abs(dx), abs(dy)) + floor(min(abs(dx), abs(dy)) / 2)
```

Используются Q12 координаты мира. Это приближённая метрика, не евклидов круг.
Все сравнения со следующими порогами строгие:

| Ветка | Условие |
|---|---|
| Существо, обычный режим0 | d < 800hex |
| Запасной объект, обычный режим0 | d < 400hex |
| Объекты, режим1 | d < 800hex |

По одной оси 800hex соответствует половине клетки, 400hex — четверти клетки.
Не нужно интерпретировать это как круг того же радиуса. Проверены границы
Object3FF/400 и7FF/800, Creature800. Переполнение signed32/INT_MIN в разностях
не проверено; справочный API расстояния явно исключает границу INT_MIN.

## Кого выбирает функция

В обычном режиме0 побеждает **первое подходящее существо**. После выбора
следующее существо не заменяет его, даже если находится ближе. Поэтому
перестановка двух существ меняет результат; перестановка их Priority0/255 — нет.

До выбора существа объекты запоминаются по наименьшему расстоянию. Существо
имеет преимущество перед уже запомненным объектом. Если подходящего существа
вообще нет, возвращается ближайший запомненный объект.

В режиме1 существа игнорируются, среди подходящих объектов выбирается ближайший.
При равных расстояниях остаётся более ранний кандидат. Проверен режим1;
утверждение обо всех ненулевых значениях аргумента не делается.

Для существ оригинальные инструкции требуют ActorType0 и исключают:

- ActorBYTE36F==2Ehex;
- ActorDWORD3E6&200000;
- ActorDWORD25E в состояниях D6,4C,D1.

Отдельно выполнены случаи BYTE2E, флага200000 и состоянияD1. Два других
состояния подтверждены инструкциями, но динамически не прогонялись. Значениям
состояний и runtime-байту не присвоены новые смысловые имена.

Для объектов нужны ActorType2 и **бит100 в определении либо ActorBYTE12C==13
десятичное**. Исходный Gold1 проходит по биту; DoorKey17 не проходит; DungeonHeart13
проходит через исключение ID13, хотя соответствующий бит не установлен.

При успехе функция возвращает1 и записывает указатель выбранного экземпляра.
При неудаче возвращает0 и оставляет прежний выходной DWORD. Сохранность
контрольного значения CAFEBABE проверена на пустой сцене, отказах и порогах.

## Что именно исключено для Priority/Jump

Проверены CreaturePriority-пары0/255,255/0,1/40,128/255,255/255: остаётся первый
кандидат. Перестановка списка меняет выбор. ObjectPriority0/1/255 не меняет выбор
ближайшего объекта. Jump0/80000000/FFFFFFFF не меняет выбор.

Ни одна из34 трасс `44DEC0` не читает Creature6EB/75C или Object112. Существование
реальных игровых потребителей этих полей **по-прежнему открыто**. Из нового
результата нельзя делать вывод, что приоритет сломан или нигде не используется.

В оригинальном caller `5992B0` сначала есть CALL `572820` по адресу59968A,
позднее — CALL44DEC0 по599707. Первый путь перебирает графические экземпляры
через588A60 и вызывает их virtual0C. Оба caller-листинга и исходные байты
сохранены как статическое доказательство; полный графический путь не исполнялся.
Он остаётся конкретным следующим местом поиска потребителя приоритета.

## Проверки и интеграция

Получено34 полных прогона запасного поиска,68 полных Creature-загрузок и34
Object-загрузки. В8 независимых CPU-прогонах Ghidra совпали273 области памяти,
653000 байт. Сверены69 исходных диапазонов кода:67 выполнялись,2 — статические
caller/главный графический поиск. Покрыты3615 уникальных исполненных PC и1
блок виртуальной таблицы World.

Сцена подготовлена явно: World, Session, списки клеток и экземпляры Actor.
Новых фабрик Actor, обычного World scheduler, графики, клика и фактического
поднятия существа нет. Внешние адаптеры ограничены загрузочным graphics/sound IO;
оригинальные инструкции и виртуальные таблицы не заменяются. Чтения низкой
страницы допустимы только для настоящего FS:0 в загрузчике; runtime-данные не
подменяются ленивым отображением нулевой памяти.

Проверены328 точных правок приоритетов на82 контейнерах каждого семейства:
3734 записи Creatures и11756 Objects. Каждая правка меняет один выбранный байт;
обратная правка восстанавливает исходник, публичный decode→rebuild сохраняет
все неизвестные байты и заголовки.
