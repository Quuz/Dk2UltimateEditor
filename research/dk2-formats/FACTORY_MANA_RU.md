## Полный обработчик маны

Раньше этап23 проверял отдельные арифметические участки и часть handlers с явно заменёнными соседними helpers. Новые случаи выполняют **всю4C10E0 и настоящую4C17A0**. Подготовленные условия:нет активного вселения,способности или imp-стоимости; helper читает реальные агрегаты затрат из структурыигрока. Его нельзя считать константой в других состояниях.

| RuntimePlayer | Игровая роль, подтверждённая прежней диагностикой |
|---|---|
| DWORD82 | CurrentMana |
| DWORD86 | ManaIncreaseRate; множитель только положительного результата |
| DWORD9A | ManaGainTick |
| DWORD10D6 | Агрегат содержания |
| DWORD10DE | MaxManaGainPerSecond, потолок дохода |
| DWORD10E2 | ManaGainPerSecond, накопленный компонент дохода |
| DWORD10E6 | BasicManaPerSecond |
| DWORD10EA | MaxMana, предел запаса |
| DWORD10EE/10F2 | OneShotManaGain/OneShotManaLoss |

Вызов выполняет обновление при **unsigned `now >= low32(last+TPS)`**; равенство разрешает обновление. В конце успешной обычной ветки сохраняетnow в9A. Приnow100/TPS20,last81 обновления нет,last80 — есть.

Внутри проверенного пути:

```text
обнулить старые OneShotGain/OneShotLoss
cost1 = настоящая4C17A0(player)
gross = min_signed32(s32(extra + basic + cost1 + currentOneShotGain), ceiling)
cost2 = настоящая4C17A0(player)
net = s32(gross - cost2)
если net > 0: net = s32(net * rate)
применить дополнительные ветки mode3/setting0 или2
прибавить net кCurrentMana с32-битным переполнением
отрицательнаяветка ограничивает отрицательныйCurrentMana нулём
неотрицательнаяветка ограничивает CurrentMana сверхуMaxMana
```

Helper вызывается дважды; нельзя заменять весь расчёт одной формулой с постоянной ценой для произвольного мира. Агрегаты уже включают другие операции:например,прежняя регистрация содержанияTrap одновременно меняет10D6 и10E2. Подставлять «чистый доход местности» в10E2 без этих изменений нельзя.
