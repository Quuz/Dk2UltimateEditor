**Оба оригинальных загрузчика одинаково сохраняют младшие16 бит значений113/114. Их игровые формулы по-прежнему не установлены.** Новые32 сценария не подтверждают «+6% ко всем характеристикам/здоровью», даже несмотря на базовые имена параметров и текущее значение6.

Схема — `possession-scalar-version-semantics.json`, компонент `possession_scalar_version_semantics`. API для точечной правки — `native_possession_scalars.py`.

## Сырые записи и runtime-хранилище

Каждая запись Variables занимает16 байт: DWORD типа по0, DWORD значения по4, затем два сохраняемых DWORD по8/C. Это отличается от type224, у которого по4 находится StatId, а значение по8.

| Тип | Базовое имя | Runtime старого EXE | Runtime DX |
|---|---|---|---|
|112|PERCENTAGE_OF_MANA_GAINED_BY_SACRIFICING|WORD6DD978|WORD6F28F0|
|113|POSSESSION_FRIENDLY_STAT_INCREASE_PERCENTAGE|WORD6DD97A|WORD6F28F2|
|114|POSSESSION_FRIENDLY_HEALTH_INCREASE_PERCENTAGE|WORD6DD97C|WORD6F28F4|

Названия — перечисление базовой схемы. Тип112 проверен как соседний контроль хранения; новое доказательство не устанавливает весь его игровой механизм.

Настоящие callbacks510AF0 и51CD90 читают тип из подготовленного record+10h, значение из+14h: перед физической16-байтовой записью находится16-байтовый префикс. Native-тест передаёт этот буфер напрямую; весь файловый parser в новой композиции не выполнялся.

Обе исходные switch-таблицы отдельно сверены с EXE и программой Ghidra. Для113/114 таблицы выбирают соответствующие WORD-присваивания, поэтому это не вывод только из похожих абсолютных адресов.

## Что показало выполнение

На каждом профиле проверены112/113/114 со значениями0,6,FFFFh,ABCD0006h,FFFFFFFFh. Результат — соответственно0,6,65535,6,65535 в выбранном WORD. Остальные4094 байта подготовленного блока4096 байт не меняются.

В двух дополнительных последовательностях сначала загружается113, затем112,114 и повторно113. Все четыре callback возвращают1. Соседние WORD остаются независимыми, повторная113 заменяет только собственные два байта. Всего32 сценария содержат38 реальных callback-выполнений. Сравниваются весь блок переменных, входы с защитными байтами и выходы; игровые функции, таблицы или vtable не заменялись.

Эти операции устанавливают хранение, а не знаковость будущей игровой формулы. Полный исходный DWORD значения сохраняется нашим API; высокие биты нельзя автоматически очищать лишь потому, что этот загрузчик их не использует.

## Перекрывающее чтение не является потребителем113

В старой функции476600 обнаружено чтение DWORD по6DD978, охватывающее WORD112 и WORD113. По4767E9 выполняется `AND ECX,FFFFh`: все биты113 отбрасываются до дальнейшей арифметики. Аналогичный исходный фрагмент DX по47BB4E тоже сверён.

Поэтому числовое пересечение DWORD с113 не доказывает прибавку характеристик. Полная старая476600 сохранена как статический контекст; она не выдаётся за новый исполненный игровой процесс.

Новый линейный поиск старого EXE сохранил110 обращений в окрестности scalar-хранилища. Загрузки113/114 подтверждены, нового отдельного абсолютного игрового потребителя для них не установлено. Индексация, смещённые указатели, копии структур, косвенные вызовы и другие бинарники не исключены. Ответ Ghidra «нет ссылок» до разметки switch arms также не использовался как доказательство отсутствия обращения.

## Безопасная физическая правка

```python
from native_possession_scalars import view, patch_value_bits
info = view(raw_variables_record)
changed = patch_value_bits(raw_variables_record, 12)
```

API принимает только полную16-байтовую запись112/113/114 и меняет ровно DWORD+4. Значение12 здесь — пример физической записи, не обещание эффекта «+12%».

В557 ранее принимаемых Variables-контейнерах обнаружено по474 записи каждого из трёх типов, всего1422. Для каждой выполнены пять правок целого контейнера —7110 пересборок с повторным разбором. Тип, два непрочитанных DWORD, заголовки, соседние записи и порядок сохранены. Все источники сверены по историческим SHA. Предыдущие24 strict-refusal файла не исправлялись и не объявляются повреждёнными.

## Подтверждённый объём

Сверены три полных code extents и четыре блока таблиц/явных фрагментов. Из трёх функций исполнены два scalar-callback; old476600 исследована статически. Полное чтение диапазона не означает выполнения всех ветвей switch.

Ранние недопущенные MCP-вызовы измерительного стенда не вошли в32 принятых случая: стенду требовались настоящий function entry и обязательный аргумент registers. Это не сбой игры или её редактора. Принятые результаты сохраняются с точными входами, ожидаемыми буферами и SHA и не исполнялись повторно при публикации.

Настоящий процесс вселения, перечень затрагиваемых характеристик, здоровье, радиус воздействия и формулы113/114 остаются открыты. Ранее установленные скорость224/21, перезарядка224/31+210 и hardcoded снижение урона имеют собственные доказательства и не подменяются этими именами.
