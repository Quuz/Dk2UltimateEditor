## Установленные значения TileConstruction

Поле находится по **raw+0x395**, один байт. Подтверждённый путь — raw+0x395 → intermediate+0x469 → runtime+0x452; игровой конвертер **0x56DFD0**, loader **0x4EACC0**. Таблица Editor Pro по **VA0x513438** состоит из пар DWORD ID/указатель UTF-16, шаг8 байт, окончание по младшему байту ID0xFF. Инициализатор **0x466E90** читает эту таблицу и сохраняет ID независимо от индекса строки combo.

В baseline-перечислении не было трёх известных native-значений: **3 = 3 By 3**, **4 = 3 By 3 Rotated**, **8 = 5 By 5 Rotated**. Их подписи теперь доступны в дополнительной схеме; baseline сохранён для аудита.

В таблице ниже B — имя `CompleteResource`, ArtResource по **raw+0xC8**, его name занимает первые64 байта. Числа — суффиксы имён, а не индексы записей Rooms. Это запросы моделей; их количество не определяет число клеток комнаты.

| Значение | Native-подпись Editor Pro | Запрашиваемые базовые/напольные модели |
|---|---|---|
| 1 | Complete | точное B; затем B без последнего символа +0,1,2,6,7,8,9 |
| 2 | Quad | B0…B3 |
| 3 | 3 By 3 | B0…B8 |
| 4 | 3 By 3 Rotated | B0…B2 |
| 5 | Normal | B0…B9 |
| 6 | Center Pool | подпись есть; отдельная ветка генерации напольных ресурсов в исследованном loader отсутствует |
| 7 | Double Quad | B0…B14; особый случай Water для RoomId13 |
| 8 | 5 By 5 Rotated | B0…B3; отдельно Dungeon_Destroyed0…5 |
| 9 | Hero Gate | B1…B9 |
| 10 | Hero Gate [ Tile ] | точное B без цифрового суффикса |
| 11 | Hero Gate [ 2 By 2 ] | B0…B3 и BDestroyed0…3 |
| 12 | Hero Gate [ Front End ] | B1…B16 |
| 13 | Hero Gate [ 3 By 1 ] | B0…B6 и B0_DESTROYED…B6_DESTROYED |

Режим1 удаляет **последний байт имени**, не проверяя, является ли он цифрой. Например, `AbcX` даёт точный `AbcX`, затем `Abc0,Abc1,Abc2,Abc6,Abc7,Abc8,Abc9`. Слоты3,4,5 пропускаются; остальные слоты runtime-массива не сдвигаются. Это подтверждено assembly0x4EAF7A..0x4EB02F, включая вычисление длины минус1 и индекс цикла.

У режимов9 и12 номер увеличивается **перед** форматированием имени. Поэтому Hero Gate [ Final ] с реальным B=`hero door0` запрашивает `hero door01…hero door09`, а FrontEnd с B=`3DFrontend` — `3DFrontend1…3DFrontend16`. Автоматически удалять конечную цифру для всех режимов нельзя.

Режим11 использует строку формата `%s%s%d` с литералом `Destroyed`; режим13 — `%s%d%s` с литералом `_DESTROYED`. Форматы прочитаны непосредственно из PE, порядок аргументов проверен по assembly. В этих двух режимах intact/destroyed вызовы чередуются по одному индексу.

## Условия загрузки и адреса runtime

До всех перечисленных веток проверяются `world+0xA3C7 ==0` и наличие resource service. В другом режиме загрузка этих ресурсов пропускается. Проектор предполагает полную исходную запись KWD, уже прошедшую native-конвертер; частичные промежуточные обновления отдельно не моделируются.

Точный B в режиме1 загружается при ненулевом type ресурса, даже если имя пустое. Индексные запросы проверяют **непустое имя**, но не проверяют ненулевой type. Нельзя просто удалить все запросы с type0 из диагностического представления и назвать это эмуляцией loader. Успех или отказ ресурсного менеджера отдельно не установлен.

Фиксированные `Dungeon_Destroyed0…5` в режиме8 запрашиваются и при пустом B. В режимах11/13 разрушенные варианты зависят от непустого B. Этим условиям соответствуют отдельные граничные проверки.

Большинство напольных вариантов размещается в массиве `CWorldEntry` от runtime+**0xC1**, шаг**27 байт**. В режиме1 точный B идёт в отдельный слот+**0x1B**, индексные варианты — в0xC1+27*i с пропуском3…5. В режимах9/12 суффиксы начинаются с1, но первый элемент массива остаётся0xC1. Разрушенные варианты режимов8/11/13 размещаются от+**0x271** с тем же шагом27.

Для **TileConstruction7 + RoomId13 + непустого B** после15 обычных моделей игра запрашивает `Water` дважды: resource type2, затем type1, service flags0x20000. Первый результат связан со слотом+0x256, второй — с+0xA6. Это специальная ветка по числовому ID, а не по строке имени комнаты. Её наличие не доказывает, что любой пользовательский RoomId13 обязан иметь смысл Temple.

Отдельно подтверждено принудительное выставление runtime-флага **0x8** (baseline HAS_WALLS) в режимах **1,5,7,9,12,13**. Игра сначала берёт младшие16 бит файловых Flags+0x370, затем выполняет OR8 для этих режимов. Промежуточная структура перед полным преобразованием очищается initializer0x56DE40, включая слот Flags; OR исходных флагов в converter не добавляет неучтённых начальных битов. Снятая галочка в файле не гарантирует снятый бит в загруженном определении. Старшие16 бит сохраняются в raw, но не попадают в этот16-битный слот runtime. Подстановка не меняет исходный файл.

## Что установлено для неизвестного Rooms+0x1C4

Это самостоятельный84-байтовый ресурс:

```text
raw+0x1C4 → intermediate+0x298 → editor model+0x280
```

Переносы подтверждены converter0x42DF90 и callback0x49FC30. Writer0x4A7AC0 получает model+0x280 и копирует21 DWORD в `auStack_274`; начало записи — `uStack_438`. Разность равна0x1C4. В поток уходит вся запись0x41F байт.

Проверены **все девять прямых ArtResource-кнопок** панели Rooms, включая MFC-записи и getters:

| Кнопка | Raw-ресурс | Editor model |
|---|---|---|
| GUI Icon | 0x020 | 0x010 |
| Complete Mesh | 0x0C8 | 0x16C |
| Straight Mesh | 0x11C | 0x1C8 |
| Inside Corner Mesh | 0x170 | 0x224 |
| Outside Corner Mesh | 0x218 | 0x2DC |
| Wall Mesh | 0x26C | 0x338 |
| Cap Mesh | 0x2C0 | 0x394 |
| Torch Mesh | 0x3C7 | 0x3F0 |
| Ceiling Resource | 0x314 | 0x44C |

Кнопки Inside/Outside Corner действительно **пропускают** неизвестный слот; переименовать его в Outside Corner нельзя. Все девять кнопок видимы в шаблоне диалога251; состояние работающего окна отдельно не проверялось. Неизвестный слот переносится моделью и writer, но не имеет установленной привязки к этим кнопкам. Загрузка из intermediate+0x298 не найдена в исследованном теле игрового loader; это не доказательство отсутствия всех потребителей в игре и редакторе.

У всех78 записей трёх основных областей ресурс целиком нулевой. Дополнительно целевым проходом проверены80 файлов карт с секциями Rooms — **2023 записи**, также без ненулевого ресурса0x1C4. Нулевые примеры не устанавливают назначение поля и не разрешают удалять его.

## API и проверки

`native_room_resources.room_floor_resource_plan(record, update_mode=False, resource_service_present=True)` возвращает native-подпись режима, ожидаемые запросы имён с типами/флагами/адресами назначения, проекцию runtime-флагов и диагностику. Имена формируются из исходных ANSI-байтов; `name_hex` сохраняет точное представление.

```python
from native_room_resources import room_floor_resource_plan
plan = room_floor_resource_plan(room_record)
for request in plan['requests']:
    print(request['name'], hex(request['runtime_entry_offset']))
```

Это план запросов **base/floor/destroyed/Water**, без Start/End-анимаций и общих GUI/wall/cap/torch/ceiling ресурсов. Он не подтверждает наличие моделей в WAD, успешную загрузку или расположение/повороты моделей на клетках карты. Для неполной строки без NUL в64-байтовом поле план удерживается с диагностикой; переполнение64-байтового локального буфера сгенерированным именем сообщается отдельно, без усечения или записи в игру.

Выполнены **297 граничных проверок**, включая все256 значений TileConstruction, пустые/длинные имена, type0, режим обновления, special Water и16-битные флаги. На78 реальных записях получены244 запроса в каждой области и нет диагностических находок. **156 замен неизвестного ресурса** с произвольными84 байтами прошли пересборку секции и повторное чтение; другие записи и соседние байты сохранены, план запросов не меняется.
