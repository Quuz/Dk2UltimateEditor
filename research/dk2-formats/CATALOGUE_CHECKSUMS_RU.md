# Суммы определений каталогов и неизвестный массив Terrain

25 октября 2026, этап22. Первичный источник — инструкции `DKII-DX.exe` и `DK2 Editor pro.exe` в Ghidra. Исследование не меняет файлы игры.

## Что удалось установить

В девяти загрузчиках определений есть отдельный DWORD: при нулевом управляющем значении загрузчик обнуляет его и складывает **беззнаковые байты всей промежуточной структуры**. Если управляющее значение ненулевое, прежний DWORD сохраняется. Это ещё один механизм помимо уже разобранного аккумулятора мира `0x5108C0`.

| Каталог | Загрузчик | Размер intermediate | Поле суммы в runtime | Условие пересчёта |
|---|---|---|---|---|
| Terrain | `0x4F66E0` | `0x2E0` /736 | `+0x84` | global DWORD `0x6FCDCF == 0` |
| Rooms | `0x4EACC0` | `0x4F3` /1267 | `+0xA2` | world DWORD `+0xA3C7 == 0` |
| Creatures | `0x492320` | `0x1939` /6457 | `+0x5AF` | world DWORD `+0xA3C7 == 0` |
| Doors | `0x4A7100` | `0x2DC` /732 | `+0x87` | global DWORD `0x6FCDCF == 0` |
| Traps | `0x4AA440` | `0x2EB` /747 | `+0x6C` | global DWORD `0x6FCDCF == 0` |
| Objects | `0x49DD60` | `0x3FE` /1022 | `+0xF0` | global DWORD `0x6FCDCF == 0` |
| KeeperSpells | `0x4F7CE0` | `0x20E` /526 | `+0x36` | global DWORD `0x6FCDCF == 0` |
| CreatureSpells | `0x4F7860` | `0x15A` /346 | `+0x1B` | global DWORD `0x6FCDCF == 0` |
| Shots | `0x4ACDF0` | `0x177` /375 | `+0x33` | global DWORD `0x6FCDCF == 0` |

В циклах перед загрузкой младшего байта регистр обнуляется: `XOR ECX,ECX; MOV CL,[...]` либо аналог с EDX. Поэтому `FF` в этой сумме означает255. Признаки присутствия полей также входят в просматриваемый диапазон; сумма не ограничивается значениями уже известных скаляров.

При обычной вставке записи callback прибавляет полученный DWORD к накопителю соответствующего семейства в CWorld. Для Terrain..Shots это `+0x15B0/+0x15C0/+0x15D0/+0x15E0/+0x15F0/+0x1600/+0x1610/+0x1620/+0x1630` в порядке таблицы. Сложение DWORD идёт по модулю2³². Ветка обновления существующего ID возвращается до этого прибавления. Это не позволяет самостоятельно установить, когда игра включает конкретный режим.

## Отличие от общего аккумулятора мира

`0x5108C0` выполняет `MOVSX` из байта и прибавляет результат к world DWORD `+0x72E7`. Он начинает с уже имеющегося значения и не сбрасывает его внутри этой функции. При нулевой длине значение не меняется.

| Входной байт | Добавка к сумме определения | Добавка в `0x5108C0` |
|---|---|---|
| `7F` |127 |127 |
| `80` |128 |−128 |
| `FF` |255 |−1 |

Перестановка двух байтов не меняет ни одну из этих сумм. Само наличие аккумулятора не доказывает проверку целостности при чтении KWD, сетевую проверку или причину рассинхронизации: потребители итоговых значений в этом этапе не разобраны.

## Что это означает для вашего редактора

Поля заголовка KWD N/D/S остаются количеством записей и размерами. Эти runtime-суммы не являются дополнительными полями исследованного заголовка. Операции добавления/удаления записей и пересчёта заголовка из предыдущих этапов сохраняются.

Чтобы получить **ту же сумму, что движок**, недостаточно сложить байты записи файла. Сначала нужно воспроизвести конструктор и raw→intermediate преобразование: присутствие полей, развёрнутые ресурсы, строки, OR-присваивания, состояние обновления и все байты просматриваемого буфера. В этом этапе не заявлена полная реализация такого преобразования. API принимает уже готовый intermediate точной длины и намеренно отклоняет raw-буфер другой длины.

`native_catalogue_checksums.py` предоставляет `definition_checksum`, `signed_world_accumulate` и арифметику добавления к накопителю семейства. Машинная схема — `catalogue-checksums.json`, компонент33 общего пакета.

## Terrain: ещё32 байта с подтверждённым сохранением

Массив `raw+0x1AE..0x1CD` содержит16 элементов по2 байта:

1. Game converter `0x56ED20` переносит WORD в `intermediate+0x266+2*i`, устанавливая presence DWORD `+0xB4`.
2. Editor getter `0x42F120` читает соответствующий intermediate WORD при индексе<16.
3. Editor callback `0x49F5E0` вызывает setter `0x425420`, который сохраняет WORD в модели `+0x328+2*i`. Индекс16 и выше игнорируется.
4. Getter модели `0x425400` возвращает WORD при индексе0..15, иначе0. Прямой xref ведёт к writer `0x4A7690`.
5. Writer строит указатель `ESP+0x1FA`; база552-байтной записи при финальном write — `ESP+0x4C`. Разность `0x1FA−0x4C=0x1AE`. В цикле записываются все16 WORD.

Все32 intermediate-байта входят в диапазон суммы Terrain `0x2E0`. Это подтверждает участие байтов в расчёте, **не раскрывая игрового назначения**. В просмотренном runtime-loader отдельного переноса этого массива в определение не установлено; это не доказательство отсутствия других потребителей.

В80 файлах карт проверены3224 записи Terrain: во всех16 значениях массива находятся нули. Нельзя по этому корпусу установить единицы, ссылки на другие каталоги или допустимый смысл ненулевых значений. Для собственного редактора сохранять32 байта как непрозрачный массив.

## Продолжение поиска четырёх неизвестных скаляров

`scan_overlapping_unknowns.py` проверяет и чтения, которые начинаются перед целевым смещением и могут захватывать его более широким операндом. Получено1344 кандидата;446 проходят предварительный фильтр пересечения и чтения. Это кандидаты дизассемблера, а не446 подтверждённых обращений к нужным структурам. `LEA`, косвенные CALL/JMP, ложные начала инструкций, локальные стеки и другие типы объектов нельзя считать смысловым потребителем поля.

В частности, `0x4D4760` и диагностический `0x4D5C00` используют DWORD `+0x106` в структуре навигации. Диагностическая строка прямо называет его `path_last_progress`. Это не WORD Objects.Mana Gen, хотя числовое смещение совпадает. Имена неизвестных Terrain+0x198/+0x224 и Traps+0x204 по этому проходу не установлены; игровой потребитель Objects+0x34C также не подтверждён. Ошибка `No function found` для другого адреса сохранена отдельно и не используется как доказательство.

## Проверка

`phase22-validation.json`:669 граничных проверок,53 native-эмуляции и369 точечных пересборок контейнеров в памяти. В53 прогона входят45 ветвей определения —9 семейств ×5 наборов — и8 прогонов signed-аккумулятора мира. Проверены нули, всеFF, смешанные байты, ненулевые управляющие значения, сохранение старой суммы, пустой буфер и перенос DWORD.

Эмуляция выполняет оригинальные циклы и условные переходы; окружающий пролог пропущен, входные указатели заданы явно, выход читает DWORD и возвращает результат. Там, где вход начинается с JNZ, adapter исполняет TEST для установки ZF. Вычисление адреса управляющего значения подтверждается полной assembly загрузчика; соответствующая инициализация игры не эмулируется. У Rooms оба выхода имеют readout-adapter. Для `0x5108C0` выполняется весь исходный цикл с заменой конечного RET на чтение результата и RET8.

Повторные выгрузки всех9 функций сохранили инструкции; у старой выгрузки Rooms отличается только завершающая пустая строка. Все17 исходных файлов и2 EXE сохранили SHA-256. Игра с изменёнными данными не запускалась.
