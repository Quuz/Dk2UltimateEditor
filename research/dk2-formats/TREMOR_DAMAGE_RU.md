# Shots: Tremor, здоровье Terrain и смена типа клетки

Этап 151, 31 октября 2026. Проверен предоставленный `DKII-DX.exe`, SHA-256 `d7a8b854e4e4f02709eba271bead6fe2307dd6e332b5a96e70857e5b0e19fb8a`.

Режим Shots `DamageType = 8`, ранее подписанный `CONSTANT_FOR_TREMOR`, доведён от настоящих raw-загрузчиков до повреждения клеток, смены Terrain и обновления навигации. Величина Data1 в этом пути применяется к WORD здоровья клетки. Например, 65536 не снимает HP, а 65537 снимает 1. Data2 задаёт размер области в Q12: одна клетка соответствует 4096.

В 5 551 исходной Shot-записи из 82 контейнеров режима 8 нет. Выполнены диагностические копии исходной записи Shot 17 с явно заданным ProcessType NONE. Это подтверждение поддержки режима данным EXE; штатное заклинание с таким режимом в проверенном корпусе не найдено.

## Физические поля

| Файл | Поле | Смещение в записи | Хранение |
|---|---|---:|---|
| Shots | Data1 | `0x98` | DWORD, API u32 |
| Shots | Data2 | `0x9C` | DWORD, API u32 |
| Shots | DamageType | `0xC5` | BYTE |
| Shots | ProcessType | `0xC7` | BYTE |
| Terrain | Flags | `0x190` | DWORD |
| Terrain | StartingHealth | `0x1D7` | WORD |
| Terrain | DestroyedTypeTerrainId | `0x1DA` | BYTE |
| Terrain | MaxHealth | `0x1FF` | WORD |

Размер Shots — 239 байт; для точечной правки Terrain поддержаны варианты 548/552 байта. Здоровье игровой клетки находится в WORD по `+6` от начала её 16-байтового runtime-объекта. В этой же клетке `+8` содержит владельца и флаги, `+A` — Terrain ID. Эти смещения не относятся к четырёхбайтовой сериализованной KLD-клетке; неизвестный raw-байт 3 этим этапом не раскрывается.

## Какие клетки затрагиваются

Оригинальная `4ACCA0` вычисляет:

```text
cx = signed32(ShotX) >> 12
cy = signed32(ShotY) >> 12
R  = signed32(instanceData2) >> 12

для x от cx-R до cx+R, не включая верхнюю границу:
    для y от cy-R до cy+R, не включая верхнюю границу:
        проверить границы карты
        проверить Terrain
        передать запрос изменения HP
```

Получается заполненный полуоткрытый квадрат с обходом сначала по X, затем по Y. Проверки расстояния по окружности нет. В тесте R=2 повреждаются и угловые клетки за пределами круга радиуса 2.

Raw Data2 = 0, 1 и 4095 дают R=0 и не вызывают повреждение; 4096 даёт R=1, 8192 — R=2. Проверенный отрицательный `0xFFFFF000` даёт R=-1 и также не выполняет цикл. На карте 32×32 выходящие за границы координаты пропускаются настоящим World getter `509090`.

Предикат `453D10` требует Terrain flag `SOLID = 1` и запрещает `IMPENETRABLE = 2`. Исходный Rock 2 проходит, Impenetrable Rock 1 и Dirt Path 3 пропускаются. Владельцем запроса становится `cellWORD8 & 0xFFF`. В диагностических вариантах 7 и `0xF007` обработчик получает 7; владелец создателя снаряда отдельно не подставляется.

## Как применяется Data1

Перед `452F60` выполняется 32-битовое отрицание Data1. Знак получившегося DWORD выбирает ветку повреждения или прибавления HP. В сравнении величины повреждения и в добавке используется младшее WORD.

| Raw Data1 | Переданная дельта | HP Rock из 165 |
|---:|---:|---:|
| 80 | -80 | 85 |
| 0 | 0 | 165 |
| 65536 | -65536 | 165 |
| 65537 | -65537 | 164 |
| `0xFFFFFFB0`, представление -80 | +80 | 245 |
| `0x80000000` | -2147483648 после x86 NEG | 165 |

Отрицательная дельта с младшей величиной не меньше текущего HP устанавливает HP в 0. Для прибавления исходный код сначала ограничивает промежуточное здоровье 32000, затем учитывает MaxHealth и возможную смену типа. Новые положительные результаты остаются ниже MaxHealth исходного Rock, равного 660; дальнейшее превращение при полном лечении не проверено.

Физические Data1/Data2 остаются u32. Знаковую и фиксированную трактовку нужно выбирать по режиму. Отдельная система ProcessType использует те же два поля, поэтому значения нельзя автоматически переносить между разными сочетаниями обработчиков.

## Разрушение и DestroyedTypeTerrainId

В исходном Terrain 2 поле `DestroyedTypeTerrainId = 3`. При запросе -165 HP Rock достигает 0, после чего настоящая `44FC40` меняет тип клетки на Dirt Path 3. Новый тип получает своё StartingHealth = 1, а навигационный байт меняется с 8 на 0.

Проверены разрушение одной клетки, трёх клеток и трёх клеток внутри полного Shot tick `4AB180`. Прошли исходные загрузчики Terrain/Shot, фабрика снаряда, обработчик HP, CMap и обновление навигационного графа. Снаряд после полного tick имеет HP 31; два подготовленных Creature-соседа сохраняют HP 1000. Запросов к обычному обработчику Creature HP в этом пути нет.

Положительный контроль формата меняет raw `Terrain+0x1DA` на собственный ID 2. После такого загрузчика у трёх клеток получается HP 0, но тип остаётся Rock 2, навигационный байт остаётся 8 и CMap-смена типа не вызывается. Поэтому нулевое HP само по себе не гарантирует замену Terrain. Поведение всех последующих действий живой игры при таком диагностическом содержимом здесь не устанавливается.

Два последовательных полных tick при Data1=80 дали для трёх Rock-клеток 165→85→5. Это подтверждение повторения запроса в выбранном tick-пути; частота в реальном времени и полный World scheduler отдельно не выполнялись.

## Стенд и проверка достоверности

Для навигации вызваны оригинальные `4CE690`, `4CE740`, `4C8F30`, `4CEF20`. Подготовлены 32×32 клетки, настоящий CMap с исходной vtable, буфер треугольников и корректные навигационные признаки 8 для solid / 0 для обычного пола. Разрушение проверено на не принадлежащем игроку Rock с owner 0 и нулевым указателем tag 0 как концом списков.

Ранние варианты стенда с отсутствующими CMap/ресурсным сервисом, неверным объектом в tag 0 и неполным NAV исключены. Возврат функции оказался недостаточной проверкой: отдельный незавершённый вариант графа обращался к нулевой странице. В принятых 24 сценариях низкие адреса читаются только штатными FS:0-инструкциями SEH, исходная цепочка SEH восстанавливается, защитные байты буфера треугольников сохраняются.

Внешний ресурсный сервис явно возвращает отсутствие ассетов, звук обслуживается описанными адаптерами. Оригинальные игровые функции и vtable не заменяются. Реальные модели, GPU, звук, успех визуальных эффектов, все Terrain-типы, золото, комнаты и полный игровой планировщик этим стендом не покрыты.

## Артефакты

Приняты 24 сценария: 74 запроса изменения HP Terrain и семь переходов Rock→Dirt. Шесть независимых Ghidra-контролей сравнили 450 областей памяти, 2 093 064 байта. Сверены полные байты 177 функций и пяти блоков таблиц, покрыты все 11 453 уникальных исполненных адреса оригинального PE.

Проверены 246 точных пересборок: 164 для параметров Shots и 82 для Terrain DestroyedType. В исходном корпусе 5 551 Shot-запись и 3 306 Terrain-записей. Все прочие байты, обратное восстановление и decode → rebuild проверены. SHA-256 310 исходных файлов и семи путей EXE сохранены.

Машинная схема — `tremor-damage-semantics.json`, актуальные параметры — `editor-format-package.json → effective_shot_parameters → damage_types → 8`. Узкий helper `native_tremor.patch_destroyed_type(raw, terrain_id)` сохраняет соседние поля Terrain.

```text
python emulate_tremor_damage.py
python crosscheck_tremor_damage.py
python prepare_tremor_primary.py
python validate_tremor_api.py
python build_tremor_damage.py
python audit_tremor_damage.py
```

Прежние 129 компонентов спецификации остаются побайтно прежними. Новых имён непрозрачных полей нет; цель по всем 15 семействам остаётся открытой, общая оценка около 75% сохраняется.
