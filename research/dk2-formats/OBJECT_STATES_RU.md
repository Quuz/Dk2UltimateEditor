# Начальное состояние Object и периодические эффекты

Уточнение этапа111: настоящая фабрика Object101/108/114 перекрывает StartState состоянием42 и задаёт период2*TPS. Проверенные ниже условные пути состояния39 не устанавливают естественное состояние ManaVault. Новые полные цепочки создания и отдельный доход Terrain описаны в `MANA_VAULT_RU.md`; полный захват клетки остаётся открытым.

Этап 110, 29 октября 2026. Проверен предоставленный `DKII-DX.exe`, SHA-256 `d7a8b854e4e4f02709eba271bead6fe2307dd6e332b5a96e70857e5b0e19fb8a`. Машинная схема — `object-state-semantics.json`, компонент пакета — `object_state_semantics`.

Установлено конкретное ограничение совместимости: оригинальный инициализатор заполняет позиции состояний **0–58**, хотя справочное перечисление содержит также 59–63. Диспетчер не проверяет индекс перед косвенным вызовом. Для значений 59, 63 и 255 изолированный запуск воспроизвёл копирование стартового состояния при первом обновлении и попытку перехода по нулевому адресу при втором. Защитный backend остановил переход до исполнения; это не наблюдение краша живой Windows-игры. Новые неизвестные поля этим этапом не названы.

## Физическое поле и порядок обновления

Все смещения сырых полей ниже указаны **от начала одной 894-байтовой записи Objects**, а не от начала файла.

| Представление | Поле |
|---|---|
| Сырой Object | BYTE `+35B`, StartState |
| Промежуточная запись | BYTE `+3DB` |
| Загруженное определение | BYTE `+11B` |
| Экземпляр Object | DWORD `+13A`, активное состояние; DWORD `+13E`, возраст состояния |

Выполнена настоящая цепочка `56D4F0 → 56D620 → 49DD60 → 49BD20 → 49EED0`: инициализация промежуточной записи, преобразование сырой записи, загрузка определения и обновление существующего экземпляра. Код и оригинальные vtable не заменялись.

Если активное состояние равно нулю, а StartState ненулевой, `49EED0` копирует StartState, обнуляет возраст и возвращает 1. Сам обработчик нового состояния в этом обновлении ещё не вызывается. Если оба значения нулевые, возраст остаётся прежним.

При ненулевом активном состоянии возраст увеличивается как DWORD с переполнением, затем вызывается обработчик. Нулевой результат обработчика сбрасывает активное состояние в ноль, сохраняя уже увеличенный возраст. Если StartState остался ненулевым, следующее обновление может снова скопировать его.

Один оригинальный обработчик `484940`, возвращающий 0, назначен состояниям 2, 7, 57 и 58. Поэтому название состояния само по себе не доказывает соответствующую игровую анимацию. Другой обработчик `4B4C20`, возвращающий 1 без изменения экземпляра, назначен состояниям 16, 22, 51 и 56. Проверены также приоритет уже активного состояния над другим StartState и переполнение возраста `FFFFFFFF → 0`.

## Оригинальная таблица

Инициализатор `49E600` выполнен целиком. Его результат совпал с независимым извлечением констант из исходных инструкций: 360 исполненных инструкций, 1180 байт, 59 записей с шагом 20.

Начало дескрипторов — `6E4B38`; база указателей обработчиков, которую использует диспетчер, — `6E4B3C`. Они отличаются на четыре байта. Первый DWORD сохраняет начальный ноль PE/BSS; инициализатор записывает остальные 1176 байт. Назначение трёх других слов дескриптора полностью не устанавливается. Число заполненных позиций не следует превращать в утверждение о границах любого выделенного массива во всех версиях игры.

В схеме сохранены все 59 привязок. Имена взяты из прежнего справочного перечисления и помечены как справочные: исполнение каждого из 58 ненулевых состояний целиком не проверялось. Значения 59–63 нельзя автоматически считать поддерживаемыми этим EXE только на основании перечисления. Flame, другой EXE или изменённая во время работы таблица требуют отдельной проверки.

## Что делает периодический обработчик Mana Vault

Состояние 39, справочное имя `MANA_VAULT`, вызывает `4A3400`. После увеличения возраста оно проверяет остаток от деления возраста на `3*TicksPerSecond`. На границе периода запрашивается **эффект 288**, независимо от поля Mana Gen. При TPS20 проверены переходы возраста 58→59 без запроса и 59→60 с запросом. Это конкретный периодический запрос эффекта, а не доказанная выдача маны.

Состояние 40, справочное имя `TORTURE_COALS`, вызывает `4A3450`. Период тот же, но ID эффекта берётся из **WORD raw `+358` → definition `+117`**, MiscEffectId. Нулевое значение пропускает запрос, проверенное значение 123 передаётся в запрос.

Полный путь запроса `509580 → 50E490` доведён до оригинального `CPCEngineInterface +90`, адрес `4430D0`. Исходная реализация возвращает ноль. Значения шести аргументов проверены по чтениям стека оригинальным мостом: обе координаты ссылаются на XYZ экземпляра, владелец — 7. Внешний синтетический обработчик не внедрялся. Видимые частицы, настоящая графика и жизнь созданного эффекта здесь не воспроизводились.

Отдельно загружены реальные определения Mana Vault101 и Claimed Mana Vault108. В текущем файле у обоих StartState0, а MiscEffectId — 287 и 288 соответственно. При подготовленном активном состоянии39 оба запрашивают288. **Естественное включение этого состояния, захват хранилища и награда за захват ещё не проверены.** Экземпляр подготовлен из прежнего корректного снимка Object; фабрика для этих двух типов заново не исполнялась.

Значения raw `+34C` / Mana Gen 0, 100 и FFFFh прошли настоящую загрузку и выбранные обработчики, включая границу периода39. Чтений definition `+106/+107` не наблюдалось. Это ограничение выбранных путей, а не доказательство общей неиспользуемости поля.

## Использование в нашем редакторе

`native_object_states.patch_start_state(raw, value)` меняет только BYTE35B. Низкоуровневый API допускает все значения0–255 для сохранения исходных файлов. `supplied_dx_state_status(value)` отдельно сообщает установленную для точного DX классификацию. Не нужно молча исправлять неизвестное значение или удалять его при чтении.

Проверены **738 точных пересборок на 82 Object-контейнерах**, включая значения за пределами инициализированных состояний. При каждой правке все остальные байты, неизвестный Mana Gen, заголовки, порядок записей и другие секции сохранены. Все **11 756 записей** прошли тождественную проверку; ни одна исходная запись не имеет StartState59 или выше. Это характеристика нашего корпуса, не всех существующих модификаций.

Итого: 26 новых композиций в Unicorn — 23 с обычным возвратом и 3 с ожидаемой остановкой нулевого перехода; 38 входов в Object tick, 35 возвратов. Три дополнительные композиции совпали в Ghidra. Сверены 19 целых диапазонов функций, из них 13 с выполненными путями, и два блока оригинальных vtable. Четыре EXE и 82 файла данных сохранили SHA. Пакет содержит 89 компонентов; предыдущие 88 схем сохранены побайтово.

Загрузка использует gate1: графические ресурсы, звук и обновление checksum пропускаются этим штатным режимом. Полные промежуточная запись, определение, сырой вход, экземпляр с защитным хвостом и прочие подготовленные области сравниваются. Это не запуск World с нуля, не полный планировщик и не полная игровая сессия. Раннее чтение таблицы со сдвинутой базой и диагностический запуск без подготовленного graphics slot90 оставлены как исключённые материалы исследования.

Воспроизведение: `object_state_tables.py`, `emulate_object_states.py`, `crosscheck_object_states.py`, `validate_object_states_api.py`, `prepare_object_states_primary.py`, `ghidra_probe.py phase110-primary-queries.json`, `build_object_states.py`, `build_format_package.py`, `audit_object_states.py`. Эмуляции читаются из кэша только при совпадении входных данных и зафиксированного backend.
