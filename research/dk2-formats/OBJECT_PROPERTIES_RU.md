## Установлена подпись Objects+0x34C

Прежнее `X34c` — WORD, связанный в родном редакторе с контролом **Mana Gen:**.

```text
файл+0x34C → intermediate+0x3CC
           → модель редактора+0x3BE
           → panel+0x8C → edit1318 / 0x526
           → модель+0x3BE → файл+0x34C

игровой loader отдельно копирует WORD в runtime+0x106
```

Fill0x45A400 читает модель как **signed16** и расширяет в DWORD панели. DDX0x4597B0 связывает указатель panel+0x8C именно с edit1318 и проверяет0..32000. Commit0x45A870 сохраняет low16 обратно, writer0x4A9390 переносит слово в файл. Отрицательные значения, внесённые через hex, отображаются как отрицательные и выходят за диапазон этой проверки GUI; например, `FFFF` отображается−1.

Это установленная **нативная подпись интерфейса**, не доказательство генерации маны в игре. Игровой потребитель runtime+0x106 с таким эффектом пока не найден. Статус в `unresolved-field-traces.json` уточнён: имя GUI известно, игровой эффект неизвестен. Соседнее Mana Value — другое слово+0x34E, модель+0x3C0, panel+0x90, edit1320.

Constructor0x459270 запрашивает ресурс диалога256. Есть также альтернативный ресурс327 с теми же ID и подписями, но отличающимися visibility/disabled битами. Mana Gen скрыт в обоих шаблонах. Наличие привязки не означает, что поле сейчас видно пользователю. В схеме сохранены оба полных описания контролов и подписей.

Пять DWORD-полей редактор сначала расширяет нулём до64-битного целого, затем выполняет FILD и умножение на reciprocal. Поэтому исходный `FFFFFFFF` в этих native-представлениях положителен. Прежние baseline-обозначения `i32/4096`, `i32/65536` не описывают этот способ отображения; они сохранены для истории источника. ## Runtime уже, чем файл

У Objects Width/Height/Mass/AirFriction игровой загрузчик сохраняет только low16 исходного DWORD в runtime+0xF8/+0xFA/+0xFC/+0xFE. Это факт переноса, а не полное описание физики или signedness последующих потребителей. Например, Height raw65536 отображается как16 в GUI, но скопированные runtime-биты равны0. Нельзя менять ширину поля **в файле** только потому, что runtime-поле короче.

Speed переносится иначе, через unsigned деление на TPS:

```text
quotient = raw_u32 / positive_TPS
runtime_bits = quotient & 65535
если runtime_bits == 0 и raw_u32 != 0:
    runtime_bits = 1
```

Проверка нуля идёт **после сужения**, поэтому при raw1310720 и TPS20 quotient=65536, но runtime=1. При raw1310740 quotient=65537 и runtime тоже1, уже без замены нуля. Делитель API требует передать явно;20 — только сценарий аудита.

## Флаги: два разных преобразования родного редактора

Flags находятся по+0x344. Native decode0x420E80 и encode0x420D20 поддерживают25 битов, маска **0x07F7F7FF**. Биты11,19 и27..31 этим проходом теряются. Их смысл не выдумывается; в сохраняющем raw сериализаторе они должны оставаться.

Отдельно подтверждение панели свойств нормализует семь битов типа объекта. При загрузке выбирается первый установленный бит по такому приоритету:

| Индекс выбора | Нативный тип | Маска |
|---|---|---|
| 0 | Normal | ни одного из семи битов |
| 1 | Special | 0x4 |
| 2 | Spell Book | 0x8 |
| 3 | Level Gem | 0x1000 |
| 4 | Crate | 0x10 |
| 5 | Lair | 0x20 |
| 6 | Gold | 0x40 |
| 7 | Food | 0x80 |

При commit все семь model-переменных очищаются и устанавливается только выбранная. Поэтому даже если остальные свойства не трогать, комбинация Special+Food в этой ветке превращается в Special. Сам decode/encode без подтверждения панели сохраняет оба поддерживаемых бита — это **разные** этапы, и API возвращает оба результата отдельно.

В Ghidra выполнены четыре цепочки исходных функций decode→encode: все32 бита, только неподдерживаемые биты, смесь типов, обычная маска. Все завершились возвратом на sentinel и совпали с маской0x07F7F7FF. Полный MFC-диалог не эмулировался; выбор/commit радио-типа подтверждён его кодом и отдельными граничными проверками всех128 сочетаний семи битов.

## Корпус и границы выводов

Проверены80 файлов карт: **11466 Objects и3224 Terrain**. У всех Objects поле Mana Gen равно0. Неподдерживаемых битов и комбинаций типов, изменяемых панелью, в этом корпусе нет. В сценарии TPS20 не найдено сужения Speed после деления; также не найдено потери старших16 битов Width/Height/Mass/AirFriction. Это наблюдения корпуса, а не запрет других значений.

При этом **в77 файлах Dungeon Heart имеет Health34464**, выше ограничения GUI32000. Такие значения не обнулялись и не ограничивались. Диапазон родной панели не равен диапазону допустимого файла; редактору следует сохранять существующие значения и отдельно показывать сведения об ограничении GUI. Число34464 само по себе не доказывает, от какого исходного числа оно когда-либо получилось.

Для оставшихся Terrain+0x198/+0x224 и Objects runtime+0x106 расширен поиск на всю `.text`, включая участки без сохранённых function spans. Использованы линейное дизассемблирование и декодирование вокруг точных displacement-байтов. Найденные совпадения включают другие классы, библиотечный код и ложные начала внутри инструкций, например пропущенный префикс WORD может выглядеть как DWORD. Эти результаты являются кандидатами, а не доказательствами смысла. Новых игровых назначений указанным полям не присвоено; косвенные/вычисляемые указатели и другие EXE такой поиск не исключает.
