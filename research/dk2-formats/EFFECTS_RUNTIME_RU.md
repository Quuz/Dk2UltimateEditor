# Effects и EffectElements: проверка по движку

22 октября 2026. Выводы относятся к `DKII-DX.exe` с SHA-256 из `effect-semantics.json`. Сохранены декомпиляции и выборочные инструкции загрузчиков, обновлений, генерации и столкновений. Изменённые карты в игре не запускались.

Машинная схема: `effect-semantics.json`; аудит пользовательских определений: `effect-catalogue-audit.json`. Базовая разметка файлов и названия OpenKeeper остаются в `layouts.json`; новые сведения не меняют порядок или размер байтов.

## Размеры и чтение

| Семейство | Запись файла | Runtime-определение | Header callback | Converter | Runtime loader |
|---|---:|---:|---|---|---|
| Effects | 246 | 148 (`0x94`) | `0x440720` | `0x56AFE0` | `0x4358C0` |
| EffectElements | 182 | 79 (`0x4F`) | `0x4405A0` | `0x56B570` | `0x4366A0` |

Число определений берётся из заголовка; размер runtime не является размером записи файла. В обоих семействах ID — u16. Сохранены 21 буквальный скалярный путь Effects и 24 EffectElements; вместе с другими каталогами это 266 путей для десяти семейств.

У 19 полей загрузчик сужает 32-битное файловое значение до 16 бит: Mass, AirFriction, Elasticity, Min/MaxSpeedXy, Min/MaxSpeedYz, Min/MaxScale; дополнительно Radius у Effects. Mass и скорости затем читаются как signed16. Масштабы и коэффициенты в проверенных применениях читаются unsigned; знаковость Radius здесь отдельно не установлена.

Сохранять все четыре байта файла. Например, raw Mass `0xFFFFFCCD` и `0x0000FCCD` дают одно signed16 значение, но это разные raw-буферы. В каждом из трёх проверенных наборов 321 такое поле имеет ненулевые старшие биты; все обнаруженные случаи относятся к Mass/скоростям и представляют отрицательные значения. Это не 321 ошибка данных.

## CUBE_GEN: точные условия и единицы

Флаг `0x40` (`GENERATE_EFFECTS`) выбирает каталог Effects. Когда бит снят, этот обработчик создаёт EffectElements; дополнительной проверки бита `0x80` нет. При обоих битах идёт ветка Effects. Это правило относится к type 4; автоматически переносить его на другие режимы нельзя.

GenerateRandomness по raw `+0xEC` читается как signed16. Выполняется RNG(`r+1`), и генерация идёт только при результате 0 и положительном счётчике времени экземпляра. Для обычного `r>=0` это шанс `1/(r+1)` на вызов; 0 означает каждый вызов. При `r=-1` вызывается RNG(0): проверенная RNG `0x5558D0` пишет сообщение и возвращает 0, а не делит на ноль. Параметр не следует подписывать как процент.

Диапазоны положения по `+0xDA` (outer), `+0xEA` (inner), `+0xDC/+0xDE` (height) в этом обработчике читаются signed16, хотя файл содержит u16. Для горизонтального радиуса применяется множитель 23, для высоты — 16; координата позиции имеет 4096 единиц на клетку. Например, raw 256 соответствует горизонтальному радиусу 5888/4096 клетки и высоте 4096/4096 клетки. При обычном возрастающем диапазоне helper `0x435660` выбирает верхнюю границу исключительно; равные границы дают фиксированное значение.

WhirlpoolRate по raw `+0xE4`: прочитать signed16, затем если значение >=128, вычесть 256 **один раз**. Получается 128→−128, 255→−1, 256→0, 512→256. Ветка элементов передаёт результат ×16 в `0x438520`; в ветке генерации Effects этот whirlpool-путь не выполняется. Это отличается от обычного преобразования в signed byte при произвольном raw выше 255.

CircularPathRate по raw `+0xE8`: ветка элементов применяет такое же однократное вычитание 256; далее helper `0x438620` ограничивает значение −1024..1023. Ветка Effects ограничивает исходный signed16 непосредственно. Поэтому raw 128 означает −128 для элементов и +128 для эффектов.

Whirlpool использует целочисленный знаменатель `square(dx>>5)+square(dy>>5)+128`, ограничивает угол и добавляет смещение к отдельному импульсу положения дочернего элемента. Это не прямая замена его обычной скорости. Формула OpenKeeper с другой зависимостью от расстояния остаётся приближением к этому алгоритму.

## GenerateIds — восемь физических слотов

Raw `+0xCA`, восемь u16. Последний индекс определения вычисляется поиском ненулевого слота от 7 к 1; если их нет, остаётся 0. Случайный getter выбирает индекс от 0 до last включительно, сохраняя пропуски и повторения. Есть отдельные getters первого и последнего физических слотов.

В CUBE_GEN при RANDOM_DISTRIBUTION (`0x400`) используется случайный выбор; при снятом бите обходятся все восемь слотов и пропускаются нули. В случайной ветке элементов также есть предварительная проверка первого слота на 0 с возвратом 0 из обработчика. Точное поведение нельзя выразить одним компактным списком уникальных ненулевых ID.

Три примера из ваших файлов:

| Effect ID | Имя | Восемь слотов |
|---:|---|---|
| 125 | Horny Grand Entrance Data 0 | `[0,0,497,497,497,497,0,0]` |
| 266 | Cannon Ball Shot Effect | `[0,458,459,459,0,0,0,0]` |
| 293 | Horney enter data0 | `[208,209,210,0,434,434,435,435]` |

У этих трёх текущих записей RANDOM_DISTRIBUTION снят. Пропуски не объявлены ошибкой; особенно важно сохранить их при дальнейшем переключении режима/флагов. Парсер OpenKeeper удаляет нули из своего списка, поэтому для собственного редактора нужен raw-массив из восьми элементов.

## Поля, меняющие смысл в других режимах

У EXPLOSION_2(5), SPRAY(6), EXPLOSION(7), SPIRAL(8) и TEST_0(15) первый и последний физические GenerateIds задают **числовой диапазон ID** для случайного выбора, включая обе границы. Промежуточные ID не обязаны быть записаны в восьми слотах. EVERYTHING(9) обходит числовой диапазон с исключённой последней границей; сравнение подтверждено инструкцией `0x436C64 JC`. Для этих режимов список восьми конкретных элементов не описывает всю генерацию.

У SPRAY raw `+0xDA`, названный в baseline OuterOriginRange, используется как **SecondaryEffectId**. Когда elapsedTicks%3 == 0, вызывается создание Effects с этим ID. В ваших файлах это Effect 27 `Frost Ball`, где значение 14 является ссылкой на Effect 14. Основные элементы берутся из числового диапазона, ограниченного первым и последним GenerateIds. Для редактора нужен режимный смысл поля, а не универсальная подпись «радиус».

У GOLD_COST(14) первый GenerateId — начало серии **десяти** ElementId для десятичных цифр. Callback берёт отображаемое число из экземпляра +0x12F и создаёт `base+digit`; восемь физических GenerateIds не ограничивают ряд цифрами 0–7. В вашем каталоге Effect 22 `Gold Cost` использует элементы 27..36, а Effect 364 `Mana Cost` — 573..582. ElementsPerTurn у обоих равен 0 и не выключает этот обработчик. Все десять ссылок каждого набора проверены.

У TEST_3(18) используются лишь GenerateIds[0..3], обход в порядке 3..0; число партий равно floor(ElementsPerTurn/4). Ненулевой ID создаётся как Effects только при бите0x40. Значения ElementsPerTurn ниже 4 дают ноль партий. В текущих шести определениях этого режима ElementsPerTurn равен 4.

## Время жизни, цепочки и столкновения

MinHp/MaxHp выбирают начальный счётчик из включительного диапазона. У EffectElements `0x436430` сначала вычитает число прошедших тиков, затем при ненулевом NextEffectId вызывает создание **Effects**, по одному вызову на обновление, вне цикла физических подшагов. Это не DeathElementId. В ваших данных элемент 550 `Fear trap Ghost trail 0` указывает на Effect 337. Новая проверка этой ссылки проходит во всех трёх наборах.

DeathElementId используется при обычном удалении дочернего элемента через `0x435420`, а при принудительной очистке родителя соответствующая ветка подавляется аргументом. DeathEffectId родителя проверяется в `0x4354F0`; в просмотренном пути есть также проверка состояния движка перед созданием. В этапе17 найден потребитель Effects.NextEffectId:0x440350 создаёт цепочку немедленно в одном вызове; подробности — `EFFECT_CHAINS_RU.md`.

Для столкновений различаются пути:

- При горизонтальном столкновении EffectElements используется HitSolidElementId.
- В ветке, где элемент оказался ниже поверхности, `0x447219..0x4472B3` выбирает первый ненулевой слот в порядке HitLavaElementId → HitWaterElementId → HitSolidElementId. Проверки вида поверхности внутри этой ветки нет. Нельзя описывать её только по названиям из OpenKeeper.
- Для родительских Effects в аналогичной ветке проверяются флаги terrain: `0x100` выбирает HitLavaEffectId, `0x80` — HitWaterEffectId, иначе HitSolidEffectId. Это согласуется с расположением lava по raw +0xC6 и water по +0xC8; в дополнительном BT-шаблоне подписи этих двух полей переставлены.

## Трение, гравитация и обновление определений

Общий физический шаг `0x4476E0` сначала уменьшает вертикальную скорость на signed16(MassRaw), затем умножает компоненты скорости на `(4096-u16(AirFrictionRaw))/4096` с целочисленным округлением к нулю. Промежуточное умножение — 32-битное. Для вертикального перемещения используется velocity>>4. Представление AirFriction/65536 в исходной схеме OpenKeeper отличается от коэффициента одного native-шага; обе интерпретации сохранены отдельно.

12 хвостовых u16 Effects по raw `+0xDA..+0xF0` в runtime loader заменяются только при ненулевом входном значении. В случае обновления уже существующего определения ноль может сохранить предыдущее значение. Показываемая codec-проекция CubeGeneration описывает входную запись; для точного воспроизведения состояния требуется учитывать порядок загрузки файлов.

## Что добавлено для редактора

`dk2_formats.py` выдаёт дополнительный `engine_fields` для обоих семейств: raw и суженные значения отдельно, GenerationDispatch, GenerateIdSlots; для CUBE_GEN — преобразования диапазонов и вращения, для SPRAY/GOLD_COST/TEST_3 — отдельные режимные представления. Эти представления не являются инструкцией переписать raw при сохранении.

В единый `editor-format-package.json` добавлен четырнадцатый компонент `effect_semantics`. Проверены границы type 0/18/19/255, комбинации битов 0/0x40/0x80/0xC0, сохранение ненулевых старших битов Mass и пропусков/дубликатов GenerateIds, ссылка Frost Ball →14 и десять цифровых элементов у Gold/Mana Cost. После расширения проверка каталогов включает 1530, 1678 и 1679 ненулевых ссылок без отсутствующих ID. Итоговые проверки структуры находятся в validation.json и corpus-validation.json.

Не восстановлены полностью палитровые RandomColorIndex/TableColorIndex и вся семантика каждого режима генерации. Native-тайминг Effects.NextEffectId установлен в этапе17 — см. `EFFECT_CHAINS_RU.md`. Неизвестный хвост Effects +0xF4 сохраняется; в просмотренном converter он не читается.
