# Objects +0xC8: иконка объекта в оригинальном редакторе

Этап 121, 29 октября 2026. **Назначение прежде неустановленного ресурса `Objects+0xC8` подтверждено: он задаёт иконку объекта на карте оригинального редактора.** Подпись интерфейса — `Object Icon`. Это отдельный ресурс от `GUI Icon` по `+0x74` и `In Hand Icon` по `+0x170`.

Основной образ — предоставленный `DK2 Editor pro.exe`, SHA-256 `989c45df779bccfc9a9e509b2ad0224a9bd269629f74792adc0320fa4b99fb09`. Все 14 проверенных диапазонов функций совпадают с обычным редактором побайтно; отдельное исполнение обычного EXE не проводилось. Машинная схема: `editor-object-icon-semantics.json`.

## Цепочка исходного кода

| Стадия | Установленная связь |
|---|---|
| Файл | ArtResource 84 байта по `+0xC8`; первые 64 байта — имя, например `ObjectIcons#2` |
| Конвертер `42D570` | Raw `C8` → intermediate `148`, presence DWORD `14` |
| Callback `4A1D80` | Передаёт ресурс в `model+6C` через `41BB90` |
| Класс ресурса | Vtable 4 байта, затем исходные 84 байта по `model+70`; вычисленный номер хранится отдельно в WORD `model+C4` |
| Разбор `41C0B0` | Находит первый `#`, преобразует следующий текст через `atoi 4ACE5A`, сохраняет low16; без `#` номер равен 0 |
| Getter `41CB30` | Возвращает WORD `model+C4`; реальный Object vtable `50AFFC`, слот `24` |
| Расчёт `49E960` | Ищет ObjectId в массиве Objects `global54F550+528`, получает номер через слот `24` и вычисляет прямоугольник |
| Карта `497AC0` | Перебирает размещённые объекты, получает прямоугольник из `49E960` и передаёт его в `497E20 → StretchDIBits` |

При числе колонок `C` и индексе `N` получаются `x=(N%C)*64`, `y=(N//C)*64` и прямоугольник `[x,y,x+64,y+64]`. У предоставленного `Graphics/ObjectIcons.bmp` размер 256×256, то есть сетка 4×4 и 16 ячеек. Примеры: `#2` → `[128,0,192,64]`, `#9` → `[64,128,128,192]`.

В самом `49E960` проверки числа строк нет. Индекс 16 при четырёх колонках даёт `[0,256,64,320]`, вне этого изображения. Это установленный расчёт координат, а не воспроизведение падения живого редактора. Размер других bitmap нельзя автоматически считать тем же. Произвольная подмена bitmap изменением префикса имени этим исследованием не подтверждена: выбранный путь использует номер в атласе семейства Objects.

**ABI проверен по assembly:** `49E960` получает три стековых аргумента `outRect, ObjectId, 3` и завершает `RET 0xC`. Третий аргумент в этом Object-helper не используется; декомпилятор показывает неполную сигнатуру.

## Интерфейс и сохранение

Диалоги 327 у обычного редактора и 256 у Pro содержат видимую группу `Object Icon` (1310), preview 1308 и spin 1309. `45A400` читает номер через слот `24`; `45AC40` меняет его через слот `28`, вызывающий `41C8E0`. Setter заменяет суффикс на `#%u` и обновляет вычисленный WORD. Полный цикл событий GUI здесь не исполнялся.

Writer `4A9390` получает исходные 84 байта через `41CE60(model+6C)`, копирует 21 DWORD в позицию raw `C8` и записывает запись 894 байта. Вычисленный WORD `model+C4` находится за пределами этих 84 байт и отдельно в KWD не записывается. Это объясняет, почему номер находится внутри строки, а не в новом числовом поле записи. Полная операция сохранения оригинальным редактором проверена только статически.

В ранее исследованном игровом loader `49DD60` этот слот не создаёт ресурс в runtime-определении Object. Это согласуется с найденным назначением в редакторе, но не доказывает глобальное отсутствие других игровых потребителей.

## Проверки и комплект для нового редактора

Выполнены 18 отдельных ограниченных запусков исходных инструкций: 5 полных конвертаций записи Objects, 6 преобразований числа и 7 расчётов прямоугольника с настоящим getter/vtable. Среди значений 0, 2, 9, 15, 16, 65535 и отдельное преобразование 65536. Конвертация сравнивается по всем 1022 байтам intermediate и защитному хвосту; при расчёте проверяются все подготовленные области. Оригинальный код, импорты и vtable не заменяются, страница нулевых адресов не отображается, внешних API-заглушек нет.

Это **не единая исполненная цепочка raw → MFC-модель → отрисовка**: MFC-конструктор, выделение строк и GDI не исполнялись; номер в fixture модели задан явно. Связь между стадиями подтверждается исходными инструкциями. Два независимых Ghidra CPU-контроля проверили полный converter и atlas getter: 6 областей, суммарно 4872 байта. Отдельно сверены с оригинальным PE все инструкции 14 функций и два блока vtable.

API `native_editor_object_icons.py` предоставляет `view`, `patch_icon_index` и `icon_rect`. Правка меняет только необходимые байты имени и новый NUL. Байты после нового NUL, флаги/union/type ресурса, остальные ресурсы и все остальные части файла сохраняются. Нестандартные имена остаются непрозрачными; незавершённые и слишком длинные строки не переписываются автоматически.

На 82 исходных контейнерах изучено 11756 записей; 328 точных пересборок целого файла в памяти, из них 246 изменений и 82 identity. Десять неверных входов отклонены. Исходные контейнеры, шесть путей EXE и bitmap сохранили хеши. Файлы игры и параллельного редактора не записывались.

В `editor-format-package.json` используйте **`effective_object_resource_bindings`**: слот C8 получает рекомендуемое имя `EditorMapIconResource`. Исторический `object_resource_bindings` и его ошибочно подходящий alias `InHandIconResource` сохранены для аудита; `semantic_corrections` явно указывает замену. Нельзя переносить C8 в 170 или синхронизировать эти ресурсы.

Воспроизведение: `emulate_editor_object_icons.py`, `crosscheck_editor_object_icons.py`, `prepare_editor_icon_primary.py`, `validate_editor_object_icons.py`, `build_editor_object_icons.py`, `build_format_package.py`, `audit_editor_object_icons.py`. Ghidra редактора работает на отдельной копии исследовательского проекта, порт 8090; база DX на 8089 продолжает работу.

В пакете 100 компонентов, прежние 99 схем сохранены побайтно. Это одно подтверждённое назначение оставшегося ресурса; существенные неизвестные всех 15 семейств ещё открыты, цель не завершена.
