## Физическая запись

Envelope8: `tag:u32=205 (CD)`, `payloadBytes:u32=84`. Полная современная запись92 байта. Смещения таблицы относятся к payload.

| Смещение | Байт | Поле |
|---|---:|---|
| `00..0B` | 12 | Position, три DWORD |
| `0C..17` | 12 | PositionMinClipExtent, три DWORD |
| `18..23` | 12 | PositionMaxClipExtent, три DWORD |
| `24/28/2C` | 4+4+4 | ViewDistance value/min/max |
| `30/34/38` | 4+4+4 | Zoom value/min/max |
| `3C/40/44` | 4+4+4 | Lens value/min/max |
| `48` | 4 | Flags DWORD |
| `4C/4E/50` | 2+2+2 | Углы Yaw/Roll/Pitch в baseline-порядке |
| `52` | **1** | ID пресета, BYTE |
| `53` | **1** | Неизвестный байт, converter его не копирует |

Исходная схема ошибочно объединяла52/53 в WORD Id. Native converters `56F900` и `42FE20` читают только BYTE52; BYTE53 нужно сохранять отдельно. Его неизвестное назначение не означает, что он должен быть нулём.

Все DWORD хранятся как исходные32-битные значения. В converter и при помещении в банк пресетов не выполняется деление на4096. Baseline Q12-представление остаётся удобной интерпретацией; единицы каждого поля Lens/ViewDistance независимо на экране не измерялись. Активация пресета содержит дополнительные преобразования, зависящие от режима камеры и мира.

## Парсер и intermediate

Game parser `570A20` использует callback в contextA4, editor parser `431220` — в contextA8. При длине84 читают84 байта. При иной объявленной длине сначала обнуляют84-байтовый raw buffer, потом читают объявленную длину **без проверки верхнего предела**. Oversized callback-path не исполнялся. API принимает только0..84 и дополняет недостающие байты нулями; исходная физическая длина сохраняется.

Intermediate152 содержит17 DWORD признаков наличия0..40. Raw0..47 копируются в mid44..8B; flags48 объединяются OR с mid8C; углы4C..51 — в mid90..95, ID52 — в mid96. Mid97 не назначается. Полные parsers сначала очищают весь intermediate через `56F850`/`42FD70`; standalone converter оставляет seed mid97 и OR-флаги, что проверено на00/A5/FF.

Если callback отсутствует, parsers пропускают payload через seek на объявленную длину, без преобразования. Отдельные прогоны проверяют такой пропуск для длин0/84/255; это безопасный seek-path, не чтение255 байт в84-байтовый буфер.

## Банк пресетов игры

Game callback `5215F0` получает camera manager через `world+4 → child+10 → virtualD0`, передаёт intermediate152 checksum helper и вызывает настоящий `449A30`. Он всегда возвращает1, даже если ID не принят.

`449A30` принимает только unsigned ID **1..18**. ID0 и19..255 игнорируются. Для принятого ID копирует152 байта в `cameraManager + 0x28 + ID*0x98`. Это сохранение конфигурации в слоте, а не немедленное перемещение активной камеры.

Есть дополнительное условие: при unsigned globalDWORD759AEC<5 выполняется `ZoomMax = ZoomMin + trunc0(signed32(ZoomMax-ZoomMin)/3)` с32-битными вычислениями; также presenceDWORD20 принудительно становится1. При обычных bounds3000/12000 новый max6000. Проверены обратный порядок и переполнение разности. Назначение global759AEC отдельно не установлено; называть его качеством графики или конкретным renderer пока нельзя.

Пятнадцать прогонов полной цепочки callback→store сравнивают весь0xC00-байтовый банк: изменяется только выбранный допустимый слот. Варианты rawBYTE53=0/255 не меняют промежуточную запись и результат банка при одинаковом BYTE52.

## Флаги и активные настройки

Статически прослеженный участок `44ACE0` переносит flags пресета в activeDWORDD92, zoom bounds — вD50/54, lens bounds — вD58/5C, view bounds — вD60/64. Полная активация, переключение режимов, timeline и режимы управления существом этим этапом не исполнялись. Следующие native-проверки задают активное состояние непосредственно и проверяют конкретные функции.

| Маска | Подтверждённый потребитель |
|---:|---|
| `01` | `449D40` пропускает относительное изменение yaw, activeWORDD84 |
| `02` | `449D40` пропускает относительное изменение roll, activeWORDD88 |
| `04` | `449D40` пропускает относительное изменение pitch, activeWORDD86 |
| `08` | `449CA0` блокирует относительный zoomDWORDD80 |
| `10` | `449FC0` блокирует относительный ViewDistanceDWORDD8A; исправляет baselineUNKNOWN_10 |
| `20` | `44A070` блокирует относительный LensDWORDD8E; исправляет baselineUNKNOWN_20 |
| `40` | `449AC0` и449BD0 блокируют прямое и относительное изменение XYZ |
| `80` | В assembly44ACE0:44AF3F блокирует переход к применению другого режима; эта ветвь здесь не эмулировалась |

Это **ограничения отдельных операций**, а не запрет любого изменения поля. Прямой ViewDistance setter449F70 и прямой Lens setter44A020 не проверяют соответствующие флаги; это подтверждено с flagsFFFFFFFF. У функций zoom/position дополнительно есть проверка busyDWORDDD8. Относительные view/lens в изученных методах busy не проверяют.

Signed ограничения используют **верхний предел минус1**. Например, bounds100/200 позволяют максимум199. Сложения DWORD выполняются с переполнением32 бит; затем применяются signed сравнения. Для пустых/обратных bounds это не универсальный безопасный clamp: API воспроизводит конкретную арифметику, а не чинит данные.

Относительные углы в449D40 имеют ограничения по режиму. Jump tables подтверждают свободное modulo2048 для mode1/2/10/11; семь native cases используют mode1 и маски01/02/04. Другие режимы ограничивают roll/pitch отдельно. Matrix rebuild44D6D0 заменён fixture счётчика вызовов: готовая матрица и изображение не проверялись.

## Что происходит в Editor Pro

В найденном обычном пути `48B5F0` контекст чтения сначала обнуляется настоящим42C730. Затем назначаются callbacks размещений. Участок регистрации `48B703..48B84D` проверен на seed00/A5/FF: RoomA0 получает492030, а **cameraA8 остаётся0**. Предшествующий A4 также остаётся0. Полная функция регистрации просмотрена; camera callback там не назначается.

Следствие для этого пути: `431220` видит A8=0 и пропускает CD через seek. Сам converter в EXE существует и умеет разобрать CD при искусственно зарегистрированном callback; его наличие не означает, что штатная модель редактора сохраняет камеры.

Полный Things writer4947C0 содержит присваивания record tagsC2..CC, но не CD и не цикл сериализации камер. Поэтому проверенный путь чтения/записи **не сохраняет CD как неизвестную raw-запись**. Для пользовательской карты с CD это риск потери данных. Реальный GUI open/save с такой картой не проводился; утверждение ограничено исследованными registration/parser/writer, не всеми версиями редакторов.

Первоначальные адресные кандидаты4921B0/4922B0 оказались callbacks условий и действий триггеров, не камер. Их discovery snapshots сохранены, но они не входят в финальную camera primary manifest.

## Проверка и интеграция

`phase40-validation.json` фиксирует84 эмуляции:16 parsers,6 converters,6 skip-path,15 game callback/store,21 относительных scalar controls,4 прямых scalar controls,6 position controls,7 angle controls,3 registration fragments.1786 API/boundary проверок,16 синтетических добавлений CD в копии двух контейнеров в памяти и472 точечных изменения с точным сравнением. Все110 исходных Things parse→pack без изменений.2857 первичных инструкций,21 повторный disassembly и21 live memory range совпали с исходными PE. Прежние17 основных данных и два EXE сохранили хеши; игровых изменений и запусков —0.

Машинная схема — `camera-semantics.json`, компонент51 `camera_semantics`. `native_cameras.py` разделяет raw view/patch, intermediate, preset projection и арифметику активных controls. Сохранять полный payload, BYTE53 и все неизвестные bits независимо от ограничений native preset ID. Ограничение1..18 относится к проверенному loader, а не к физической ширине BYTE и не к разрешению удалять нестандартную запись.

Для нового редактора безопасный подход остаётся прежним: сохранять полный raw-record и менять только выбранные поля. Визуальную семантику режимов, точные экранные единицы ViewDistance/Lens и смысл global759AEC нужно продолжать исследовать отдельно.
