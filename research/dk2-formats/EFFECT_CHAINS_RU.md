# Effects: немедленная цепочка NextEffectId

24 октября 2026, этап17. Установлен потребитель поля, которое в предыдущем отчёте оставалось с неизвестным моментом применения. Основание — код исследованного `DKII-DX.exe`, функция `0x440350`, полный сохранённый assembly. Игра с изменёнными картами не запускалась.

## Размещение поля

| Поле | В файле Effects | Промежуточная структура игры | Runtime definition |
|---|---:|---:|---:|
| EffectId | +0xB8, u16 | +0x16C | +0x79, u16 |
| NextEffectId | +0xC0, u16 | +0x174 | +0x7B, u16 |

Физическая запись —246 байт. Нулевой NextEffectId завершает цепочку. ID остаётся16-битным: диагностический код не отсекает старший байт и не трактует значения32768..65535 как отрицательные.

## Когда создаётся следующий эффект

Метод CBridge по vtable+0x98, `0x440350`, создаёт первый эффект, инициализирует его через `0x4347E0`, затем читает NextEffectId из определения этого экземпляра. Если ID ненулевой, управление возвращается к созданию следующего экземпляра **в том же вызове**. Ожидания смерти или завершения первого эффекта в этом цикле нет.

Четыре аргумента после EffectId передаются каждому initializer без изменения. Каждый созданный экземпляр вставляется в начало глобального списка bridge+0x336. Поэтому порядок новых узлов списка обратен порядку создания. Выходной указатель вызывающего получает только **первый** успешно созданный экземпляр.

Возврат — признак «создан хотя бы один». Если очередное выделение возвращает0 после создания части цепочки, функция возвращает1; ранее созданные экземпляры в этом caller не откатываются. Если ничего не создано, выходной указатель здесь не записывается. При выключенном глобальном разрешении создания по адресу0x69793C цикл также останавливается. Семантика остальных владельцев этого глобального состояния отдельно не восстановлена.

В просмотренном цикле нет проверки посещённых ID и предела длины цепочки. Цикл в данных может приводить к повторным выделениям, пока создание разрешено и allocator возвращает память. Это не доказательство безусловного бесконечного цикла: внутренности allocator и предел его пула пока не установлены. Передаваемое allocator число **0x159 — размер запроса**, его нельзя выдавать за число доступных эффектов.

Effects.NextEffectId отличается от EffectElements.NextEffectId: ранее установленный element-путь создаёт Effects при каждом обновлении элемента. DeathEffectId и DeathElementId также разобраны отдельно в `EFFECTS_RUNTIME_RU.md`.

## Применение в своём редакторе

`effect-chain-semantics.json` входит в общий пакет как `effect_chain_semantics`. `native_effect_chains.py` читает сырые записи, проверяет граф и строит ограниченную проекцию последовательности создания:

```python
from native_effect_chains import graph_audit, project_chain
checks = graph_audit(effect_section.records)
view = project_chain(effect_section.records, 239, step_budget=100)
assert view['created_ids'] == [239, 243, 245, 336]
```

`step_budget`, остановки при цикле, неоднозначном ID и отсутствующем определении — защитные проверки **нашего диагностического инструмента**. Их нет в таком виде в исследованном native-caller. Для корректных положительных уникальных ID используется явное отображение определений; алгоритм game-getter дополнительно записан в схеме. Не назначать дубликатам правило last-wins. Каталог с определением ID0 также останавливает проекцию как неподдержанный ввод.

Необязательный `allocation_successes` задаёт искусственный сценарий отказа после заданного числа успешных созданий. Он нужен для проверки частичного возврата, не эмулирует настоящий allocator. Отрисовка, RNG, ресурсы и полная инициализация экземпляров не моделируются.

Общий аудит этапа:52 граничных проверки,1248 точечных пересборок контейнеров в памяти, хеши17 исходных файлов и обоих EXE совпали. Полные результаты — `phase17-validation.json`; новые native-эмуляции не выполнялись.
