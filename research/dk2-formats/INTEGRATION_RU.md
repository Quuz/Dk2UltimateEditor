1. Прочитать последовательность секций до EOF. Не определять формат по расширению. Для каждого заголовка проверять маркеры, границы и длины.
2. Для каталога определять размер записи как D/N и выбирать известный вариант. Сохранить заголовок, raw записи, порядок и файл-источник. Не выводить ID из индекса массива.
3. Для Things читать N записей с парой tag/payloadBytes. Поле внешней длины D в одном штатном файле устарело; не отбрасывать согласованный по N и полной длине файл автоматически. Triggers имеют заголовок 60 байт и два счётчика; D часто считает лишь 16 байт на условие, без действий и оболочек.
4. Для Variables сохранять 16 байт целиком, включая повторения типов и неизвестные варианты. Порядок ResearchOrder существенен; type 224 не имеет измерения level.
5. Для карты читать по 4 байта на клетку. Четвёртый байт сохранять. При изменении размеров согласованно менять карту, области игроков, AP и размещения; одного изменения width/height недостаточно.
6. Изменять нужный диапазон байтов, сохраняя всё остальное. Для флага — только выбранную маску. Строки имеют фиксированную ёмкость, ANSI/UTF-16 различаются; не сдвигать следующие поля.
7. При добавлении/удалении записи пересчитать N и полную длину только её секции; D изменять с учётом семейства и исходного соглашения о длине. Следующие секции сдвинутся при сборке. Другие байты сохранять. Реальные ограничения ID/массивов движка отдельно от размера файла.
8. Передавать диагностику отсутствующих ID пользователю; не перенумеровывать всё автоматически. Globals и самостоятельные каталоги — отдельные области определений. AutoSave фактически ссылается на kop4Globals, это не AutoSaveGlobals.
9. Для Terrain проверять ID относительно суммы N реального прохода подсчёта: выделяется N+1 ячеек, запись адресуется напрямую по ID. Для семи простых семейств движок сортирует записи сам; дубликат не является обновлением. В Creatures сравнение учитывает CloneCreatureId при IS_UNIQUE, поэтому произвольная перестановка может нарушить поиск. Подробности и два creature getter — в CATALOGUE_LOADING_RU.md.

## Пример исследовательского API

```python
import dk2_formats as fmt

source = r'D:\Games\DK2\Dungeon Keeper 2\Data\editor\Creatures.kwd'
sections = fmt.parse(open(source, 'rb').read())
catalogue = sections[0]
records = list(catalogue.records)
records[0] = fmt.set_engine_scalar(records[0], 'MaxAngleChangeRaw', 2048)
catalogue.replace_records(records)
result = b''.join(section.pack() for section in sections)
# result — изменённый файл в памяти. Записывать в отдельный выбранный путь.
```

`set_scalar` использует исходную именованную схему OpenKeeper, поэтому для конфликтующих полей Creatures применять `set_engine_scalar`. Например, baseline Unk3cc трактуется как i16/4096; правильное игровое представление по +0xF20 — u16 угловых единиц. Дополнительные слоты флагов автоматически не синхронизируются.

Для FootstepFrames предусмотрен `set_footstep_frames(record, animation_slot, left_frame, right_frame)`: 48 пар u16. У Mass проверять класс `(raw & 65535) >> 12` в пределах 1..5. `compatibility_findings` отделяет проблемы, способные проявиться в движке, от формально корректного бинарного контейнера. Для Shots Data1/Data2 показывать обе интерпретации — ProcessType и DamageType. Текстовые ANSI-буферы отображаются через cp1252 с экранированием неопределённых байтов; raw остаётся авторитетным, кодировка локализованных строк может отличаться.

Effects/EffectElements также имеют `engine_fields`: суженные runtime-значения не заменяют четыре байта файлового скаляра. Значение полей зависит от GenerationType: у SPRAY +0xDA является SecondaryEffectId, у GOLD_COST первый GenerateId задаёт десять цифровых ElementId. GenerateIds хранить как восемь физических слотов с нулями и повторениями. Полные правила и оговорки — EFFECTS_RUNTIME_RU.md.

У заклинаний `engine_fields` отделяет AlternativeShot как selector пригодности от непереносимых AlternativeShotId/AlternativeRoomId. В KeeperSpells хранятся обычная и улучшенная тройки Shot/Data1/Data2. ResearchTime/BonusRTime не заменяют ResearchPointsRaw из Variables type17. Расчёт таймеров требует явно переданного TPS; неизвестный хвост CreatureSpells содержит ненулевые данные и сохраняется. Подробности — SPELLS_RUNTIME_RU.md.

`native_catalogue_loading.project_files(paths)` принимает явную область файлов в порядке загрузки, моделирует размещение и поиск ID и возвращает `findings`. Это отдельная проверка от codec `compatibility_findings`, поскольку сумма N зависит от области. Она не разрешает ссылки descriptor и не моделирует игровые поля. В Traps raw+0x204 имеет подтверждённую native-ширину 2 байта; baseline-дамп двух байтов не означает два независимых свойства. Назначение поля остаётся неизвестным.

`native_editor_views.editor_views(record, family)` показывает числовое представление исходного GUI отдельно от файлового хранения и игровой интерпретации. Ограничения GUI не являются пределами движка. `trap_commit_projection(record)` только сообщает возможное обнуление ManaCostToFire при снятом Require Mana. Не переносить это побочное действие в raw-пересборку автоматически. Terrain+0x224 масштабируется редактором /4096, но назначение остаётся неизвестным; скрытая подпись Mana Gen. не доказывает смысл Traps+0x204.

`native_editor_composition` привязывает Lean H/V к шести байтам Terrain и внешнему ключу Rooms.TerrainId. `set_terrain_lean(record, axis, values)` изменяет ровно три выбранных байта. `room_terrain_projection` показывает установленные принудительные присваивания GUI: три нулевых скаляра и известную часть флагов связанного Terrain. Это не полная эмуляция сохранения, автоматический ремонт или игровой валидатор. Редактирование Lean из Rooms не создаёт новых полей в записи Rooms.

`native_object_resources.object_resources(record)` показывает девять физических ресурсов с baseline-именем и отдельно native-подписью. `set_object_resource(record, raw_offset, resource_bytes)` заменяет ровно84 байта одного явно выбранного слота. Полный игровой смысл +0xC8 остаётся открытым.

Дополнены значения3/4/8, ранее отсутствовавшие в baseline enum. Принудительный runtime HAS_WALLS0x8 не копируется в raw автоматически. Неизвестный Rooms+0x1C4 по-прежнему сохраняется отдельно; все девять прямых resource-кнопок его пропускают. План не проверяет наличие моделей в WAD и не моделирует расстановку на клетках.

`native_trap_semantics` показывает Flags через native-маску0x3FFBF, charge-порог с явно заданным TPS и32-битный квадрат LOS-радиуса. `trap_charge_projection(record, ticks_per_second)` сообщает недостижимость порога>255 для проверенного byte-счётчика; это не полная симуляция выстрела. `trap_los_range_projection(record, tracking=False)` не определяет смысл TriggerData для других trigger callbacks. `trap_editor_flags_projection` не изменяет raw и не назначает игровые имена битам0x4/0x4000. Сценарий20TPS в аудите не подставлять в приложение как установленную частоту игры.

`native_trap_fire.trap_shot_origin(record, position_raw, heading)` использует точные таблицы PE и отдельное32-битное умножение/сдвиг для каждого слагаемого; heading0..2047, координаты4096 единиц/клетку. `trap_post_creation_projection` показывает только присваивания после успешного создания, отдельно возможную замену Data2 для TrapId16. ThreatDuration сужается в байт, но отсутствие duration не выключает проверенный emission gate, который читает Threat отдельно. Глобальный lifecycle угрозы API не моделирует.

У JSON авторитетны `raw_hex`, `header_hex`, `cells_hex`, `raw_data_hex`; поясняющие `fields`, `engine_fields`, `properties_fields` не являются командой изменить файл. Для JSON → binary использовать `rebuild_decoded`, изменив нужные raw-байты. Для редактирования ссылок descriptor и строк в этом исследовательском API нет отдельного setter; формат уже документирован.
