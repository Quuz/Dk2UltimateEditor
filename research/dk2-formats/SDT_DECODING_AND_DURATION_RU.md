# SDT: фактическое декодирование и длительность SFX

13 ноября 2026, продолжение проверки SDT после этапа 206. Закрыт вопрос о возможности декодирования закреплённых русских payload библиотекой FFmpeg. Игровой загрузчик, замена звука и воспроизведение пересобранного архива этим опытом не проверены.

## Что действительно декодировано

В установленном FFmpeg для Audacity использованы `avcodec-59.dll` (59.18.100) и `avutil-57.dll` (57.17.100). DLL и исходные архивы закреплены SHA-256 в [отчёте](sdt-decode/russian-decode-report.json). Ничего не устанавливалось, игровые файлы и PCM-аудиофайлы не записывались.

| Измерение | Результат |
|---|---:|
| Исследованные архивы с дефектом длины +40 | 32 |
| Декодированные записи | 3385 |
| Кадры, возвращённые FFmpeg | 150739 |
| Сэмплы на канал, суммарно | 173651328 |
| Выданные байты PCM | 347302656 |
| Ошибки API в основном проходе | 0 |
| Потоки, доведённые до EOF | 3385 |

Каждый возвращённый кадр содержит 1152 сэмпла, формат `s16p`, моно. Частота 32000 Hz и число каналов прочитаны из контекста декодера после получения кадра; число сэмплов, формат и PCM — из возвращённого `AVFrame`. Это фактический вывод декодера, отдельно от прежнего подсчёта позиций заголовков. Все числа сэмплов совпали с прежним расчётом по MPEG-заголовкам. Нулевой пакет длиной 720 байт отрицательного контроля отклонён с `AVERROR_INVALIDDATA`.

Координатор и независимый Sol повторили весь проход. JSON, включая все PCM-хеши, совпал после исключения измеренного времени выполнения. Вывод не распространяется на остальные SDT, другие издания, декодеры или повреждённые варианты.

## Метод и границы результата

Скрипт [audit_sdt_decode.py](sdt-decode/audit_sdt_decode.py) проверяет SHA-256 каждого из 32 исходных архивов. Payload определяется физической границей следующей записи/EOF; после проверки известного шаблона исключается один конечный NUL. Каждый 720-байтовый MPEG-кадр передаётся отдельным пакетом декодеру `mp2`. Полученные PCM-плоскости хешируются без выравнивающих байтов; затем подаётся NULL packet и выполняется чтение до EOF. Контексты, пакеты и кадры освобождаются через API библиотеки.

Использован Python ctypes с префиксами публичных структур; полные объекты выделяет FFmpeg. Реальная проверка относится к закреплённым Windows x64 DLL. Проверка major version и записанные ctypes-offsets сами по себе не доказывают совместимость с любой другой сборкой. Порядок полей сверялся по официальным [AVFrame](https://ffmpeg.org/doxygen/5.0/frame_8h_source.html), [AVPacket](https://ffmpeg.org/doxygen/5.0/packet_8h_source.html); порядок send/receive/drain — по [FFmpeg API](https://ffmpeg.org/doxygen/5.1/group__lavc__encdec.html).

`decode_errors=0` означает отсутствие отрицательных ошибок API в успешном проходе. Скрипт не читает полное `AVFrame.decode_error_flags` и не исключает маскировку повреждений самим FFmpeg. Это не проверка CRC, качества на слух, исходного звучания, игрового декодера, скорости или высоты тона в игре.

## Что теперь известно о `pcmBytes`

Все 3385 значений SDT `+20` отличаются от фактического необрезанного 16-битного PCM: 3322 больше, 63 меньше. Имя поля `pcmBytes` не следует подменять обещанием, что оно равно полному выводу любого декодера.

Пример: `speech_level1/speech_level1hd.sdt`, запись 1, SHA-256 `494fb4eab04ddfc5d500b9ad952e44ec3349e0c5bab773af708de7b7b48ebfbc`. Из 203 кадров FFmpeg вернул 233856 сэмплов, 467712 байт, 32000 Hz; длительность необрезанного потока 7308 ms. В SDT сохранены `pcmBytes=963546`, nominal rate 22050. SFX group/item/sound `1/1/1` содержит 21849 ms, что совпадает с округлением номинальной геометрии `963546 / (2 × 22050)`. Эти значения нельзя молча заменять длительностью 7308 ms: реакция игры остаётся неизвестной.

## Корреляция длительностей SFX

Новый [аудит](audit_sdt_duration_geometry.py) обходит BANK/SFX и разрешает ссылки отдельно в HD и HW. Исследована гипотеза `round_half_up(1000 × pcmBytes / (rate × bits/8 × channels))`, с каналами 1 для типов 02/24 и 2 для 03/25. Ниже считаются ссылки, включая повторные, а не уникальные аудиозаписи.

| Ссылки | Сопоставлено | Совпадение с ближайшей миллисекундой |
|---|---:|---:|
| HD MP2 mono, тип 24 | 6295 | 6294 |
| HD MP2 stereo, тип 25 | 328 | 328 |
| HW MP2 mono, тип 24 | 2563 | 210 |
| HD PCM, тип 02 | 87 | Все 87 по размеру payload; поле `+20` равно 0 |
| HW PCM, тип 02 | 84 | 0 по размеру payload; поле `+20` равно 0 |

Результат одинаков по числу совпадений для `Sfx` и `Sfx  rus`; исправление 32 известных полей длины выполнено только в памяти после проверки SHA. Отчёты: [stock](sdt-duration-stock.json), [russian](sdt-duration-russian.json). Для каждого корпуса: 6772 Sound-строки, 13544 попытки HD/HW-разрешения, 9359 разрешённых ссылок, 4123 отсутствующих архивов, 62 выхода индекса за диапазон. Две разрешённые ссылки на пустой тип 00 не участвуют в формуле. В русском дереве отдельно сохранены три прежних отклонения signature `speech_demo*SFX.map`.

Единственное расхождение HD MP2: `speech_horny/back/speech_hornysfx.map`, group/item/sound `1/1/1`, банк 1, `speech_horny/speech_hornyhd.sdt`, запись 1. В SFX 15020 ms; геометрия даёт 6009 ms при floor и **6010 ms при округлении к ближайшему**. Эта категория уже имела 60 выходов индексов за диапазон. Проверка не устанавливает назначение категории или способ её обработки игрой.

Таким образом, 6622 из 6623 разрешённых HD MP2-ссылок согласуются с номинальной геометрией. Значение нельзя автоматически пересчитывать по фактической длительности HW или по выводу FFmpeg для русской озвучки. Корреляция файлов не доказывает единицы и правила native-таймера для всех событий.

## Ограничение переноса Qt-плеера

Повторно прочитаны исходники Dethware ревизии [28adde55](https://github.com/Dethware/DK2/tree/28adde55f91145abdaab2df900a0bb6994aa04db), Git blob сверены с сохранённым индексом. В [clipcache.cpp, строки 112–125 и 148–154](https://github.com/Dethware/DK2/blob/28adde55f91145abdaab2df900a0bb6994aa04db/player/src/core/clipcache.cpp) декодеру запрашивается частота SDT, затем в Pcm сохраняется частота фактического Qt-буфера. Размер массива float приводится к `pcmBytes/2`: лишние значения обрезаются, недостающие дополняются нулями. Число PCM-кадров вычисляется делением числа значений на каналы.

В этом снимке `Pcm.sampleRate` далее не читается. [Layer](https://github.com/Dethware/DK2/blob/28adde55f91145abdaab2df900a0bb6994aa04db/player/src/core/layer.cpp) копирует сэмплы непосредственно, а [Mixer](https://github.com/Dethware/DK2/blob/28adde55f91145abdaab2df900a0bb6994aa04db/player/src/core/mixer.cpp) исходит из фиксированной частоты слоя 22050. Если backend вернёт другую частоту без нужного преобразования, эта цепочка не компенсирует различие. Мы не запускали Qt и не установили, как его backend выполнит запрос частоты; вывод сырого `avcodec` нельзя выдавать за вывод `QAudioDecoder`.

Поле `durationMs` в этом исходном снимке только объявляется и читается из карты; других употреблений не найдено. Завершение клипа определяется длиной PCM, а задержка — отдельным расчётом секвенсора. Это поведение самостоятельного Qt-плеера, не подтверждённая семантика DX. Ошибочные утверждения о неизбежной неверной скорости Qt без проверки backend в итог не приняты.

## Следующая проверка для редактора

Нужен отдельный опыт на копии SDT: замена одной записи с сохранением номера, контроль частоты/каналов, правильных смещений, `pcmBytes` и связанных SFX длительностей, затем проверка игрового загрузчика. До этого существующая пересборка доказывает сохранение структуры, а нынешний проход — только успешное FFmpeg-декодирование исходных физических payload.

Воспроизведение из опубликованного репозитория, Python 3.10+ и те же установленные Windows x64 DLL:

```powershell
python -B research/dk2-formats/sdt-decode/audit_sdt_decode.py 'GAME/Data/Sound/Sfx  rus' --report decode.json
python -B research/dk2-formats/audit_sdt_duration_geometry.py 'GAME/Data/Sound/Sfx' --baseline research/dk2-formats/sound-russian-sdt-length-audit.json --report duration-stock.json
python -B research/dk2-formats/audit_sdt_duration_geometry.py 'GAME/Data/Sound/Sfx  rus' --baseline research/dk2-formats/sound-russian-sdt-length-audit.json --report duration-russian.json
```

Хеши принятых файлов и выполненные проверки находятся в `phase207-sdt-validation.json`. Общий машинный пакет и очередь других форматов не объявляются завершёнными. Freebuff/Coarena после прежнего сбоя и исчерпания квоты повторно не запускались; Kilo завершился без измерений после ошибки инструмента. Реализацию декодера выполнил резервный Codex; связь длительностей измерил координатор; OpenCode сверил Qt-исходники; Sol независимо воспроизвёл оба аудита. Финальная приёмка выполнена координатором.
