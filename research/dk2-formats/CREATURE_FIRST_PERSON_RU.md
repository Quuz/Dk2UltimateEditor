# Creatures: покачивание и Sniper Zoom Multiplier

Этап25,25 октября2026. Исследован игровой `DKII-DX.exe` с ранее закреплённым SHA-256. Новые результаты получены из потребителей полей, а не из названий сторонних шаблонов. Схема: `creature-first-person-semantics.json`; чистые числовые проекции и точечные правки копий: `native_creature_first_person.py`. В общем пакете это компонент36 — `creature_first_person_semantics`.

## Хранение

Смещения raw одинаковы в проверенных вариантах Creatures5449/5537 байт. Intermediate и runtime — другие структуры; их смещения нельзя использовать для записи KWD.

| Raw | Представление | Native-параметр | Game intermediate | Game runtime |
|---|---|---|---|---|
| `0x107B` | unsigned DWORD /4096 | Sniper Zoom Multiplier | `0x146B` | `0x79B`,DWORD |
| `0xDBC` | unsigned DWORD /4096 | Waddle Scale | `0x11AC` | `0x863`,DWORD |
| `0xDC0` | unsigned DWORD /4096 | Oscillate Scale | `0x11B0` | `0x867`,DWORD |
| `0xD3D` | unsigned byte | Walk Cycle Scale | `0x112D` | `0x86B`,DWORD |

Игра переносит три DWORD без нормализации; byte расширяет нулями до DWORD. Native UI/writer уже описаны в `CREATURE_EDITOR_SCALED_RU.md` и `CREATURE_EDITOR_NORMALIZATION_RU.md`. В частности, Editor Pro сбрасывает Waddle/Oscillate>1 в0 и WalkCycle>12 в4 при callback загрузки модели. Эти правила редактора не следует автоматически применять при чтении/сохранении своим редактором.

## Sniper: дробь отбрасывается, порог — 2

В функции `0x40FDF0` значение runtime+`0x79B` сначала сдвигается **логически вправо на12**. Дальше проверяется `integerFactor>1`. Поэтому Q12-значение1,5 (`raw=6144`) не проходит,1,999755859375 (`raw=8191`) тоже;2 (`8192`) проходит. Значение2,89990234375 (`11878`) используется как2.

Эта проверка находится до выбора ветки включения/выключения. Даже при уже установленном SniperMode значение меньше2 приводит к выходу без команд из этой функции. Это не доказывает невозможность выключить режим другими игровыми путями.

Далее проверяются физические слоты заклинаний0,1,2 по порядку. Getter `0x4943F0` возвращает запись `runtime+0x5E1+19*i`, если `i<runtimeByte789`; иначе — инициализированную нулевую запись. Учитываются:

- `CreatureSpellId`, byte+0: должен быть ненулевым;
- `LevelAvailable`, byte+1: должен быть не больше текущего unsigned уровня существа `instance+0x403`.

Побеждает первый подходящий слот. Если такого нет, команд нет, включая случай уже включённого SniperMode. Raw-массив начинается с`0xDC4`, содержит3 записи по24 байта; ID и уровень лежат в каждой на+22/+23. Полная раскладка — `CREATURE_SUBRECORDS.md`.

После выбора вызывается lookup определения заклинания через world vtable+`0xE8`. Его результат здесь не проверяется. В эмуляции пустой каталог возвращал0, и функция всё равно создавала команды. В самом теле также нет проверки конкретного SpecialAbility enum; условия внешнего вызывающего кода этим результатом не заменяются.

## Какие команды создаются

Bridge getter `0x43A980` возвращает `bridge+0x3E5`, встроенный объект камеры. Из `camera+0x1D8` читается базовый DWORD `B`. Привязка vtable к getter проверена непосредственно по байтам EXE. По дополнительной структуре sgmap этот DWORD лежит в конфигурационной записи режима2, поле+`0x80`; физическая единица поля здесь не установлена.

Состояние SniperMode — бит`0x80000000` DWORD `instance+0x3E6`. Название подтверждено native diagnostic dump.

| Исходное состояние | Первая команда: тип`0xE` | Вторая команда: тип`0x27` |
|---|---|---|
| SniperMode выключен | `(low32(B*integerFactor),300,0)` | `(1,0,0)` |
| SniperMode включён | `(B,300,0)` | `(0,0,0)` |

В таблице показаны три payload DWORD. Далее в пакете идут DWORD типа на+`0xC` и WORD player tag на+`0x10`. Умножение при включении сохраняет только младшие32 бита; деления обратно при выключении нет — используется вновь прочитанное базовое значение.

Native initializer `0x511A80` записывает type27 и handler`0x5171D0` в одну action-запись по`0x6A5A1C`; связь не выводится только из названия sgmap. Обработчик для команды27, если у игрока есть possessed creature, устанавливает:

```text
flags = (flags & 0x7FFFFFFF) | ((actionValue & 1) << 31)
```

Другие биты сохранены. При отсутствии possessed creature запись пропускается. Producer отправляет пакеты через очередь действий. Единицу параметра300, конечный угол обзора/пиксельный zoom и работу renderer нельзя достоверно вывести только из этого producer; обработчик камеры здесь не моделируется.

## Waddle и Oscillate: точная арифметика

Функция ввода от первого лица `0x40E910` использует таблицу из2048 signed DWORD по адресу`0x6C1488`. Таблица извлечена из исходного EXE и включена в схему: диапазон−65536..65536, значения на индексах0/512/1024/1536 —0/65536/0/−65536. Пересчитывать её через floating-point sine для точного повторения не требуется.

Глобальная фаза `P` хранится в`0x6CE968`. При нулевом флаге движения и результате instance vcall88==0 код сбрасывает фазу и запоминает текущий timestamp. Иначе `P=unsigned32(now-origin)//50`. Единица timestamp отдельно не подтверждена.

Обозначения: `u32` — младшие32 бита, `s32` — интерпретация32 бит со знаком, `tz` — деление с усечением к нулю. Пусть `C` — расширенный WalkCycle byte:

```text
p = u32(C * P)
W = (u32(p << 7) >> 2) & 2047
O = (u32(p << 8) >> 2) & 2047
w = s32(u32(table[W] * rawWaddle))
o = s32(u32(table[O] * rawOscillate))

добавка Waddle к локальному вводу = tz(tz(w / 512) / 4096)
payload DWORD0 команды 0x80       = tz(tz(w / 4096) / 4096)
добавка Oscillate                 = tz(tz(o / 128) / 4096)
```

При ненулевом локальном half-флаге добавка Oscillate дополнительно делится на2 с усечением к нулю. Сложение с локальным DWORD идёт modulo2^32. Для отрицательных значений нельзя подменять усечение к нулю обычным Python `//`.

Пример: rawWaddle=rawOscillate=4096, C=4,P=4 дают Waddle input128 и action80 payload16, Oscillate0. При P=6 и half=true Oscillate=−256. Разные делители двух потребителей Waddle подтверждены независимо; объединять их в одну амплитуду без учёта места использования нельзя.

Добавка к вводу Waddle требует изменившейся фазы, vcall88==0 и ненулевого Waddle. Во всей функции есть дополнительные условия состояния/ввода/местности. API `motion_terms` возвращает именно числовые члены после этих условий, а не полный результат игрового контроллера. Команда80 и локальные координаты здесь не получают новых неподтверждённых физических единиц.

Cycle=0 не вызывает деления на0: оба индекса0 и добавки0. При слишком больших амплитудах результат может переполниться ещё до делений. Поведение исходных32-битных инструкций сохранено; автоматического ограничения диапазоном GUI в этих фрагментах нет.
