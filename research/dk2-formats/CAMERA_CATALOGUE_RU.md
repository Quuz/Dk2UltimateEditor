## Как собирается секция камер

| Поле заголовка | Смещение | Значение |
|---|---:|---|
| Signature | `00` | 190 |
| Size field width | `04` | 4 |
| Whole size S | `08` | `56 + 92*N` |
| Info tag / size | `0C/10` | 191 / 28 |
| Record count N | `14` | Размер массива камер |
| Version DWORD | `18` | 1 |
| Data tag / size D | `30/34` | 192 / `92*N` |

Смещения здесь шестнадцатеричные. Физическая запись: `CD:u32`, `84:u32`, затем84 байта. Pro берёт массив из context60C, count610; RC3 — array608, count60C. Getter проверяет индекс относительно count; writer затем пишет непрерывный участок `model+4` длиной84. Никакой сортировки ID, удаления дубликатов или ограничения1..18 при записи здесь нет. Нулевые указатели этот writer безопасно не фильтрует; такие случаи не эмулировались.

Дата и запись файла в тестах заменены контролируемыми fixtures. При fixture, назначающем9 байт даты, header37/47 сохраняют ранее лежавшие байты стека. Это не полная спецификация реального clock/date helper: он не исполнялся. Новый редактор должен сохранять исходный56-байтовый header и менять необходимые N/S/D через контейнерный codec; воспроизводить случайные stack bytes не требуется.

## Последний байт и короткие записи

Различаются два поведения:

- Сам writer пишет все84 байта модели, включая последний байт, полный Flags DWORD и BYTE ID.
- Полный parser431220 очищает intermediate152, converter42FE20 не копирует raw53, callback49F550 переносит обнулённый mid97 в последний байт модели. Поэтому цепочка **parser→model→writer обнуляет raw53**. Короткие payload0..83 в этом пути также превращаются в полную84-байтовую запись.

Во всех39 реальных камерах raw53 равен0; потеря ненулевого значения подтверждена отдельной синтетической записью. Для нашего редактора исходный байт53 и исходная длина остаются авторитетными: нативная нормализация — отдельно вызываемая проекция, а не правило обычного сохранения.

## Повторяющиеся ID и порядок загрузки

39 записей содержат18 разных ID:1..11 по одному разу,12..18 — **по четыре раза**. Это состояние фактического файла; по этим данным не устанавливается историческая причина появления повторов. Нельзя автоматически считать21 запись мусором или исправлять count на18.

В четырёх нативных проверках игра получила все39 записей в прямом и обратном порядке при Machine Spec Level4/5. Полные callback `5215F0` и store `449A30` исполнились156 раз, сравнивался весь банк0xC00. Manager provider и checksum helper являются fixtures.

Для принятого ID последующая камера заменяет сохранённый152-байтовый пресет в его слоте. У ID13 Flags после исходного порядка равен `0x2A`, после обратного — `0x22`. Таким образом, порядок реально влияет на результат. Это проверенное правило **каталога камер**, а не универсальное правило дубликатов остальных KWD. Ограничение игрового store1..18 не даёт редактору права удалять raw ID0/19..255 или перенумеровывать записи.

Это загрузка конфигураций пресетов, не проверка применения режима к активной камере или конечного изображения. Полная активация и renderer остаются отдельными неизвестными.

## Интерфейс RC3

Источник: установленный `DK2 Editor rc3.exe`, SHA-256 `7368d200cc5ac7e0cdb28c9852d9aa51b960fd718d9eea8dd927c4084add102c`. Его отдельная исследовательская копия не меняет оригинал. DDX437790, fill437D50, commit437F80 и ресурсы333 сверены с первичными байтами EXE.

| Поля | Числовое представление RC3 | DDV диапазон GUI |
|---|---|---|
| Position, MinClip, MaxClip | signed DWORD /4096 | 0..32000 |
| ViewDistance value/min/max | signed DWORD /4096 | −64000..64000 |

Это пределы GUI, не физические пределы raw32/16-битных полей и не измеренные экранные единицы. Commit умножает double на4096 и вызывает ftol4B9850; произвольное дробное округление нативно не сертифицировано этим этапом. Имена XY/YZ/XZ не дают основания объявлять значения градусами.

Семь чекбоксов Angle XY/YZ/XZ, Zoom, View Distance, Lens, Position соответствуют маскам01/02/04/08/10/20/40. Setter считает любой ненулевой DWORD истинным и сохраняет все остальные биты model4C. GUI fill/DDX/commit изучены статически, не исполнялись. Игровые ограничения отдельных операций по этим маскам описаны отдельно в `CAMERAS_RU.md`.
