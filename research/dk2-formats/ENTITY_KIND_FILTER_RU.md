# Типы сущностей: обход по kind/owner и зацепки Doors236

Этап69, 27 октября 2026. Уточнены источники указателей у оставшихся текущих кандидатов чтения DoorWORD99. Нового игрового назначения Doors236 или Traps204 не установлено. Совпадение числового смещения не считается подтверждением типа, а наличие типизированного пути не доказывает невозможности ошибочного вызова с другим объектом.

## Полный native-фильтр

Функции DX453700 и старого EXE44C250 имеют по91 байту. Полные тела совпадают после замены только двух DWORD-адресов общей tag table:6EE540 против6D95C8. Профили выбираются по точным SHA, не по имени папки или предполагаемой версии.

ECX указывает на WORD головы списка. Первый аргумент — требуемый kindDWORD, второй — owner, из которого используется только low16, третий — адрес выходного DWORD. Код:

1. Берёт только первый WORD по ECX и получает указатель из общей таблицы.
2. Проверяет entityDWORD12 на равенство всему32-битному kind и entityWORD28 на равенство low16 owner.
3. При несовпадении переходит по nextWORD0C через ту же таблицу.
4. Первое совпадение записывает через выходной указатель и возвращает1. При NULL возвращает0, не изменяя прежний выходной DWORD.

Это поиск в порядке списка, не сортировка ID и не перечисление всех совпадений. Второй WORD по ECX+2 не просматривается. OwnerFFFFFFFF означает сравнение сFFFF, а не любой владелец. Kind00010003 не равен3. В этом helper нет чтения validity array, RTTI/vtable, проверки циклов или специального запрета tag0. Синтетический ненулевой slot0 может дать успех; это не утверждение о штатном выделении entity0 миром.

Полные функции исполнены в32 случаях, по16 на профиль: пустота, первое/позднее совпадение, неверный тип/owner, старшие биты параметров, kind0/4, порядок100→1→50, NULL-завершение, slot0, tagFFFF, неиспользование второго headWORD и отсутствие wildcard. Все заданные64-байтные экземпляры, source head и table slots сравниваются неизменными. Native returnEAX и выходной указатель проверяются отдельно; при неудаче выход сохраняет CAFEBABE.

## Какие указатели удалось связать с ловушками

В штатных подтверждённых цепочках kind3 связан с Traps; native CTrap RTTI/конструктор/инициализатор и поле definitionF7 ранее закреплены этапами62/68. Нельзя распространять это на любую вручную повреждённую runtime-структуру с произвольно установленным kind.

| Чтение DWORD9A в DX | Подтверждённый источник |
|---|---|
| 4A7D58 | Ранее: CTrap vtable slot14 →4A84E0→4A7D10 |
| 4A9C99 | Ранее: CTrap vtable slot4C →4A9B70, диагностический вывод |
| 4A7DD9 | 458F60 проверяет kind3 по458F99, затем передаёт тот же объект в4A7D90; второй caller4A0930 использует case3 native jump table |
| 4A9163 | 4A8E70 явно передаёт kind3 в453700, получает выходной указатель в ESI, затем читает definitionF7 и его DWORD9A |
| 4A8381 /4A839B | Та же выбранная фильтром ловушка передаётся как ECX в4A80E0 по4A9210 |

Jump table4A0E14 содержит пять targets; case3 ведёт в4A0ACE, откуда вызов4A7D90 получает выбранный объект. Эти шесть адресов имеют реальные пути от ловушек и читают поле Trap ManaCostToFire DWORD9A, а не физическое DoorWORD99. Оба слова могут пересекаться численно при анализе разных структур, но это не перенос данных двери в ловушку.

Список семи старых потребителей не объявляется проверенным только потому, что отдельный89-байтный префикс фильтра был похож. Финальное доказательство эквивалентности включает все91 байт; старые callsites требуют отдельного анализа. Первоначальная длина префикса89 исправлена до публикации, поскольку последняя инструкция RET imm16 занимает ещё два байта операнда. Нативные32 прогона всегда исполняли полные функции; диагностика сохранена в `phase69-superseded-filter-length.json`.

## Отдельный нетипизированный путь

Полный33-байтный handler513730 берёт tag из low16 messageDWORD0, получает ECX из общей tag table и передаёт messageDWORD4 в4A7E70 по513744. В самом handler нет проверки NULL, validity array или kind. Это не один из форматов KWD/KLD, а отдельный командный вход. Название «ручная активация» — описание поведения по вызываемой функции, а не новая подтверждённая строковая подпись команды.

Чтение4A7EBF поэтому сохраняется как нетипизированный маршрут. Вызываемая функция затем может вызвать тот же4A80E0, у которого выше подтверждён путь от нормальной ловушки. Наличие такого маршрута не позволяет объявлять все его инструкции глобально доступными только CTrap. Контракт производителя/диспетчера команды, приём неверного ID в обычном интерфейсе и фактические последствия не проверены. Намеренно переданный неправильный kind не устанавливает штатное назначение Door236 и не доказывает, что редактор повредил файл.

## Пакет и ограничения

Сверены после эмуляций9 полных PE-функций, из них только два фильтра исполнялись в новом этапе. Семь остальных — статические контексты. Отдельно сверена20-байтная jump table. Проверены исторические SHA82 исходных файлов и четырёх EXE. Новых raw-патчей нет; прежние656 Door-пересборок этапа67 и Trap-проверки этапов60/61 остаются самостоятельными доказательствами, не повторяются в новых счётчиках.

`entity-kind-filter-semantics.json` вложен в `trap-semantics.json.phase69_entity_filter`; Doors содержит ссылку с SHA в `phase69_consumer_review`. Отсутствующий entry считается NULL; обнаружение цикла — диагностическое ограничение API, отсутствующее у native-кода. Это не сериализатор карты.
