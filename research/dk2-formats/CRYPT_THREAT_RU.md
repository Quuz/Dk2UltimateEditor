## Распределение и накопитель

Источник содержит специальный tag поWORD502 и два массива по8WORD с504 и514. Сначала считаются **все ненулевые слоты**, затем Threat делится на это число с усечением к нулю. Только после деления каждый получатель проверяется по таблицам существования/указателей, типу Creature и настоящей4512F0. В новых сценах одинаковыеXY дают её штатный ранний успех; прохождение стен или дверей не моделировалось.

Два слота с разными целями при базе100 дали50 каждой. Один действующий tag и один несуществующий ненулевойtag дали действующей цели50, не100. Три одинаковыхtag не объединяются: каждая запись даёт33, итог99.

У получателя:

```text
WORD524 = (oldWORD524 + adjustedThreat) & FFFFh
если signed32(adjustedThreat) > unsignedWORD535:
    WORD533 = sourceTag
```

Порог строгий: при добавке100 и пороге100 прежний sourceTag не меняется. Сравнивается отдельная добавка, а не сумма накопителя. Переполнение WORD не насыщается:65500+100→64.

Перед распределением предыдущий sourceWORD524 переносится в526 с коэффициентом расстояния и обнуляется:

```text
distance = min(10, max(abs(sourceTileX-ownerWORD_B43), abs(sourceTileY-ownerWORD_B45)))
sourceWORD526 = low16(oldWORD524 * distance / 10)
sourceWORD524 = 0
```

Настоящая4C5F50 возвращает указательowner+B43. Происхождение этой опорной точки здесь не установлено; её нельзя объявлять координатой сердца только по имени поля стенда. В проверках100 превратилось в60 при дистанции6, в0 при0 и в100 при дистанции больше10.

Состояния209/255/256/257 и ненулевой sourceWORD44B останавливают распределение до изменения накопителей. Новые сценарии выполнили state209 и WORD44B; остальные три значения подтверждены исходной48F350, не новыми отдельными прогонами.

## Vampire, Unique Vampire и Maiden of the Nest

Это три группы уже подтверждённой Crypt-карты18 счётчиков. Счётчики меняет настоящая4D8E60; коэффициенты в потребителях заданы EXE, новых полей процентов KWD нет.

**Vampire, ID8, ownerBYTE108E источника:** при положительном signed8 счётчике применяется `(100+30*count)%` с signed32-произведением и усечением к нулю. Для базы100 один даёт130, два —160.

**Unique Vampire, ID42, ownerBYTE108F источника:** положительное значение108F включает дополнительную ветку, но коэффициент берётся из **108E**:

```text
если signed8(owner108F) > 0:
    D = trunc0(s32(low32((100 + 40*signed8(owner108E)) * D)) / 100)
```

Это подтверждено байтами исходных инструкций:

```text
45E638  MOV BL,[ESI+108E]      # счётчик Vampire
45E667  MOV AL,[ESI+108F]      # только проверка Unique Vampire
45E671  MOVSX EAX,BL          # коэффициент снова из Vampire
```

| Счётчики Vampire / Unique Vampire | Угроза из100 |
|---|---:|
| 0 / 0 | 100 |
| 1 / 0 | 130 |
| 0 / 1 | 100 |
| 0 / 3 | 100 |
| 1 / 1 | 182 |
| 1 / 3 | 182 |
| 2 / 1 | 288 |

Регистрация ID42 настоящей Crypt-функцией при нулевом108E оставила100; при108E=1 дала182. Удаление вернуло130. Это похоже на ошибку использования счётчика, но намерение разработчиков не доказано. Нельзя подписывать эффект «+40% за каждого Unique Vampire», исправлять файлы или подменять формулу обычным ожидаемым поведением.

**Maiden of the Nest, ID45, ownerBYTE108D получателя:** при положительном signed8 счётчике получаемая добавка становится `(10-count)*D*10/100` с signed32-произведением и усечением к нулю. Один уменьшает100→90. Применяется после обоих исходящих бонусов;182→163. Регистрация у владельца цели8 дала90, у другого владельца7 оставила100. Отдельная45C5D0 использует такую же поправку.

Локального clamp нет: счётчик10 дал0,11 превратил100 в−10 и при нулевом накопителе записал65526. Это диагностическая проверка арифметики, не рекомендуемый диапазон GUI и не доказательство бесстрашия в полном ИИ. Значения128 счётчиков читаются как отрицательные и не проходят положительные gates.
