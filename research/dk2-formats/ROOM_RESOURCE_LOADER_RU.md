# Rooms: игровые запросы ресурсов и четыре сохранённых блока

Этап 150, 31 октября 2026. Только предоставленный `DKII-DX.exe`, SHA-256 `d7a8b854e4e4f02709eba271bead6fe2307dd6e332b5a96e70857e5b0e19fb8a`.

Оригинальный загрузчик Rooms выполнен с сервисом запросов ресурсов, который возвращает успех. В проверенных путях четыре 84-байтовых блока влияют только на сумму байтов промежуточной записи. Их изменение не меняет запросы моделей и остальные проверенные выходные данные загрузки. Изменение имени `Complete Mesh` меняет реальные имена запросов.

Для нашего редактора это уточняет границу между подписью свойства в оригинальном интерфейсе и его применением игрой. Подписи Straight/Inside/Outside подтверждены как элементы редактора, но независимая замена моделей пола через эти поля в выполненном загрузчике не обнаружена.

## Какие блоки проверены

Размер записи Rooms — 1055 байт. Смещения отсчитываются от её начала.

| Поле оригинального редактора | Raw | Промежуточная запись | Размер |
|---|---:|---:|---:|
| Straight Mesh | `0x11C` | `0x1F0` | 84 |
| Inside Corner Mesh | `0x170` | `0x244` | 84 |
| Назначение неизвестно | `0x1C4` | `0x298` | 84 |
| Outside Corner Mesh | `0x218` | `0x2EC` | 84 |

В 2 075 исходных Room-записях из 82 контейнеров все четыре блока целиком нулевые. Заполненные имена, метаданные и типы для новых проверок заданы на диагностических копиях. Это исследование поведения загрузчика при таких данных; штатное применение заполненных блоков в исходном корпусе не найдено.

Каждый блок сохраняется конвертером в промежуточной записи. При обычной загрузке все его 84 байта читаются инструкцией `4EACFC` в общем цикле суммы. Других чтений этих диапазонов в принятых исполнениях загрузки нет.

Прежний этап 124 отдельно доказал сохранение неизвестного `0x1C4` через настоящий выделенный редактором объект модели и writer. Новый этап проверяет игровую сторону. Ни одной новой подписи для неизвестного ресурса не вводится.

## Результаты выполнения

Проверены все 13 режимов TileConstruction на шаблоне Temple: исходные четыре нулевых блока и вариант, где заполнены все четыре. Дополнительно каждый блок изменён отдельно, выполнены варианты с типами неизвестного ресурса 0/255, без сервиса ресурсов и в режиме обновления. Все 26 исходных записей standalone `Rooms.kwd` также прошли настоящие конвертер и загрузчик.

Для 19 пар сравнены полностью 51 область памяти, 240 039 байт на пару. Различаются только выбранные 84-байтовые диапазоны raw/MID и до четырёх байтов контрольного значения. Журнал запросов ресурсов и остальные проверенные байты совпадают. В паре обновления контрольное значение тоже сохраняется.

Положительный контроль меняет имя `Complete Mesh` на `P150_Control` и получает другие имена запросов. Это подтверждает, что проверка четырёх блоков проводится при работающей ветке запросов. Их последовательность для пола совпадает с независимо построенным прежним `room_floor_resource_plan` во всех принятых режимах; дополнительные Start/End и общие ресурсы записаны отдельно.

Сервис запросов явно подготовлен: он принимает имя, тип, флаги и указатель на возвращаемый handle, записывает журнал и возвращает успех с последовательным идентификатором. Настоящая `504D80` разбирает метаданные ArtResource и записывает их в runtime-дескрипторы. Реальные файлы моделей, геометрия и изображение на GPU не загружаются. Одинаковый порядковый handle при другом имени означает другой запрос в отдельном запуске, а не доказательство одинаковых моделей.

Исходный HeroPortal ID 19 не делает запросов в этом загрузчике. Это не означает, что у него нет графики в других игровых путях.

## Контрольное значение

При World DWORD `+0xA3C7 = 0` функция `4EACC0` обнуляет runtime DWORD `+0xA2` и складывает все 1267 байт промежуточной записи Rooms. В сумму входят флаги присутствия и четыре рассмотренных блока.

Для исходного Temple получено 6520; после диагностического заполнения четырёх блоков — 20980. В обоих случаях это в точности сумма промежуточных байтов. Такое изменение не следует трактовать как свидетельство, что изменился запрашиваемый набор моделей.

При ненулевом World `+0xA3C7` эта инициализация и сумма пропускаются. В тесте явно заданное прежнее значение `0x12345678` осталось прежним. Начальное ожидание нуля исправлено после сверки исходных инструкций: путь обновления сохраняет прежнее значение.

`+0xA2` здесь — смещение в runtime-определении, а не место для правки внутри KWD. Обычный загрузчик рассчитывает это значение сам. Новый сериализованный checksum-параметр этим результатом не вводится.

## Реализация редактора

Нужно сохранять все четыре блока, даже если они нулевые и игровой потребитель модели пока не установлен. В интерфейсе нельзя обещать отдельную замену углов/прямых участков только на основании подписи оригинального редактора. Названия моделей пола в выполненных ветках формируются из `Complete Mesh` по правилам TileConstruction; подробные последовательности находятся в машинной схеме ресурсов Rooms.

Для точечной правки явных 84 байт добавлен узкий API:

```python
from native_room_resource_loader import patch_resource
changed_record = patch_resource(raw_record, 0x1C4, resource_bytes_84)
```

Он сохраняет все остальные байты. Это контракт хранения, а не проверка пригодности произвольного имени/типа для отображения. На 82 контейнерах выполнены 328 точных изменений, обратное восстановление и decode → rebuild; прочие данные и исходные файлы сохранены.

## Доказательства и ограничения

Приняты 62 сценария и шесть независимых проверок Ghidra: 312 областей, 1 440 258 байт. Сверены полные байты 21 функции и пяти блоков таблиц/строк, покрыты все 2 616 уникальных исполненных адресов оригинального PE. SHA-256 310 исходных файлов и семи путей EXE сохранены; прежние 128 компонентов спецификации не меняются.

Это полная цепочка raw-конвертеров и загрузчиков с подготовленными World, Terrain cache и внешним ресурсным сервисом. Создание геометрии комнаты, размещение клеток, поздние потребители, обычный World tick и реальный renderer в неё не включены. Нельзя объявлять глобальную неиспользуемость блоков или переносить результат на другой EXE/Flame-патчи.

Машинная спецификация — `room-resource-loader-semantics.json`; актуальные примечания доступны в `editor-format-package.json → effective_room_resource_consumption`.

```text
python emulate_room_resource_loader.py
python crosscheck_room_resource_loader.py
python prepare_room_resource_loader_primary.py
python validate_room_resource_loader.py
python build_room_resource_loader.py
python audit_room_resource_loader.py
```

Назначение неизвестного `0x1C4` остаётся открытым. Уточнено подтверждённое поведение четырёх блоков при загрузке; общая цель по 15 семействам не завершена, оценка около 75% сохраняется.
