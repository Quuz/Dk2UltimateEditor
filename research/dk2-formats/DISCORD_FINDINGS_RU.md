# DK2 Hex Editing: полезные наблюдения и проверка

Уточнение первичным анализом,этап86 — `CREATURE_HATE_JOBS_RU.md`: наблюдение опотереHateJob3/4 теперь подтверждено собственными native-проверками. ConvertersDX/Pro читают14E1/14E5,но перезаписываютalternative0;writerPro не сохраняет туда дополнительныеHateJobs,а дваждыпишетrawE7C/E80. ПервыеальтернативныеJob/Mood формируют runtime-запреты. Подтверждены две реальные Prince-записи и22native-композиции. Исходные сообщения остаются историческимконтекстом,не первичнымдоказательствомэтихновыхвыводов.

Дата чтения: 21 октября 2026. Публичный WidgetBot на [Keeper Klan](https://keeperklan.com/forum.php). Ветка **DK2 Hex Editing** доступна через список веток `general`, без входа и отправки сообщений. Прямой путь WidgetBot с ID ветки в позиции обычного channel ID сообщает Channel unavailable, поэтому для открытия нужно пользоваться родительским каналом и списком веток.

Прочитаны участки истории за 2022–2026 годы. Полнота всей истории, всех вложений и удалённых сообщений не подтверждается. Ниже пересказ технических фактов, а не полная копия переписки. Старые сообщения содержат предположения, ошибки и сведения о конкретных старых версиях игры — они не считаются автоматически верными для Flame 2026.

## 1. Порядок исследований — подтверждённая структура

nsdr2025, 25 марта 2026, описывает тип `0x11` в переменных как запись исследования. Наблюдение согласуется с новым шаблоном `variables_struct.bt` и всеми 29 записями этого типа в вашем GlobalVariables.kwd.

| Смещение в 16-байтовой записи | Тип | Значение |
|---|---|---|
| `+0x00` | u32 | `17 = 0x11`, ResearchOrder |
| `+0x04` | u32 | Категория: 1 Room, 2 Door, 3 Trap, 4 KeeperSpell |
| `+0x08` | u32 | ID определения внутри выбранной категории |
| `+0x0C` | u32 | Сырое значение стоимости исследования. В шаблоне ResearchPoints; перевод в секунды здесь не проверен |

Порядок записей в файле задаёт последовательность. В вашем файле первая по `0x238`: `[17,4,4,1000]`, то есть KeeperSpell ID 4, стоимость raw=1000. Далее 12 записей spells, 6 doors, 11 traps; все их ID существуют в соответствующих текущих каталогах. Последняя по `0x3F8`: `[17,3,5,1000]`.

Важное различие: эти категории **не совпадают с AvailabilityType**. Там 1 Room, 2 Creature, 3 Trap, 4 Door, 5 KeeperSpell. Нельзя пользоваться одной таблицей enum для обоих случаев.

OpenKeeper на закреплённом коммите оставляет тип 17 как Unknown. Поэтому это полезное дополнение к базовой схеме; в дампы добавлено пояснение `research_order_interpretation`, сырые записи не менялись.

## 2. Жертвоприношения

nsdr2025, 25 марта 2026, обсуждает тип `0x2B`. Сам тип и структура из трёх пар type/ID, rewardType, speechID, rewardValue уже совпадают со схемой OpenKeeper. Например, группа type=1 означает creature, type=3 keeper spell. В сообщении есть предположение об иконке; это не доказанное поле и в схему как факт не перенесено.

BlueFire в январе/ноябре 2022 описывает зависимость рецептов от GlobalVariables и проблемы сохранения индивидуальных изменений старым редактором. Поддержка изменения сырых записей не доказывает, что любое переопределение будет принято движком во всех версиях.

## 3. Hate Jobs

BlueFire, 26 ноября 2022: третий Hate Job исчезает после сохранения/загрузки. Бинарная схема подтверждает **два** штатных u32 Hate Jobs в основной группе. Не строить три редактируемых слота по одному только количеству полей UI.

Поздний шаблон указывает ещё две 4-байтовые области по `0x14E1` как неиспользуемые Hate Jobs 3–4, которые редактор не записывает, а игра перезаписывает. Это дополнительная интерпретация шаблона, не повод включать ещё два рабочих слота в интерфейсе.

## 4. HP и ограничения UI

BlueFire, 15 ноября 2022, сообщает о базовом HP выше 32767. Поле Creatures по `0xF0C` действительно **u16**, оно вмещает 0..65535. Диапазон старого контрола с максимумом 32767 не является диапазоном бинарного поля. Сообщение об итоговом HP порядка 800000 относится к дальнейшим игровым модификаторам, не к прямому хранению такого числа в u16.

## 5. Расширение каталогов

Обсуждения февраля 2022 подтверждают практическую необходимость различать ID, порядок отображения в редакторе и количество записей. Для Creatures поле OrderInEditor по `0xCF6` отделено от CreatureID по `0xF4B`. Нельзя просто дублировать запись и оставить оба значения прежними.

В ветке описаны игровые/редакторские особенности отдельных ID, включая проблемы ID 80 в панели существ версии 1.7. Это исторические наблюдения, не проверенный список допустимых ID текущей Flame.

Есть обсуждения того, как редактор удаляет неизвестные ему записи исследований/новых заклинаний после пересохранения. Для нового редактора существенно сохранять неподдержанные записи побайтово, не заменяя их нулями или известными по умолчанию элементами.

## 6. Ограничения старого редактора и игры

В ветке есть сведения о 80/255 action points, рекурсивной заливке и стеке, ручной правке размеров области строительства игрока после Resize, привязке скриптов к членам Hero Party, различиях версий для эффектов. Это полезные направления проверки. Формат поля, ограничение UI и ограничение движка нужно рассматривать отдельно.

Примеры, которые нельзя принимать буквально: в одном обсуждении ошибочно названо `FF = 256`; верно `0xFF=255`. Также из предельной координаты нельзя делать вывод о 16/32-битности приложения. Оригинальные DK2 и редактор — x86 32-bit.

### Дополнительные имена для Creatures

Это **интерпретации дополнительного шаблона**, а не независимый результат тестирования движка в этой задаче. Смещения лежат внутри уже восстановленных записей; исходные байты и базовая схема OpenKeeper сохранены.

| Смещение | Имя OpenKeeper | Уточнение нового шаблона |
|---|---|---|
| `0xCEC` | Unkcec | SwipeSpeed, скорость first-person swipe |
| `0xCEE` | Unkcee | WorkModifierDefault; по комментарию движок использует фиксированное 0.8 вместо этого поля |
| `0xCF2` | Unkcf2 | WorkModifierLevelIncrease |
| `0xEA0` | Unkea0 | Width, ширина столкновения; радиус = width/2 |

Последующая декомпиляция игры подтвердила u16, деление на TPS и полный оборот 2048 единиц. Базовая схема оставлена для аудита, а в дампы добавлено правильное представление `engine_fields`. Подробности — ENGINE_FINDINGS_RU.md.

### Два места дополнительных флагов

OpenKeeper называет DWORD `0x1545` Flags3 (неизвестные флаги), а DWORD `0x1599` в длинной записи — Flags2 с именами lightning immunity / Stone Knight / emotionless / hero portal. Новый шаблон утверждает, что игра использует именно `0x1545`, а редактор сохраняет свои флаги в `0x1599`.

Оригинальный декодер редактора `0x004287C0` читает `record+0x1599`. Последующая проверка игры подтвердила чтение **0x1545** конвертером 0x568E30 и перенос в runtime+0x68A. Проверены отдельные пути применения битов 1/4/8. Оба слота сохранены раздельно, автоматического зеркалирования нет. Подробности — ENGINE_FINDINGS_RU.md.

### Конфликт Variables 66

OpenKeeper и исторический компилятор трактуют тип `0x42=66` как alliance. У NovFR `Compiler_GenerateAlliesVariables` буквально записывает этот тип. Новый шаблон подписывает его ManaGenerationForJob. В запрошенном GlobalVariables нет записей типа 66. Конфликт разрешён по игровому callback **0x51DC90**: он использует два ID игроков и записывает симметричный союз. Для исследованного DKII-DX.exe имя Alliance подтверждено; подпись нового шаблона не принята.

## Практический итог для исследования

Ветка дала полезную проверку структуры, новый смысл записей `0x11` и список направлений для разбора неизвестных полей. При этом она хорошо показывает, почему комментарий сообщества, имя поля библиотеки и реальное поведение движка нужно фиксировать раздельно.
