## Подтверждённые флаги

Установлена вся цепочка по EXE: constructor4322B0 выбирает ресурс278; fill4323A0 читает маски из model+38; DDX432530 связывает DWORD панели с control ID; apply432850 вызывает setters. Подписи получены из PE-ресурса `[5,278,2057]`, а не из OpenKeeper. Этим закрыта оговорка этапа33 о неподтверждённой привязке подписи к биту.

| Control ID | Подпись native-ресурса | DWORD панели | Маска Flags | Setter |
|---:|---|---|---:|---|
|1836|Reveal Through Fog Of War|+68|0x10|41B930|

|1841|Tool Box|+70|0x20|41B970|

Flags в файле — WORD по raw+12, в editor-модели — BYTE+38. Панель меняет только маску `0x71`, остальные биты байта `0x8E` сохраняет, включая `0x04/0x08`. Их игровой смысл не установлен. Отдельный writer этапа33 может устанавливать0x04 всем AP при наличии хотя бы одной ненулевой waypoint-связи.

Apply считает переключатель включённым только при DWORD==1. Значения2 иFFFFFFFF очищают соответствующий бит; setters получают уже нормализованный младший байт. Три эмуляции сравнивают все60 байт модели с различимыми значениями: изменяются next+34, wait+36..37 и flags+38, сохраняются ID, координаты и остальные байты при указанных UI-заглушках.

Подпись Ignore Solid не подтверждает проход сквозь стены. Сохраняется вывод этапа33: проверенный C5-loader игры не переносит raw0x40 в runtime, а patrol при установленном runtime0x40 отвергает определённые клетки до вызова перемещения.

## Wait Delay и ID

Wait Delay control1837 связан с panelDWORD+60. DDX432530 передаёт в4E4B5D границы0..32767; fill задаёт те же пределы spinner1838 сообщением0x465. Apply копирует младшие16 бит в modelWORD+36. Прямой вызов с непроверенным DWORD подтверждает сужение, но не означает, что такой ввод принимается настоящим GUI. Поле raw+10 хранит все16 бит. Игровой таймер `low16(WaitDelay*TPS)` описан отдельно.

Action Point ID control1449 имеет ES_READONLY в шаблоне; panel+5C заполняется существующим ID, apply не пишет его обратно. Команда41B840 выбирает **первый свободный ID1..80**, просматривая массив AP настоящим getter48A910. Занятые0/81..255 не расходуют эти значения. Если заняты все1..80, возвращает AL=0 и оставляет прежний modelID без изменения.

Это диапазон команды создания, а не доказанный предел загрузчика игры. Raw+16 — byteID: наш редактор должен сохранять0/81..255. При успехе native-код также форматирует `Action_Point_%u`; CString helpers в эмуляции заменены, проверены выбор и запись ID.

## Next Waypoint и самоссылки

Builder4325C0 создаёт первый элемент `<none>` с byte0, затем перебирает AP в исходном порядке. Исключает **все записи с ID, равным текущему ID**, сравнивая значения, а не указатели. Другие повторяющиеся ID остаются. Lookup432820 возвращает индекс первого совпадения, при отсутствии —0. Apply записывает выбранный byte в model+34.

Самоссылка next==собственный ID отсутствует в вариантах и отображается индексом0. Применение такой панели проецирует next в0; отсутствующая цель ведёт к тому же результату. При единственном AP fill отключает combo1453 и label2140, сохраняя описанный способ формирования модели выбора.

Размер вспомогательного массива panel+84 равен числу AP. Если несколько записей имеют текущий ID, видимый список короче массива; в свежих проверенных буферах оставшийся хвост нулевой. `next_choices()` возвращает логические варианты без хвоста. Apply локально не проверяет индекс; диагностический API отклоняет выход за границы.

В109 Things-файлах исследованного корпуса3422 AP. Обнаружены **170 самоссылок в31 файле**: например, `level1Things.kld`, ID1→1, и `level2Things.kld`, ID13→13. Все170 изменений, предсказанных проекцией панели, относятся именно к самоссылкам; отсутствующих целей нет. Это проверка файлов и композиции функций, не наблюдение сохранения через настоящее окно Windows. В корпусе нет повторяющихся AP ID, ID0, ID>80 или WaitDelay>32767. Неизвестный bit04 установлен3193 раза, bit08 —65 раз.

Для нашего редактора raw next надо сохранять до явной правки. Самоссылка встречается в штатных данных; превращать её в0 при открытии/сохранении нельзя. Native-проекцию следует применять отдельно, если требуется воспроизвести Editor Pro.

## Воспроизводимость и границы

`action-point-editor-semantics.json` —45-й компонент пакета. `native_action_point_editor.py` моделирует поля панели, apply, auto-ID, варианты и lookup без изменения файлов. `emulate_action_point_editor.py` сохраняет полные входы/выходы EmulatorHelper; `audit_action_point_editor.py` проверяет доказательства и пересборку.

46 native-прогонов:7 фрагментов fill,17 полных apply с чтением выходных полей,3 apply с побайтным сравнением всех60 байт модели,2 полных DDX с записью control ID и сравнением32 байт `(ID,pointer)`,5 полных auto-ID,4 lookup и8 полных choice builder с сравнением всего массива. Четыре дополнительных builder начинают с null-pointer и A5-буфера, вызывают allocation fixture и настоящий zero helper403CA0; нули начального элемента и хвоста получаются из native-кода. DDX helpers, UpdateData/закрытие окна, CString, родитель карты и оконные сообщения заменены явно. В четырёх исходных случаях builder использует предварительно выделенную нулевую память и заглушки array-reset/zeroing; в четырёх дополнительных zeroing выполняет настоящий403CA0. Реальные allocator/reallocator и оконные контролы не проверены. В auto-ID работает оригинальный bounded array getter.

Аудит:4603 граничных случая;252 точечных пересборки реальных Things в памяти, включая ID81/255, Wait32768/65535 и полные FlagsWORD. Сравнение с ожидаемой заменой только выбранного диапазона подтверждает сохранность остальных байтов контейнера.583 инструкции,13 повторных disassembly и13 диапазонов живой памяти Ghidra побайтно совпадают с PE.17 входных файлов и2 EXE сохранили SHA-256. Результаты — `phase34-validation.json`. Реальная игра и GUI не запускались с изменёнными данными.

Unknown04/08, эффект WanderRadius и неизвестные поля каталогов остаются открытыми; общий анализ продолжается.
